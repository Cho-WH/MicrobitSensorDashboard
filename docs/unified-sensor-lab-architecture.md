## 1. 설계 결정과 범위

**게이뤼삭 앱의 준비·측정·저장·분석 구조를 이 저장소로 이식하고, 센서 정의와 활동 정의를 분리한다.** 대시보드에서는 링크 복사·QR과 센서 항목 표시 방식을 재사용한다. M3는 도구의 공개 진입 주소 공유로 한정하며, 교사 실험 JSON의 서버 보관·배포는 후순위다. 센서·활동마다 앱을 복제하지 않는다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 언어·UI | JavaScript ES Modules + JSDoc, 기존 DOM·CSS 컴포넌트 | 기존 코드와 UX를 보존하며 채널 일반화에 집중한다. React/Vue 전환과 전체 TypeScript 재작성은 하지 않는다. |
| 구성 방식 | 하나의 앱 제어기에서 모듈을 생성·연결 | 전역 이벤트 버스·DI 프레임워크·서비스 로케이터 없이 의존성을 드러낸다. |
| 분석·저장 | 게이뤼삭의 Workspace / RunStore / Repository 분리 유지 | 화면 상태, 작업 정의, 원자료, DB 쓰기의 소유권을 혼합하지 않는다. |
| 센서·활동 확장 | 빌드에 포함되는 명시적 레지스트리 | 서버 플러그인·사용자 코드 실행·원격 모듈 설치 없이 필요한 확장만 허용한다. |
| 장치 | 초기 실물 기준은 micro:bit V2, USB 설치 + BLE UART 측정 | 원본 프로그램 전송 어댑터의 V2 확인을 유지한다. V1은 센서·HEX별 검증 후 명시적으로 추가한다. |
| 외부 의존성 | 기존 고정 배포본과 공식 USB 라이브러리 재사용 | 측정 중 CDN이나 다른 저장소의 최신 코드에 의존하지 않는다. |
| 개발 도구 | Node 테스트 러너, 작은 정적 빌드·개발 서버, JSDoc 타입 검사 | 서버 런타임·프런트엔드 프레임워크·범용 번들러를 필수로 만들지 않는다. |

센서 앱의 `lab.sco.pe.kr` 연결과 기존 주소 전환은 §12.4에 포함한다. 상위 포털은 앱 소개·실행 링크의 연결 경계만 다루며, 다른 교육 도구의 이전·포털 자체 기능은 범위 밖이다. 현재 앱 내부 경로·자원은 설치 위치에서 계산한다. M3에서는 외부 배포 설정의 `publicBaseUrl`로 공개 공유 주소와 OG 메타데이터를 생성한다. Cloudflare를 사용하는 후속 교사 자료 공유의 저장·API 경계는 §10에 두며, 기본 측정·분석·도구 공유에는 공유 API·DB를 필수로 만들지 않는다. 기능 변경은 기획서, 내부 계약 변경은 이 문서를 기준으로 함께 갱신한다.

## 2. 재사용 기준과 이식 범위

### 2.1. 기준 원본

- **D:** [대시보드 `303a0bb`](https://github.com/Cho-WH/MicrobitSensorDashboard/tree/303a0bb957472d3a762ab05c6a2a043bedd29e8d).
- **G:** [bme280 `59c5c14`](https://github.com/Cho-WH/bme280/tree/59c5c149450f970bace2deaa183857c275595853). 아래 G 경로는 별도 표기 없으면 `gay-lussac/` 기준이다.
- G의 [기존 아키텍처](https://github.com/Cho-WH/bme280/blob/59c5c149450f970bace2deaa183857c275595853/gay-lussac/ARCHITECTURE.md)는 상태 소유권과 기존 동작의 근거다. 이 문서의 범용 채널·활동 계약이 이식 후 목표다.

재사용은 **고정 커밋에서 코드를 가져와 이 저장소가 유지보수하는 방식**이다. 실행 시 타 저장소를 import하거나, 원본 앱을 iframe에 넣어 통합 앱으로 가장하지 않는다. 3D 배선 뷰어만 독립 표시 자원으로 재사용한다. 이식 커밋에 원본 경로·커밋·변경 목적을 남긴다.

## 3. 라이브러리와 오픈소스

다음 버전은 G의 [vendor 기록](https://github.com/Cho-WH/bme280/blob/59c5c149450f970bace2deaa183857c275595853/gay-lussac/vendor/README.md)에 있는 **이식 기준 고정본**이다. 최신 버전이라는 의미가 아니다. 이식 시 실제 파일의 해시와 고지를 다시 확인한다.

| 기능 | 채택 | 접근 위치 | 선택 근거 |
|---|---|---|---|
| 그래프·PNG | Chart.js 4.5.0 / MIT | `ui/chart-view.js` | 기존 상호작용·시간선·산점도·출력을 유지한다. |
| IndexedDB | idb 8.0.4 / ISC | `data/repository.js` | 기존 트랜잭션 구조와 `tx.done`을 재사용한다. |
| CSV | Papa Parse 5.7.0 / MIT | `data/files/csv.js` | 따옴표·줄바꿈 처리를 직접 재구현하지 않는다. |
| USB 설치·HEX | 기존 microbit-usb 번들: microbit-connection 1.0.0, universal-hex 0.2.2 / MIT; nrf-intel-hex 1.4.0 / BSD-3-Clause | `device/programmer.js` | 검증된 공식 전송 경로와 포함 의존성 고지를 유지한다. |
| QR | Project Nayuki 고정 소스 / MIT + D의 SVG 래퍼 | `sharing/qr-adapter.js` | 버전 태그를 추측하지 않고 이식한 파일 SHA와 출처로 고정한다. |
| 아이콘 | 기존 Lucide 0.468.0 SVG / ISC | UI의 로컬 SVG 자원 | 전체 아이콘 런타임 없이 필요한 심벌만 재사용한다. |
| 표 | 기존 HTML table 가상화 | `ui/data-table.js` | 원자료 읽기·선택·정렬·계산 표시에는 현행 표를 유지한다. |
| 단위·수식·회귀 | 기존 제한된 계산 엔진 | `analysis/` | 사칙연산·거듭제곱·선형회귀를 재사용하고 임의 JavaScript 수식을 실행하지 않는다. |

UMD 배포본의 `globalThis.Chart/idb/Papa` 접근은 위 어댑터 내부로 제한한다. 그 객체·라이브러리 타입을 도메인 계약에 노출하지 않는다. USB 번들 재생성은 원본 `dev/usb-library/`의 lockfile·빌드 스크립트와 esbuild 0.25.12를 함께 이식한다. 일반 앱 코드를 빌드하기 위해 USB 번들을 매번 재생성하지 않는다.

초기 도입에서 제외하는 도구는 React/Vue, Redux/RxJS, XState, Dexie, 대형 데이터 그리드, math.js, 추가 3D 엔진이다. 이들은 나쁜 도구라서가 아니라 기존 동작을 대체할 실익이 아직 없기 때문이다. 복잡한 셀 편집·다중 시트·수식 언어·고속 수집을 실제 범위로 채택할 때 해당 어댑터만 재검토한다.

`vendor/manifest.json`에는 정확한 파일·버전 또는 커밋·출처·SHA-256·라이선스 파일·변형 여부를 기록한다. 원본 헤더와 제3자 고지는 보존한다. bme280 루트에는 이번 확인 범위에서 공통 LICENSE 파일이 없으므로 자체 작성 코드의 적용 라이선스는 이식 시 명시하고, 제3자 코드·3D 자산에 같은 라이선스를 임의 적용하지 않는다. 출처가 불명확한 자산은 공개 이식 전에 확인하거나 검증된 그림으로 대체한다.

## 4. 모듈 구조와 의존 방향

```text
src/
  app/          bootstrap.js, controller.js, router.js,
                context-resolver.js, capabilities.js
  domain/       contracts.js, validation.js, columns.js
  catalog/      index.js
    sensors/    bmp280/{definition.js,codec.js}
                magnetometer/{definition.js,codec.js}
    activities/ gay-lussac/{definition.js,policy.js,content.js}
  device/       ble-client.js, transport.js, programmer.js
  guide/        steps.js, progress.js, viewer-adapter.js
  measurement/  session.js, reception-monitor.js, diagnostics/
  data/         run-store.js, repository.js
    files/      json.js, csv.js, validation.js, legacy-gay-lussac.js
  analysis/     workspace.js, scope.js, table-data.js, calculations.js,
                graph-data.js, regression.js, reflection.js
  sharing/      tool-link.js, qr-adapter.js  # 미리보기 공개 주소·QR
  ui/           home-view.js, guide-view.js, measurement-view.js,
                analysis-view.js, share-view.js, chart-view.js,
                data-table.js, 기존 공통 UI 모듈
public/         vendor/, firmware/, viewers/, assets/
scripts/        dev.mjs, build.mjs
tests/         unit/, browser/, fixtures/
```

목표 책임 배치이며 모든 파일을 빈 껍데기로 선생성하지 않는다. 재사용 UI의 세부 분리는 유지하고 기능이 필요한 단계에 파일을 옮긴다. 후속 교사 자료 공유의 API·파일 수신 모듈은 해당 단계에서 추가한다. `utils`나 `common`에 무관한 업무 로직을 모으지 않는다.

호출 방향은 **UI의 사용자 행동 → App 제어기 또는 Workspace 명령 → 도메인 처리 → RunStore → Repository**다. 센서·활동 정의와 분석 계산은 DOM·IndexedDB·장치를 참조하지 않는다. 장치 어댑터는 읽기 입력을 전달할 뿐 Workspace나 화면을 변경하지 않는다.

| 소유자 | 소유하는 상태 | 경계 |
|---|---|---|
| AppController | 현재 화면, 탐색 중 설정, 활성 실험 참조, 준비 확인 | 모듈 생성·호출 순서만 소유. 샘플·회귀·DB 배열을 별도로 만들지 않는다. |
| Transport / Programmer | 연결 시도·장치·타이머 / USB 전송 작업 | 라이브러리 및 브라우저 자원을 감싼다. |
| MeasurementSession | 기록 게이트, 샘플 순번, 수신 진단·활동 진행 상태 | 표준 Reading만 소비하고 샘플·사건을 RunStore에 전달한다. |
| RunStore | 열린 Run, 원자료·사건·미저장 변경, 저장 상태·잠금 | 모든 기록 변경의 단일 진입점. |
| Workspace | 분석 대상·제외·계산식·축·근거·해석·revision | 직렬화한 불변 작업 사본만 RunStore에 전달한다. |
| View / 표·차트 어댑터 | DOM, 캔버스, 스크롤, 편집 초안 | 저장·연결·실험 종료를 소유하지 않는다. |

생성 함수에는 필요한 의존성만 인자로 전달한다. 시계·타이머·BLE·Repository 같은 외부 효과는 테스트 대체가 가능하게 하고, 매 함수 호출을 감싸는 범용 인터페이스 계층은 추가하지 않는다.

### 실제 앱 시작 경계

현재 앱의 고정 틀·초기 스타일은 `lab.html`이 선언한다. `startApp(root, options)`은 필수 스타일·서체 결정을 거쳐 Controller를 만들고, 반환된 `ready`가 최초 경로 적용·렌더를 끝낸 뒤 조작을 공개한다. 이는 장치 연결이나 기록 시작 완료를 뜻하지 않는다. 초기 로딩·실패 안내는 bootstrap과 HTML이, 메뉴·설정창 이벤트는 Controller 수명에 묶인 `bindAppShell`이 맡는다. 개발·전체 앱 검사는 같은 시작 경로를 사용하고, View 단위 검사는 Controller 생략을 명시한다. 측정·분석 작업 영역의 남은 높이는 공통 표시 도우미가 전달하고 내부 배분은 각 화면 CSS가 맡는다. 개발 서버와 빌드는 같은 CSS 결합 함수를 사용한다. 이들은 Session·RunStore·Workspace 상태를 소유하지 않는다. 현재 시각 규칙의 소유권은 [디자인 문법](design/visual-language.md#8-기본-ui-구조)을 따른다. 전환 과정은 [구조 전환 이력](design/history/design-implementation.md#기본-ui-구조-전환)에 보존한다.

### 최소 공개 인터페이스

패널의 표시 전환은 `ui/panel-transition.js`가 전환 전 높이 측정, 애니메이션 수명, 크기·서체·움직임 설정 변경에 따른 취소와 일반 접이식 안내의 공통 활성화를 소유한다. 앱 전체의 안내는 `bindAppShell`에서 연결하고, 준비 화면은 자체 전환 관리자로 단계 이동과 접이식 안내를 함께 처리한다. 각 View는 그 밖의 DOM 갱신·초점과 전환 대상을 결정하며 데이터·측정 상태는 이 모듈에 전달하지 않는다. 자동 적용·제외 조건과 공통 전환의 사용 계약은 [디자인 문법 §5](design/visual-language.md#공통-패널-전환)를 따른다.

다음 이름은 이식 후 목표 API다. 기존 내부 함수의 이름을 모두 바꾸기 위한 요구가 아니라 모듈 사이에서 합의할 호출면이다.

| 모듈 | 공개 호출 | 반환·효과 |
|---|---|---|
| 구성 해석 | 등록된 경로와 센서·활동 참조 해석 | 직렬화 가능한 검증된 구성 또는 구성 오류. M3에 수업 설정 병합을 추가하지 않음 |
| 연결 | `connect(context, onInput, onState)`, `disconnect(reason)` | 표준 Reading/오류·연결 상태; 기록 여부에는 관여하지 않음 |
| USB | `prepare()`, `install()`, `dispose()` | 진행 상태와 전송 결과; 활성 기록 변경은 Controller가 담당 |
| 세션 | `acceptInput(input)`, `pause()`, `resume()`, `finish()`, `startAdditional(confirmation)` | 입력 게이트·순번·사건; 저장은 주입된 RunStore 사용 |
| RunStore | `appendSample()`, `appendEvent()`, `saveWorkspace()`, `getSnapshot()`, `flush()` | 원자료·사건·분석 사본의 단일 변경 경로와 일관된 사본 |
| 증분 읽기 | `readSamples({ afterId, throughId })`, `getLatestSample()` | 해당 구간의 읽기용 자료만 반환; 내부 변경 가능 배열을 노출하지 않음 |
| Workspace | 범위 적용·제외·계산 열·그래프·새 자료 반영·근거 보관의 명시적 명령 | 한 행동을 한 revision으로 확정하고 RunStore에 전달 |

검증 오류는 `code`와 필요한 세부 정보를 포함해 호출자에게 전달하고, 화면에서 학생용 문장으로 바꾼다. 예외를 삼킨 뒤 기본 센서나 빈 데이터로 성공처럼 진행하지 않는다.

## 5. 센서·활동·자료 구성 계약

### 5.1. 선언과 실행 코드 분리

| 계약 | 필수 내용 |
|---|---|
| `SensorDefinition` | `id`, `version`, 한국어 이름, 지원 보드, 채널 목록, 펌웨어 참조, codec ID, 배선·보정 안내, 연결 정책, 기본 시간 그래프 |
| `ChannelDefinition` | 안정된 `id`, 이름, 수량 종류(`quantity`), 저장 단위, 선택적 물리량 표시명(`quantityLabel`), 표시 자릿수, 지원 여부, 유효성 범위, 계산·축 사용 가능 여부 |
| `FirmwareArtifact` | `id`, `version`, 로컬 경로, 보드, SHA-256와 해시 정규화 방식, codec ID, 시작 명령, 검증 상태, 알려진 측정 간격 |
| `ActivityDefinition` | `id`, `version`, 호환 센서, 필수 채널, 준비 단계, 활동 사건, 기본 분석 제안, 질문·내용, policy ID |
| 도구 공유 대상(M3) | 현재 미리보기 중인 등록 센서·활동의 소개 경로. 제목·채널·그래프 등의 설정 payload 없음 |
| 교사 공유 자료(후순위) | 검증된 실험 자료 사본, 수업 안내, 형식 버전·출처와 서버 측 만료 정보. 세부 계약은 §10에서 구분 |
| `ResolvedExperiment` | 검증된 센서·활동 사본, 채널 카탈로그, 펌웨어 참조, 조립된 준비 단계 |

정의와 저장 사본에는 함수·DOM·장치 객체가 없다. codec과 활동 policy는 레지스트리의 신뢰된 로컬 함수이며 ID로 연결한다. URL이나 가져온 JSON에서 모듈 경로·펌웨어 URL·실행 함수를 받지 않는다.

구성 해석은 센서 지원 범위와 활동 필수 조건·기본값을 검사·결합하는 순수 처리다. M3의 도구 링크는 이를 바꾸지 않는다. 임의 deep merge 대신 필드별 허용 목록을 사용하며, 파일·URL 입력으로 필수 채널·단위·펌웨어·전송 명령·보정 조건을 덮어쓰지 않는다. 학생의 이후 분석 변경은 Workspace에만 반영한다.

일반 진입과 M3 도구 링크는 등록된 현재 도구를 연다. 과거 정의 버전을 고정하는 cfg 계약을 새로 만들지 않는다. 과거 Run·가져온 파일은 보관한 정의 버전과 사본을 사용하며 없는 버전을 최신으로 조용히 치환하지 않는다. 해당 실행 정의가 없어도 자료 분석·파일 내보내기와 근거 읽기는 가능해야 한다. 기존 `context.classConfig` 필드의 읽기·보존은 유지하되, M3의 URL 입력이나 새로운 편집 기능으로 연결하지 않는다.

M2의 등록 지점은 `src/catalog/modules.js`다. 센서 모듈의 정의·codec·모의 입력·준비 안내,
활동 모듈의 정의·준비 안내·policy를 묶어 등록한다. 홈 목록과 정적 진입 주소도 같은
등록에서 만든다. 설치 가능한 펌웨어 허용 목록은 별도 검증 경계로 유지한다.
확장 절차와 현재 한계는 [모듈 등록 안내](../src/catalog/README.md)에 정리한다.

공통 화면의 문구는 `catalog/ui-copy.js`의 기본값을 사용하고, 등록 모듈의 선택적
`uiCopy`로 필요한 항목만 덮어쓴다(공통 → 센서 → 활동). 표시 문구와 공통 준비 단계의
제목·설명만 대상으로 하며 저장 context·수업 설정·장치 조건은 변경하지 않는다.
홈·탐색 대상·현재 실험·보관한 분석 자료는 각자의 문맥으로 문구를 해석한다.

### 5.2. 구현된 센서·활동

| 구분 | 구성 |
|---|---|
| BMP280 | `temperatureC`, `pressureHpa`. 원본 3열은 온도·습도 자리·압력 순서, 시작 명령은 `bme\n`. 습도 자리는 미지원이며 0% 측정값으로 표시하지 않는다. |
| 내장 자기장 | X/Y/Z/크기, 저장 단위 `µT`; 한국어 화면은 자기장 성분·크기로 표시. 4열 수치와 보정 상태를 분리한 v2 규약으로 HEX를 생성·검증한다. |
| 내장 온도 | `temperatureC`, `℃` (기존 BMP280와 같은 단위 표기), 1초 명목 간격. 보드 기반 근사 온도임을 안내하며 `temperature-csv-v1` 1열을 해석한다. |
| 내장 밝기(조도) | `lightLevel`, 단위 `상대값`, 범위 0–255, 100ms 명목 간격. lux로 환산하지 않으며 `light-level-csv-v1` 1열을 해석한다. |
| 내장 가속도 | `accelerationX`, `accelerationY`, `accelerationZ`, `accelerationStrength`, 센서 정의 v2의 기록 단위 `m/s²`, 100ms 명목 간격. 기존 `accelerometer-csv-v1` 4열(mg)을 수신 시 환산해 모두 저장하고 기본 그래프는 크기만 표시한다. |
| 게이뤼삭 | BMP280 정의를 참조하고 용기·수조 준비, 배치·가열·물 추가 사건, 온도–압력 그래프와 탐구 질문을 추가한다. 별도 펌웨어·분석 엔진은 만들지 않는다. |

새 채널 ID는 센서 정의에서 고정하고 표시 이름 변경과 분리한다. 기존 `temperatureC`, `pressureHpa`는 유지한다. 자기장 채널은 `magneticX`, `magneticY`, `magneticZ`, `magneticStrength`로 정의하고 구형 기본 필드 `x/y/z/strength`는 호환 어댑터에서만 대응시킨다. 알 수 없는 사용자 정의 필드를 이름만 보고 특정 물리량으로 추정하지 않는다.

일반 측정의 기본 분석은 시간–대표 채널, 게이뤼삭은 온도–압력이다. 센서 선택은 측정 환경을 준비하고 활동 선택은 탐구 맥락을 추가한다. 분석 구간·제외·해석을 자동 확정하지 않는다.

추가 내장 센서 세 개는 공통 준비물·설치·연결·새 수신 확인만 사용하며 외장 배선·자기장
보정·게이뤼삭 활동은 붙이지 않는다. 모두 `start`로 송신을 시작하고 다른 명령이나 단절에서
중단하며, 재연결 후 자동 재개하지 않는다. 첫 유효값 제한 5초, 시작 재시도 1초 간격 최대
3회, 준비 확인 유효값 3개·1초 이상, 중단 판정 5초를 적용한다. 실제 간격을 보장하는 장치
시각은 없으며 수신 시각으로 기록하므로 고속 진동 분석을 지원한다고 표시하지 않는다.
밝기의 초기 준비용 0만 버리고 실제 어두움의 0은 보존한다. 가속도 ±8g 설정과 중력 포함,
정지 상태 크기 약 9.8m/s²의 의미는 준비물 도움말에 명시한다.

가속도 전송 프로그램·HEX·해시는 유지한다. MakeCode가 명시하는 milli-g 단위에 따라 수신 codec에서 `m/s² = mg × 9.80665 / 1000`으로 한 번 환산하며 저장 전에 반올림하지 않는다. 9.80665m/s²는 단위 g의 표준 중력가속도이며 실제 기기의 영점·감도 보정을 대신하지 않는다. [MakeCode 단위 설명](https://makecode.microbit.org/reference/input/acceleration)

측정·기록의 `g로 보기`는 SI 가속도 채널에만 제공하는 View 상태다. 숫자 카드·실시간 그래프(툴팁 포함)는 저장값을 9.80665로 나누어 그린다. X/Y/Z/크기는 같은 단위와 축을 유지하며, 원자료·Session·Workspace·JSON/CSV에는 토글 상태나 변환된 표시값을 쓰지 않는다. 다른 실험을 열거나 다시 접속하면 기본 SI 표시로 시작한다.

기존 센서 정의 v1은 `mg` 자료 해석용으로 등록을 유지하고 해당 로컬 모듈의 `recording:false`로 장치 실행만 제한한다. 기존 자료의 값·단위·분석은 자동 변환하지 않는다. 이전 기록에 SI 수신값을 이어 붙이지 않으며 새 측정은 v2 실험에서 시작한다. `codecId`는 기존 전송 형식을 식별하고, 디코딩 후 단위는 센서 정의 버전으로 구분한다.

### 5.3. 준비 단계와 활동 policy

준비 단계는 `id`, 종류, 제목·내용 참조, 완료 근거, 의존 단계 ID를 갖는 작은 목록이다. 공통 USB·수신 단계, 센서 배선·보정 단계, 활동 장치 구성 단계를 정해진 슬롯에 조립한다. 범용 워크플로 편집기나 임의 그래프 실행 엔진은 만들지 않는다.

현재 조립 슬롯은 센서의 `beforeProgram`·`afterConnect`, 활동의 `afterReception`이다.
공통 조립기와 준비 UI는 센서 ID로 분기하지 않는다. 단계의 그룹·문구·요약 확인 여부와
3D·도움말 자원은 해당 모듈이 제공한다. 준비 안내와 활동 policy도 정확한 등록 버전으로
해결하며, 저장 파일의 임의 안내·실행 정보는 사용하지 않는다.

V3의 센서별 수신 설명은 기존 모듈 `uiCopy.guide`를 사용한다. 활동 단계는 짧은 `description`과 선택적인 `instructions` 목록으로 표시하며, 이 목록은 안내일 뿐 추가 완료 조건이나 저장 상태를 만들지 않는다.

완료 근거는 사용자 확인과 장치 관측을 구분한다. 배선 그림을 보았다는 사실이 센서 통신 성공을 뜻하지 않으며, 과거 열람 이력으로 현재 수신 확인을 대신하지 않는다. 센서·펌웨어·연결 시도가 바뀌면 관련 준비 확인만 무효화한다.

#### M2 준비 UI 연결 계약

- Transport가 준비용 연결 시도·새 수신·최근 유효 수신 시각을 소유한다. `getState()`는 호출 시점의 신선도를 검사한다. 모의 장치도 같은 Transport와 codec을 거치며 controller에 두 번째 수신 monitor를 두지 않는다. Session의 monitor는 기록 구간의 공백·사건 판정에만 사용한다.
- GuideProgress는 수동 확인·설치 근거·현재 시도에서의 보정·배터리 확인을 소유한다. GuideView는 선택한 단계·표시 방식·확인 초안만 변경하고, 장치 조작은 `onInstall`, `onConnect({reuseDevice})`, `onDisconnect`로 controller에 요청한다. controller는 Transport의 사실과 Programmer의 상태, 기록/저장 가드를 `GuideFacts`로 전달한다.
- 준비 체크와 측정 허용은 분리한다(2026-10-20). `ready`는 준비 체크 완료 이력이고, `canMeasure`는 현재 연결과 정상 연속 수신 여부다. 연결·수신 단계와 준비 결과의 측정 이동은 `canMeasure`로 판단한다. 기록 시작·재개는 Transport의 현재 유효 수신을 다시 검사하며 수동 체크를 요구하지 않는다. 체크하지 않은 설치·보정·배터리·배치는 완료로 바꾸지 않고 `setup`에 실제 근거만 저장한다. 수신 중단·새 연결 시에는 이전 수신으로 시작할 수 없다.
- 수동 단계의 주 버튼은 확인 성공 후 다음 단계로 이동한다. 프로그램·연결·수신·배터리 단계의 다음 이동은 해당 완료 조건을 만족해야 한다. 이전·그룹 탐색은 확인을 만들지 않는다. 마지막에는 완료 요약과 아직 필요한 항목을 보여 주고, `onMeasure`는 화면만 전환한다.
- 준비된 장치 경로는 준비물·배선·프로그램을 사용자가 각각 확인하는 요약이다. 현재 수신·보정·배터리·활동 조건을 자동 확인하지 않는다. 설치 중에는 단계·구성 변경을 막고, 연결 중에는 취소를 사용할 수 있다. 실패 후 재시도는 기존 시도 근거를 무효화한다.
- 그림·도움말·활동 안내는 등록된 센서/활동 content에서만 가져온다. 저장 파일의 임의 URL을 그림·iframe·실행 코드로 사용하지 않는다. 표시 채널·시간 범위는 UI 설정이며 모든 지원 채널의 저장을 유지한다.

활동 policy의 공개 형태는 `reduceActivity(state, command, facts) -> { nextState, events, error? }`다. 주입된 facts에서 기록 상태·수신 확인·배치 여부를 읽고 결과를 반환한다. 타이머·DOM·DB·BLE를 직접 조작하지 않는다. 공통 Session은 기본 메모를 처리하고, 게이뤼삭 policy만 `placement`, `heating-start`, `water-added` 등의 조건을 판단한다. 활동 진행 상태는 Session 한곳에서 소유하고, 별도 DB 상태를 중복 저장하지 않는다. 재열기 시 버전이 기록된 사건을 확정된 사실로 읽어 복원하며 새 수신 조건으로 과거 관측 결과를 다시 판정하지 않는다.

## 6. 장치 통신과 펌웨어

보드의 명령·상태·측정값·LED 표시와 용어는 [센서 프로그램 공통 동작 규약](sensor-program-contract.md), 설치 파일 생성과 버전 관리는 [펌웨어 빌드·배포](../dev/firmware/README.md)를 기준으로 한다. 이 절은 앱의 수신·준비·설치 경계를 정의한다.

### 6.1. 입력 경계

```text
BLE notification bytes
  → ble-client: UTF-8 스트림·줄 경계 복원
  → sensor codec: 필드 해석·채널별 유효성
  → Transport: attemptId·UTC 수신 시각·단조 시각 부여
  → 준비 미리보기 또는 활성 MeasurementSession
  → RunStore.appendSample / appendEvent
```

알림 하나를 CSV 한 행으로 가정하지 않는다. 나뉜 행·한 알림의 여러 행·CRLF를 처리하고, 재연결 때 decoder와 부분 행 버퍼를 비운다. 누적 프레임은 초기 상한 1 KiB로 제한한다. 초과 프레임은 오류로 보고하고 다음 줄부터 복구한다.

`Reading`은 `{ type:'reading', values, validity, rawExtra?, attemptId, receivedAt, monotonicAt }`다. 구조가 해석되지 않는 행은 `parse-error`로 보낸다. 빈 문자열을 `Number('')`로 0으로 만들지 않는다. 한 채널의 결측·범위 이탈이 다른 채널의 유효한 수치를 없애지 않도록 채널별 판정을 유지한다. 범위 밖 유한 수치는 기록하되 분석에서 구분한다. 미지원 습도 토큰은 필요 시 rawExtra에 보관하고 측정 채널 값은 null/unsupported로 취급한다.

수신 확인은 센서·활동의 필수 채널에 대해 수행한다. 값이 같아도 새 Reading이 들어오면 정상 수신이다. `attemptId`가 지난 콜백은 무시하고 연결·종료 작업은 직렬화한다. UI 이벤트의 사용자 활성화가 필요한 장치 선택은 불필요한 await 전에 실행한다.

일반 연결·이전 장치 재연결에도 연결 수립 6초, 서비스·특성 조회 단계별 2초, 알림 준비 6초의 제한 시간을 적용한다. 취소는 진행 중인 Bluetooth 요청의 응답을 기다리지 않고 연결 시도를 무효화하고 해제한다. 설치 연결 인계 도중 취소하면 인계도 중단하며, 늦게 완료된 작업이 측정 연결을 시작하거나 이후 연결을 정리하지 못하게 한다. 브라우저 장치 선택창은 앱에서 닫을 수 없으므로 선택창이 닫힐 때까지 중복 선택창을 열지 않는다.

### 6.2. 센서별 연결 정책

준비·측정·장치 설정의 연결 영역은 하나의 ‘연결에 문제가 있나요?’ 도움말 팝업을 공유한다. 전원·거리·잠시 대기, 다른 탭·앱 종료, 리셋 또는 USB·배터리 전원 재연결 순으로 일반적인 복구 행동을 안내한다. 센서별 보정 안내는 포함하지 않는다. 팝업은 연결·기록 상태를 변경하지 않으며 닫으면 호출 버튼으로 초점을 돌려준다.

BMP280의 이식 초기값은 원본의 첫 값 제한 3초, 시작 재시도 간격 300ms·최대 5회, 중단 판정 5초, 준비 확인 3개·1초다. 이것은 센서 공통 상수가 아니라 BMP280의 검증 기준값이다. [원본 설정][G-program]

자기장 통신 규약 v2는 연결 후 `prepare` → 장치의 선택 대기 응답 → 앱의 보정 시작/생략 선택으로 진행한다. 보정 시작·완료·생략은 각각 장치 상태 행으로 확인한다. 응답 대기·보정 중에는 수치 칸을 숨기고 센서 전용 안내를 표시한다. 완료 또는 생략 응답 뒤 첫 수치를 5초 안에 받은 후 공통 연속 수신 검사를 적용한다. 프로그램 응답 제한은 10초, 선택 응답은 5초, 보정은 120초이며 사용자 선택 자체에는 제한시간이 없다. 시간 초과·전송 실패는 연결을 정리하고 재연결을 안내한다. 재연결 시 이전 보정 근거를 지운다. 새 연결에서 장치가 이번 부팅 중 완료한 보정을 `calibrated`로 보고하면 선택을 반복하지 않고 수신 확인으로 이어간다. `calibrating`은 앱이 보정을 시작한 연결에서만 시작 확인으로 받으며 재연결 복원에 사용하지 않는다. 현재 연결의 `calibrated`와 새 측정값을 받기 전에는 보정 완료·측정 준비로 인정하지 않는다. 응답 자체가 없는 경우에는 기기가 보정 중이면 보정을 완료한 뒤 재연결하고, 그 외에는 보드 리셋 후 재연결하도록 안내한다.

보드의 완료 기억·전원 초기화·보정 중 응답 제한은 [센서별 계약](sensor-program-contract.md#4-센서별-계약)을 따른다. 앱은 과거 기록의 보정 근거를 현재 연결의 상태로 복원하지 않는다.

명령과 상태 순서, 전용 그림·버튼·문구·모의 동작은 자기장 모듈의 선택적 `preparation`에 둔다. 공통 Transport는 상태 이벤트를 해당 세션에 전달하고 수신 허용을 확인하며, 공통 GuideView는 모듈이 제공한 패널과 단계 제안을 사용한다. 상태 행은 Sample로 저장하지 않는다. 기록 시작의 `setup.calibration`은 `device-reported / skipped / unknown`으로 구별하고 전체 JSON에 보존한다. `device-reported`는 장치 보정 루틴의 종료 응답이며 물리적 정확도 보증은 아니다. CSV는 기존처럼 측정값·열 정보용이다. 사용자 결정에 따라 미배포 v1 펌웨어와의 호환을 요구하지 않는다. 이전 기록의 준비 상태를 현재 연결에 복원하지 않는다.

지원하지 않는 원격 측정 간격 변경을 UI에 노출하지 않는다. 기존 `basic.pause(100)`은 명목 간격이지 정확한 10Hz 보증이 아니다. 실험에는 실제 수신 시각을 저장하며 브라우저 도착 시간을 장치 측정 시각으로 표시하지 않는다. 고속 진동 측정용 장치 timestamp·sequence는 후속 프로토콜 범위다.

### 6.3. USB 설치·식별

USB 연결 안내는 별도 확인 단계 없이 프로그램 설치 단계에서 제공한다. 설치 성공과 기설치 사용자 확인은 기존처럼 구분한다. M6-2는 같은 화면의 글자 링크로 USB↔무선 설치를 전환하며 별도 단계나 창을 만들지 않는다. 설치 확인 뒤 기존 연결·수신·보정 흐름을 계속한다. 정식 앱 통합은 모의 검증했고 실물 인수는 남아 있다. 지원 범위·사용 흐름·실물 근거는 [설치 개선 설계](sensor-program-installation-roadmap.md)를 따른다.

기존 공식 USB 어댑터의 파일 사전 준비 → 해시 검증 → 보드 확인 → 전송 → 자원 해제 순서를 보존한다. 원본 BMP280 해시는 UTF-8 텍스트의 CRLF만 LF로 바꾸어 계산하므로 manifest의 `digestMode`에 그 규칙을 명시한다. 새 해시를 계산하지 않고 raw-byte 해시로 의미를 바꾸지 않는다. 전체 전송 경로와 V2 확인을 먼저 유지한다. [원본 어댑터][G-programmer]

기록 중에는 새 펌웨어 설치·보정·센서 구성을 시작하지 않는다. Controller가 기록 마감·저장 성공을 확인한 뒤 Programmer를 활성화하고, 전송 직전에도 같은 가드를 확인한다. 장치 선택·설치·BLE 선택은 서로 다른 성공 상태다.

숫자 CSV는 실제 센서 종류·펌웨어 버전·USB와 BLE 장치의 동일성을 증명하지 못한다. `expectedFirmware`, `installedThisSession`, `reportedFirmware:null`, `readingsCompatible`을 구분한다. 장치가 버전을 보고하지 않으면 추정값을 보고된 버전으로 저장하지 않는다. 재설치 안내와 장치 이름 확인을 제공하고, 자동 식별은 명시적인 장치 응답을 추가할 때만 확장한다.

#### M6-2 Bluetooth 설치 계약 — 제품 통합 구현·실물 인수 대기

USB를 기본으로 두고, 2026-10-27 BMP280 전송 실측을 근거로 공통 런타임 안의 무본딩 부분 교체를 무선 설치 1안으로 확정했다. 상세 선택 근거는 설치·연결 설계 §1.1을 따른다. 최초 준비·런타임 변경·비호환·전송 손상은 USB로 처리한다. 이번 제품 구현은 부분 교체만 포함한다. 런타임 불일치는 전송 전에 USB 설치로 안내하며, DFU 지원 여부와 관계없이 전체 교체로 전환하지 않는다. 비본딩 전체 C는 실험 기록으로만 보존한다. OS 본딩·기기 등록 삭제·외부 모바일 앱을 정상 절차에 넣지 않는다. 범위·상태·실물 근거의 단일 기준은 [설치·연결 설계](sensor-program-installation-roadmap.md)다.

**확정된 복구 계약(2026-10-27):** 재부팅 해제 이벤트는 최대 10초 기다리고, 명령 쓰기 완료 뒤에도 이벤트가 없으면 이전 연결을 정리해 새로 조회한다. 연결·필수 서비스/특성·읽기 진단·측정 시작 전 알림 준비는 즉시 시도 후 2초·4초·8초 대기, 총 4회로 제한한다. 권한 거부·취소·식별 불일치·프로토콜 오류는 즉시 중단한다. 모드 진입·펌웨어 전송·Execute·측정 시작을 이 루프에 넣지 않는다. 세부 실패 분류와 단계별 상태는 [§5](sensor-program-installation-roadmap.md#5-연결재시도실패-처리-계약)를 따른다.

소진하면 **뒤쪽 리셋 버튼을 한 번 누른 뒤 다시 시도**하도록 안내한다. 사용자 동작으로 새 연결·상태 검증부터 시작하며 기존 전송 완료 근거는 유지한다. 이미 대상 프로그램이 확인되면 전송하지 않고 후속 연결로 진행한다. 전송 중단·검증 불가·비호환은 USB 복구로 안내한다. 안내 문구·버튼·수동 재진입은 [§3](sensor-program-installation-roadmap.md#3-설치-화면과-사용자-흐름)이 기준이며 정식 UI에 반영했다.

연결 제어권의 작성자는 하나다. Controller가 기록 마감·저장 성공·설치 허용을 확인하고 설치 어댑터와 UART 사이 인계를 조율한다. 이전 소유자가 요청·알림을 마친 뒤 releaseConnection()으로 넘기고 다음 소유자가 reuseConnection으로 받는다. 진단↔UART·측정 중단·성공 종료만으로 유효 GATT 연결을 끊지 않는다. 실패·취소·명시적 해제에서는 정리하며 늦은 응답이 새 작업의 성공이나 해제를 만들지 않게 한다.

파일·해시·V2·메모리 범위 검증과 센서별 등록 목록은 USB와 공유한다. Programmer가 USB/무선 어댑터의 수명을 단독 관리하며 무선 어댑터가 보드 식별·전송·완료 판정을 맡는다. 측정 Transport에는 전송 기능을 넣지 않는다. 공통 런타임/새 센서의 빌드·등록은 [§9](sensor-program-installation-roadmap.md#9-공통-런타임-구축과-확장-설계)를 따른다. 등록 5종은 B 공통 런타임의 새 버전으로 교체했다. 저장 자료의 과거 펌웨어 버전·해시·codec은 stale 메타데이터로 보존하고 호환되는 구버전 보드의 이어 측정은 유지한다. 정식 V1 이전 설치 파일은 제거했으며 stale 자료에서는 재설치를 제공하지 않는다. 새 설치는 정식 V1의 새 실험에서 진행한다.

전송 완료·프로그램 확인·새 수신은 별도 사실이다. 100%·단절·개별 쓰기만으로 설치 성공을 만들지 않고 전송 후 재연결 실패가 기존 전송 완료 근거를 지우지 않는다. 설치 성공은 보정 완료·기록 시작·이전 기록 재개를 자동 생성하지 않는다. 측정 시작 뒤 단절은 기존 Session/Transport 계약을 유지한다.

**구현 근거:** 개발 B/C는 같은 재시도 정책을 사용한다. 부분 B 32회와 전체 C 4회를 실물 확인했고 실제 오류의 자동 복구가 관찰됐다. 현재 개발 코드·제품 통합 시 재사용 지점·미확인 항목은 [§5.3](sensor-program-installation-roadmap.md#53-상태-소유권과-재사용-코드)과 [§8.4](sensor-program-installation-roadmap.md#84-현재-검증-결과와-남은-작업)에 둔다. 반복 시험의 2MB 로그 제한 오류는 개발 도구 문제이며 Bluetooth 실패와 구분한다.

### 6.4. 내장 센서 펌웨어 빌드

공통 빌드·배포·런타임 호환 검증은 [펌웨어 빌드·배포](../dev/firmware/README.md)를 따른다. 앱은 검증된 설치 허용 목록만 사용하며, 빌드 성공이나 파일 다운로드만으로 보드의 설치 성공을 만들지 않는다. 새 센서는 소스·배포 파일뿐 아니라 센서 정의·codec·준비 흐름까지 등록해야 한다. 설치 어댑터의 호환 판정과 복구 경계는 [설치 개선 설계 §9](sensor-program-installation-roadmap.md#9-공통-런타임-구축과-확장-설계)를 따른다.

## 7. 실험 생명주기와 데이터 계약

### 7.1. 실행 순서

| 행동 | 처리 |
|---|---|
| 홈·카드·직접 링크 열기 | ResolvedExperiment와 준비 초안만 생성한다. Run·장치 연결을 자동 생성하지 않는다. |
| 장치 연결 | 준비용 수신을 표시하고 확인한다. 과거 미리보기는 원자료로 소급 기록하지 않는다. |
| 기록 시작 | 구성·준비·쓰기 가능 여부 검사 → RunStore 생성·잠금 획득 → 설정 사본 보관 → Session 기록 게이트 열기. 연속 클릭은 한 요청으로 처리한다. |
| 같은 실험의 준비·측정·분석 이동 | View만 전환한다. 기존 Session·RunStore를 유지한다. |
| 실험 선택·새 실험 준비·다른 실험으로 이력 이동 | 분석 초안 확정 → Session 기록 마감 → RunStore 저장 완료 → 장치·USB 자원 해제 → RunStore 닫기와 작성 잠금 해제. 실패 시 실험·연결을 유지하고 이동하지 않는다. |
| 일시정지 | 저장용 입력 게이트를 닫고 사건·Run 상태를 저장한다. 수신 미리보기는 유지할 수 있다. |
| 재개 | 준비·동일 구성 확인 후 같은 Run에 순번을 이어 붙이고 불연속 사건을 남긴다. |
| 기록 마치기 | 먼저 입력을 마감하고 종료 사건을 추가한 뒤 flush한다. 실패해도 닫힌 입력 게이트와 같은 RunStore를 유지한다. |
| 종료 후 추가 측정 | 같은 센서·펌웨어·활동과 활동별 조건을 확인한다. 저장이 완료된 같은 Run에 새 측정 구간 사건을 남긴다. |
| 호환되는 장치 출처 JSON 이어 측정 | source/importedFrom/provenance는 보존한다. 등록된 runtime과 펌웨어 해시·채널 단위/범위를 검사하고, 사용자의 연결·수신 확인·재개 또는 추가 측정 뒤 순번을 이어 붙인다. CSV·출처 불명·임시 분석은 입력 게이트를 열지 않는다. |
| 다른 센서·활동 실행 | 기존 실험을 마치고 저장한 뒤 준비한다. 새 Run은 새 기록 시작 때 생성한다. |
| 새로고침·강제 종료 후 열기 | 저장 자료를 복원한다. 자동 연결·자동 기록 재개를 하지 않고 필요하면 interrupted로 표시한다. |

전송 상태, 기록 상태, 저장 상태는 별도 축이다. 예를 들어 `연결됨 + 기록 마침 + 저장 오류`를 표현할 수 있어야 한다. 새 실험 생성 전에 저장소를 열지 못하면 미리보기만 제공하며 저장되는 것처럼 보이지 않게 한다.

실험 이름 변경·삭제와 사건 메모 편집도 RunStore를 거친다. 다른 Run의 관리에는 해당 Run의 작성 잠금을 얻고
작업 후 해제한다. 삭제는 열린 실험의 기록·저장을 먼저 마감하며 실패 시 자료를 유지한다. 사건 목록과 측정 그래프의
표시 캐시는 사건 개수뿐 아니라 `eventsVersion`으로 갱신하여 같은 사건의 메모 변경도 반영한다.

활동별 조작 종류·일시정지 허용과 추가 측정 조건은 등록된 활동 정의/policy에서 제공한다. 추가 측정 사건에는
조건별 `same/changed/unsure`와 메모, 이전 마지막 sampleId를 보존한다. 가져온 JSON의 고정 숫자 열은 기존 셀을 유지하고,
새 장치 측정에서 제공되지 않는 열은 결측과 사유를 저장한다. 기존 분석 대상·보관 근거는 명시적인 새 자료 반영 전까지 유지한다.

선택 화면의 활성 `context`는 null이다. `targetContext`는 미리보기 대상 표시만 소유하며
장치 runtime·Session·RunStore를 만들지 않는다. 명시적 준비 진입에서만 활성 context와
runtime을 설정한다. 종료한 실험의 준비 확인·수신 버퍼·앱이 기억한 재연결 대상은
다음 실험으로 넘기지 않는다(브라우저 자체의 장치 허용 권한을 철회하는 것은 아니다).
Controller가 버튼과 앱 내부 이력 이동을 같은 종료 확인·저장 경계로 처리하고 저장·전환 중 중복 조작을
차단한다. 활성 실험을 나갈 때는 확인 후 저장을 완료하고 목적지 문서를 새로 불러온다.
이때 앱의 장치 해제 작업을 먼저 실행하지 않고 브라우저의 문서 종료에 연결 정리를 맡긴다.
취소·저장 실패 시 문서를 교체하지 않으며, 같은 실험의 준비·측정·분석 이동에는 적용하지 않는다.
저장소의 기존 Run별 ID·쓰기 잠금 계약은 유지한다. 미리보기 경로는
`?view=preview`로 직렬화하며 이력 이동 실패 시 표시 중인 실험의 주소를 복구한다.

앱이 제어하는 이동은 저장 후 진행하거나 취소할 수 있다. 탭 닫기·모바일 강제 종료까지 비동기 저장을 보장할 수는 없다. 자동 저장을 주된 보호 수단으로 하고 `visibilitychange`는 추가 flush 기회, `beforeunload`는 필요한 경우의 보조 경고로 사용한다. [브라우저 생명주기 제한][W-lifecycle]

### 7.2. 저장 데이터

아래는 목표 레코드의 핵심 형태다. 함수·Set·Map은 저장 전에 일반 객체·배열로 변환한다. 도메인 타입은 `domain/contracts.js`의 JSDoc으로 한 번 정의한다.

```javascript
// Run
{
  id, schemaVersion: 1, runRevision,
  name, createdAt, updatedAt, status, source,
  context: { sensor, activity, classConfig, channels, firmware, setup },
  lastSavedSampleId, lastSavedEventId,
  provenance // 원본 앱·파일 버전·가져온 시점 등
}
// Sample: source 값은 보존하고 계산 결과를 덮어쓰지 않는다.
{
  runId, sampleId, receivedAt,
  values: { temperatureC: 29.1, pressureHpa: 1012.4 },
  validity: { temperatureC: 'valid', pressureHpa: 'valid' },
  rawExtra, sourceSampleId
}
// Event
{ runId, eventId, receivedAt, type, payload, source }
```

`sampleId`는 Run 내 증가 정수이며 표시 행 번호·정렬 순서와 무관하다. `validity`는 `valid / missing / unsupported / out-of-range / error`를 구분한다. 값 0은 유효 숫자이며, 결측을 0이나 보간값으로 채우지 않는다. 수신 시각은 UTC 밀리초, 연결 진단용 단조 시각은 런타임 전용이다. 시계 역행·연결 중단·일시정지에는 불연속 사건을 남겨 시간선을 임의로 잇지 않는다.

CSV에 시각이 없으면 원래 시각을 만들어내지 않는다. 가져오기 메타데이터에 그 사실을 기록하고 순번 기반 보기나 명시적으로 입력받은 간격을 사용한다. 가져온 값의 단위를 이름만으로 변환하지 않는다.

채널 카탈로그는 `getSourceColumns(run.context)`와 `readCell(sample, columnId)`를 통해 분석·표·파일에서 함께 사용한다. 고정 온도/압력 필드를 직접 읽는 코드를 각 화면에 남기지 않는다. 기존 sampleId·receivedAt 같은 시스템 열과 센서 열·가져온 열·계산 열의 ID 충돌을 검사한다.

## 8. 저장·복원·파일

### 8.1. RunStore와 Repository

새 앱은 `microbit.sensor-lab` DB v1을 사용한다. 기존 `bme280.gay-lussac` DB를 직접 업그레이드하거나 삭제하지 않는다. 새 DB 버전, Run schemaVersion, 파일 버전, 센서·활동 정의 버전은 서로 다른 값이다.

| 저장소 | 키 | 내용 |
|---|---|---|
| runs | id | 실험 메타데이터·구성 사본·저장 경계 |
| samples | [runId, sampleId] | 추가 전용 원자료; runId 조회 인덱스 |
| events | [runId, eventId] | 사건; 사용자 메모만 검증 후 수정 |
| workspaces | runId | 분석 정의·revision·근거·해석 |

기존의 약 1초 묶음 저장을 출발점으로 한다. 종료·실험 변경·명시적 저장은 flush 경계를 사용한다. Repository는 관련 레코드를 한 readwrite 트랜잭션에 넣고 `tx.done` 후에만 저장 완료를 응답한다. 트랜잭션 도중 네트워크·파일·사용자 입력을 기다리지 않는다. [idb 계약][W-idb]

실패 묶음은 같은 ID·같은 내용으로 재시도한다. 동일 ID의 다른 원자료 덮어쓰기는 충돌이다. `baseRunRevision`과 완료 revision으로 낡은 쓰기를 검출한다. revision 1을 저장하는 사이 생긴 revision 2를 저장 완료로 표시하지 않는다. 삭제도 쓰기 잠금을 유지한 하나의 트랜잭션으로 처리한다. [원본 RunStore][G-store]

Web Locks의 Run별 잠금을 유지한다. 잠금 미획득 시 읽기 전용, Web Locks 미지원 시 초기판의 영구 쓰기를 비활성화한다. localStorage 플래그를 동시성 잠금으로 대체하지 않는다. 새 실험 UUID가 다르더라도 BLE 선택 장치를 여러 탭이 함께 사용할 수 있다고 가정하지 않는다.

내부 IP의 HTTP 환경에서도 초기 화면과 파일의 임시 분석은 제공한다. 식별자는 공통 `domain/uuid.js`에서 UUID v4로 생성하며, `crypto.randomUUID`가 없으면 `getRandomValues`를 사용한다. 이 호환 처리는 Bluetooth·USB의 보안 컨텍스트 조건이나 영구 저장의 Web Locks 조건을 완화하지 않는다.

저장 오류에서 원자료 대기열을 비우지 않는다. 입력을 보존할 수 없는 상태가 지속되면 기록을 일시정지하고 재시도·전체 실험 파일 보관을 제공한다. 분석은 같은 메모리 사본으로 열 수 있으나 저장 실패 표시를 유지한다. 브라우저 저장소는 장기 백업이 아니므로 JSON 내보내기를 제공한다.

### 8.2. 파일 호환

새 전체 실험 형식은 `{ format:'microbit-sensor-lab', fileVersion:1, run, samples, events, workspace }`로 시작한다. 초기에는 읽기 쉬운 레코드를 유지하며 일반 내보내기에 별도 압축 라이브러리를 도입하지 않는다. 기존 compact-samples는 구형 JSON v2 가져오기 경계에서만 필요하다.

앱 CSV는 `timestamp`(UTC 수신 시각)와 `elapsed_seconds`(경과 초)를 함께 저장한다. 경과 시간 기준은 `run.timeOrigin`이 있으면 그 UTC 밀리초, 없으면 전체 자료의 첫 유효 수신이다. 구간 CSV를 가져올 때 두 열의 차로 기준을 복원하여 `run.timeOrigin`에 보관하고 모든 유효 행의 기준 일치·밀리초 정밀도를 검증한다. 시각 없는 행은 두 칸 모두 비워 두며, 음수 경과 시간은 시계 역행을 보존한다. 복원 기준은 DB·JSON·CSV 재저장과 Workspace·원자료/관계/해석 그래프·구간 선택이 공유한다. 이번 앱 CSV 규격에는 경과 초가 필수이며, 경과 초 없는 이전 앱 CSV의 자동 복원 호환 처리는 추가하지 않는다.

기준 불일치는 전체 파일의 나머지 검증이 통과한 뒤 `CSV_TIME_CONFLICT`로 알린다. 사용자가 원본 시각 기준 복원을 선택하면 수신 시각·측정값을 유지하고 첫 유효 수신을 기준으로 다시 읽는다. 복원 선택 사실은 `run.csvImport.timeRestoredFromTimestamp`에 남긴다. 취소는 현재 Run과 DB를 변경하지 않으며, 복원 후에도 일반 가져오기의 저장·전환 절차를 따른다.

기존 게이뤼삭 JSON v1/v2는 원본 식별·검증 규칙으로 해석한 뒤 `temperatureC/pressureHpa`를 values로 옮긴다. 샘플 ID, 시간, 제외 사유, 계산식, 사건, 근거와 해석을 보존한다. 새 Run ID를 발급하고 모든 참조를 일관되게 다시 연결한다. 기존 파일은 변경하지 않는다. 이전 DB를 열거나 도메인 이전을 수행하는 코드는 이 설계에 포함하지 않는다.

CSV는 Papa Parse로 문자열을 해석한 뒤 헤더·필드 수·숫자·단위·중복 열을 앱이 검증한다. 기존 게이뤼삭 CSV와 대시보드 기본 CSV를 픽스처로 지원한다. 알 수 없는 CSV는 열 대응 확인 후 가져오고 계산 결과 열은 고정 숫자로 취급한다. 수식으로 역추정하지 않는다. CSV는 전체 분석 작업 복원의 대체 형식이 아니다.

가져오기 완료 전 크기·행 수·채널 수·참조 무결성·수식 순환을 확인한다. 초기 안전 상한은 파일 32 MiB, 복원 샘플 100,000개, 원자료 채널 16개, 계산 열 32개이며 제한값은 한곳에서 관리한다. 기록과 작업 변경에도 같은 직렬화 예산을 적용하여, 한도 도달 전에 경고하고 필요하면 기록을 일시정지한 뒤 보관·새 실험 시작을 안내한다. 앱이 내보낸 파일을 자체 가져오기 제한 때문에 복원하지 못하는 조합은 허용하지 않는다. 압축 구형 파일은 복원 후 크기도 제한한다. 실패 시 현재 열린 Run이나 일부 DB 레코드를 바꾸지 않는다. 인용문·메모 등 CSV 문자열 셀은 수식 삽입 방어를 적용하고 음수 숫자를 문자열로 변조하지 않는다. ## 9. 공통 분석 계약

Workspace는 불러온 자료 경계, 기본/지정 분석 모드, 후보 ID, 제외 ID·사유, 계산 열, 그래프, 보관 근거와 글을 소유한다. 표의 현재 체크·정렬·필터와 실제 분석 대상을 구분한다. 표 렌더러가 반환한 보이는 행을 분석 대상으로 사용하지 않는다.

새 수신은 RunStore에만 추가된다. **새 자료 반영**에서 Workspace의 읽기 경계를 갱신하며 기본 모드는 후보를 새 전체 자료로 확장하고, 지정 모드는 기존 후보 ID를 유지한다. 제외 사유·계산·보관 근거·해석은 보존한다. 구간 지정과 전체 자료로 전환하는 명령은 원본 게이뤼삭 UX를 계승한다.

`workspaceRevision`은 저장·되돌리기 단위이고 `analysisInputRevision`은 계산 대상·식·적용 축의 변경 단위다. 비동기 계산을 추가할 경우 현재 입력 revision과 다른 결과는 폐기한다. 계산·회귀·표·CSV는 같은 카탈로그와 사용 자료 판정을 소비한다.

계산식은 기존 `{ id, name, unit, lhs, op, rhs }` 형태와 제한된 연산자를 유지한다. 참조 무결성·순환·0으로 나누기·비유한 결과를 검사한다. 단위는 명시적 메타데이터이며 사용자가 붙인 이름으로 차원적으로 타당하다고 판정하지 않는다. 켈빈 변환 같은 검증된 템플릿은 활동이 일반 계산 열 초안을 제공하는 방식이다.

`graph`의 기존 `xColumnId`·`yColumnId`·`type`·`connectGaps`·`view` 계약에 선택적인 `right: { yColumnId, trendEnabled, view }`를 추가한다. 오른쪽 항목은 하나이며 왼쪽과 같은 열을 중복 선택하지 않는다. 오른쪽 정의가 없는 기존 파일은 단일 세로축으로 연다. 두 계열은 X·분석 후보·제외·그래프 모양을 공유하고, 유효점·회귀·연장 상태는 각각 계산한다. 축 추가·제거도 Workspace 명령과 이력에 포함하며, 오른쪽 계산 열의 의존성과 삭제 보호를 유지한다. 보관 근거와 JSON은 두 축의 정의를 저장하고 PNG·인쇄도 같은 표시 모델을 소비한다. 물리량과 단위가 모두 같은 계열의 스케일은 측정/원자료 차트와 동일한 공통 축 규칙으로 묶는다.

회귀는 기존 중심화·스케일 조정 알고리즘을 재사용한다. 유효점 부족, 서로 다른 X값 부족, 상수 Y의 R² 등 정의할 수 없는 결과를 0으로 대신하지 않는다. 시간축 회귀와 표시의 기준점은 전체 자료의 첫 수신이며, 분석 구간·제외·오른쪽 축·보관 근거에서도 동일하게 유지한다. 큰 UTC 숫자를 그대로 쓰지 않고 기준 시각을 뺀 초 단위로 회귀를 계산하며 식의 단위를 표시한다. 그래프 정의의 `receivedAt` 및 원자료 UTC 밀리초 계약은 유지하고 화면·출력에서 경과 초로 투영한다. 공통 눈금 포맷은 UI가 맡으며 표시 반올림은 계산 입력에 적용하지 않는다.

보관 근거는 당시 후보·제외·식·축·자료 경계를 고정한 사본이다. 이후 측정·분석 변경으로 조용히 교체하지 않는다. 근거 재현에도 공통 계산 엔진을 쓰고, 게이뤼삭의 교육 질문만 활동 content에 둔다. 일반 센서 분석에 절대영도·가열·기체 누설 관련 문구가 노출되지 않도록 한다.

## 10. 도구 링크와 후속 자료 공유 계약

### 10.1. 기본 도구 링크·QR — M3

도구 공유는 **도구 미리보기에서만** 현재 도구의 소개 URL을 복사·QR로 제공한다. 대상은 표시 중인 미리보기의 센서·활동이며, 이전에 열었던 Run의 구성을 참조하지 않는다. 홈 공유·공유 대상 선택·다른 화면의 공유 진입점은 만들지 않는다. 서버에 수업 레코드를 만들거나 `ClassConfig`를 인코딩하지 않으며 Session·RunStore·Workspace·장치 권한에는 쓰지 않는다.

| 공유 대상 | 최종 주소 구성 | 수신자의 첫 화면 |
|---|---|---|
| 센서 | `publicBaseUrl` + 등록된 `sensors/<id>/` + `?view=preview` | 해당 센서 실험 소개 |
| 활동 | `publicBaseUrl` + 등록된 `activities/<id>/` + `?view=preview` | 해당 활동 소개 |

`publicBaseUrl`은 배포 시 제공하는 HTTPS 공개 앱 루트이며 하위 경로와 끝의 `/`를 정규화한다. 특정 도메인을 공유 모듈에 하드코딩하지 않는다. 현재 `location.href`나 내부 탐색용 `appBaseUrl`을 그대로 복사하지 않고, 표시 중인 미리보기의 등록 경로에 `view=preview`만 붙여 공식 주소를 만든다. 기존 `mock`, `cfg`, 화면 상태·파일·로컬 Run ID·해시를 상속하지 않는다. 공개 주소가 없거나 유효하지 않으면 생성 오류를 보여 주고 임의 개발 주소를 대신 제공하지 않는다.

공개 기준 주소는 빌드가 만드는 `og:url`, `og:image`, `twitter:image`와 canonical URL에도 적용한다. 센서·활동 페이지의 OG URL은 해당 경로로 유지한다. 앱 내부 이동·스크립트·스타일·그림·HEX는 현재처럼 설치 위치 기준으로 해석한다. `src/app/deployment.js`의 기본값과 빌드 시 `PUBLIC_BASE_URL` 재정의를 사용하며, 빌드가 같은 값을 배포할 앱 설정·메타데이터에 반영한다. 현재 운영값은 기존 GitHub Pages 주소이고 공식 전환 후 `https://lab.sco.pe.kr/`로 변경한다. 공개 주소 설정과 공유 UI는 구현했으며 새 도메인 연결·배포 완료를 뜻하지 않는다.

**QR 생성 결정:** 저장소의 `vendor/qrcodegen.js`(Project Nayuki, MIT)와 `vendor/simple-qrcode.js`의 SVG 래퍼를 재사용해 브라우저 안에서 생성한다. 외부 QR API·CDN·단축 URL 서버를 사용하지 않는다. 기존 래퍼의 오류 정정 MEDIUM 요청과 인코더의 동일 크기 내 자동 상향을 유지하고, 사방 4모듈의 흰 여백·진한 단색 격자를 보존한다. 로고·그라데이션을 QR 안에 넣지 않는다. 화면·확대는 SVG, 저장은 같은 격자를 정수 픽셀 배율로 그린 고해상도 PNG로 제공한다. PNG에는 불투명 흰 배경과 여백을 포함한다. 출처·라이선스·고정본 관리는 §2의 기준을 따른다.

데스크톱은 미리보기에서 QR을 바로 생성·표시하고 **링크 복사·크게 보기·QR 저장**을 제공한다. 모바일은 제목 옆 **도구 공유** 버튼으로 큰 QR·복사·저장 대화상자를 연다. 확대와 모바일은 같은 QR 대화상자를 재사용하고, 닫으면 실행 버튼으로 초점을 돌려준다. 안내는 **‘실험 소개 화면으로 연결됩니다.’**만 표시한다. 세부 반응형 배치는 기존 미리보기의 화면 폭 기준을 따른다.

복사·표시·확대·PNG 저장은 하나의 검증된 URL과 QR 격자를 사용한다. 미리보기 대상이 바뀌면 함께 갱신하고 이전 도구의 QR을 남기지 않는다. 클립보드 거부 시 선택 가능한 주소를 제공하며 QR 생성·저장 실패 시 링크는 유지한다. 교실 화면·휴대폰에서 화면 QR과 저장 PNG의 판독을 확인한다. 인코더 용량 오류를 숨기거나 주소를 잘라 내지 않는다.

수신자는 소개에서 **처음부터 준비하기 / 준비된 장치 확인**을 고른다. 링크 열람·새로고침·재방문으로 자동 연결·기록·Run 생성을 수행하지 않는다. 기존 직접 준비 주소는 지원하고, 기존 실험으로부터의 앱 내부 전환은 §7.1의 저장·종료 경계를 따른다. 단순 도구 링크에는 과거 정의 버전 고정이나 동일 수업 식별 기능을 약속하지 않는다.

구형 `cfg`는 현재처럼 미지원 오류와 홈 복구 안내를 제공한다. 압축 v2 코덱·구형 v1 설정 링크 복원·임의 필드 및 시작 명령 설정은 M3에서 구현하지 않는다. 구형 **실험 파일**의 JSON·CSV 호환 및 기존 `classConfig` 데이터 보존과 혼동하지 않는다. [기존 공유 구현][D-config]은 출처 참고로 남긴다.

### 10.2. 교사 JSON 기반 자료 공유 — 후순위

**확정 범위(2026-10-26):** 로그인 없는 자료 생성·조회·비밀 관리 링크에 의한 삭제, 생성 후 30일 자동 만료. 학생에게 원측정값·조작 기록·교사 안내를 배포하고 학생은 새 분석을 만든다. 보관 연장, 교사 계정·수업 목록, 학생 제출·동기화는 초기 범위에 포함하지 않는다.

Cloudflare Workers는 생성·조회·삭제·만료 판정을 담당하고 R2 Standard는 자료 파일, D1은 공유 식별자·상태·생성/만료 시각·파일 참조·삭제 권한 검증값 등 작은 관리 정보를 저장하는 구성을 기준으로 설계한다. 교사 원본과 학생 분석은 기존 로컬 Repository에 남는다. 후속 서버가 없어도 기본 앱·M3를 실행할 수 있다. 이 문서 수정은 Cloudflare 자원 생성·유료 전환·서버 배포를 수행하지 않는다.

| 자료 경계 | 계약 |
|---|---|
| 입력 | 기존 파일 어댑터로 실험 JSON을 검증. 공유 전 포함 자료·메모와 수업 제목·질문·안내를 확인 |
| 배포 사본 | 센서·활동 및 채널 정의, 원측정값·단위·시각·유효성·경과 시간 기준, 원자료 해석에 필요한 사건과 조작 기록·교사 안내 보존 |
| 제외 | 교사의 분석 구간·제외 판단·계산 열·그래프 작업 상태·회귀·보관 근거·해석 답안. 교사 원본은 변경하지 않음 |
| 원자료 보존 | 교사가 분석에서 제외했던 행도 원측정값으로 포함. 결측·이상값 표시와 수신 공백을 유지하고 값을 재계산하거나 채우지 않음 |
| 서버 관리 | 추측하기 어려운 공유 식별자, 형식 버전·출처, 서버 생성 시각과 `expiresAt`, 파일 참조, 삭제 상태와 관리 토큰의 검증값 |
| 학생 사본 | 명시적인 ‘내 분석 시작’에서 새 로컬 Run과 참조 관계 생성. 원자료·교사 안내·출처는 보존하고 학생 분석은 초기화 |

자료 링크는 공유 식별자를 전달하고 JSON 본문·관리 비밀을 넣지 않는다. 조회는 설정된 공유 API에서만 수행하며 임의 외부 JSON URL 가져오기 기능으로 확장하지 않는다. 업로드는 서버에서도 크기·허용 구조를 검사하고 학생 수신 시에도 기존 파일 검증 경계를 통과해야 한다. 미등록 정의·손상 자료를 최신 기본값으로 바꾸거나 검증 실패 후 부분 저장하지 않는다. 사용자 문자열은 `textContent`로 표시하고 파일의 URL·명령·함수를 실행하지 않는다.

공유본의 원래 실측/모의 출처를 보존하되 학생 사본은 분석용 가져오기 출처로 구분한다. 교사가 사용한 USB/BLE 권한·준비 완료 상태·Run 잠금을 학생에게 넘기지 않으며, 링크를 통해 장치 연결이나 기존 기록에 이어 측정을 자동 허용하지 않는다. 센서 자체 측정을 하려면 일반 도구 경로에서 새로 준비한다.

같은 공유 식별자를 다시 열면 로컬 사본이 있는지 확인하여 이어하기와 새 사본 만들기를 명시적으로 구분한다. 학생 분석을 덮어쓰지 않으며 링크 열람만으로 사본을 누적 생성하지 않는다. 서버 공유가 만료·삭제되어도 기존 로컬 사본은 저장된 실험에서 이어갈 수 있다. 현재 실험을 바꾸는 경우 저장 실패·임시 분석·쓰기 잠금에 관한 기존 전환 규칙을 유지한다. 공유 서버에는 학생의 분석·답안을 되돌려 저장하지 않는다.

### 10.3. 관리 링크·만료·운영 경계

생성 성공 시 **학생용 링크·QR**과 별도의 **비밀 관리 링크**를 발급한다. 관리 링크는 삭제 권한 자체이며 로그인으로 대체하거나 학생용 링크에 포함하지 않는다. 충분히 무작위인 토큰을 생성하고 서버에는 검증용 해시만 보관한다. 토큰은 URL fragment로 전달한 뒤 삭제 API의 인증 헤더 등으로 사용하고 학생 링크·QR·Referer·서버 로그에 노출하지 않는다. 관리 화면을 여는 GET만으로 삭제하지 않으며 대상 자료를 확인한 명시적 삭제 요청에만 사용한다. 토큰 분실 시 복구는 제공하지 않고 30일 자동 만료를 안내한다.

만료는 클라이언트 시계가 아닌 서버 생성 시각부터 **30일(30×24시간)**로 고정한다. 조회·파일 다운로드마다 만료/삭제 상태를 검사하고 만료 뒤 새 다운로드를 차단한다. R2 공개 버킷의 영구 주소나 만료보다 오래 유효한 다운로드 주소로 이 판정을 우회하지 않는다. 초기판 응답은 공유 자료를 공용 캐시에 남기지 않도록 구성한다.

수동 삭제는 먼저 공유 접근을 차단하고 파일·관리 정보를 정리한다. 30일 자동 삭제는 만료 판정과 파일 정리를 분리해, 정리가 늦어져도 새 접근을 허용하지 않는다. R2 lifecycle·정기 정리로 파일을 제거하고 실패한 삭제·고아 업로드를 재처리한다. R2 자동 정리에는 지연이 있을 수 있으므로 정확한 만료 시각의 접근 차단을 lifecycle만으로 구현하지 않는다. 이미 다운로드되거나 학생 브라우저에 저장된 사본의 회수·삭제는 보장하지 않는다.

로그인 없는 업로드는 파일별 크기·생성 빈도·전체 보관량을 서버에서 제한한다. 제한 초과 시 새 생성만 거부하고 기존 유효 링크·로컬 분석을 유지한다. 실제 JSON 크기와 Workers CPU 사용량을 측정해 수치 한도·남용 방지 수단을 후속 구현 전에 확정한다. 큰 JSON의 검증을 브라우저에만 맡기거나 CPU 한도를 확인하지 않고 서버에서 전체 재분석·압축하지 않는다. 무료 제공량은 계정의 다른 사용량과 공유되고 초과 과금될 수 있으므로 무료 운영은 앱 한도와 사용량 확인으로 관리한다. 가격·무료량을 제품의 영구 보장으로 표시하지 않는다.

API와 배포 경계는 §10.4를 따르고, 파일별 수치 한도·정리 주기는 실제 자료를 측정해 후속 구현 전에 확정한다. 보관 기간·로그인 여부·공유 내용 범위는 위 확정 사항을 따른다. 운영 확인 근거: [Workers 한도](https://developers.cloudflare.com/workers/platform/limits/), [R2 요금](https://developers.cloudflare.com/r2/pricing/), [R2 자동 삭제](https://developers.cloudflare.com/r2/buckets/object-lifecycles/), [D1 요금](https://developers.cloudflare.com/d1/platform/pricing/).

### 10.4. Cloudflare API와 자료 저장 경계

앱의 공식 주소를 먼저 연결한 뒤, 같은 앱 Worker에 공유 API를 추가한다. API는 **`https://lab.sco.pe.kr/api/shares`** 아래에 둔다. 프런트엔드와 API를 같은 origin에서 제공하고 포털을 경유한 업로드나 별도 API 도메인은 초기 구성에 넣지 않는다. M3의 URL·QR 생성에는 이 API를 호출하지 않는다. 아래 경로는 앱 루트 기준이다.

| 경로·메서드 | 역할과 응답 계약 |
|---|---|
| `POST api/shares` | 검증된 공유 자료와 교사 안내 생성. 저장 성공 후 공유 ID·서버 생성 시각·만료일과 관리 링크를 구성할 정보를 반환 |
| `GET api/shares/<id>` | 유효한 자료의 제목·안내·센서·채널·행 수·만료일 등 개요. 관리 토큰·해시·R2 내부 키는 제외 |
| `GET api/shares/<id>/data` | 만료·삭제 상태를 다시 확인한 뒤 분석용 자료 제공. R2 공개 주소로 리다이렉트하지 않음 |
| `DELETE api/shares/<id>` | `Authorization` 헤더의 비밀 관리 토큰을 검증하고 접근 차단을 먼저 확정. 파일 정리 실패는 재처리 |

학생용 화면은 `share/?id=<공유 ID>`, 관리 화면은 `share/manage/?id=<공유 ID>#token=<비밀 토큰>`으로 구분한다. 두 화면 모두 `publicBaseUrl` 아래의 주소이며 후속 단계에서 실제 진입 HTML과 명시적 앱 경로를 추가한다. 현재 라우터가 이 경로를 지원한다고 간주하지 않는다. 제목·JSON·비밀 토큰을 학생용 URL에 담지 않고, 공유 화면의 OG는 일반 앱 소개를 사용한다. 관리 화면은 검색 색인을 막고 외부 추적 스크립트 없이 토큰을 취급한다.

Worker는 허용 경로·메서드·입력 크기·형식 버전을 검사한다. 잘못된 요청, 자료 없음·만료·삭제, 요청 한도 초과, 저장소 장애는 구별되는 상태 코드와 오류 코드로 반환한다. API 실패를 홈 HTML이나 정상 자료로 바꾸지 않는다. 업로드·조회·삭제 응답은 `Cache-Control: no-store`로 제공하고 CDN 캐시 규칙에서도 제외한다. 같은 origin이라는 조건은 삭제 권한 검증이나 업로드 남용 제한을 대신하지 않는다.

R2는 공개 접근이 꺼진 전용 버킷을 Worker 바인딩으로만 읽고 쓴다. D1은 상태·만료·삭제 권한의 기준이며 조회 때 이 판정을 생략하지 않는다. 삭제 직후 오래된 상태가 조회되지 않도록 초기판은 읽기 복제본·상태 캐시를 사용하지 않는다. 전체 공유 목록을 공개하는 API는 만들지 않는다.

R2 파일 저장과 D1 기록은 하나의 트랜잭션이 아니므로 생성 중 자료는 공개하지 않는다. 파일 저장을 확인한 뒤 D1을 조회 가능 상태로 바꾸고, 중간 실패의 파일·레코드는 회수한다. 브라우저는 생성 요청 전에 암호학적 난수로 요청 식별자와 관리 토큰을 만들고 응답 확인까지 유지한다. 서버는 토큰의 해시만 저장하며 같은 요청 식별자·토큰·자료의 재전송은 동일한 공유를 반환한다. 동일 식별자에 다른 토큰이나 자료가 오면 거부한다. 이렇게 응답 유실에 따른 중복 업로드를 막되, 토큰 자체를 잃은 뒤의 관리 링크 복구는 제공하지 않는다.

30일 만료 차단은 모든 조회에서 서버 시각으로 판단한다. 같은 Worker의 정기 작업이 만료·삭제 대기·실패한 생성 자료를 작은 묶음으로 정리하고, R2 lifecycle은 누락 파일의 보조 정리로 사용한다. 정리 대상이 남아 있으면 재시도에 필요한 상태를 보존하며, 작업을 여러 번 실행해도 이미 삭제된 자료가 되살아나지 않게 한다. 서버 장애나 한도 초과는 공유 기능에 표시하고 로컬 기록·분석·파일 가져오기는 계속 제공한다.

운영·미리보기·로컬 환경은 저장소와 비밀을 분리한다. 미리보기에서 운영 D1/R2를 연결하거나 실수로 운영 자료를 생성·삭제하지 않게 하고, 기본값은 공유 API 비활성 또는 별도 시험 자원으로 둔다. 배포 자격 증명은 CI 비밀로 관리하고 브라우저 코드·정적 `dist/`에는 포함하지 않는다. 응답·요청 본문·인증 헤더·관리 링크 전체를 운영 로그에 남기지 않는다. 공개 전에는 대표 JSON 크기·최대 입력의 CPU 사용량·동시 수업 조회량을 측정해 §10.3의 제한을 설정한다.

## 11. UI·자원·성능

화면은 전달받은 표시 모델과 명령으로 동작한다. 기본 수명은 `mount → render → dispose`이고 dispose는 DOM 이벤트·ResizeObserver·차트만 정리한다. 화면 dispose가 Session·RunStore를 종료하지 않는다. 표와 차트는 원자료를 변경하지 않고 sampleId로 사용자 선택을 전달한다.

기존 준비·분석 화면의 주요 배치와 조작을 먼저 보존한다. 동작이 같은 버튼·팝업·파일·상태 표시를 재사용하고 센서별 화면 분기는 정의가 제공하는 항목으로 처리한다. `<dialog>`·레이블·키보드 조작·포커스 복귀를 유지하며 색상만으로 저장 오류·제외·결측을 구분하지 않는다. 수신값을 매번 스크린리더 알림으로 반복하지 않는다.

M2의 도입 결정과 검증 결과는 [인수 기록](history/m2-implementation.md)에 보존한다. 준비용 수신 사실은 작성자를 하나로 정해 장치 패널·가이드가 공유하고, Session의 기록 연속성 판단과 구분한다. 표시 채널·최근/전체 보기 설정은 수집 채널이나 분석 범위를 변경하지 않는다. 변경하는 준비 UI·표시 모델·controller 호출 계약을 JSDoc 검사에 포함한다.

BMP280 3D 뷰어는 로컬 자원으로 이식하고 기존 메시지 계약을 감싼다. `postMessage`의 origin·source·메시지 종류를 검사하며 임의 파일 내용으로 iframe 주소를 구성하지 않는다. 뷰어 실패 시 배선 표·그림으로 준비를 계속할 수 있다. 다른 센서는 필요할 때 해당 안내 자원만 로드한다.

공통 장치 자산은 `public/assets/devices/`에서 모델·연결 장면·메타데이터를 관리한다.
기존 BMP280와 같은 Three.js r180 런타임을 사용하며 장치 연결·준비 완료 상태를 소유하지 않는다.
별도 장치 페이지에서는 본체·USB·배터리 장면과 그림 저장을 제공한다. 내장 센서와 BMP280의 준비물·USB·배터리 안내는
동일 모델에서 생성한 정지 PNG를 사용하며 3D 런타임을 로드하지 않는다. 이미지 참조는 등록된 센서 guide의
`illustrations`에서만 가져오고 공통 GuideView가 표시한다. 배터리 안내를 펼치는 동작은 연결·준비 완료 근거를 만들지 않는다.
사용 계약·출처는 [장치 자산 안내](../public/assets/devices/README.md)를 따른다.
BMP280의 센서·확장 보드·연결선 끝 형상은 기존 배선 뷰어와 정지 이미지 생성기가 같은 함수를 사용한다.

자기장 보정 시범은 센서 모듈이 같은 micro:bit 모델과 Three.js 런타임을 필요할 때만 불러온다. 화면 가시성과 보정 단계에 따라 렌더링을 멈추고, 종료할 때 렌더러와 전용 자원을 해제한다. 공통 모델의 공유 재질은 보존한다. 로딩 실패·WebGL 미지원·컨텍스트 손실에는 정지 그림과 영상 링크를 유지하며, 시범의 재생 상태는 장치 보정 근거를 만들지 않는다.

초기 성능 검증 기준은 4채널·명목 10Hz·1시간에 해당하는 36,000행이다. 2026-10-26 시간 압축 입력으로 이 자료량의 실제 브라우저 저장·측정/분석 화면·파일 왕복을 확인했다. 소요 시간과 범위는 [M4 검증 현황](history/m4-verification.md#m4-검증-현황--2026-10-26)을 따른다. 실제 한 시간 BLE 수신이나 모든 기기의 성능을 보증하는 결과는 아니다. RunStore의 전체 메모리 보관 구조를 우선 유지하되 매 수신마다 전체 스냅샷을 복사하지 않는다. 최신값 조회, 추가 구간 읽기, 변경 버전 조회를 사용하고 전체 복사는 내보내기·분석 반영 경계로 제한한다.

화면 그리기는 수신과 분리해 최대 초당 5회로 묶고 숨겨진 차트는 갱신을 줄인다. 원자료 저장은 그리기 빈도로 제한하지 않는다. 기존 가상 표를 유지하고 시간선의 표시 간소화가 필요하면 구간·공백을 보존한다. 회귀·CSV에는 간소화된 점이 아닌 전체 분석 자료를 사용한다. 관계 산점도에는 시간선용 자동 decimation을 그대로 적용하지 않는다. [Chart.js 성능 지침][W-chart]

초기판은 백그라운드 기록·화면 잠금 중 연결 유지·완전한 오프라인/PWA를 보장하지 않는다. 브라우저 기능은 이름 대신 capability로 검사하고, BLE 미지원이 파일 분석까지 막지 않게 한다. 서비스 워커·Web Worker는 실제 오프라인 요구나 측정된 병목이 생겼을 때 별도 도입한다.

Bluetooth 지원 판정은 `device/browser-support.js`가 소유하며 BLE 어댑터와 Transport의 `getSupport()`·`isSupported()`가 같은 결과를 사용한다. 보안 컨텍스트, `requestDevice` 존재, 확인 가능한 Permissions Policy를 동기적으로 읽는다. 이 결과는 API 사용 가능 여부이며 장치 존재·권한 허용·연결 성공을 증명하지 않는다. 자동 장치 선택·권한 요청·주기적 하드웨어 탐색은 하지 않는다. `getAvailability()`의 false를 브라우저 미지원이나 전원 꺼짐으로 취급하지 않는다.

UI는 이 판정으로 공통 안내 하나를 현재 화면에 배치한다. OS 추정은 iOS용 도움말 선택에만 쓰며, API를 제공하는 iOS 브라우저를 막지 않는다. 모의 Transport는 실제 브라우저의 미지원 안내 대상이 아니다. Bluefy 링크와 검증 범위는 [설치 개선 설계 §3](sensor-program-installation-roadmap.md#3-설치-화면과-사용자-흐름)에 기록한다.

## 12. 구현 단계와 검증

### 12.1. 개발·빌드

앱 소스는 native ES Modules로 관리한다. `scripts/build.mjs`는 등록된 센서·활동의 내부 진입 HTML을 생성하고, esbuild로 앱 모듈을 내용 해시가 붙은 ESM 묶음으로 만든다. 동적 import는 별도 묶음으로 유지하며 모듈 기준 자원 URL은 원래 소스 위치를 보존한다. 글꼴은 고정 버전의 공식 가변 분할본을 복사해 실제 글자 범위만 같은 사이트에서 받는다. 앱 자원과 내부 이동은 설치 기준 경로에서, 공개 도구 링크와 OG URL은 M3에서 도입한 `publicBaseUrl`에서 계산한다. source definition과 생성된 진입 정보의 ID·버전 불일치는 빌드 오류다. Cloudflare 배포 전환과 공개 주소의 적용 순서는 §12.4를 따른다.

M1에서 `package.json`의 module 모드, 지원 중인 Node LTS 버전과 lockfile을 고정한다. JSDoc 계약은 TypeScript의 `allowJs/checkJs/noEmit` 검사로 확인하되 TypeScript는 개발 도구로만 쓴다. 기존 코드의 일괄 형식 변경과 타입 전환을 이식에 섞지 않는다. 테스트 명령은 다음 책임으로 구성한다. **현재 실행 명령은 [README](../README.md#로컬-개발과-배포), 단계 상태는 [문서 안내](UNIFIED-PLAN-INDEX.md)를 따른다.** 당시 구현·검증 근거는 [이력](history/README.md)에 보존한다.

| 명령 | 책임 |
|---|---|
| `npm run dev` | 로컬 정적 서버·직접 진입 경로 제공 |
| `npm test` | Node 테스트 러너로 순수 도메인·codec·저장/세션 계약 테스트 |
| `npm run typecheck` | JSDoc 공개 계약과 import 의존성 검사 |
| `npm run test:browser` | 브라우저의 실제 IndexedDB·DOM·가상 표·탐색 테스트 실행 경로 |
| `npm run test:e2e` | 격리된 Chromium에서 브라우저 suite와 실제 페이지·탭 종료 복원·3D 복구 검사 실행 |
| `npm run test:e2e:build` | 빌드 후 생성된 배포 파일의 하위 경로·지연 로딩·파일 분석과 출력 확인 |
| `npm run build` | 내부 진입 HTML·자원 생성 및 레지스트리 정적 검증 |

브라우저 테스트는 원본 `tests/browser.html`·`browser.js`의 유효한 사례를 이식한다. 기존 DOM·저장 검사는 유지하고 기본 UI 전환 관련 묶음을 Playwright Test의 독립 BrowserContext에서 실행한다. 새 화면 크기·3D 복구 검사는 실제 최상위 페이지에서 사용자 입력과 준비 응답을 확인한다. 재시도 없이 최초 실패의 trace·화면·결과를 남기며 실제 장치 확인과 구분한다. [Node 테스트 러너][W-test]

**구현 순서와 선행 조건**

- M1은 센서·활동·채널 계약과 대표 픽스처 → RunStore/Repository와 공통 계산 → Workspace·파일·분석 UI 연결 순으로 진행한다. BMP280 자유 측정과 게이뤼삭 활동이 같은 기반을 사용하는지 먼저 확인한다.
- M3는 M2의 등록된 직접 경로와 미리보기·준비 흐름을 사용한다. M2는 2026-10-26 사용자의 실기기 검증 완료 확인으로 인수를 마쳤다. QR UI나 공유 서버 구현을 실물 검증의 대체 근거로 삼지 않는다.
- 도메인 전환은 §12.4에 따라 정적 앱·기존 자료 이전·공개 주소를 먼저 확인한다. M3 구현 중에는 유효한 현재 운영 주소를 사용하고, 새 주소 연결 전 QR을 발행하지 않는다.
- 후속 교사 자료 공유는 M3의 링크·QR 조작과 M1의 파일 검증·가져오기 경계를 재사용한다. 도메인 전환 후 §10.4의 API·D1·R2를 연결하고 운영 한도를 확인한 뒤 공개한다. 관리 권한은 §10.3의 비밀 관리 링크 계약을 따른다. 수업 설정 압축 URL을 중간 단계로 구현하지 않는다.
- 저장·계산·호환성 검증은 해당 구현과 함께 수행한다. M4는 누적된 기능의 통합 확인 단계이며 앞 단계의 핵심 검증을 미루는 단계가 아니다.

**M4 완료 상태(2026-10-26):** 소프트웨어 인수 검증과 사용자의 최종 완료 지시에 따라 M4를 완료 처리했다. 실제 검사 결과와 단계 인수 결정은 [M4 검증 현황](history/m4-verification.md#m4-검증-현황--2026-10-26)에 구분해 기록한다. 도메인 전환과 후속 교사 자료 공유는 별도 작업으로 유지한다.

**후속 단계의 기술 계약:** 작업 목록·선행 조건·미정 사항은 [기획 §10.1](unified-sensor-lab-plan.md#101-후속-단계와-미구현-작업)에서 관리한다. M5는 §12.4의 배포·자료 이전 경계, M6은 §6.3과 [설치 개선 과제](sensor-program-installation-roadmap.md), M7은 §10.2–10.4의 API·자료·권한 계약, M8-1은 §13의 모듈 추가 절차를 따른다. M8-2는 [한 점 기록·연속 연계 설계](point-recording-design.md)의 UX·상태·자료 확장 계약을 적용한다. 앱 내부 Bluetooth 설치는 M6-2의 완료 조건이다. 외부 모바일 앱 전달 안내는 제외하며 네이티브 앱 제작은 확정하지 않는다. 이 분류는 새 서버·펌웨어·저장 형식 구현을 수행한 것이 아니다.

**M8-2 확장 계획·미구현:** Session·RunStore·Repository·Workspace·UI의 상태 소유권을 유지하고, 불변 samples를 참조하는 점 기록과 수동 조건 열을 추가한다. 수동 전용도 같은 Sample 검증·계산·분석 엔진을 사용한다. 자료별 분석 상태·희소 ID·수동 입력 사본·보관 근거 재현을 지원하고, 기존 자료를 보존하는 DB·Run·파일 버전 확장이 필요하다. 이 문서 §7–9의 기존 단일 자료 계약을 대체할 구체 변경은 [상세 설계 §12–14](point-recording-design.md#12-모듈-경계와-의존-방향)에 모으며, 구현 전까지 현재 형식의 지원 범위를 바꾸어 안내하지 않는다.

파일의 세부 분리, 내부 함수와 작업 묶음은 위 경계 안에서 구현자가 판단한다. 공개 계약이나 사용자 흐름이 달라질 때만 관련 설계를 갱신한다. 작업·테스트 운영 원칙은 [AGENTS.md](../AGENTS.md)를 따른다.

소스 코드를 그대로 재서술하는 테스트보다 위 계약을 검증한다. 기존 `.test.mjs`와 픽스처를 우선 이식하고 변경 범위의 검사부터 수행한다. 모의 BLE·메모리 Repository 통과를 실제 하드웨어·IndexedDB 검증으로 보고하지 않는다. 이번 문서 작성은 구현·성능·실물 검증 완료를 의미하지 않는다.

### 12.4. 도메인 연결과 배포 전환

**확인한 구성(2026-10-26)**

포털 저장소는 `Cho-WH/scope-portal`이며 확인 기준은 [`ebc8894`](https://github.com/Cho-WH/scope-portal/tree/ebc88945b06ca79840ea1a448ccb49922f8ba9eb)다. [`astro.config.mjs`](https://github.com/Cho-WH/scope-portal/blob/ebc88945b06ca79840ea1a448ccb49922f8ba9eb/astro.config.mjs)는 `site: https://sco.pe.kr`, 정적 출력과 끝 슬래시를 지정한다. [`wrangler.jsonc`](https://github.com/Cho-WH/scope-portal/blob/ebc88945b06ca79840ea1a448ccb49922f8ba9eb/wrangler.jsonc)는 Worker 이름 `scope-portal`과 `assets.directory: ./dist`를 지정한다. Cloudflare Pages가 아니라 **Workers Static Assets** 구성이다.

같은 커밋의 [`sensor.json`](https://github.com/Cho-WH/scope-portal/blob/ebc88945b06ca79840ea1a448ccb49922f8ba9eb/src/content/tools/sensor.json)은 실행 주소로 기존 GitHub Pages를 사용한다. 포털의 [유지보수 문서](https://github.com/Cho-WH/scope-portal/blob/ebc88945b06ca79840ea1a448ccb49922f8ba9eb/docs/maintenance.md)는 도구 ID·소개 경로 유지와 주소 이전 시 저장 자료·기기 권한 확인을 요구한다. DNS 레코드·사용자 지정 도메인·계정 바인딩은 저장소 설정에 없어 실제 Cloudflare 연결 값은 배포 단계에서 확인한다. 당일 외부 요청에서 `sco.pe.kr`은 HTTP 200, `www.sco.pe.kr`은 522를 반환했다. 이는 응답 확인이며 DNS·Worker 연결 설정 전체를 검증한 결과는 아니다. `www` 복구·리디렉션은 포털 측 확인 사항으로 남기고 앱 공식 주소로 사용하지 않는다.

**확정 주소와 운영 책임**

|---|---|---|

| 센서 앱 소개 | `https://sco.pe.kr/tools/sensor/`, 도구 ID `sensor` 유지 | `Cho-WH/scope-portal`의 소개 콘텐츠 |
| 센서 앱 | **`https://lab.sco.pe.kr/`**, 별도 Workers Static Assets 배포. Worker 이름은 `sensor-lab`을 계획값으로 사용하고 기존 자원과 충돌 여부 확인 | `Cho-WH/MicrobitSensorDashboard` |
| 도구 직접 진입 | `lab.sco.pe.kr/sensors/<id>/`, `lab.sco.pe.kr/activities/<id>/`; 공유 시 `?view=preview` | 앱 레지스트리·빌드 |
| 후속 교사 자료 공유 | 같은 앱 Worker의 `/api/shares`, `/share/`, `/share/manage/`; 비공개 R2·D1 바인딩 | 센서 앱 저장소 |

포털 아래 경로 대신 전용 하위 도메인을 선택해 정적 배포·API·브라우저 저장 공간을 포털과 분리한다. 포털 Worker에 센서 앱 프록시·저장소를 추가하지 않는다. 별도 게이뤼삭·자기장 도구의 소개 주소나 실행 앱도 이번 전환에서 변경하지 않는다.

**정적 앱 연결 → 공식 주소 전환 → 공유 백엔드 추가**

1. **앱 배포 준비:** 이 저장소에 별도의 Wrangler 설정을 추가하고 기존 `npm run build`의 `dist/`를 배포한다. Node 24·lockfile과 기존 검사 기준을 유지한다. GitHub Actions에서 Cloudflare 배포를 관리하는 것을 기준으로 하며 같은 운영 Worker를 수정하는 자동 배포 경로를 중복 운영하지 않는다. 먼저 정적 파일만 연결하므로 이 단계에는 D1·R2·업로드 API가 필요하지 않다. 서버 코드·비밀·실험 자료는 정적 빌드 대상 밖에 둔다.
2. **새 도메인 연결:** Cloudflare의 `sco.pe.kr` zone과 `lab`에 이미 연결된 자원을 확인한 뒤 앱 Worker에 `lab.sco.pe.kr`을 Custom Domain으로 연결한다. Wrangler의 `routes`에 해당 hostname과 `custom_domain: true`를 명시하고 DNS·인증서 활성화를 확인한다. GitHub Pages의 사용자 지정 도메인에 같은 주소를 중복 설정하지 않는다. 기존 포털의 루트 도메인 연결은 유지한다. [Custom Domains 공식 문서](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)
3. **실제 경로 확인:** Wrangler에 `assets.html_handling: "auto-trailing-slash"`를 명시한다. 루트·등록된 모든 센서/활동의 `index.html`을 제공하고 모든 미지정 경로를 홈으로 보내는 SPA fallback은 사용하지 않는다. 이 HTML 정규화는 `lab.html`을 `/lab`으로 바꾸므로 현재 `parseRoute()`에 `lab` 별칭을 추가해 기존 홈·화면 이동을 보존한다. 소개의 `?view=preview`, 현재 `lab.html?view=…` 탐색과 리디렉션 후 검색 매개변수 보존, 뒤로 가기, 펌웨어·중첩 뷰어·아이콘·manifest 경로를 새 호스트에서 검증한다. 이 별칭은 M5에서 추가한 호환 경로다. [HTML 처리 공식 문서](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/)
4. **최초 공식 배포:** 기존 센서 실험실은 공개 배포한 적 없다는 사용자 확인에 따라 이전 안내 배너·별도 구버전 빌드·동결 배포는 만들지 않는다. 최종 공식 주소를 적용한 빌드로 HTTPS·직접 진입·자원·파일 열기·공유 링크·QR·OG·canonical·아이콘·홈 화면 바로가기를 검증한 뒤 포털의 실행 주소를 변경한다. 브라우저 저장소와 USB/BLE 권한은 origin별로 분리되며, 개발 확인 중 저장한 자료를 옮길 필요가 있으면 기존 전체 실험 JSON 내보내기·열기를 사용한다.
5. **포털 연결 갱신:** `scope-portal/src/content/tools/sensor.json`의 `launchUrl`을 새 공식 주소로 바꾸고 이름·설명·기능 목록·대표 이미지·지원 환경(`environment`)을 현재 앱에 맞춘다. USB·Bluetooth 각각의 확인된 브라우저·기기 조건을 반영하고 미확인 지원 범위를 추가하지 않는다. ‘설정 링크·QR 공유’는 제거하고 구현된 ‘도구 링크·QR 공유’를 안내한다. 기존 `/tools/sensor/`를 유지하며 포털의 실행 버튼에서 앱을 여는 경로를 확인한다. 이 작업은 포털 저장소의 별도 변경이며 실제 반영 결과를 배포 기록에 남긴다.
6. **후속 API 연결:** 동일 앱 Worker에 API 코드·R2·D1 바인딩과 정기 정리를 추가한다. `assets.run_worker_first`는 `/api/*`에만 우선 적용하고 일반 앱 자원은 정적 제공을 유지한다. 알 수 없는 API 경로는 JSON 오류를 반환한다. §10.4의 공유·관리 진입 HTML과 라우터도 이 단계에서 추가한다. 별도 시험 자원으로 생성·조회·삭제·만료와 한도를 확인한 뒤 교사 자료 공유 UI를 공개한다. [Worker와 정적 자원 라우팅](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)

운영 주소·공개 설정·배포 버전은 코드와 함께 추적한다. GitHub Pages의 main 푸시 자동 배포는 해제해 운영 배포 대상이 분산되지 않게 한다. 공식 공개 이후 문제가 생기면 같은 lab.sco.pe.kr origin의 호환 버전으로 복구한다. 포털 링크를 다른 주소로 바꾸는 것만으로 저장 자료가 이전되지 않으므로 새 주소의 자료 열기·JSON 내보내기 기능을 보존한다.

공식 전환 후 운영 Worker는 `workers_dev: false`, `preview_urls: false`를 명시해 별도 호스트에 학생의 기록·기기 권한이 흩어지지 않게 한다. 시험 배포가 필요하면 별도 Worker와 접근이 제한된 시험 주소를 사용하고 수업용으로 배포하지 않는다. 시험 주소의 자료도 공식 주소로 자동 이전되지 않으며 시험 주소를 공식 링크·QR·OG의 기준으로 사용하지 않는다. 운영 Worker에 다른 공개 별칭·시험 주소가 남아 있는지도 전환 때 확인한다. [workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)·[버전별 주소](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/)

M5는 `main` 기준으로 구현한다. Wrangler 설정, `/lab` 호환 경로, 배포 검사를 추가했다. 센서 확장 작업 브랜치의 미병합 기능은 포함하지 않는다. 사용자 요청으로 GitHub 자동 배포 연결은 보류하고 수동 실행용 워크플로만 준비한다. 운영 반영·검증 상태는 [M5 배포 기록](m5-deployment.md)에서 관리한다. 완료 판정은 실제 도메인·파일 복원 검사와 새 origin의 장치 권한·실물 수신 확인을 구분한다.

**구현·배포에 필요한 접근 환경**

앱 구현·빌드·검사와 Wrangler/Actions 설정 작성은 Cloudflare 인증 전에 진행할 수 있다. 실제 계정 자원 조회·배포는 인증된 도구로 계정·zone·권한을 확인한 뒤 진행한다. Cloudflare API MCP 또는 로컬 Wrangler/API를 사용할 수 있으며, MCP 연결 자체를 M5의 필수 조건으로 만들지 않는다. Sites 플러그인의 호스팅은 사용자의 기존 Cloudflare 계정을 직접 관리하는 대체 경로로 간주하지 않는다.

| 작업 | 자동 처리 범위와 사용자 개입 조건 |
|---|---|
| Cloudflare 연결 | 공식 API MCP는 `https://mcp.cloudflare.com/mcp`에서 제공하며 최초 연결 시 사용자 OAuth 승인과 권한 선택이 필요하다. 로컬 Wrangler를 쓰면 유효한 로그인 또는 API 토큰이 필요하며 만료·갱신 실패 시 사용자가 재인증한다. |
| Worker·도메인 배포 | 인증 후 계정·`sco.pe.kr` zone·기존 `lab` 연결을 조회하고 허용된 권한 안에서 앱 배포·Custom Domain 연결·상태 확인을 수행한다. 계정 선택이 모호하거나 권한·zone 소유권이 부족하면 해당 부분만 사용자에게 확인한다. |
| GitHub Actions | 로컬 OAuth나 MCP 연결과 별도로 CI용 Cloudflare API 토큰과 계정 ID가 필요하다. 대상 계정·zone에 필요한 범위로 제한한 인증 수단을 마련하고 GitHub Actions secrets에 등록한다. 토큰 발급·등록 권한이 없거나 사용자 인증이 필요하면 그 단계에만 사용자 개입을 요청한다. 토큰 값은 채팅·문서·저장소에 남기지 않는다. |
| 장치 인수 | HTTP·경로·파일 복원 검사는 배포 도구와 브라우저로 확인한다. 새 origin의 USB/Bluetooth 장치 선택·권한 승인과 실제 센서 수신은 사용자 조작·실물 검증으로 구분한다. |

**접근 환경 확인(2026-10-30):** Cloudflare 플러그인 연결 후 계정과 활성 `sco.pe.kr` zone, 기존 `scope-portal` 연결을 조회했다. 착수 시 `sensor-lab` Worker와 `lab.sco.pe.kr` 연결은 없었다. 조회 성공·계정 역할 정보는 플러그인의 실제 쓰기 성공과 구분하며 결과는 배포 기록에 남긴다. 사용자가 제외한 ‘계정 API 토큰 쓰기’ 권한은 요구하지 않는다. 로컬 Wrangler OAuth는 만료 상태이고, 플러그인 인증은 로컬 CLI나 GitHub Actions에 자동 적용되지 않는다. CI용 `CLOUDFLARE_API_TOKEN` 등록과 푸시 자동 배포는 사용자 요청으로 보류했다.

연결 근거: [Cloudflare 공식 MCP](https://developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/), [Codex MCP 인증](https://developers.openai.com/codex/mcp/), [GitHub Actions 인증](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/).

## 13. 새 센서·활동을 추가하는 절차

**새 센서:** definition과 codec을 등록하고, 펌웨어 소스·고정 HEX·해시·보드·라이선스·검증 기록을 추가한다. 배선·보정 안내와 대표 수신 픽스처를 넣은 뒤 공통 준비·측정·분석·공유 검사를 통과시킨다. 새로운 물리량이라는 이유만으로 RunStore·Workspace·차트 엔진을 수정하지 않는다.

**새 활동:** 호환 센서·준비 내용·사건 policy·분석 초안·질문을 등록한다. 같은 센서면 기존 펌웨어와 codec을 사용한다. 학생 행동이 기존 준비·측정·분석 계약 안에 들어오면 새 화면·새 세션을 만들지 않는다.

새 요구가 공통 계약을 벗어나면 먼저 계약과 기존 활동의 영향을 설계한다. 사용 사례 하나를 맞추기 위해 `if (sensorId === ...)`를 공통 저장·계산 모듈에 넣거나, 아직 사용하지 않는 범용 플러그인 API를 미리 구축하지 않는다.
