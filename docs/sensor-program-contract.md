# 센서 프로그램 공통 동작 규약

센서 실험실의 micro:bit V2용 센서 프로그램을 작성·수정할 때 따르는 기준이다. 앱 쪽 상태 소유권은 [기술 설계 §6](unified-sensor-lab-architecture.md#6-장치-통신과-펌웨어), 빌드·설치 파일·버전 관리는 [펌웨어 빌드·배포](../dev/firmware/README.md)를 따른다. 같은 규칙을 다른 문서에 다시 작성하지 않는다.

## 1. 용어

| 용어 | 뜻과 사용 위치 |
|---|---|
| 센서 프로그램 | 센서별 측정·통신·보정 코드. 사용자 화면에서는 보드에 설치하는 소프트웨어도 이 이름으로 안내한다. |
| 펌웨어 | 센서 프로그램과 기반 코드를 포함하는 보드용 소프트웨어·배포본. 개발 문서의 빌드·검증·버전·배포 설명에 사용한다. |
| 공통 런타임 | 센서 프로그램들이 공유하는 MakeCode/CODAL 네이티브 기능과 Bluetooth 설정. |
| USB 설치 / 무선 설치 | 같은 센서 프로그램을 설치하는 두 방법. 별개의 센서 프로그램이나 별도 측정 모드가 아니다. |
| 연결 / 송신 / 기록 | Bluetooth 연결, 보드의 값 송신, 앱의 실험 자료 저장은 별개의 상태다. 연결이나 송신만으로 기록을 시작하지 않는다. |
| 통신 규약 버전 / 펌웨어 버전 | 메시지 형식과 배포본을 각각 식별한다. 자기장 `@mag,2,...`의 2는 정식 펌웨어 V1과 별개다. |

사용자 문구는 “센서 프로그램 설치”, “프로그램 응답이 없어요”처럼 행동 중심으로 쓴다. UUID·런타임 해시·본딩·통신 규약 버전은 사용자 안내에 노출하지 않는다.

## 2. 구현 상태

2026-10-27 기준:

- **구현됨:** 연결 후 새 시작 요청, 중단·연결 변경 시 송신 무효화, 센서별 CSV, 자기장 선택·보정·완료 응답과 이번 부팅 중 완료 상태 유지.
- **정식 V1에 구현됨·실물 확인 대기:** 연결 대기 중 십자 아이콘과 기기 이름 교대, 측정값 송신 중 파형 상하 이동. 조도 측정과 나침반 보정에는 표시를 겹치지 않는다.
- **이번 범위에 포함하지 않음:** 조별 이름 설정, 이름 입력·패턴 입력 UI, 실물 확인 버튼이나 확인 응답 추가. 교실 식별 개선은 아이콘과 이름 표시부터 적용한다.

## 3. 공통 수명과 통신

| 상태·사건 | 보드의 동작 |
|---|---|
| 부팅 | UART 서비스를 준비한다. 연결 전에는 측정값을 송신하지 않는다. |
| 새 연결 | 이전 송신 요청을 재사용하지 않고 센서에 맞는 새 시작·준비 요청을 기다린다. |
| 시작 요청 | 연결이 유효할 때만 초기화·준비 절차를 진행하고 송신한다. |
| `stop` 또는 연결 해제 | 수치 송신을 중단한다. 이미 대기 중인 초기화·준비 작업이 나중에 반환해도 이전 요청을 되살리지 않는다. |
| 재연결 | 새 요청과 새 수신으로 준비를 확인한다. 자기장 보정 완료 기억은 §4의 예외를 따른다. |
| 설치 모드 | 공통 런타임이 담당한다. 센서 프로그램의 명령 처리·LED 표시가 계속 실행된다고 가정하지 않는다. |

- Nordic UART Service로 개행 구분 UTF-8 텍스트를 교환한다. 앱→보드 명령은 줄 끝에 `\n`을 붙이고, 현재 센서 프로그램은 앞뒤 공백 제거·소문자 변환 후 처리한다.
- 한 측정 행은 정해진 순서와 개수의 CSV 필드로 구성한다. 명령·상태·디버그 문장을 측정 행에 섞지 않는다. 빈 필드는 결측이며 숫자 0과 다르다.
- BLE 알림 하나가 한 행이라는 보장은 없다. 앱은 부분 행·여러 행·CRLF를 복원하고 센서 codec으로 해석한다. 프레임 크기와 오류 처리는 기술 설계 §6.1을 따른다.
- 현재 보드는 측정 시각·순번을 보내지 않는다. 앱이 부여하는 시각은 **수신 시각**이다. 기본 목표 간격은 100ms, 내장 온도는 1000ms다. 센서·활동 특성에 따라 예외를 허용한다. 현재 구현은 측정·전송 뒤 해당 시간만큼 쉬므로 처리·스케줄링 시간이 더해지며 정확한 10Hz를 보증하지 않는다. LED 애니메이션 대기는 별도 실행 흐름에 두고 측정 루프에 추가하지 않는다.
- 알려지지 않은 명령은 측정 시작으로 취급하지 않는다. 현재 일반 센서는 시작 명령 이외의 명령에 송신을 멈추고, 자기장은 허용된 상태 전이 이외의 명령을 무시한다. 이 차이를 센서별로 해석한다.
- 앱의 준비 미리보기와 실험 기록은 같은 수신을 사용할 수 있다. 기록 여부는 앱이 결정하며 보드에 별도 기록 상태를 만들지 않는다.

## 4. 센서별 계약

### 명령·측정값

| 센서 | 시작·준비 명령 | 송신 필드 순서 | 명목 간격 |
|---|---|---|---|
| 내장 온도 | `start` | 보드 온도 °C | 1000 ms |
| 내장 밝기 | `start` | 상대 밝기 0–255 | 100 ms |
| 내장 가속도 | `start` | X, Y, Z, 크기 — mg | 100 ms |
| 내장 자기장 | `prepare` 후 아래 절차 | X, Y, Z, 크기 — µT | 100 ms |
| BMP280 | `bme` | 온도 °C, 빈 습도 필드, 압력 hPa | 100 ms |

- 온도는 프로세서 기반 보드 온도로, 정밀한 주변 공기 온도라고 설명하지 않는다.
- 밝기는 lux가 아니다. 시작 시 최초 `lightLevel()`의 준비용 결과를 버리고 100ms 뒤 같은 연결·요청인지 확인한다. 이후의 실제 0은 유효한 어둠이다. LED 화면은 켜진 상태에서 표시만 비운다.
- 가속도는 ±8g 범위를 사용하며 중력을 포함한다.
- BMP280는 0x76/0x77의 장치 ID·보정 계수를 확인하고 온도·압력 6바이트를 한 번에 읽는다. 드라이버의 Pa를 hPa로 변환해 보낸다. 습도를 측정하지 않으며 초기화·읽기 실패는 `,,`로 보낸다. 과거 값을 정상 새 값처럼 재사용하지 않는다.

### 자기장 통신 규약 v2

| 요청·사건 | 응답과 다음 동작 |
|---|---|
| `prepare`, 이번 부팅 중 보정 완료 없음 | `@mag,2,choice` 후 사용자 선택 대기 |
| `prepare`, 이번 부팅 중 보정 완료 있음 | `@mag,2,calibrated` 후 수치 송신 |
| 선택 대기에서 `calibrate` | `@mag,2,calibrating`을 한 번 보낸 뒤 보정 루틴 실행 |
| 보정 루틴 반환 | 완료 상태를 기억한다. 같은 연결·요청이 유효하면 `@mag,2,calibrated` 후 수치 송신 |
| 선택 대기에서 `skip` | `@mag,2,skipped` 후 수치 송신. 완료 기억은 만들지 않음 |
| `stop` 또는 연결 변경 | 이전 요청에 의한 송신·완료 응답을 무효화. 진행 중인 보정을 취소한 것으로 처리하지 않음 |

보정 완료 기억은 **정식 V1의 RAM 상태**다. 연결 해제·재연결·송신 중단 후에도 유지하고 전원 차단·리셋·프로그램 재시작 시 초기화한다. 비휘발성 나침반 보정값의 존재와 혼동하지 않는다. 연결 밖에서 보정을 마쳤어도 다음 `prepare`에 완료를 보고한다. 완료 응답은 물리적 정확도 보증이 아니며 앱은 이후의 새 측정값도 확인한다.

보정 중에는 측정·식별 표시·상태 조회 응답을 기대하지 않는다. `calibrating`은 보정 시작 직전에 한 번 보내는 응답이며 주기적인 진행 알림이나 재연결 복원 응답이 아니다. 보정 중 재연결에 응답이 없으면 보정을 완료하고 다시 연결하도록 안내한다. 그 외 응답 없음에는 리셋 후 재연결을 안내한다. A/B 버튼을 보정 생략 명령으로 사용하지 않는다.

이 상태 행은 앱의 자기장 codec만 해석하며 측정 Sample로 저장하지 않는다. 전체 JSON의 보정 근거와 화면 상태는 기술 설계 §6.2를 따른다.

## 5. 기기 식별과 측정 표시

교실에서 여러 보드가 검색될 때 자기 기기를 찾도록, **일반 실행 중 Bluetooth 광고·연결 대기 구간에 앱 아이콘 → 기기 이름 → 짧은 공백을 반복**한다. 이름은 `control.deviceName()`이 제공하는 다섯 글자 이름을 사용한다. 센서 프로그램을 바꿀 때 새 이름을 임의로 만들지 않는다.

아이콘은 앱 로고의 네 모서리 프레임과 중앙 십자를 5×5 LED로 표현한다. `#`는 켜짐, `.`은 꺼짐이다.

```text
##.##
#.#.#
.###.
#.#.#
##.##
```

- 대기 중 제자리 아이콘 1000ms → 공백 200ms → 런타임 기본 글꼴로 이름만 스크롤(열당 150ms) → 공백 400ms를 반복한다. 아이콘은 이름 스크롤 전에 완전히 지운다. 실물 가독성 확인은 별도로 한다.
- 연결 후 시작 요청 전에는 화면을 비운다. 상태 변경은 진행 중인 스크롤을 취소하고 이전 실행을 무효화한다. 늦게 돌아온 표시 작업이 새 화면을 켜거나 지우지 않는다.
- 연결이 끊기면 일반 연결 대기로 돌아온 경우에만 표시를 재개한다. `connected=false`만으로 설치 모드나 보정 중에도 광고 중이라고 단정하지 않는다.
- 표시 우선순위는 **런타임의 설치·페어링 표시 / 센서 보정 → 연결·측정에 필요한 화면 상태 → 연결 대기 식별 표시**다. 특히 자기장 보정과 밝기 측정에 식별 애니메이션을 겹치지 않는다.
- 앱 안내는 “이 표시 뒤에 나오는 이름과 같은 기기를 선택하세요” 수준으로 제한한다. 일반 연결과 무선 설치 진입에서 실제 광고 이름·LED 동작을 실기기로 대조한 뒤 안내에 적용한다.
- 이 이름은 보안 식별자나 전 세계적으로 유일한 ID가 아니다. 중복 이름, 보정 중, 설치 모드 등에서 이 표시만으로 기기를 확정했다고 기록하지 않는다.

측정값 송신 중에는 아래 파형을 **중앙 → 한 칸 위 → 중앙 → 한 칸 아래**, 각 300ms 간격으로 이동한다. 이 표시는 센서 프로그램의 송신 상태이며, 앱의 기록 여부나 전송 성공을 증명하지 않는다. 조도 측정 중에는 화면을 비우고, 나침반 보정 중에는 런타임이 화면을 소유한다.

```text
.....
.#...
#.#.#
...#.
.....
```

[공통 표시 모듈](../firmware/common/sensor-display.ts)을 5종에 함께 빌드한다. 센서 코드는 상태 변경만 전달하고 자체 표시 루프를 복제하지 않는다. 기본 간격도 이 공통 소스에서 제공하며, 센서별 채널·준비·보정·측정 함수는 해당 센서 소스가 소유한다.

근거: [micro:bit 이름 설명](https://support.microbit.org/support/solutions/articles/19000067679-how-to-find-the-name-of-your-micro-bit), [MakeCode 기기 이름](https://makecode.microbit.org/reference/control/device-name), [Scratch 연결 안내](https://support.microbit.org/support/solutions/articles/19000026080-using-the-micro-bit-with-scratch). 공식 모바일 앱의 패턴 입력 방식은 참고했지만 이번 제품 범위에는 포함하지 않는다.

## 6. 변경 시 확인할 것

- 시작 전 송신 없음, 새 연결의 새 요청, 중단·해제 후 늦은 송신 차단을 확인한다.
- CSV 순서·단위·결측과 센서별 준비 절차를 검증한다. 자기장은 완료 기억·생략·전원 초기화·보정 중 응답 부재를 구분한다.
- 식별 표시 구현 시 다수 보드의 이름 대조, 표시 도중 연결·해제, 표시 중단, 밝기 측정·자기장 보정과의 간섭을 실기기로 확인한다.
- 모의 검사·실물 연결/설치·센서 정확도 검증은 별도로 기록한다. 정식 V1 이전 자기장 v5의 완료 기억과 재연결은 [사용자 실기기 확인](sensor-program-installation-roadmap.md#84-현재-검증-결과와-남은-작업)이 있으나 정식 V1의 LED 표시·실제 수신 간격·센서 간섭이나 모든 기기·브라우저의 정확도를 검증한 것은 아니다.
- 소스·규약 변경 후 빌드·배포 절차를 거쳐야 보드에 적용된다. 문서 변경만으로 현재 배포 파일이 바뀌지는 않는다.
