## 1. 디자인의 약속

**빛을 머금은 밝은 표면 위에, 짙은 남색의 정밀한 글자와 선명한 신호색이 놓인다.**

창의적이고 세련되며 미래지향적이되, 오래 관찰해도 정신 사납지 않은 과학 실험 도구를 만든다. 미래적인 인상은 복잡한 장식보다 표면의 깊이, 빛의 방향, 절제된 색의 대비, 정밀한 숫자와 아이콘에서 만든다.

`Luminous Lab`은 내부 디자인 문법의 이름이다. 사용자에게 표시하는 앱 이름 **센서 실험실**과 저장소 이름을 변경하지 않는다.

이 작업의 우선순위는 **선택한 시안의 시각적 완성도를 실제 앱에 구현하는 것**이다. ‘UI보다 디자인에 집중한다’는 뜻은 기존 UI를 고정한다는 뜻이 아니다. 레이아웃, 탐색의 배치, 영역의 비례, 정보의 묶음, 조작부 형태와 노출 방식도 디자인 목표에 맞게 조정할 수 있다.

기존 기획과 기술 설계는 실험 기능·과학적 의미·데이터 보존의 기준으로 사용한다. 화면 배치는 기준 화면을 만들며 다시 판단한다. 현재 기능을 제공하는 방법은 바꿀 수 있지만, 기록·저장·분석의 의미나 실제 실험 절차를 바꾸는 결정은 시각 조정과 구분해 검토한다. [R1, R2]

**이 문서의 색·크기·간격·재질 수치는 출발값이다.** 실제 브라우저의 전체 측정 화면을 구현하고 사용자와 시안을 검토한 뒤 공통 규칙을 확정한다. 수치를 먼저 고정해 결과를 거기에 맞추기보다, 검증된 화면에서 반복 가능한 규칙을 추출한다.

### 1.1. 시안에서 반드시 이어갈 인상

| 핵심 | 화면에서 보이는 방식 |
|---|---|
| 밝은 깊이감 | 푸른 기운이 아주 약한 바탕, 희고 반투명한 외곽 표면, 얇은 빛 테두리 |
| 단단한 중심 | 남색 제목·아이콘·핵심 조작, 검정에 가까우나 차갑게 느껴지지 않는 글자 |
| 살아 있는 신호 | 오렌지·코발트·바이올렛을 작은 표시와 실제 자료에 선명하게 사용 |
| 차분한 미래성 | 부드러운 광원과 곡면, 정밀한 선, 절제된 입체감. 상시 움직이는 배경 없이 구현 |
| 역할에 따른 형태 | 일반 버튼·주요 행동·기록 조작·입력창의 형태와 밀도를 구분 |

### 1.2. 시안과 실제 제품의 경계

시안은 미술 방향의 기준이며 기능 명세나 실측 화면이 아니다. 이미지 속 문구·숫자·장치 그림을 그대로 옮기지 않는다.

- 사이드바·상단 탐색·혼합 배치 중 실제 화면의 비례와 사용성에 맞는 방식을 선택한다. 현행 상단 탐색을 보존할 의무도, 시안의 사이드바를 그대로 복제할 의무도 없다.
- 측정값·기록 조작·연결 상태·그래프·도움말을 재배치하거나 묶을 수 있다. 접기·펼치기와 노출 시점도 실제 상태에서 검토하며, 필요한 기능과 현재 실험 상태를 찾을 수 있게 한다.
- 미니 그래프·사건 표시처럼 기존 자료를 보여주는 방식은 디자인에 도움이 되면 활용할 수 있다. 별도의 새 통계·수집·편집 기능은 필요한지 검토하고, 시안에 있다는 이유만으로 필수 구현하지 않는다.
- 내장 밝기는 현재 정의에 따라 **0–255 상대값**으로 표시한다. 시안의 `312 lx`를 사용하지 않는다. 지원 채널·단위·정밀도는 실제 센서 정의를 따른다. [R6]
- 실제 연결 상태와 장치 이름을 표시한다. 시안의 `COM7`을 Bluetooth 장치의 이름처럼 고정하지 않는다.
- 검증된 장비 모델·배선 정보를 출발점으로 사용하되, 카메라·조명·재질·배경·구도를 재설계하고 필요한 시각 자산을 추가할 수 있다. 실습 안내에 쓰는 단자·배선은 실제 하드웨어와 대조한다. 장식 자산과 실습 안내 자산의 역할을 구분한다.
- 글자·버튼·숫자·그래프는 실제 DOM과 Canvas로 구현한다. 시안 전체를 배경 이미지로 붙여 작동하는 화면처럼 보이게 하지 않는다.

### 1.3. 먼저 확정할 것은 화면 전체의 비례

| 판단 대상 | 기준 화면에서 결정할 사항 |
|---|---|
| 주 시각 대상 | 측정값·그래프·기록 조작 중 어디에 먼저 시선이 가는지와 그 우선순위 |
| 영역의 비례 | 탐색·헤더·측정값·그래프·보조 도구의 실제 폭과 높이, 화면 안의 균형 |
| 정보 밀도 | 실제 한글 문구와 지원 채널 수를 넣었을 때의 여유, 줄바꿈, 장식의 비중 |
| 표면의 연결 | 어디를 하나의 큰 면으로 묶고 어디에 간격·구분선·깊이를 줄지 |
| 시각적 리듬 | 큰 숫자와 작은 단위, 얇은 선과 강한 행동 표시의 대비 |
| 작은 화면 | 같은 인상을 유지하면서 탐색·보조 도구·여백을 어떻게 재배치할지 |

먼저 **전체 화면을 실제 브라우저로 렌더링**한다. 그 결과를 기준 시안과 비교해 큰 비례부터 다듬고, 이후 표면·서체·아이콘·미세 간격을 조정한다. 버튼 표본이나 토큰 파일만으로 전체 화면을 승인하지 않는다.

검토한 기준 화면에는 뷰포트·자료·기록 상태·사용 자산을 함께 남긴다. 주요 치수와 표현은 실제 CSS에 구현하고, 문서에는 다른 화면에 적용할 원칙과 필요한 차이만 기록한다. 문서와 코드에 같은 치수를 이중 관리하지 않는다.

## 2. 시각적 서명

### 2.1. Frost Edge — 얇은 빛 테두리

큰 표면의 위쪽에는 얇은 밝은 선, 아래쪽에는 넓고 약한 남색 그림자를 출발점으로 둔다. 외곽·주요 패널·메뉴의 깊이에 차이를 주어 겹침과 가벼움을 만든다. 어느 표면을 띄울지는 전체 구도에서 결정하며, 모든 영역에 같은 그림자를 반복하지 않는다.

표면이 가벼워 보여도 버튼·입력창의 경계와 글자는 흐리지 않는다. 장식용 테두리와 조작을 식별하는 테두리는 다른 토큰을 사용한다.

### 2.2. Signal Accent — 작은 면적, 선명한 색

대부분의 면적을 흰색·옅은 블루그레이·남색이 담당한다. 오렌지는 행동과 온도 신호, 코발트는 선택과 압력 신호, 바이올렛은 다른 측정 채널과 아주 작은 광원에 쓴다.

채도가 높은 큰 면은 현재의 핵심 행동에 우선 배정한다. 여러 조작이 함께 필요하면 크기·형태·강조 강도로 위계를 만든다. 자료 선의 색은 행동 강조와 구분하고 필요한 채널 수에 맞춘다.

### 2.3. Orbital Light — 시선을 모으는 광원

홈 또는 준비에서 희미한 궤도선·빛의 호·추상적인 곡면으로 중심 장면을 만든다. 주 광원과 보조 빛의 관계를 정해 시선이 분산되지 않도록 한다. 과학적 그래프처럼 보이는 장식은 자료 영역과 구분한다.

측정·분석에서는 광원을 바깥 배경 가장자리로 약하게 밀어낸다. 그래프·표·입력 영역 뒤는 단색이다. 모서리에 희미한 빛이 있다는 사실보다 **자료가 더 먼저 보이는 정도**로 조정한다.

### 2.4. Precision Type — 정밀한 숫자

큰 측정값은 단정한 산세리프 숫자로, 글자 폭과 단위의 기준선을 안정적으로 유지한다. 전자시계체·SF 장식체·모든 제목의 대문자 처리는 사용하지 않는다. 정밀한 느낌은 서체의 특이함보다 간격과 정렬에서 만든다.

## 3. 색상 체계

아래 값은 v1에서 가져온 **시안 제작용 초기값**이다. V1의 전체 화면에서 조정하고 V2에서 공통 토큰으로 확정한다. 실제 합성 배경·투사 환경·색각 차이는 적용 단계에서 검토한다. 색을 바꿀 때는 개별 화면의 HEX가 아니라 공통 토큰을 수정한다.

### 3.1. 기본색

| 의미 | 토큰 | 값 | 용도 |
|---|---|---|---|
| 바탕 | `--sl-bg` | `#F6F8FC` | 페이지 바깥, 패널 사이 |
| 자료 표면 | `--sl-surface-data` | `#FFFFFF` | 그래프·표·입력·읽기 영역 |
| 보조 표면 | `--sl-surface-soft` | `#EEF3FA` | 비활성 도구 영역·부드러운 구획 |
| 본문 | `--sl-text` | `#1F2937` | 일반 문장 |
| 보조 글자 | `--sl-text-muted` | `#53657D` | 단위·설명·시각·보조 상태 |
| 남색 중심 | `--sl-navy` | `#0B1F3B` | 제목·핵심 아이콘·일반 주요 버튼 |
| 장식 경계 | `--sl-border-subtle` | `#E1E8F2` | 영역 분리. 조작 식별의 유일한 단서로 사용하지 않음 |
| 조작 경계 | `--sl-border-control` | `#7F8DA4` | 입력창·체크박스 등 식별에 필요한 경계 |

### 3.2. 신호색과 읽기용 변형

| 색 계열 | 밝은 표현 | 그래프/도형 | 작은 글자 | 사용 예 |
|---|---|---|---|---|
| 오렌지 | `#FF7A45` | `#D65A20` | `#B54416` | 핵심 행동, 온도 |
| 코발트 | `#246BFD` | `#246BFD` | `#1D4ED8` | 선택, 압력 |
| 바이올렛 | `#7C5CFF` | `#7C5CFF` | `#6740CF` | 밝기 등 보조 채널 |

같은 HEX를 작은 글자·버튼 바탕·그래프 선에 무조건 공용하지 않는다. 밝은 오렌지는 색면에 쓰고, 글자와 선은 같은 계열의 읽기용 색으로 조절한다.

**주황 버튼의 글자는 남색이다.** `#FF7A45` 위의 흰 글자는 이 명세의 기본 조합이 아니다. 대화 시안의 생동감을 유지하면서 글자 대비를 확보한다.

### 3.3. 상태색

| 의미 | 색 | 표현 |
|---|---|---|
| 수신 정상·완료 | `#137D55` | 작은 아이콘/점 + 상태 글자. 넓은 초록 패널을 만들지 않음 |
| 주의·지연 | `#8A5B00` | 주의 아이콘 + 구체적 안내 + 필요한 행동 |
| 오류·저장 실패 | `#B42335` | 오류 아이콘 + 문구. 실제 실패일 때만 사용 |
| 선택 | 코발트 | 테두리/체크/선택 표시를 함께 사용 |
| 기록 중 | 오렌지 | 고정된 점 + ‘기록 중’. 상시 점멸하지 않음 |
| 연결되지 않음 | 보조 글자색 | 중립 상태. 곧바로 빨간 경고로 표현하지 않음 |

녹색은 정상 상태를 알리는 소규모 기능색이다. 이전 청록색 중심 테마를 다른 이름으로 되살리는 용도로 사용하지 않는다.

### 3.4. 색의 비중

밝은 측정·분석 화면에서는 약 85–90%의 중성·저채도 면, 7–10%의 남색 중심 요소, 나머지의 선명한 강조색을 출발점으로 삼는다. 어두운 준비 장면에 같은 명도 비중을 강제하지 않는다. 이는 픽셀 계산이나 자동 판정 기준이 아니라 **한눈에 느껴지는 면적의 균형**이다. 채널이 많아도 패널 전체를 채널색으로 채우지 않는다.

## 4. 표면·빛·그림자

| 표면 | 기본 재질 | 깊이 | 적용 |
|---|---|---|---|
| 바깥 배경 | `--sl-bg` + 약한 정적 방사형 광원 | 없음 | 페이지 가장자리 |
| 앱 틀/헤더 | 거의 흰 반투명 표면, 얇은 밝은 윗선 | 낮은 그림자 | 고정된 공통 영역 |
| 일반 패널 | 흰색, 필요 시 아주 약한 보조 면 | 낮거나 없음 | 기존 섹션 |
| 그래프·표 | 불투명 흰색 | 없음 | 자료 작업면 |
| 메뉴·팝오버 | 불투명에 가까운 흰색 | 한 단계 높은 그림자 | 실제 떠 있는 조작부 |
| 준비 장면 | 짙은 남색 + 방향성 있는 광원·곡면·겹침 | 장면의 전경/중경/배경으로 깊이 표현 | 장비 영역 또는 준비 작업 화면 전체 |

반투명한 느낌은 정적 색면·밝은 테두리·그림자만으로도 먼저 시험할 수 있다. 장면에 필요한 경우 `backdrop-filter`를 선택적으로 사용하고, 범위와 강도는 실제 화면의 읽기성과 성능으로 판단한다. 그래프·표의 자료 바탕은 선명하게 유지하며, 필터가 없을 때도 읽기성과 계층이 유지되는 대체 표현을 둔다. [W3]

그림자는 남색 기운을 가진 넓고 약한 것으로 통일한다. 카드마다 서로 다른 그림자·그라데이션·테두리를 중첩하지 않는다. 조작 상태를 그림자만으로 전달하지 않는다.

## 5. 형태와 버튼

부드러운 곡면을 디자인의 한 요소로 사용하되, **모든 요소가 같은 둥근 네모가 되지 않도록 역할별 형태를 구분**한다. 아래 치수는 후보값이며 실제 화면의 크기와 밀도에 맞춰 조정한다.

| 대상 | 기준 형태 | 규칙 |
|---|---|---|
| 바깥 큰 틀 | 24px 모서리 | 넓은 화면에서만 외곽 여유. 작은 화면은 외곽 액자 느낌을 줄임 |
| 주요 패널 | 18px 모서리 | 안쪽 섹션은 선·간격으로 구분하며 재차 큰 카드를 중첩하지 않음 |
| 측정값 그룹 | 16px 모서리 | 채널의 작은 색 표시, 숫자와 단위 정렬 |
| 일반 버튼 | 10px 모서리 | 흰/남색 바탕, 분명한 라벨. 높이 40px, 터치 영역은 최소 44px 권장 |
| 입력창 | 10px 모서리 | 흰색·뚜렷한 경계. 버튼보다 장식이 적음 |
| 한 단계의 강조 행동 | 캡슐형 가능 | 오렌지 바탕+남색 글자. 현재 맥락의 한 행동에 한정 |
| 일시정지·재개 등 기록 조작 | 원형 가능 | 최소 44px 조작 영역과 보이는 짧은 라벨을 함께 제공 |
| 선택된 탭 | 얇은 선/작은 표시+남색 글자 | 넓은 민트색 채움으로 모든 탭을 동일하게 강조하지 않음 |

원형 버튼은 기록 기능 전체의 필수 형태가 아니다. 이미 긴 문구가 필요한 ‘기록 마치기’ 등은 읽을 수 있는 텍스트 버튼을 유지한다. 원형화 때문에 기능을 아이콘만으로 숨기지 않는다.

### 5.1. 버튼 상태

| 상태 | 표현 |
|---|---|
| 기본 | 역할에 맞는 바탕·글자·경계 |
| 마우스 올림 | 바탕/경계의 명도 변화. 큰 확대·도약 없음 |
| 누름 | 색이 조금 짙어지거나 눌린 면으로 변화. 동작 위치 유지 |
| 키보드 초점 | 2px 코발트 외곽선과 2px 간격. 어두운 장면에서는 밝은 초점선 |
| 비활성 | 중립 표면·보조 글자, 클릭 불가 상태를 실제 속성과 일치시킴 |
| 진행 중 | 원래 너비 유지, 동작에 필요한 진행 표시. 반복 실행 차단 |
| 오류 후 | 오류를 버튼 자체의 색만으로 표현하지 않고 가까운 메시지로 설명 |

연결 버튼과 기록 버튼의 상태는 각기 실제 연결·기록 상태를 반영한다. 보기 전환을 위해 상태를 초기화하지 않는다.

## 6. 타이포그래피·아이콘·간격

### 6.1. 서체

1차 지정 서체는 **Pretendard 계열의 한글 산세리프**를 후보로 삼는다. 적용 전에 정식 배포본·라이선스·필요한 파일 범위를 확인하고, 채택 시 로컬 자원으로 관리한다. 폰트 파일은 이 설계 묶음에 포함하지 않는다. 로딩 실패 시 기존 한국어 시스템 서체로 즉시 표시한다.

본문·숫자·단위를 같은 계열로 묶고 `font-variant-numeric: tabular-nums`를 사용한다. 별도 숫자 서체를 추가하는 결정은 최초 실제 화면 검토 후로 남긴다.

| 역할 | 크기 | 굵기 | 세부 규칙 |
|---|---|---|---|
| 화면 제목 | 22–26px | 650–700 | 짧게, 과도한 음수 자간 없음 |
| 영역 제목 | 16–18px | 600 | 불필요한 큰 제목 반복 없음 |
| 본문·주요 안내 | 15–16px | 400–500 | 줄간격 1.6–1.7 |
| 버튼·핵심 라벨 | 14–15px | 550–600 | 문구를 읽을 수 있는 폭 유지 |
| 표·보조 라벨 | 13–14px | 400–500 | 정렬과 대비를 우선 |
| 주요 측정값 | 32–36px | 550–650 | 줄간격 약 1.1, 숫자 폭 안정화 |
| 단위 | 14–16px | 400–500 | 값의 기준선에 맞춤 |

핵심 조작과 설명은 읽을 수 있는 크기로 유지한다. 실제 한글 문구·채널 수·큰 숫자를 넣고, 공간이 부족하면 배치·묶음·줄바꿈·보조 도구의 제시 방식을 먼저 조정한다. 반응형 배치도 새 구도에 맞게 바꿀 수 있다.

### 6.2. 아이콘

기존 로컬 Lucide 자원을 우선 재사용한다. [R2] 일반 18–20px, 선 두께 약 1.5–1.8px, 같은 시각적 무게를 기준으로 한다. 제품 이모지·다른 스타일의 입체 아이콘·서로 다른 아이콘 세트를 혼용하지 않는다.

아이콘의 흰 공간과 클릭 영역은 구분한다. 핵심 조작에는 짧은 라벨을 유지하고, 장식 아이콘은 보조기술에서 읽지 않도록 한다.

### 6.3. 간격

기본 간격 후보는 4/8/12/16/24/32px이다. 전체 구도를 다듬으며 주요 영역 사이의 리듬과 같은 역할의 안쪽 여백을 맞춘다. 화면 전체를 넓게 비우기보다 숫자·범례·조작 주변에 필요한 여유를 둔다. 필요한 치수는 기준 화면의 구현에서 확정한다.

## 7. 그래프·표의 표현

### 7.1. 자료 우선

그래프 바탕은 불투명 흰색이다. 미세한 회색 격자, 읽을 수 있는 축 글자, 선명한 실제 자료를 사용한다. 선 뒤에 네온 광채·진한 면 채움·움직이는 장식파를 넣지 않는다.

축 범위·데이터 제외·값의 정밀도·회귀·시간 공백·샘플링은 바꾸지 않는다. 기존 `animation: false`와 원자료 공백 처리의 의미를 유지한다. [R4]

### 7.2. 일관된 채널 정체성

측정값, 항목 선택, 시간 그래프, 표의 채널 표시에서 같은 물리량의 색을 연결한다. 온도는 오렌지 계열, 압력은 코발트 계열, 밝기는 바이올렛 계열을 우선한다. 벡터 채널은 X/Y/Z 글자와 선 모양도 함께 사용한다.

새 테마의 채널색은 **표시 계층**에서 결정한다. 저장된 과거 센서 정의의 `color`를 읽어 과거 청록 테마가 섞여 나오지 않도록 새 테마의 해석 규칙을 공용한다. 저장 파일의 정의 사본·원자료·버전을 시각 변경 때문에 수정하지 않는다. 알려지지 않은 채널에는 안정적인 대체색과 라벨/선 모양을 적용한다. [R3, R4]

관계 그래프는 여러 물리량이 합쳐진 자료 쌍이므로 남색 점 + 오렌지 추세선을 기본으로 한다. 이를 ‘온도 데이터 전체가 오렌지여야 한다’는 규칙과 혼동하지 않는다. 축 제목에는 실제 물리량과 단위를 표시한다.

### 7.3. 분석 상태

| 상태 | 표현 |
|---|---|
| 일반 포함 자료 | 채워진 점 또는 실제 채널선 |
| 선택 자료 | 기존 채널색을 유지하고 남색/코발트 외곽 고리나 크기 차이를 추가 |
| 제외 자료 | 속이 빈 점·명시적 범례. 지워진 것처럼 취급하지 않음 |
| 추세선 | 충분히 읽히는 오렌지 선, 자료 점과 형태로 구분 |
| 연장선 | 같은 계열의 점선 |
| 선택 중 구간 | 반투명 옅은 코발트 면+명확한 경계. 적용 완료와 문구로 구별 |
| 수신 공백 | 연결되지 않은 선. 예쁘게 보이도록 보간하지 않음 |

선택 상태를 오렌지 색 변경만으로 표시하면 온도 채널색과 충돌하므로 모양을 함께 바꾼다.

조작 사건은 기존 시각·내용·측정값과의 관계를 보존하면서 표식·메모 줄·시간축 등의 제시 방식으로 재구성할 수 있다. 기존 사건의 재표현과 새 사건 편집 기능의 추가는 구분한다. 시안에 나타난 모든 기능을 구현할 의무는 없다.

### 7.4. PNG와 기타 출력

현재 화면과 그래프 PNG는 같은 글자·채널색·포함/제외·추세선 규칙을 사용한다. 출력 배경은 흰색이며, 화면 밖에서 생성하는 Canvas에도 명시적인 테마 값을 전달한다. 장식 광원과 반투명 앱 틀은 출력 이미지에 포함하지 않는다.

CSV/JSON 내용·정밀도·필드 순서·호환성은 외형 작업으로 변경하지 않는다.

## 8. 화면별 표현 강도와 준비 장면

| 화면 | 표현 방향 | 시각적 중심 | 보존할 동작·의미 |
|---|---|---|---|
| 홈 | 밝은 깊이감, 인상적인 한 장면 | 센서/활동 선택과 이어하기 | 필요한 선택·진입·기존 실험 접근 |
| 장비 준비 | 남색 무대 또는 준비 작업 화면 전체의 어두운 연출 | 정확한 장비, 구도·빛·전후 겹침, 현재 행동 | 준비 절차·수신 확인·배선·보정의 의미 |
| 측정 | 밝은 표면과 선명한 신호색 | 측정값·그래프·기록 조작의 균형 | 연결/기록/저장 상태와 기록 수명 |
| 분석 | 밝고 차분한 작업면, 자료에 집중하는 깊이 | 축·점·선택·표·해석 | 분석 범위·선택/적용·제외·해석의 의미 |
| 저장된 실험 | 담백하고 정돈된 면 | 실험 이름·시간·이어하기 | 기존 자료 보존·파일 동작 |

이 표는 역할별 방향이지 레이아웃 템플릿이 아니다. 홈·측정·분석의 탐색, 도구 배치, 패널 묶음은 기준 화면에서 검증한 문법으로 설계한다.

### 8.1. 준비 장면은 별도 시각 산출물로 검증

남색 바탕만 추가한 상태와 시안의 장면 완성도를 구분한다. **정확한 장비 + 카메라 구도 + 빛의 방향 + 배경 곡면 + 전후 겹침**을 함께 설계하고, 대표 장면 한 컷을 먼저 렌더링해 검토한다.

기존 모델·뷰어의 지원 범위를 확인해 카메라·조명·배경·재질을 조절한다. 자산 재사용은 현재 외관까지 고정한다는 뜻이 아니다. 시안에 필요한 보강 자산이나 정적 렌더를 추가할 수 있으며, 사용한 자산의 출처와 사용 범위를 남긴다. 실습에 중요한 단자 색·배선·장비 형상은 실제 자료와 일치시킨다.

장면 전체를 실시간 3D로 만들 필요는 없다. 분위기를 위한 정적 배경과 실제 조작이 필요한 장비 뷰어를 조합하거나, 소개 장면과 정확한 배선 확인 화면을 구분할 수 있다. 장식 장면이 실습 정보를 대체하지 않도록 역할을 명확히 한다.

어두운 표현을 그림 영역에만 적용할지 준비 작업 화면 전체로 넓힐지는 실제 시안에서 결정한다. 화면별 밝기 연출은 전역 다크 모드·사용자용 테마 선택 기능을 새로 만드는 것과 별개다.

## 9. 움직임과 정적 상태

| 종류 | 기준 |
|---|---|
| 버튼·입력 피드백 | 120–160ms, 색·테두리 위주 |
| 누름 피드백 | 약 80ms, 위치 변동 최소 |
| 기존 패널 전환 | 180–240ms, 기존 연속성과 초점 유지 |
| 수신값·그래프 갱신 | 실제 데이터에 즉시 대응. 보기 좋은 중간 값을 만들지 않음 |
| 준비 그림·배경광 | 정적이 기본. 장식 자동회전·입자·점멸 없음 |
| 반복 상태 표시 | 실제 작업 중인 표시 외에는 반복 애니메이션 없음 |

`prefers-reduced-motion: reduce`에서는 장식 이동과 크기 변화는 제거하고 상태 변경을 즉시 표시한다. 사용자 설정은 CSS와 필요한 Canvas/뷰 전환 경로에 함께 반영한다. 진행 중인 작업의 의미는 남긴다. [W4]

3D 뷰어의 배치·카메라·조명을 바꾸더라도 단계 이동 시 불필요한 재생성, 초기화 깜빡임, 조작 상태 손실이 생기지 않게 한다. 필요한 내부 조정은 기존 수명 관리와 함께 검증한다.

## 10. 접근성·가독성·성능 기준

일반 글자는 최소 4.5:1, 큰 글자는 3:1, 이해에 필요한 조작 경계·그래픽은 인접색과 3:1을 기준으로 검토한다. 이는 WCAG 대비 기준이며, 여기서 제안한 모든 화면이 이미 통과했다는 의미는 아니다. 색상 외에 라벨·아이콘·모양으로 상태를 전달한다. [W1, W2]

| 조합 | 계산 대비 | 사용 판단 |
|---|---:|---|
| 남색 `#0B1F3B` / 오렌지 `#FF7A45` | 6.38:1 | 오렌지 버튼 글자 |
| 흰색 / 오렌지 `#FF7A45` | 2.59:1 | 기본 버튼 글자 조합에서 제외 |
| 오렌지 글자 `#B54416` / 흰색 | 5.52:1 | 작은 색상 라벨 |
| 오렌지 그래프 `#D65A20` / 흰색 | 3.93:1 | 그래픽 및 큰 글자. 작은 글자는 더 진한 변형 사용 |
| 코발트 글자 `#1D4ED8` / 흰색 | 6.70:1 | 작은 색상 라벨 |
| 바이올렛 글자 `#6740CF` / 흰색 | 6.54:1 | 작은 색상 라벨 |
| 조작 경계 `#7F8DA4` / 흰색 | 3.36:1 | 필요한 입력 경계 |

이 수치는 불투명한 두 색의 계산값이다. 반투명 표면·호버·그라데이션·안티앨리어싱·실제 프로젝터에서의 읽기성은 별도 확인한다. [별도 대비 기록](contrast-check.md)

작은 화면에서는 장식과 바깥 여백을 먼저 줄인다. 폰트를 일괄 축소하지 않는다. 키보드 초점, 200% 글자 확대, 읽기 순서, 터치 대상, 내부 표 스크롤을 확인한다.

성능 목표는 새 디자인으로 실시간 값 갱신·차트 조작·표 스크롤이 눈에 띄게 나빠지지 않는 것이다. 이를 보장한다고 추정하지 않고 V0 기준과 같은 장치·같은 자료로 비교한다. 매 샘플마다 스타일 토큰을 다시 읽거나, 큰 그림자를 애니메이션하거나, 모든 패널에 배경 필터를 적용하지 않는다.

## 11. 화면 검토 기준

기술적으로 정상 작동하는 것과 시안의 미술 방향을 구현한 것은 별도로 확인한다. V1에서 실제 측정 화면을 완성하며 검토하고, 그 결과로 V2 공통 문법을 확정한다. 실제 앱 캡처를 기준 이미지의 해당 화면과 비교해 다음을 평가한다.

| 평가 항목 | 통과 판단 |
|---|---|
| 인상 변화 | 기존 청록 버튼 중심 화면과 한눈에 다른 인상인가 |
| 전체 비례·밀도 | 탐색·숫자·그래프·조작부의 면적과 간격이 의도한 위계를 만드는가 |
| 기준 이미지의 연속성 | 밝은 깊이감·남색 중심·오렌지/코발트 신호가 함께 보이는가 |
| 차분함 | 눈길을 끄는 주 대상이 분명하고 주변 장식은 물러나 있는가 |
| 완성도 | 글자 굵기·숫자 기준선·모서리·아이콘·상태 표현이 서로 맞는가 |
| 과학적 명료함 | 값·단위·축·공백·선택 상태가 장식보다 먼저 읽히는가 |
| 실사용 일관성 | 빈 화면·오류·비활성·모바일에서도 같은 문법이 유지되는가 |

‘색만 바뀌었지만카드·버튼의 인상은 이전과 같다’면 인상 변화가 충분하지 않은 것이다. 반대로 장식이 과해서 자료가 묻히면 차분함과 과학적 명료함이 부족한 것이다. 이미지와 픽셀 단위로 일치시키는 것은 목표가 아니다.

검토 자료는 **전체 화면 캡처 + 같은 화면의 주요 상태 + 남은 시각 차이와 수정 방향**으로 구성한다. 예를 들어 ‘헤더가 무거워 그래프가 작아 보임’, ‘경계가 진해 표면이 상자처럼 보임’처럼 관찰 가능한 차이를 적는다. 필요하면 배치와 토큰 모두 수정하고, 검토한 화면의 표현을 공통화한다. 지침만으로 완성도를 보장했다고 표시하지 않는다.
