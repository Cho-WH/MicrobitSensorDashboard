## 1. 채택한 방향과 범위

밝은 표면, 남색 중심 글자, 절제된 신호색을 사용한다. 측정은 숫자·그래프·기록 조작에 집중하고, 준비 B안은 남색 장면 위에 장비와 설명을 배치한다. 배선 3D 작업면은 단자 글자와 접지선을 읽을 수 있도록 밝게 유지한다. 장식 광원과 궤도는 자료 영역 밖에 둔다.

준비 탭과 메모는 **직선 강조선 + 배경 오버레이**를 사용한다. 이를 둥근 테두리 버튼으로 되돌리지 않는다. 외곽 패널·일반 버튼·입력은 역할에 맞는 곡률을 유지한다. 기록 조작은 아이콘과 보이는 글자를 함께 제공한다.

V5부터 홈·센서·활동의 기본 화면에 적용한다. 테마 선택 매개변수는 필요하지 않다. 기존 `?visual=luminous` 주소도 열리지만 새 링크에는 이를 붙이지 않는다. A안의 캡처와 구현은 개발 보관 경로에 유지하며 현재 화면에서 선택지로 제공하지 않는다. 분석·해석·홈·저장 목록·PNG·인쇄까지 같은 문법을 적용한다.

| 작업 공간 | [viewport-layout.js](../../src/ui/viewport-layout.js) | 측정·원자료·관계·해석에 남은 높이 전달. 내부 배분·최소 크기는 각 화면 CSS 소유 |
| 스타일 전달 | [styles.mjs](../../scripts/styles.mjs) | 개발 서버와 정적 빌드에서 같은 순서·자원 주소로 공통 CSS 결합 |
| Canvas 연결 | [visual-theme.js](../../src/ui/visual-theme.js) | CSS 값을 읽어 DOM 계기·범례와 그래프에 같은 표시값 전달 |

HTML은 준비 CSS와 공통 진입 CSS를 정적으로 선언한다. 공통 진입의 정확한 순서는 `luminous.css` 한곳에 둔다. 공통 조작이 기본 크기·상태를 정하고 앱 틀·분석의 지역 규칙이 이를 구체화한다. A안 검토 진입만 준비 CSS를 archive 스타일로 바꾸며 나머지 공통 진입·동작은 동일하다. 기본 앱은 archive 자원을 요청하지 않는다. 기존 CSS는 비계층이므로 새 파일만 `@layer`에 넣지 않는다. `:is()` 안에 ID와 클래스를 섞으면 클래스 쪽도 ID 우선순위를 얻으므로 공통 역할 선택자는 분리한다.

실행 값의 단일 기준은 `src/ui/tokens.css`다. 문서의 후보 토큰 사본은 제거했다. 문서는 값의 의미·사용 조건·예외를 설명하고 CSS 치수를 복제하지 않는다.

소스 `luminous.css`의 로컬·무조건부 import 목록은 개발 서버와 빌드가 같은 함수로 결합한다. CSS 파일의 책임은 유지하고, 전달할 때만 공통 CSS 한 개로 만든다. 준비 CSS는 A안 대체 경계를 유지하기 위해 별도 링크다. 파일 순서를 바꾸거나 조건부 import를 임의로 펼치지 않으며, 지원하지 않는 import와 순환 참조는 오류로 처리한다. 이미지·글꼴 주소는 결과 CSS 위치를 기준으로 다시 계산한다.

## 3. 역할별 색과 표면

| 역할 | 토큰 계열 | 사용 규칙 |
|---|---|---|
| 페이지·자료 표면 | `--sl-bg`, `--sl-surface`, `--sl-surface-soft` | 그래프·입력은 흰 자료 바탕. 장면 그라데이션은 화면 파일에 둠 |
| 글자·영역 구분 | `--sl-navy`, `--sl-text`, `--sl-muted`, `--sl-line` | 제목, 본문, 보조 설명, 장식 구분선을 구별 |
| 입력 경계 | `--sl-input-border` | 장식 구분선과 별도 관리. 흰 면·밝은 도구 면에서 3:1 이상, [대비 기록](contrast-check.md) 참조 |
| 일반 주요 행동 | `--sl-primary-*` | 밝은 화면에서는 남색 바탕과 흰 글자. 준비 B의 지역 주요 행동은 강조 행동 값으로 연결 |
| 강조 행동 | `--sl-action-*` | 주황 바탕과 남색 글자. 기록 시작·재개, 준비의 다음 행동 |
| 선택·초점 | `--sl-selection`, `--sl-focus`, `--sl-tab-*` | 선택선과 키보드 초점을 구분. 준비 B의 현재 단계는 주황선+흰 글자 |
| 기록·수신 | `--sl-recording-*`, `--sl-success`, `--sl-idle*` | 점·글자와 함께 표시. 연결되지 않음은 중립 상태 |
| 준비의 완료·확인 필요 | `--sl-stage-success`, `--sl-stage-attention` | 어두운 면에서 읽을 수 있는 상태색. 완료는 체크와 근거, 생략은 대시와 생략 문구로 구분 |
| 기록 마침 | `--sl-finish-*` | 옅은 주황 바탕과 진한 글자. 삭제/저장 실패로 오인시키지 않음 |
| 사건·메모 | `--sl-event-*` | 파란 강조선, 짧은 내용·시각, 호버 오버레이 |
| 실제 자료 | `--sl-channel-1`…`4`, `--sl-chart-*` | 행동·선택 토큰과 분리. 값이 같아도 다른 의미로 관리 |
| 분석 표시 | `--sl-analysis-*`, `--sl-selected-bg`, `--sl-inspected-bg` | 포함/제외/추세선/점 살펴보기와 표 체크를 구분. 원자료에 기록하지 않음 |

온도 선의 주황과 기록 시작 버튼의 주황은 같은 역할이 아니다. 자료선을 바꿀 때 행동 버튼까지 함께 바뀌지 않아야 한다. 오류·비활성·선택을 채널색만으로 표현하지 않는다.

준비의 어두운 표현은 `.guide:not([data-stage-style=light])` 안에서만 적용한다. `--sl-stage-*`, 비활성 값과 초점 값을 이 범위에서 재정의한다. 흰 자료 표면, 버튼의 주황/남색 조합, 밝은 A안은 이 범위 밖에 있다.

기존 `--ink`, `--muted`, `--teal`, `--line`, `--pale`은 아직 이행하지 않은 UI를 연결하는 별칭이다. 새 규칙은 역할별 `--sl-*`를 사용한다. 기존 `--teal`을 모든 행동·상태·자료의 공통색으로 확장하지 않는다.

## 4. 형태와 조작 상태

| 대상 | 형태·역할 |
|---|---|
| 준비의 큰 단계 탭 | 직각, 상단 직선, 투명 기본면, 현재 단계선과 호버 오버레이 |
| 분석 작업·표/그래프 보기 탭 | 직각, 하단 직선, 현재 위치와 호버 오버레이. 둥근 선택 캡슐을 사용하지 않음 |
| 메모 목록·시간축 표찰·메모 기록 버튼 | 직각. 목록은 왼쪽 선, 표찰은 아래 선. 전체 둘레를 감싸지 않음 |
| 일반 조작·입력 | `--sl-radius-control`, 읽을 수 있는 라벨 |
| 이미 준비된 장치로 이동 | `--sl-radius-compact`, 보조 조작의 작은 밀도 |
| 패널·계기 묶음·메뉴·대화상자 | 역할별 `--sl-radius-*`와 깊이. 패널 안에 같은 카드를 반복 중첩하지 않음 |

버튼의 기본·호버·누름·비활성은 공통 스타일 한곳에서 처리한다. 역할 선택자는 `--sl-button-bg/text/line/hover/pressed` 같은 **부품 내부 값**만 연결한다. 새 버튼마다 상태 선택자 세트를 복제하지 않는다. 화면 파일은 크기·위치를 맡는다.

| 상태 | 규칙 |
|---|---|
| 기본 | 남색 주요 행동, 주황 강조 행동, 중립 보조 행동의 역할 구분 |
| 호버·누름 | 색면·경계 변화. 크기·위치가 이동하지 않음 |
| 키보드 초점 | 공통 외곽선. 밝은 화면은 코발트, 어두운 준비는 밝은 파랑 |
| 비활성 | 실제 `disabled` 속성과 중립 표현. 배경색만으로 비활성 처리하지 않음 |
| 진행 | 기존 상태 소유자가 활성/비활성을 결정. `aria-busy`가 있으면 진행 커서. 별도 UI 상태를 만들지 않음 |

초점 복귀는 CSS의 역할이 아니다. 기록 버튼 교체와 대화상자 닫기의 기존 동작 계약을 유지한다. 원형·캡슐형 버튼을 공통 기본값으로 도입하지 않는다.

V3 준비의 보조 버튼·선택 상태도 공통 역할 바인딩을 사용한다. 설치의 `aria-busy`와 수신 표시 상태는 전달받은 사실에서 파생하며, UI가 별도의 수신 타이머나 완료 상태를 소유하지 않는다. 3D·용기 배치도·보정 그림의 밝은 면은 판독을 위한 예외다.

## 5. 글자·간격·움직임

시간 그래프는 같은 물리량·같은 단위의 방향 성분과 크기를 하나의 축·스케일로 표시한다.
공유 축 제목은 특정 선의 색을 대표하지 않는 중립색이며 각 자료선의 색은 유지한다.
그룹 기준·메타데이터·기존 자료 처리는 [모듈 등록 규칙](../../src/catalog/README.md#시간-그래프의-공통-축)을 따른다.

관계 그래프의 넓은 화면에서는 축 이름과 선택기를 한 줄에 두고 추세선 조작은 해당 축 아래에 둔다. 사용 자료 수는 통계 제목 옆에, 수치는 세 칸에, 저장·해석 행동은 하단 한 줄에 모은다. 상하단 조작과 설명의 실제 높이를 제외한 공간을 그래프·가상 표에 배분한다. 작은 화면·글자 확대·상세 설명에서는 읽기 위한 최소 높이를 지키고 필요한 페이지 스크롤을 허용한다. 외곽 패널과 직선 탭 문법을 유지하며 숨김으로 내용을 잘라 맞추지 않는다.

원 자료 보기의 시간 그래프는 하단 구간 선택·자료 보기 조작의 공간을 남긴다. 결과 해석의 저장 상태·파일 저장·인쇄·저장 오류는 근거 그래프 아래 같은 열에 둔다. 글쓰기 영역 아래에 별도 행동 행을 추가하지 않으며, 좁은 화면에서는 그래프와 저장 도구 다음에 글쓰기가 이어진다.

채널의 선·점 색(`--sl-channel-*`)과 읽기용 색(`--sl-channel-text-*`)은 같은 계열의 별도 역할이다. 작은 범례·축 제목과 크기가 변하는 계기 숫자는 읽기용 색을 쓴다. 선택 글자도 `--sl-selection-text`로 구분한다. 가상 표는 글꼴 크기에 맞춰 행 높이와 빈 공간을 함께 갱신해 확대 중에도 마지막 자료에 접근할 수 있게 한다.

- Pretendard Variable 1.3.9를 로컬에서 사용하며 실패 시 한국어 시스템 서체로 표시한다. 출처·해시는 [외부 자원 고지](../../THIRD_PARTY_NOTICES.md)와 vendor manifest에 유지한다. 아이콘은 기존 Lucide 자원을 쓴다.
- `--sl-type-*`는 rem 기반 조작·라벨·보조 글자의 반복 크기다. 큰 측정값의 컨테이너 기반 크기와 장면 제목의 비례는 화면 파일에서 관리한다. 글자 확대 시 계기는 재배치하고 숫자의 높이와 단위 기준선을 안정적으로 유지한다. 긴 값은 자르지 않고 내부 스크롤로 제공한다.
- `--sl-space-*`는 반복 간격이다. 장치 폭·차트 높이·열 비율·미세 정렬은 해당 배치에서 관리한다. 모든 숫자를 토큰으로 옮기지 않는다.
- 일반 조작은 `--sl-target`, 작은 보조 조작은 `--sl-target-compact`를 사용한다. 기존 모바일 확대 규칙을 보존한다. 작은 화면은 배치와 여백을 먼저 조정한다.
- 버튼 피드백과 준비 전환은 `--sl-motion-*`를 따른다. 동작 줄이기 설정에서는 장식 움직임을 제거한다. 실시간 측정값은 보간하지 않고 차트의 기존 `animation:false`를 유지한다.

## 6. DOM과 Canvas의 연결

`readVisualTheme(root, channels)`는 Luminous가 적용된 문서에서만 표시값을 반환한다. 특정 측정 화면 클래스의 존재에 의존하지 않는다. 뷰를 구성할 때 한 번 읽어 전달하며 매 수신마다 CSS를 조회하지 않는다.

온도는 첫 자료색, 압력은 두 번째, 상대 밝기는 세 번째를 사용한다. 다른 채널은 전체 채널 목록의 순서로 안정적으로 배정한다. 표시 항목을 숨겨도 남은 채널의 색을 다시 배정하지 않는다. 목록 밖의 알 수 없는 채널에는 ID 기반 대체색을 사용한다. 계기·범례·선은 동일한 해석 결과를 쓴다.

저장된 정의의 오래된 `color`를 새 테마로 고쳐 저장하지 않는다. 단위·정밀도·수집 채널·시각·회귀·원자료·파일 내용은 표시 토큰에 넣지 않는다. 메모 표찰도 원래 사건 시각을 가리키며, 가까운 표찰을 묶어도 상세에서 각각의 시각·내용을 보여 준다.

분석 화면을 열 때 표시값을 한 번 읽어 원자료 차트·관계 그래프·보관 근거·PNG·인쇄에 전달한다. 관계 그래프의 점은 세로축 채널색을 사용하며 계산 열은 공통 분석색을 쓴다. 포함은 채운 점, 제외는 빈 점, 살펴보는 점은 크기와 진한 색으로 구분한다. 추세선은 따뜻한 진한 색의 실선, 연장 부분은 점선이다. 표의 체크와 점 살펴보기는 서로 다른 배경이며 제외/범위 밖 상태의 문구를 유지한다.

PNG는 화면과 같은 데이터 모델·색·축·글꼴로 별도 Canvas에 그린다. 해석에서 내보내거나 인쇄할 때는 보관한 근거를 사용한다. 출력 바탕은 불투명한 흰색이며 앱의 사이드바·장식 배경을 넣지 않는다. 초기 Canvas를 만들기 전에 로컬 글꼴 로딩 또는 대체 글꼴 확정을 기다린다. JSON·CSV·저장 정의에는 표시 토큰을 넣지 않는다.

## 7. 확장·검토 기준

1. 기존 역할로 표현 가능한지 먼저 확인한다. 실제 두 곳 이상에서 쓰이거나 독립적으로 조정할 이유가 있을 때 공통 규칙을 추가한다.
2. 값은 토큰, 조작 상태는 공통 스타일, 화면 비례와 장식은 해당 화면에 둔다. 장비 장면까지 범용 카드로 바꾸지 않는다.
3. 색·모서리 변경은 선택/호버/누름/초점/비활성·어두운 준비를 함께 살핀다. 보관된 A안은 현재 디자인의 적용 대상이 아니다. [대비 기록](contrast-check.md)을 실제 사용값으로 갱신한다.
4. 기존 기준 화면과 같은 크기·자료·상태에서 비교한다. 이름만 정리하고 배치나 인상이 달라졌으면 공통화가 끝난 것이 아니다.
5. 관련 기능·원자료 보존 검사는 재사용한다. 임시 수치·소스 문자열·CSS 배치 자체를 고정하는 검사를 늘리지 않는다.

과학적 의미와 상태 소유권은 [통합 앱 기획](../unified-sensor-lab-plan.md)과 [기술 설계](../unified-sensor-lab-architecture.md)를 따른다. 브라우저·모의 검사 결과는 실물 USB/BLE 검증과 구분한다.

## 8. 기본 UI의 목표 구조

Luminous를 선택 가능한 덧씌움 테마가 아닌 앱의 기본 표현으로 정착시킨다. 현재 채택한 화면의 비례·색상 역할·형태를 기준으로 삼으며, 구조 정리와 새 디자인 제안은 별도로 다룬다. 구현 순서와 확인 범위는 [전환 계획 §14](visual-rollout-plan.md#14-기본-ui-구조-전환-계획)를 따른다.

### 8.1. 고정 구조와 동작의 경계

| 소유자 | 목표 책임 |
|---|---|
| `lab.html` | 사이드바·헤더·파일 저장 메뉴·측정 영역·장치 설정창의 최종 고정 구조, 초기 테마와 CSS 선언 |
| `app-shell.js` | 기존 메뉴·대화상자의 이벤트, 키보드 조작, 초점 복귀 연결. 구조 재배치·CSS 동적 삽입은 맡지 않음 |
| `startup.js` / `app-presentation.js` | 문서 시작의 준비 상태와 스타일·서체 결정. `Controller.ready` 후 조작 공개 |
| Controller와 각 View | 경로·문구·버튼 허용 상태·실험별 내용·동적 목록·차트 갱신. 기록·저장 상태의 기존 소유권 유지 |
| 표시 어댑터 | 토큰에서 계기·범례·Canvas·PNG·인쇄에 같은 색·서체 전달 |

고정된 틀은 HTML에서 한 번 선언한다. 센서 채널·활동 조작·저장 목록·필요할 때 만드는 편집 대화상자는 기존 모듈이 생성한다. 컨트롤 ID, 라벨 연결, `data-view` 등 호출 계약은 1차에서 유지한다. 프레임워크 교체나 별도의 UI 상태 저장소는 추가하지 않는다.

### 8.2. 스타일의 단일 소유권

| 규칙 | 목표 소유권 |
|---|---|
| 리셋·문서 기본 동작 | 기본 CSS. 이전 팔레트나 화면별 버튼 디자인을 포함하지 않음 |
| 의미별 값 | `tokens.css`. 행동·선택·상태·자료 색과 형태·간격·서체의 단일 기준 |
| 공통 부품과 상태 | 공통 조작 CSS. 기본·호버·누름·초점·비활성·진행 표현 |
| 화면 배치와 장식 | 준비·측정·분석·해석·홈·보관의 담당 CSS. 부품의 크기·위치와 화면별 구도 |
| 밝은 자료 면과 어두운 준비 B | 필요한 표면 범위에서 역할 값을 재정의. 조작 상태 규칙을 복제하지 않음 |
| 보관된 A안 | 개발 archive 경로의 표현 규칙. 기본 앱의 선택지·의존 자원에 포함하지 않음 |

2차에서 기존 규칙과 Luminous 덮어쓰기를 위 담당 파일로 합치고, 별도 덮어쓰기 파일 4개를 제거했다. `base.css`의 사용하지 않는 이전 화면 규칙과 이전 색상 별칭도 정리했다. 배치·표 가상화·인쇄·접근성 규칙은 유지한다. 새 수정은 담당 파일에 반영하며 별도 테마 덮어쓰기 파일을 추가하지 않는다.

HTML의 `data-visual-theme="luminous"`는 기존 선택자와 Canvas 연결의 식별자로 유지하며 실행 중 UI를 바꾸는 스위치로 사용하지 않는다. `--ink`, `--muted`, `--teal` 등 이전 별칭은 소비 경로까지 이행해 제거했다. 어두운 준비 값은 `guide.css`의 지역 변수이고 센서 전용 표현도 이를 읽는다. 일부 파일만 CSS 계층(`@layer`)으로 옮기는 변경은 하지 않는다.

### 8.3. 확장 시 재사용 단위

기존 버튼 역할, 직선 탭, 메모, 입력, 펼침 메뉴, 대화상자를 우선 재사용한다. 메뉴의 Escape·바깥 클릭·초점 복귀는 `bindDisclosureMenu`, 기록 편집 폼의 초안·진행·저장 실패 처리는 `createRecordDialogs`의 기존 책임을 유지한다. 생김새가 비슷하다는 이유로 모든 부품을 하나의 범용 카드나 폼 엔진으로 합치지 않는다.

새 조작은 역할·상태·밝고 어두운 표면을 먼저 결정한다. 화면별 CSS는 역할 값을 연결하며 호버·비활성 규칙을 새로 복사하지 않는다. 준비 탭·분석 탭·메모의 직각 및 직선 강조, 활동 카드·자료 상세 패널의 왼쪽 장식선 제거 결정도 유지한다. 일반 입력·외곽 패널의 곡률까지 일괄 변경하지 않는다.

- 버튼에는 `data-ui-action="primary|accent|quiet|finish"`로 역할을 붙인다. 기존 `.primary`도 같은 주요 행동 역할이다. 준비 B는 지역 `--sl-primary-*` 값으로 강조색을 사용하며 보관 A는 밝은 화면의 값을 유지한다. 기존 센서·활동 모듈이 스타일 파일을 새로 삽입할 필요가 없다.
- 준비 단계와 분석 작업/보기 버튼은 `.ui-tab`을 재사용한다. 선택은 기존 `aria-current`/`aria-pressed`가 결정하고, 준비의 상단선과 분석의 하단 표시선은 각 화면이 맡는다. 탭 색·호버·선택 글자·직각 형태는 공통 규칙이다. 역할만 붙이는 것으로 키보드 이동이나 탭 의미가 자동 생성되지는 않는다.
- 사건·메모는 `--sl-button-*` 역할 값과 공통 호버 상태를 사용한다. 메뉴의 이벤트 수명·대화상자의 초안·저장 책임은 기존 모듈을 유지한다.

반응형은 페이지 최대 폭, 상단·하단 조작의 필요 공간, 그래프·표의 남는 높이, 최소 읽기 크기와 줄바꿈 순서로 결정한다. 작은 화면·200% 글자·긴 내용에서 필요한 스크롤은 허용한다. 센서·활동 모듈은 내용과 절차를 제공하고 공통 부품의 모양을 직접 지정하지 않는다.

측정·분석의 넓은 화면은 공통 `--workspace-height`를 받는다. 공통 계산은 작업 영역 앞뒤 공간만 측정하고 CSS Flex/Grid가 그래프·표·해석 내용을 배분한다. 그래프와 표의 자식 높이를 JS에서 각각 빼거나 고정된 페이지 여백을 중복 차감하지 않는다. 작은 화면에서는 이 예산을 해제한다. Canvas와 가상 표는 기존 ResizeObserver로 실제 영역을 따르며 원자료·축·자료색·차트 인스턴스를 재생성하지 않는다. 최소 읽기 크기를 지키기 위해 내용이 많거나 확대된 화면에는 세로 스크롤을 허용한다.
