# 센서 실험실 시각 디자인 문법

> Luminous Lab · V2 공통 규칙 · 2026-10-25
> 기준: [사용자 시안](reference/approved-moodboard.png), [측정 화면](review/v1/measurement-refined.png), [준비 B안 채택](review/v1/preparation-comparison.md)
> 적용 순서: [V0–V5 계획](visual-rollout-plan.md)

## 1. 채택한 방향과 범위

밝은 표면, 남색 중심 글자, 절제된 신호색을 사용한다. 측정은 숫자·그래프·기록 조작에 집중하고, 준비 B안은 남색 장면 위에 장비와 설명을 배치한다. 배선 3D 작업면은 단자 글자와 접지선을 읽을 수 있도록 밝게 유지한다. 장식 광원과 궤도는 자료 영역 밖에 둔다.

준비 탭과 메모는 **직선 강조선 + 배경 오버레이**를 사용한다. 이를 둥근 테두리 버튼으로 되돌리지 않는다. 외곽 패널·일반 버튼·입력은 역할에 맞는 곡률을 유지한다. 기록 조작은 아이콘과 보이는 글자를 함께 제공한다.

현재 적용은 `?visual=luminous` 개발 선택 경로다. 기본 앱 전환은 V5에서 판단한다. 보관한 준비 A안의 캡처와 직접 조작 경로는 유지한다. 분석·해석·홈·저장·PNG 전체 디자인 적용은 V4 범위다.

## 2. 규칙의 소유권

| 층 | 실행 소스 | 책임 |
|---|---|---|
| 값 | [tokens.css](../../src/ui/tokens.css) | 표면·행동·선택·상태·자료의 역할별 값, 형태·간격·서체·모션 |
| 공통 조작 | [luminous-controls.css](../../src/ui/luminous-controls.css) | 버튼 상태, 초점, 직선 탭/메모 형태, 대화상자 공통 표면 |
| 측정·앱 배치 | [luminous-preview.css](../../src/ui/luminous-preview.css) | 사이드바·헤더·계기·차트·메모의 배치와 반응형, 장식 |
| 준비 배치 | [luminous-preparation.css](../../src/ui/luminous-preparation.css) | B안 구도·장치 카드·설명·뷰어와 반응형 |
| DOM 구성 | [luminous-preview.js](../../src/ui/luminous-preview.js) | 실제 조작부를 배치. 기록·연결·저장 상태를 복제하지 않음 |
| Canvas 연결 | [visual-theme.js](../../src/ui/visual-theme.js) | CSS 값을 읽어 DOM 계기·범례와 그래프에 같은 표시값 전달 |

로딩 순서는 **토큰 → 공통 조작 → 준비 배치 → 측정·앱 배치**다. 기존 CSS는 비계층이므로 새 파일만 `@layer`에 넣지 않는다. 작은 선택자와 역할 바인딩으로 우선순위를 유지하며 `!important`를 쌓지 않는다. `:is()` 안에 ID와 클래스를 섞으면 클래스 쪽도 ID 우선순위를 얻으므로 공통 역할 선택자는 분리한다.

실행 값의 단일 기준은 `src/ui/tokens.css`다. 문서의 후보 토큰 사본은 제거했다. 문서는 값의 의미·사용 조건·예외를 설명하고 CSS 치수를 복제하지 않는다.

## 3. 역할별 색과 표면

| 역할 | 토큰 계열 | 사용 규칙 |
|---|---|---|
| 페이지·자료 표면 | `--sl-bg`, `--sl-surface`, `--sl-surface-soft` | 그래프·입력은 흰 자료 바탕. 장면 그라데이션은 화면 파일에 둠 |
| 글자·영역 구분 | `--sl-navy`, `--sl-text`, `--sl-muted`, `--sl-line` | 제목, 본문, 보조 설명, 장식 구분선을 구별 |
| 입력 경계 | `--sl-input-border` | 장식 구분선과 별도 관리. 현재 대비 한계는 [대비 기록](contrast-check.md)에 명시 |
| 일반 주요 행동 | `--sl-primary-*` | 남색 바탕과 흰 글자 |
| 강조 행동 | `--sl-action-*` | 주황 바탕과 남색 글자. 기록 시작·재개, 준비의 다음 행동 |
| 선택·초점 | `--sl-selection`, `--sl-focus`, `--sl-tab-*` | 선택선과 키보드 초점을 구분. 준비 B의 현재 단계는 주황선+흰 글자 |
| 기록·수신 | `--sl-recording-*`, `--sl-success`, `--sl-idle*` | 점·글자와 함께 표시. 연결되지 않음은 중립 상태 |
| 기록 마침 | `--sl-finish-*` | 옅은 주황 바탕과 진한 글자. 삭제/저장 실패로 오인시키지 않음 |
| 사건·메모 | `--sl-event-*` | 파란 강조선, 짧은 내용·시각, 호버 오버레이 |
| 실제 자료 | `--sl-channel-1`…`4`, `--sl-chart-*` | 행동·선택 토큰과 분리. 값이 같아도 다른 의미로 관리 |

온도 선의 주황과 기록 시작 버튼의 주황은 같은 역할이 아니다. 자료선을 바꿀 때 행동 버튼까지 함께 바뀌지 않아야 한다. 오류·비활성·선택을 채널색만으로 표현하지 않는다.

준비의 어두운 표현은 `.guide:not([data-stage-style=light])` 안에서만 적용한다. `--sl-stage-*`, 비활성 값과 초점 값을 이 범위에서 재정의한다. 흰 자료 표면, 버튼의 주황/남색 조합, 밝은 A안은 이 범위 밖에 있다.

기존 `--ink`, `--muted`, `--teal`, `--line`, `--pale`은 아직 이행하지 않은 UI를 연결하는 별칭이다. 새 규칙은 역할별 `--sl-*`를 사용한다. 기존 `--teal`을 모든 행동·상태·자료의 공통색으로 확장하지 않는다.

## 4. 형태와 조작 상태

| 대상 | 형태·역할 |
|---|---|
| 준비의 큰 단계 탭 | 직각, 상단 직선, 투명 기본면, 현재 단계선과 호버 오버레이 |
| 메모 목록·시간축 표찰·메모 기록 버튼 | 직각. 목록은 왼쪽 선, 표찰은 아래 선. 전체 둘레를 감싸지 않음 |
| 일반 조작·입력 | `--sl-radius-control`, 읽을 수 있는 라벨 |
| 이미 준비된 장치로 이동 | `--sl-radius-compact`, 보조 조작의 작은 밀도 |
| 패널·계기 묶음·메뉴·대화상자 | 역할별 `--sl-radius-*`와 깊이. 패널 안에 같은 카드를 반복 중첩하지 않음 |

버튼의 기본·호버·누름·비활성은 공통 스타일 한곳에서 처리한다. 역할 선택자는 `--sl-button-bg/text/line/hover/pressed` 같은 **부품 내부 값**만 연결한다. 새 버튼마다 상태 선택자 세트를 복제하지 않는다. 화면 파일은 크기·위치를 맡는다.

| 상태 | 규칙 |
|---|---|
| 기본 | 남색 주요 행동, 주황 강조 행동, 중립 보조 행동의 역할 구분 |
| 호버·누름 | 색면·경계 변화. 크기·위치가 이동하지 않음 |
| 키보드 초점 | 공통 외곽선. 밝은 화면은 코발트, 어두운 준비는 밝은 파랑 |
| 비활성 | 실제 `disabled` 속성과 중립 표현. 배경색만으로 비활성 처리하지 않음 |
| 진행 | 기존 상태 소유자가 활성/비활성을 결정. `aria-busy`가 있으면 진행 커서. 별도 UI 상태를 만들지 않음 |

초점 복귀는 CSS의 역할이 아니다. 기록 버튼 교체와 대화상자 닫기의 기존 동작 계약을 유지한다. 원형·캡슐형 버튼을 공통 기본값으로 도입하지 않는다.

## 5. 글자·간격·움직임

- Pretendard Variable 1.3.9를 로컬에서 사용하며 실패 시 한국어 시스템 서체로 표시한다. 출처·해시는 [외부 자원 고지](../../THIRD_PARTY_NOTICES.md)와 vendor manifest에 유지한다. 아이콘은 기존 Lucide 자원을 쓴다.
- `--sl-type-*`는 조작·라벨·보조 글자의 반복 크기다. 큰 측정값의 컨테이너 기반 크기와 장면 제목의 비례는 화면 파일에서 관리한다. 숫자 폭과 단위 기준선을 안정적으로 유지한다.
- `--sl-space-*`는 반복 간격이다. 장치 폭·차트 높이·열 비율·미세 정렬은 해당 배치에서 관리한다. 모든 숫자를 토큰으로 옮기지 않는다.
- 일반 조작은 `--sl-target`, 작은 보조 조작은 `--sl-target-compact`를 사용한다. 기존 모바일 확대 규칙을 보존한다. 작은 화면은 배치와 여백을 먼저 조정한다.
- 버튼 피드백과 준비 전환은 `--sl-motion-*`를 따른다. 동작 줄이기 설정에서는 장식 움직임을 제거한다. 실시간 측정값은 보간하지 않고 차트의 기존 `animation:false`를 유지한다.

## 6. DOM과 Canvas의 연결

`readVisualTheme(root, channels)`는 Luminous가 적용된 문서에서만 표시값을 반환한다. 특정 측정 화면 클래스의 존재에 의존하지 않는다. 뷰를 구성할 때 한 번 읽어 전달하며 매 수신마다 CSS를 조회하지 않는다.

온도는 첫 자료색, 압력은 두 번째, 상대 밝기는 세 번째를 사용한다. 다른 채널은 전체 채널 목록의 순서로 안정적으로 배정한다. 표시 항목을 숨겨도 남은 채널의 색을 다시 배정하지 않는다. 목록 밖의 알 수 없는 채널에는 ID 기반 대체색을 사용한다. 계기·범례·선은 동일한 해석 결과를 쓴다.

저장된 정의의 오래된 `color`를 새 테마로 고쳐 저장하지 않는다. 단위·정밀도·수집 채널·시각·회귀·원자료·파일 내용은 표시 토큰에 넣지 않는다. 메모 표찰도 원래 사건 시각을 가리키며, 가까운 표찰을 묶어도 상세에서 각각의 시각·내용을 보여 준다.

분석의 선택/제외/추세선과 PNG 테마 연결은 V4에서 실제 분석 화면에 적용할 때 확정한다. 그때 흰 출력 바탕과 화면의 의미를 공유하되 장식 배경은 출력하지 않는다. 아직 사용하지 않는 분석 토큰이나 빈 부품을 미리 추가하지 않는다.

## 7. 확장·검토 기준

1. 기존 역할로 표현 가능한지 먼저 확인한다. 실제 두 곳 이상에서 쓰이거나 독립적으로 조정할 이유가 있을 때 공통 규칙을 추가한다.
2. 값은 토큰, 조작 상태는 공통 스타일, 화면 비례와 장식은 해당 화면에 둔다. 장비 장면까지 범용 카드로 바꾸지 않는다.
3. 색·모서리 변경은 선택/호버/누름/초점/비활성·어두운 준비·밝은 A안을 함께 살핀다. [대비 기록](contrast-check.md)을 실제 사용값으로 갱신한다.
4. 기존 기준 화면과 같은 크기·자료·상태에서 비교한다. 이름만 정리하고 배치나 인상이 달라졌으면 공통화가 끝난 것이 아니다.
5. 관련 기능·원자료 보존 검사는 재사용한다. 임시 수치·소스 문자열·CSS 배치 자체를 고정하는 검사를 늘리지 않는다.

과학적 의미와 상태 소유권은 [통합 앱 기획](../unified-sensor-lab-plan.md)과 [기술 설계](../unified-sensor-lab-architecture.md)를 따른다. 브라우저·모의 검사 결과는 실물 USB/BLE 검증과 구분한다.
