## 1. 채택한 방향과 범위

밝은 표면, 남색 중심 글자, 절제된 신호색을 사용한다. 측정은 숫자·그래프·기록 조작에 집중하고, 준비 B안은 남색 장면 위에 장비와 설명을 배치한다. 배선 3D 작업면은 단자 글자와 접지선을 읽을 수 있도록 밝게 유지한다. 장식 광원과 궤도는 자료 영역 밖에 둔다.

팝업은 게이뤼삭의 실험 방법 안내를 기준으로 흰 표면, 남색 제목, 스크롤 본문, 구분선으로 나뉜 하단 조작 영역을 공유한다. 안내에는 분류명과 상단 닫기를 사용할 수 있고, 종료 확인에는 취소·확정 버튼을 사용하며 취소에 초기 초점을 둔다. 입력 폼은 저장 실패 시 열린 상태와 입력을 유지한다. 작은 확인창·기본 안내 및 입력창·넓은 실험 안내의 크기를 구분하고, 화면이 낮아지면 본문만 스크롤한다.

새 팝업은 `<dialog class="ui-dialog">` 안에 `ui-dialog-header`·`ui-dialog-body`·`ui-dialog-footer`를 배치한다. 제목은 `ui-dialog-title`, 버튼 묶음은 `ui-dialog-actions`를 사용한다. 폼 전체가 제출 단위이면 세 영역을 `form.ui-dialog-form`으로 감싼다. 기본 너비는 560px이며 확인창은 `data-dialog-size="compact"`(460px), 그림·단계 안내는 `wide`(900px)를 사용한다. 상단 닫기는 `ui-dialog-close`와 구체적인 접근성 이름을 함께 사용한다. 열기·닫기·초점 복귀·저장 실패 처리는 각 화면이 소유하며 공통 CSS는 상태를 변경하지 않는다.

준비 탭과 메모는 **직선 강조선 + 배경 오버레이**를 사용한다. 이를 둥근 테두리 버튼으로 되돌리지 않는다. 외곽 패널·일반 버튼·입력은 역할에 맞는 곡률을 유지한다. 기록 조작은 아이콘과 보이는 글자를 함께 제공한다.

V5부터 홈·센서·활동의 기본 화면에 적용한다. 테마 선택 매개변수는 필요하지 않다. 기존 `?visual=luminous` 주소도 열리지만 새 링크에는 이를 붙이지 않는다. A안의 캡처와 구현은 개발 보관 경로에 유지하며 현재 화면에서 선택지로 제공하지 않는다. 분석·해석·홈·저장 목록·PNG·인쇄까지 같은 문법을 적용한다.

홈은 장비 그림 없이 제목의 크기·여백과 카드의 정보 위계로 탐색을 안내한다. 센서 카드는 기존 그리드 폭과 기본 높이를 유지하며 제목·사용 센서·설명·관련 활동을 구분한다. 겹친 그림자로 표면의 깊이를 주고, 호버에서는 확대 없이 소폭 떠오르는 이동·밝은 표면·테두리 강조를 사용한다. 움직임 줄이기에서는 이동을 없애고 색·그림자·초점은 유지한다. 활동 카드는 넓은 가로 배치와 교육과정 정보를 사용하며 **카드 가장자리에 굵은 강조선을 넣지 않는다**. 관련 활동이 많으면 공통 접이식 메뉴의 오버레이로 펼치며 센서 진입 링크와 독립적으로 조작한다.

실험 소개는 홈과 같은 제목·짧은 가로 강조선·밝은 표면·그림자를 사용한다. 제목과 설명 아래에 측정값·시작 전 안내·준비물·교육과정 정보를 정돈하고, 준비 진입 조작은 본문 하단에 모은다. 본문과 공유 카드를 하나의 최대 너비 안에서 가운데 정렬해 큰 화면의 좌우 쏠림을 막는다. 작은 화면에서는 본문을 한 열로 배치하고 기존 공유 버튼·대화상자를 사용한다. 소개 카드에는 호버 이동이나 카드 가장자리의 굵은 강조선을 적용하지 않는다.

### 카드 가장자리 강조선 — 사용 절대 금지

**카드의 가장자리에 굵은 선이나 색 띠를 붙여 강조하는 디자인은 앱 전체에서 절대 사용하지 않는다.** 카드의 위·아래·왼쪽·오른쪽 모두 해당하며, 한 변 전체를 덮는 띠와 가장자리 일부에만 붙인 짧은 강조선도 금지한다.

- 상단·하단(바닥)·좌측·우측 중 한 곳 또는 여러 곳에 붙이는 경우 모두 금지한다. 색상·방향·카드 이름과 관계없이 결과·활동·소개·요약 등 모든 카드에 적용한다.
- CSS border, 가상 요소, inset shadow, 배경 그라데이션, 별도 띠 요소 등 구현 수단을 바꾸어 같은 장식을 재현하지 않는다.
- 정보 위계는 제목·여백·표면으로, 자료의 대응 관계는 값·범례·그래프의 색으로 표현한다.
- 이 금지 대상은 카드 가장자리의 장식용 강조 띠다. 균일한 얇은 외곽선, 키보드 초점 표시, 탭의 선택 표시와 본문 구분선은 각 공통 규칙을 따른다.

### 앱 식별 아이콘

PC 사이드바와 모바일 헤더의 앱 이름 옆에는 남색 단색형을 사용하며, 크기는 micro:bit와 앱 이름 두 줄의 전체 높이에 맞춘다. 브라우저 탭은 16 CSS px 전용으로 픽셀 보정한 남색 아이콘을 사용한다. 기본 SVG와 호환용 16·32·96px PNG를 함께 제공하며 모두 눈금·발광 없는 같은 형태를 쓴다. 브라우저의 선택 방식이 다르므로 해상도에 따라 원본형으로 전환하지 않는다. 일반 UI용 축소 SVG와 구분하고, 실제 PNG의 표시 크기와 픽셀 확대로 선명도를 확인한다. 홈 화면 바로가기는 눈금·그라데이션이 있는 큰 기본형 SVG와 호환용 192·512px PNG를 매니페스트에 제공하고, 180px PNG의 apple-touch-icon도 유지한다. 실제 파일 선택은 브라우저와 설치 경로에 맡긴다. 메뉴·조작 버튼의 기능 아이콘은 기존 표현을 유지한다.

링크 미리보기에는 파스텔 블루 배경의 대표 이미지와 “센서 실험실 · 측정에서 발견까지” 제목을 사용한다. 이미지 왼쪽은 좌측 패널과 같은 Pretendard 글꼴과 micro:bit / 센서 실험실 두 줄 구조에 기본형 아이콘을 붙이고, 오른쪽은 실제 준비·측정·분석 UI를 사진 세 장처럼 겹쳐 보여 준다. 그래프 캡처는 모의 측정 데이터를 사용한다. 설명은 측정·저장·그래프 분석·결과 해석을 안내한다.

운영 자산은 `public/assets/branding/`, 홈 화면 메타데이터는 `public/manifest.json`에 둔다. 바로가기는 브라우저 모드로 열며, 오프라인 실행 기능을 의미하지 않는다. [디자인 시트](../../dev/design/icon-study/index.html)와 [내보내기 안내](../../public/assets/branding/README.md)를 기준으로 갱신한다.

HTML은 준비 CSS와 공통 진입 CSS를 정적으로 선언한다. 공통 진입의 정확한 순서는 `luminous.css` 한곳에 둔다. 공통 조작이 기본 크기·상태를 정하고 앱 틀·분석의 지역 규칙이 이를 구체화한다. A안 검토 진입만 준비 CSS를 archive 스타일로 바꾸며 나머지 공통 진입·동작은 동일하다. 기본 앱은 archive 자원을 요청하지 않는다. 기존 CSS는 비계층이므로 새 파일만 `@layer`에 넣지 않는다. `:is()` 안에 ID와 클래스를 섞으면 클래스 쪽도 ID 우선순위를 얻으므로 공통 역할 선택자는 분리한다.

실행 값의 단일 기준은 `src/ui/tokens.css`다. 문서의 후보 토큰 사본은 제거했다. 문서는 값의 의미·사용 조건·예외를 설명하고 CSS 치수를 복제하지 않는다.

준비 안내 본문에 놓인 사진·설치 그림·배선 뷰어는 휴대폰 주소창이 접히거나 펼쳐져도 크기를 유지한다. 화면 높이에 맞출 때는 안정적인 작은 뷰포트(`svh`)를 기준으로 삼고, 스크롤 중 변하는 `dvh`를 직접 사용하지 않는다. 대화상자·툴팁처럼 현재 보이는 화면 안에 들어가야 하는 팝업의 높이 제한은 `dvh`를 유지한다.

자료 표는 `data-table`과 `data-row`로 공통 스타일을 적용한다. 표 전용 입력·조작은 `table-cell-input`·`table-cell-action`을 사용한다. 편집 가능한 셀은 초점·호버 전에도 입력 경계선이 보이도록 하여 읽기 전용 측정값과 구별한다. 행의 최소 높이·셀 여백·조작 높이는 표 토큰으로 관리하며, 분석의 가상 표는 같은 최소 높이를 읽고 글자 확대·반영 대기 안내에 필요한 높이만 늘린다. 빈 공간용 행은 공통 자료 행 스타일에서 제외한다.

[table-viewport.js](../../src/ui/table-viewport.js)는 두 표의 표시 구간·여백 행·Home/End 스크롤 계산을 공유한다. 분석의 선택·정렬과 기록표의 편집 초안·버블·수신 중 위치 보존은 각 View에 둔다. 기록표는 편집 중인 행을 추가로 유지하며 기존 입력 DOM을 교체하지 않는다.

소스 `luminous.css`의 로컬·무조건부 import 목록은 개발 서버와 빌드가 같은 함수로 결합한다. CSS 파일의 책임은 유지하고, 전달할 때만 공통 CSS 한 개로 만든다. 준비 CSS는 A안 대체 경계를 유지하기 위해 별도 링크다. 파일 순서를 바꾸거나 조건부 import를 임의로 펼치지 않으며, 지원하지 않는 import와 순환 참조는 오류로 처리한다. 이미지·글꼴 주소는 결과 CSS 위치를 기준으로 다시 계산한다.

## 3. 역할별 색과 표면

| 역할 | 토큰 계열 | 사용 규칙 |
|---|---|---|
| 페이지·자료 표면 | `--sl-bg`, `--sl-surface`, `--sl-surface-soft` | 그래프·입력은 흰 자료 바탕. 장면 그라데이션은 화면 파일에 둠 |
| 글자·영역 구분 | `--sl-navy`, `--sl-text`, `--sl-muted`, `--sl-line` | 제목, 본문, 보조 설명, 장식 구분선을 구별 |
| 입력 경계 | `--sl-input-border` | 장식 구분선과 별도 관리. 흰 면·밝은 도구 면에서 3:1 이상, [대비 기록](contrast-check.md) 참조 |
| 일반 주요 행동 | `--sl-primary-*` | 밝은 화면에서는 남색 바탕과 흰 글자. 준비 B의 지역 주요 행동은 강조 행동 값으로 연결 |
| 강조 행동 | `--sl-action-*` | 주황 바탕과 남색 글자. 기록 시작·재개, 준비의 다음 행동 |
| 선택·초점 | `--sl-selection`, `--sl-focus`, `--sl-tab-*` | 선택선과 키보드 초점을 구분. 준비 B의 현재 단계는 주황선+흰 글자 |
| 기록·수신 | `--sl-recording-*`, `--sl-success`, `--sl-idle*` | 점·글자와 함께 표시. 연결되지 않음은 중립 상태 |
| 준비의 완료·확인 필요 | `--sl-stage-success`, `--sl-stage-attention` | 어두운 면에서 읽을 수 있는 상태색. 완료는 체크와 근거, 생략은 대시와 생략 문구로 구분 |
| 기록 마침 | `--sl-finish-*` | 옅은 주황 바탕과 진한 글자. 삭제/저장 실패로 오인시키지 않음 |
| 사건·메모 | `--sl-event-*` | 파란 강조선, 짧은 내용·시각, 호버 오버레이 |
| 실제 자료 | `--sl-channel-1`…`5`, `--sl-chart-*` | 행동·선택 토큰과 분리. 다섯 채널도 서로 다른 색으로 표시하며 값이 같아도 다른 의미로 관리 |
| 분석 표시 | `--sl-analysis-*`, `--sl-selected-bg`, `--sl-inspected-bg` | 포함/제외/추세선/점 살펴보기와 표 체크를 구분. 원자료에 기록하지 않음 |

온도 선의 주황과 기록 시작 버튼의 주황은 같은 역할이 아니다. 자료선을 바꿀 때 행동 버튼까지 함께 바뀌지 않아야 한다. 오류·비활성·선택을 채널색만으로 표현하지 않는다.

준비의 어두운 표현은 `.guide:not([data-stage-style=light])` 안에서만 적용한다. `--sl-stage-*`, 비활성 값과 초점 값을 이 범위에서 재정의한다. 흰 자료 표면, 버튼의 주황/남색 조합, 밝은 A안은 이 범위 밖에 있다.

2026-10-31 자료 팔레트는 [Excel·Office 테마](https://support.microsoft.com/en-us/office/foundations-experiences/new-office-theme)를 참고해 주황·진한 파랑·보라·초록·회색으로 조정했다. 가속도 크기는 진한 파랑(`#156082`), 자기장 크기는 주황(`#e97132`)을 고정 배정하며 단독/복합 센서와 선택 채널 수에 따라 바뀌지 않는다. 두 센서의 X/Y/Z는 보라/초록/회색으로 표시한다. 글자용 주황은 더 짙은 색(`#a8440f`)을 사용한다. 현재값·차트·축·범례·활동 모형·활동지 출력은 같은 표시 색을 사용하고 저장된 원자료의 채널 정의는 바꾸지 않는다.

이전 `--ink`, `--muted`, `--teal`, `--line`, `--pale` 별칭은 소비 경로까지 이행해 제거했다. 현재 규칙은 역할별 `--sl-*`를 사용하며 행동·상태·자료의 색상 역할을 구분한다.

## 4. 형태와 조작 상태

| 대상 | 형태·역할 |
|---|---|
| 준비의 큰 단계 탭 | 직각, 상단 직선, 투명 기본면, 현재 단계선과 호버 오버레이 |
| 분석 작업·표/그래프 보기 탭 | 직각, 하단 직선, 현재 위치와 호버 오버레이. 둥근 선택 캡슐을 사용하지 않음 |
| 메모 목록·시간축 표찰·메모 기록 버튼 | 직각. 목록은 왼쪽 선, 표찰은 아래 선. 전체 둘레를 감싸지 않음 |
| 일반 조작·입력 | `--sl-radius-control`, 읽을 수 있는 라벨 |
| 이미 준비된 장치로 이동 | `--sl-radius-compact`, 보조 조작의 작은 밀도 |
| 패널·계기 묶음·메뉴·대화상자 | 역할별 `--sl-radius-*`와 깊이. 패널 안에 같은 카드를 반복 중첩하지 않음 |

버튼의 기본·호버·누름·비활성은 공통 스타일 한곳에서 처리한다. 역할 선택자는 `--sl-button-bg/text/line/hover/pressed` 같은 **부품 내부 값**만 연결한다. 새 버튼마다 상태 선택자 세트를 복제하지 않는다. 화면 파일은 크기·위치를 맡는다.

일반 `button`과 버튼 모양을 사용하는 `summary.ui-button`·`a.ui-button`은 같은 공통 선택자로 기본 테두리·모서리·서체·높이·터치·진행·상태 표현을 함께 적용한다. 색상 선택자에만 요소를 추가하지 않는다. 파일 저장·그래프 메뉴와 한 점 기록표 머리글은 이 진입점을 사용한다. 일반 링크와 본문 접이식 안내는 자동으로 버튼 모양이 되지 않는다. `.ui-button`은 표시 계약이며 링크 이동·네이티브 펼침 동작·실제 비활성 판단은 기존 요소와 담당 View가 소유한다.

공통 기본 모서리는 `--sl-radius-control`이다. 카드형 머리글이나 작은 메뉴처럼 의도적인 차이는 화면에서 `--sl-button-radius`, `--sl-button-border-width`, `--sl-button-min-height`, `--sl-button-font-size`, `--sl-button-weight`를 지정한다. 공통 스타일이 이 값을 최종 속성으로 적용한다. 한 점 기록표의 상하 배치는 패널 모서리, 좌우 배치의 접힌 버튼은 일반 조작 모서리를 사용한다. 열렸을 때의 아래쪽 모서리와 직선 탭 같은 기능별 형태는 명시적으로 유지한다.

| 상태 | 규칙 |
|---|---|
| 기본 | 남색 주요 행동, 주황 강조 행동, 중립 보조 행동의 역할 구분 |
| 호버·누름 | 색면·경계 변화. 크기·위치가 이동하지 않음 |
| 패널 펼치기 | `data-ui-action="disclosure"`는 기본 모양·초점을 공유하되 호버·누름 색면을 덧씌우지 않는다. 한 점 기록표 머리글은 실험 메모와 같은 절제된 접이식 표현을 쓴다. |
| 키보드 초점 | 공통 외곽선. 밝은 화면은 코발트, 어두운 준비는 밝은 파랑 |
| 비활성 | 실제 `disabled` 속성과 중립 표현. 배경색만으로 비활성 처리하지 않음 |
| 진행 | 기존 상태 소유자가 활성/비활성을 결정. `aria-busy`가 있으면 진행 커서. 별도 UI 상태를 만들지 않음 |

초점 복귀는 CSS의 역할이 아니다. 기록 버튼 교체와 대화상자 닫기의 기존 동작 계약을 유지한다. 원형·캡슐형 버튼을 공통 기본값으로 도입하지 않는다.

설치 방식 전환 링크의 이동·누름 축소·광택 효과는 유지하기로 한 화면 전용 예외다. 다른 버튼의 기본 규칙으로 확장하지 않는다. 준비 화면의 비활성 표현은 지역 색상 값만 사용하며 공통 버튼 상태 규칙을 따른다.

V3 준비의 보조 버튼·선택 상태도 공통 역할 바인딩을 사용한다. 설치의 `aria-busy`와 수신 표시 상태는 전달받은 사실에서 파생하며, UI가 별도의 수신 타이머나 완료 상태를 소유하지 않는다. 3D·용기 배치도·보정 그림의 밝은 면은 판독을 위한 예외다.

## 5. 글자·간격·움직임

시간 그래프는 같은 물리량·같은 단위의 방향 성분과 크기를 하나의 축·스케일로 표시한다.
공유 축 제목은 특정 선의 색을 대표하지 않는 중립색이며 각 자료선의 색은 유지한다.
그룹 기준·메타데이터·기존 자료 처리는 [모듈 등록 규칙](../../src/catalog/README.md#시간-그래프의-공통-축)을 따른다.

관계 그래프의 넓은 화면에서는 축 이름과 선택기를 한 줄에 두고 추세선 조작은 해당 축 아래에 둔다. 사용 자료 수는 통계 제목 옆에, 수치는 세 칸에, 저장·해석 행동은 하단 한 줄에 모은다. 상하단 조작과 설명의 실제 높이를 제외한 공간을 그래프·가상 표에 배분한다. 작은 화면·글자 확대·상세 설명에서는 읽기 위한 최소 높이를 지키고 필요한 페이지 스크롤을 허용한다. 외곽 패널과 직선 탭 문법을 유지하며 숨김으로 내용을 잘라 맞추지 않는다.

원 자료 보기의 시간 그래프는 하단 구간 선택·자료 보기 조작의 공간을 남긴다. 결과 해석의 저장 상태·파일 저장·인쇄·저장 오류는 근거 그래프 아래 같은 열에 둔다. 글쓰기 영역 아래에 별도 행동 행을 추가하지 않으며, 좁은 화면에서는 그래프와 저장 도구 다음에 글쓰기가 이어진다.

채널의 선·점 색(`--sl-channel-*`)과 읽기용 색(`--sl-channel-text-*`)은 같은 계열의 별도 역할이다. 작은 범례·축 제목과 크기가 변하는 계기 숫자는 읽기용 색을 쓴다. 선택 글자도 `--sl-selection-text`로 구분한다. 가상 표는 글꼴 크기에 맞춰 행 높이와 빈 공간을 함께 갱신해 확대 중에도 마지막 자료에 접근할 수 있게 한다.

- Pretendard Variable 1.3.9를 로컬에서 사용하며 실패 시 한국어 시스템 서체로 표시한다. 출처·해시는 [외부 자원 고지](../../THIRD_PARTY_NOTICES.md)와 vendor manifest에 유지한다. 아이콘은 기존 Lucide 자원을 쓴다.
- `--sl-type-*`는 rem 기반 조작·라벨·보조 글자의 반복 크기다. 큰 측정값의 컨테이너 기반 크기와 장면 제목의 비례는 화면 파일에서 관리한다. 글자 확대 시 계기는 재배치하고 숫자의 높이와 단위 기준선을 안정적으로 유지한다. 긴 값은 자르지 않고 내부 스크롤로 제공한다.
- `--sl-space-*`는 반복 간격이다. 장치 폭·차트 높이·열 비율·미세 정렬은 해당 배치에서 관리한다. 모든 숫자를 토큰으로 옮기지 않는다.
- 일반 조작은 `--sl-target`, 작은 보조 조작은 `--sl-target-compact`를 사용한다. 기존 모바일 확대 규칙을 보존한다. 작은 화면은 배치와 여백을 먼저 조정한다.
- 버튼 피드백과 준비 전환은 `--sl-motion-*`를 따른다. 동작 줄이기 설정에서는 장식 움직임을 제거한다. 실시간 측정값은 보간하지 않고 차트의 기존 `animation:false`를 유지한다.

### 공통 패널 전환

내용 교체와 높이 변화는 [`createPanelTransition`](../../src/ui/panel-transition.js)을 재사용한다. 기본은 `--sl-motion-panel`(220ms)과 `--sl-motion-panel-easing`에 따른 짧은 페이드·이동이다. **일반 접이식 안내는 `<details><summary>…</summary>…</details>`만 사용하면 펼침·접힘에 높이 전환이 자동 적용된다.** `bindAppShell`이 앱 전체에 연결하므로 나중에 추가한 안내에도 별도 이벤트 등록이 필요 없다. 바깥 박스도 함께 보간하려면 해당 조상 요소에 `data-ui-height`를 선언한다. 파일 저장·그래프 선택 같은 `.disclosure-menu`는 이 규칙에서 제외하며, 효과가 필요 없는 영역은 `data-ui-motion="none"`으로 제외한다.

공통 패널 곡선은 CSS `ease`를 사용해 완만하게 출발하고 끝에서 감속한다. 초반 몇 프레임에 대부분의 이동이 몰리는 강한 감속 곡선은 피한다.

측정·기록 화면의 기록표·방향별 성분·눈금 설정·조작 및 수신 기록·준비 내용도 이 공통 접이식 처리를 사용한다. 충분히 넓은 연속 측정 화면의 한 점 기록표는 CSS에서 `--sl-disclosure-axis:inline`을 선언하고, 분석 화면과 같은 그리드 열 전환에 공통 모션 토큰을 사용한다. 이때 공통 처리기는 높이 효과를 겹치지 않는다. 좁은 화면에서는 선언을 해제해 기본 높이 전환을 유지한다. 움직임 줄이기에서는 두 방향 모두 공통 토큰과 처리기에 따라 즉시 전환한다.

준비 화면은 단계 이동과 접이식 안내에 같은 전환 관리자를 사용해 효과가 겹치지 않게 한다. 공통 처리기는 가까운 화면에서 이미 처리한 클릭을 다시 처리하지 않는다. 준비 단계 이동은 설명 패널과 시각 자료 패널의 높이를 함께 전환하며, 설명 내용의 기존 좌우 이동을 유지한다. USB/무선 설치 방식 변경과 무선 설치의 상태·안내 변경도 같은 관리자를 사용한다. 설치 안내가 바뀌면 설치 상자와 바깥 패널의 높이만 전환하며, 진행률 숫자만 바뀔 때는 효과를 다시 시작하지 않는다. 실험 방법 페이지는 페이드·좌우 이동만 사용하며 공통 모션 시간·가속 곡선을 따른다. 분석 작업·구간 입력·알림의 표시 전환도 같은 관리자를 재사용한다. 이처럼 화면이 내용을 교체하는 전환은 아래 호출 계약을 사용하고, 접이식 안내의 클릭 처리를 화면마다 다시 만들지 않는다.

```html
<section data-ui-height>
  <details>
    <summary>추가 안내</summary>
    <p>펼쳐서 읽는 내용</p>
  </details>
</section>
```

```js
const transition = createPanelTransition(panel);
const previousHeights = transition.capture([panel]);
// 같은 동기 렌더 안에서 내용을 교체한다.
renderContent();
transition.play([panel], { previousHeights });
```

높이는 전환 중에만 보간하고 완료 뒤 CSS의 자동 배치로 돌아간다. 빠르게 다시 전환하면 현재 표시 높이에서 이어가며, 창 크기·움직임 줄이기 설정이 바뀌면 진행 중 효과를 정리한다. 첫 펼침으로 필요한 글꼴이 추가 로드되어도 전환을 취소하거나 처음부터 재시작하지 않는다. 글꼴 적용으로 높이가 달라지면 현재 보이는 높이에서 새 목표 높이까지 남은 시간 안에 이어간다. 접이식 안내는 마우스와 키보드의 summary 활성화에 반응하며 내부 링크·입력 조작은 유지한다. 데이터 갱신이나 코드의 `open` 변경을 감시해 자동 애니메이션을 반복하지 않는다. 그 밖의 DOM 교체·초점 이동은 View가 맡는다. View 종료 시 `dispose()`로 이벤트와 해당 모듈이 만든 애니메이션을 정리한다.

움직임 줄이기에서도 버튼 배경·테두리·눌림 색상, 초점·선택 강조, 진행률·결과 표시는 유지한다. 자기장 보정 시범은 행동 설명이므로 설정과 관계없이 자동 재생하며, 공통 패널 전환의 취소 대상으로 삼지 않는다.

## 6. DOM과 Canvas의 연결

`readVisualTheme(root, channels)`는 Luminous가 적용된 문서에서만 표시값을 반환한다. 특정 측정 화면 클래스의 존재에 의존하지 않는다. 뷰를 구성할 때 한 번 읽어 전달하며 매 수신마다 CSS를 조회하지 않는다.

온도는 첫 자료색, 압력은 두 번째, 상대 밝기는 세 번째를 사용한다. 다른 채널은 전체 채널 목록의 순서로 안정적으로 배정한다. 표시 항목을 숨겨도 남은 채널의 색을 다시 배정하지 않는다. 목록 밖의 알 수 없는 채널에는 ID 기반 대체색을 사용한다. 계기·범례·선은 동일한 해석 결과를 쓴다.

저장된 정의의 오래된 `color`를 새 테마로 고쳐 저장하지 않는다. 단위·정밀도·수집 채널·시각·회귀·원자료·파일 내용은 표시 토큰에 넣지 않는다. 메모 표찰도 원래 사건 시각을 가리키며, 가까운 표찰을 묶어도 상세에서 각각의 시각·내용을 보여 준다.

분석 화면을 열 때 표시값을 한 번 읽어 원자료 차트·관계 그래프·보관 근거·PNG·인쇄에 전달한다. 관계 그래프의 점은 세로축 채널색을 사용하며 계산 열은 공통 분석색을 쓴다. 포함은 채운 점, 제외는 빈 점, 살펴보는 점은 크기와 진한 색으로 구분한다. 추세선은 따뜻한 진한 색의 실선, 연장 부분은 점선이다. 표의 체크와 점 살펴보기는 서로 다른 배경이며 제외/범위 밖 상태의 문구를 유지한다.

PNG는 화면과 같은 데이터 모델·색·축·글꼴로 별도 Canvas에 그린다. 해석에서 내보내거나 인쇄할 때는 보관한 근거를 사용한다. 출력 바탕은 불투명한 흰색이며 앱의 사이드바·장식 배경을 넣지 않는다. 초기 Canvas를 만들기 전에 로컬 글꼴 로딩 또는 대체 글꼴 확정을 기다린다. JSON·CSV·저장 정의에는 표시 토큰을 넣지 않는다.

## 7. 확장·검토 기준

1. 기존 역할로 표현 가능한지 먼저 확인한다. 실제 두 곳 이상에서 쓰이거나 독립적으로 조정할 이유가 있을 때 공통 규칙을 추가한다.
2. 값은 토큰, 조작 상태는 공통 스타일, 화면 비례와 장식은 해당 화면에 둔다. 장비 장면까지 범용 카드로 바꾸지 않는다.
3. 색·모서리 변경은 선택/호버/누름/초점/비활성·어두운 준비를 함께 살핀다. 보관된 A안은 현재 디자인의 적용 대상이 아니다. [대비 기록](contrast-check.md)을 실제 사용값으로 갱신한다.
4. 기존 기준 화면과 같은 크기·자료·상태에서 비교한다. 이름만 정리하고 배치나 인상이 달라졌으면 공통화가 끝난 것이 아니다.
5. 관련 기능·원자료 보존 검사는 재사용한다. 임시 수치·소스 문자열·CSS 배치 자체를 고정하는 검사를 늘리지 않는다.

과학적 의미와 상태 소유권은 [통합 앱 기획](../unified-sensor-lab-plan.md)과 [기술 설계](../unified-sensor-lab-architecture.md)를 따른다. 브라우저·모의 검사 결과는 실물 USB/BLE 검증과 구분한다.

## 8. 기본 UI 구조

Luminous는 앱의 기본 표현이다. 현재 채택한 화면의 비례·색상 역할·형태를 기준으로 삼으며, 구조 정리와 새 디자인 제안은 별도로 다룬다. 아래 소유권을 유지하고, 당시 전환 과정은 [구조 전환 이력](history/design-implementation.md#기본-ui-구조-전환)를 참고한다.

### 측정 안내 버튼의 공통 배치

측정·기록 화면의 안내 버튼은 상단 실험 제목 옆에 둔다. 활동의 기본 표기는 ‘실험 방법 보기’이며 모바일 기준 폭(760px 이하)에서는 ‘실험 방법’으로 줄인다. 센서별 ‘센서 위치’·‘측정 안내’ 같은 고유 이름은 유지한다. 제목과 버튼 사이에는 공통 8px 간격을 사용한다. 버튼은 최상단 파일 열기 버튼과 같은 공통 크기·글꼴·테두리·상태 표현을 사용하며, 데스크톱은 compact 높이, 모바일은 44px 터치 높이를 유지한다. 긴 제목·글자 확대 시 줄바꿈을 허용하며 제목이나 버튼을 잘라 한 줄로 강제하지 않는다.

안내가 있는 측정·기록 화면에서만 표시하고 다른 화면에서는 숨긴다. 기존 자동 안내·다시 열기·닫은 뒤 초점 복귀 동작은 유지한다. 활동·센서 정의는 내용과 이름을 소유하고 배치와 모바일 표기는 공통 헤더가 소유한다. 측정 탭 줄이나 카드 사이에 별도 안내 버튼 줄을 만들지 않는다.

### 8.1. 고정 구조와 동작의 경계

| 소유자 | 책임 |
|---|---|
| `lab.html` | 사이드바·헤더·파일 저장 메뉴·측정 영역·장치 설정창의 최종 고정 구조, 초기 테마와 CSS 선언 |
| `app-shell.js` | 기존 메뉴·대화상자의 이벤트, 키보드 조작, 초점 복귀 연결. 구조 재배치·CSS 동적 삽입은 맡지 않음 |
| `startup.js` / `app-presentation.js` | 문서 시작의 준비 상태와 스타일·서체 결정. `Controller.ready` 후 조작 공개 |
| Controller와 각 View | 경로·문구·버튼 허용 상태·실험별 내용·동적 목록·차트 갱신. 기록·저장 상태의 기존 소유권 유지 |
| 표시 어댑터 | 토큰에서 계기·범례·Canvas·PNG·인쇄에 같은 색·서체 전달 |

고정된 틀은 HTML에서 한 번 선언한다. 센서 채널·활동 조작·저장 목록·필요할 때 만드는 편집 대화상자는 기존 모듈이 생성한다. 컨트롤 ID, 라벨 연결, `data-view` 등 호출 계약을 유지한다. 프레임워크 교체나 별도의 UI 상태 저장소는 추가하지 않는다.

### 8.2. 스타일의 단일 소유권

| 규칙 | 소유권 |
|---|---|
| 리셋·문서 기본 동작 | 기본 CSS. 이전 팔레트나 화면별 버튼 디자인을 포함하지 않음 |
| 의미별 값 | `tokens.css`. 행동·선택·상태·자료 색과 형태·간격·서체의 단일 기준 |
| 공통 부품과 상태 | 공통 조작 CSS. 기본·호버·누름·초점·비활성·진행 표현 |
| 화면 배치와 장식 | 준비·측정·분석·해석·홈·보관의 담당 CSS. 부품의 크기·위치와 화면별 구도 |
| 밝은 자료 면과 어두운 준비 B | 필요한 표면 범위에서 역할 값을 재정의. 조작 상태 규칙을 복제하지 않음 |
| 보관된 A안 | 개발 archive 경로의 표현 규칙. 기본 앱의 선택지·의존 자원에 포함하지 않음 |

2차에서 기존 규칙과 Luminous 덮어쓰기를 위 담당 파일로 합치고, 별도 덮어쓰기 파일 4개를 제거했다. `base.css`의 사용하지 않는 이전 화면 규칙과 이전 색상 별칭도 정리했다. 배치·표 가상화·인쇄·접근성 규칙은 유지한다. 새 수정은 담당 파일에 반영하며 별도 테마 덮어쓰기 파일을 추가하지 않는다.

HTML의 `data-visual-theme="luminous"`는 기존 선택자와 Canvas 연결의 식별자로 유지하며 실행 중 UI를 바꾸는 스위치로 사용하지 않는다. `--ink`, `--muted`, `--teal` 등 이전 별칭은 소비 경로까지 이행해 제거했다. 어두운 준비 값은 `guide.css`의 지역 변수이고 센서 전용 표현도 이를 읽는다. 일부 파일만 CSS 계층(`@layer`)으로 옮기는 변경은 하지 않는다.

### 8.3. 확장 시 재사용 단위

기존 버튼 역할, 직선 탭, 메모, 입력, 펼침 메뉴, 대화상자를 우선 재사용한다. 메뉴의 Escape·바깥 클릭·초점 복귀는 `bindDisclosureMenu`, 기록 편집 폼의 초안·진행·저장 실패 처리는 `createRecordDialogs`의 기존 책임을 유지한다. 생김새가 비슷하다는 이유로 모든 부품을 하나의 범용 카드나 폼 엔진으로 합치지 않는다.

새 조작은 역할·상태·밝고 어두운 표면을 먼저 결정한다. 화면별 CSS는 역할 값을 연결하며 호버·비활성 규칙을 새로 복사하지 않는다. 준비 탭·분석 탭·메모의 직각 및 직선 강조, 활동 카드·자료 상세 패널의 왼쪽 장식선 제거 결정도 유지한다. 일반 입력·외곽 패널의 곡률까지 일괄 변경하지 않는다.

- 버튼에는 `data-ui-action="primary|accent|quiet|finish"`로 역할을 붙인다. 기존 `.primary`도 같은 주요 행동 역할이다. 준비 B는 지역 `--sl-primary-*` 값으로 강조색을 사용하며 보관 A는 밝은 화면의 값을 유지한다. 기존 센서·활동 모듈이 스타일 파일을 새로 삽입할 필요가 없다.
- 준비 단계·분석 작업/보기·실험 방법 단계 버튼은 `.ui-tab`을 재사용한다. 선택은 기존 `aria-current`/`aria-pressed`가 결정하고, 준비의 상단선과 분석의 하단 표시선은 각 화면이 맡는다. 탭 색·호버·선택 글자·직각 형태는 공통 규칙이다. 역할만 붙이는 것으로 키보드 이동이나 탭 의미가 자동 생성되지는 않는다.
- 사건·메모는 `--sl-button-*` 역할 값과 공통 호버 상태를 사용한다. 메뉴의 이벤트 수명·대화상자의 초안·저장 책임은 기존 모듈을 유지한다.

반응형은 페이지 최대 폭, 상단·하단 조작의 필요 공간, 그래프·표의 남는 높이, 최소 읽기 크기와 줄바꿈 순서로 결정한다. 작은 화면·200% 글자·긴 내용에서 필요한 스크롤은 허용한다. 센서·활동 모듈은 내용과 절차를 제공하고 공통 부품의 모양을 직접 지정하지 않는다.

측정·분석의 넓은 화면은 공통 `--workspace-height`를 받는다. 공통 계산은 작업 영역 앞뒤 공간만 측정하고 CSS Flex/Grid가 그래프·표·해석 내용을 배분한다. 그래프와 표의 자식 높이를 JS에서 각각 빼거나 고정된 페이지 여백을 중복 차감하지 않는다. 작은 화면에서는 이 예산을 해제한다. Canvas와 가상 표는 기존 ResizeObserver로 실제 영역을 따르며 원자료·축·자료색·차트 인스턴스를 재생성하지 않는다. 최소 읽기 크기를 지키기 위해 내용이 많거나 확대된 화면에는 세로 스크롤을 허용한다.

## 9. 수식·기호·단위

물리량 기호와 단위의 구분은 [NIST SI 표기 지침](https://physics.nist.gov/cuu/Units/checklist.html), 상수·함수·첨자 서체는 [NIST SP 811 §10](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-10-more-printing-and-using-symbols-and-numbers)을 따른다. 학생의 단계별 계산 도움과 그림에도 같은 규칙을 사용한다.

| 대상 | 표현 규칙 |
|---|---|
| 물리량 | `a`, `r`, `T`, `g`, `ω`는 이탤릭체. `g=9.8`처럼 값을 고정해도 물리량 기호의 서체는 유지한다. |
| 수·단위·상수·함수 | 숫자와 `m`, `s`, `cm`, `rad`, 수학 상수 π, `sin`, `cos`, `ln`은 세운 글꼴. TeX에서는 단위에 `\mathrm{}`, 함수에 전용 명령을 쓴다. |
| 첨자·평균·벡터 | 설명을 위한 첨자는 세운 글꼴, 변수 첨자는 이탤릭체. 평균은 윗줄, 벡터는 화살표를 사용한다. 크기와 벡터를 임의로 바꾸지 않는다. |
| 연산 | 분수·제곱근·위아래첨자는 수식 조판으로 표현한다. 숫자 곱셈은 `×`. 복합 단위를 나눌 때 괄호를 써 범위를 명확히 한다. |
| 값과 단위 | `9.8 m/s²`처럼 값과 단위를 띄우며 같은 줄에 둔다. 입력칸·자동 결과의 단위는 오른쪽에 표시한다. 채널의 기존 단위와 표시 정밀도를 유지한다. |
| 관계와 근사 | 모형의 관계식은 `=`, 수치의 근사 관계는 필요한 경우 `≈`. 모형의 가정·반올림·유효숫자는 해당 활동이 결정한다. 표시 모듈이 저장값을 반올림하거나 등호를 바꾸지 않는다. |

짧은 기호·단위는 `scientific-notation.js`의 HTML/SVG 도우미와 공통 CSS를 쓴다. 관계식·대입식·계산 열 미리보기·추세선 식은 `math-view.js`의 `setMath`로 표시한다. 활동 그림은 `mathSvg`가 반환한 SVG와 실제 폭·높이로 배치하며 출력에도 재사용한다. 사용자 열 이름은 `texText`, 유한 숫자는 `texNumber`로 조합한다. 사용자 입력을 TeX 명령으로 실행하지 않는다.

MathJax와 TeX 글리프는 고정한 로컬 번들로 제공한다. 단순 기호나 첫 화면을 위해 수식 엔진을 미리 불러오지 않는다. 긴 식은 작은 글씨로 축소하지 않고 수식 영역에서 가로로 살펴볼 수 있게 한다. 수식마다 읽을 수 있는 설명을 제공하며 로딩·렌더링 실패 시에도 그 설명을 남긴다. 외부 폰트 참조 없는 SVG를 써 구심가속도 그림의 PNG·인쇄를 재현한다. 기존 Canvas 그래프의 축·툴팁·내보내기 요약은 일반 텍스트를 유지하며 숫자·단위의 의미를 공유한다. 전체 앱의 문장을 수식으로 바꾸거나 계산 엔진을 교체하지 않는다.

### 측정에서 분석으로 이동

- 실험 선택·실시간 미리보기만으로는 상단 자료 분석 탭을 활성화하지 않는다. 첫 연속 측정값 또는 한 점 기록이 실제로 기록되면 활성화한다.
- 새 실험에서 최초 활성화할 때 탭 전체가 현재 화면 안에 보이는 경우에만 약 1초간 은은한 글로우를 한 번 표시한다. 화면 밖·다른 창에 가려짐·동작 줄이기 설정에서는 생략하며, 나중에 스크롤해도 재생하지 않는다. 화면과 초점을 자동 이동하지 않는다.
- 저장된 실험·파일은 자료가 있으면 바로 활성화하며 효과를 표시하지 않는다. 일시정지·재개·추가 측정에서 반복하지 않는다.
- 기록 중에도 탭으로 분석에 진입할 수 있으며 기록은 계속된다. 기록 종료 후에는 기록 마치기 자리에 자료 분석하기 버튼을 표시한다. 자료가 없으면 비활성화한다. 추가 측정은 보조 동작으로 유지한다.
- 구심가속도 등 활동별로 같은 목적의 분석 이동 버튼을 별도 배치하지 않는다. 한 점 기록 분석처럼 특정 자료를 선택하는 동작은 유지한다.

### 특화 분석 화면의 공통 틀

활동 전용 분석도 공통 analysis-topline 안에 페이지 제목과 analysis-tabs를 배치한다. 탭 수만 지정하고 글꼴·선택선·동작 상태·모바일 배치는 공통 규칙을 사용한다. 활동지 선택은 자료 요약·이력 조작 줄의 공통 드롭다운에 둔다. 목록 하단에 새 구간 분석을, 각 활동지 옆에 확인창을 거치는 삭제 아이콘을 제공하고 기능 설명은 옆 도움말에 둔다. 자료 요약과 이력 조작은 analysis-scope-bar·scope-summary·history-actions, 본문 표면은 analysis-workspace를 재사용한다. 탐구 그림·계산·발문은 활동 모듈이 소유하며 별도 범용화하지 않는다.
