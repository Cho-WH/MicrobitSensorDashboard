# 한 점 기록 P2 UI 정리 검토

> 확인일: 2026-10-28 · 기준: `codex/m8-2-point-recording`의 P2 작업 상태
> 상태: 개선안 정리. 이 검토에서 실행 UI 코드는 변경하지 않았다.

후속 반영: P3에서 고정 화면 틀을 `lab.html`로 옮기고 같은 조건·표 View를 수동 화면과 연속 화면의 접이식 영역에 연결했다. 연속 캡처와 시점 표식도 구현했다. P4에서 공통 분석 화면의 자료 선택, 조건 편집 대화상자, 변경 반영, 원자료 이동·복귀와 자료별 CSV를 연결했다. 아래 표는 P2 검토 당시의 관찰이며, 나머지 시각적 위계·입력·모바일 개선안 전체의 적용 완료를 뜻하지 않는다.

현재 캡처·편집 동작을 유지하면서 **현재값 확인 → 조건 입력 → 한 점 기록**의 흐름과 기록 표의 가독성을 먼저 다듬는다. 방향 성분의 크기와 반복 상태 표시를 줄이고, 고정 화면 틀·공통 조작·화면 배치의 소유권을 기존 표준에 맞춘다.

실사용 후 보완(2026-10-28): 분석 조건의 최신 입력·반영 대기 표시, 주요 열 중심의 한 점 분석 표, 접을 수 있는 상세 성분, 점 번호 안내를 적용했다. 같은 구성에서 방식만 바꿀 때 연결 유지와 일시정지 안내도 보완했다. 현재 동작과 검증 범위는 상세 설계 §3.1·§8·§15에 반영했으며 아래 P2 당시 검토 항목 전체를 완료한 것은 아니다.

[사용자 시안 6장](../reference/point-recording-2026-10-28/README.md)을 [상세 설계](../../point-recording-design.md) 및 [시각 디자인 문법](../visual-language.md)과 비교했다. P3 연속 화면 연계와 P4 자료별 분석은 아직 구현되지 않았으므로 현재 P2의 외관 개선과 구분한다. 아래 항목은 구현 제안이며 적용 완료 목록이 아니다.

## 1. 현재 구현에서 유지할 동작

- 기록 버튼을 누른 순간의 센서값·조건 초안·시각을 고정하고, 첫 기록이 실제로 저장될 때 실험을 만든다.
- 조건 미입력과 숫자 `0`을 구분한다. 센서 원자료·수신 시각은 편집하지 않는다.
- 이번 조건 입력과 과거 행의 편집 초안을 분리한다. 기록이 추가되어도 편집 중인 입력·한글 조합·초점을 보존한다.
- 중복 캡처, 오래된 수신값, 저장 중 재입력과 저장 실패를 처리하는 기존 경계를 유지한다.
- 표의 페이지·읽던 위치를 유지하고 새 기록으로 이동할 수 있게 한다. 취소 기록은 복구할 수 있다.
- 가속도의 `g` 표시는 화면 표시만 바꾸며 저장한 SI 값은 보존한다.

## 2. P2에서 우선 다듬을 화면

| 순서 | 현재 확인한 점 | 개선안 |
|---|---|---|
| 우선 | 비어 있는 `#point-recording` 안에 View가 고정 영역까지 생성함 | 고정 틀은 `lab.html`에 선언하고 View는 채널·행·값·편집 초안을 연결한다. 기존 ID·라벨·호출 경계는 보존한다. |
| 우선 | 측정 방식·기록 상태·개수 안내가 여러 곳에 반복됨 | 방식 선택/잠금은 상단, 수신 상태는 현재값 근처, 기록 개수는 표 제목에 모은다. 취소 기록이 없을 때까지 취소 개수를 상시 강조하지 않는다. |
| 우선 | 방향 성분을 펼치면 현재값 영역이 길어지고 별도 조건 영역의 기록 버튼이 멀어짐 | 현재값과 이번 조건·기록 버튼을 가까이 묶는다. 기록 마치기는 보조 행동으로 구분한다. 고정 조작부를 런타임에 부모 사이로 옮기지 않는다. |
| 우선 | 주 측정값과 X/Y/Z가 같은 큰 글자 규칙을 쓰고 숫자와 단위가 한 문자열임 | 주 측정값만 크게, 방향 성분은 작은 행으로 표시한다. 숫자와 단위의 시각적 크기를 구분하고 채널색은 기존 표시 테마를 재사용한다. |
| 우선 | 방향 계기에 0 표식은 있지만 native meter의 채움은 최솟값에서 시작함 | 부호가 있는 성분은 0에서 값 방향으로 채워 양·음 방향을 읽을 수 있게 한다. 읽기 전용 계기의 접근 가능한 값·단위·범위를 유지한다. |
| 우선 | 조건 입력칸이 센서값보다 크게 보이고 행 높이가 큼. 센서 열 제목에는 단위가 없고 각 셀에 반복됨 | 조건·센서값·행 조작의 밀도를 맞춘다. 센서 열 제목에 단위를 두고 수치는 정렬한다. 넓은 화면에서는 수신 시각을 기본 열로 검토하고 좁은 화면에서는 상세로 제공한다. |
| 우선 | 과거 조건 입력칸이 항상 큰 폼처럼 보이며 조작 역할이 일부 불명확함 | 기존 입력 DOM·초안을 유지하면서 편집 가능/편집 중/오류 상태를 구분한다. Enter 확정·Escape 취소를 보존하고 버튼 역할을 공통 규칙으로 명시한다. |
| 우선 | 조건 이름·단위 설정이 본문 펼침 영역으로 들어가 기록 조작과 공간을 공유함 | 자주 쓰는 이번 조건은 본문에 유지하고, 이름·단위 설정은 기존 공통 대화상자로 분리한다. 취소·초점 복귀·저장 실패 때의 입력 보존을 함께 처리한다. |
| 우선 | 잘못된 조건은 안내와 `aria-invalid`로 처리하지만 입력의 시각적 오류 구분이 약함. 연결 해제 시 현재값은 `—`로 지워짐 | 공통 입력 오류 스타일을 적용한다. 마지막 수신값·시각을 남기려면 별도 읽기 전용 표시로 구분하고 캡처 후보로 사용하지 않는다. 다시 연결 동작은 기존 연결 경로에 연결한다. |
| 다음 | 성공 안내는 있으나 새 행 강조·조건 미입력 요약·표 하단의 마지막 기록 취소는 없음 | 새 행을 짧게 표시하고 미입력 조건으로 이동하는 안내를 제공한다. 미입력은 활성 기록의 확정 `null`만 세며 `0`은 포함하지 않는다. 마지막 취소를 추가하면 기존 행 취소·복구와 같은 기록 ID를 사용한다. |
| 다음 | 작은 화면에서 펼친 성분과 행별 상세 조작이 길어지고 기록 버튼은 표 아래 일반 흐름에 있음 | 성분·표·상세의 기본 노출량을 줄여 기록 흐름을 짧게 한다. 편집 시 현재값은 압축 표시하고 입력 초점을 유지한다. 하단 고정 조작은 실제 키보드·화면 높이 검증 뒤 적용한다. |

표시 항목 메뉴는 실제로 선택 가능한 항목이 있을 때 기존 메뉴 패턴으로 제공한다. 표의 표시 열을 바꾸어도 캡처하는 센서 채널이나 저장 자료는 바뀌지 않는다. 아직 연결되지 않은 기능의 버튼이나 빈 메뉴를 시안 모양만 맞추기 위해 추가하지 않는다.

## 4. 시안 요소별 적용 경계

| 시안 요소 | 판단 |
|---|---|
| 거리·cm, 거리별 자기장 탐구 제목 | 대표 예시다. 모든 센서에 거리 조건을 강제하지 않는다. 현재 조건 정의와 활동 정보를 사용한다. |
| 주 계기 0–100 μT, 성분 ±100 μT | 예시 범위다. 센서가 정의한 범위나 사용자가 지정한 범위를 따른다. 실시간 자동 확대·축소나 시안 수치 하드코딩으로 바꾸지 않는다. |
| 이번 조건의 ± 버튼 | 조건별 증감 폭의 근거가 필요하다. 사용자가 증감 폭을 정할 수 있는 흐름 없이 임의의 `1`이나 `0.1`을 넣거나 기록 후 자동 증가시키지 않는다. |
| 조건 설정 팝업 | 공통 대화상자 규칙에 맞춰 P2 개선안으로 제안한다. 조건값의 선택 입력 계약은 유지한다. |
| 연결 해제 시 마지막 수신값 | 현재 구현에는 없는 표시다. 마지막 값·수신 시각·끊김 상태를 함께 보여 주고 새 수신 전 기록 금지를 유지하는 조건으로 검토한다. |
| 모바일 하단 기록 버튼·편집 완료 | 키보드가 입력칸과 버튼을 가리지 않는지, 확대·safe area·초점 이동을 확인한 뒤 배치를 결정한다. |
| 모바일 숫자 키패드 | 운영체제 입력기의 예시로 해석한다. 별도 숫자 키패드 구현을 요구하지 않는다. 음수·소수·한글 조합·붙여넣기를 고려한다. |
| 모바일 햄버거·상위 이동 구조 | 앱 전체 이동 구조의 변경이다. 이번 P2 정리에서 함께 재설계하지 않는다. |
| 측정 화면의 관계 미리보기 | 기존 분석/차트 경계를 활용할 후속 선택사항이다. P2 안에 별도 분석 상태나 계산 경로를 만들지 않는다. |
| 연속 기록 중 한 점 기록·그래프 표식 | P3 범위다. 현재 연속 기록 수명과 공통 캡처 계약을 연결할 때 적용한다. |
| 분석할 자료 선택·변경 반영·원래 시점으로 이동 | P4 범위다. 자료별 Workspace 상태와 원자료 참조를 연결한 뒤 적용한다. |
| 자료 분석·CSV 버튼 | P4의 실제 지원과 함께 제공한다. 현재 한 점 자료는 JSON 보관이 가능하며, 미구현 분석/점 CSV를 지원하는 것처럼 표시하지 않는다. |

## 5. 적용 순서와 확인 기준

1. **고정 구조와 공통 역할 정리:** HTML 틀과 동적 View를 나누고 버튼·입력·펼침·설정창을 기존 표준으로 맞춘다. 라벨 연결, 초점 이동과 실패 시 입력 보존을 확인한다.
2. **현재값·기록 표의 위계 조정:** 주 측정값과 성분을 구분하고 현재값–조건–기록의 거리를 줄인다. 단위·수신 시각·행 조작을 정돈해 넓은 화면과 작은 화면에서 읽을 수 있게 한다.
3. **편집·오류·모바일 상태 보완:** 새 행과 미입력 요약, 오류 입력, 단절/재연결 표시를 다듬는다. 새 데이터가 와도 편집 초안·읽던 위치를 유지한다.
4. **P3·P4로 연결:** 확정한 공통 표·설정·편집 패턴을 연속 화면과 자료별 분석에 재사용한다. 미구현 기능은 각 단계의 완료 기준으로 검증한다.

자동 검사는 [기존 P2 브라우저 검사](../../../tests/e2e/point-recording.spec.mjs)와 [캡처 계약 검사](../../../tests/unit/point-capture.test.mjs)를 우선 보완한다. 중요한 기준은 클릭 순간의 값 보존, 조건 미입력/0 구분, 편집 중 새 기록, 취소·복구, 저장 실패, 단절 후 새 수신 전 캡처 금지다. 문구·CSS 클래스·고정 치수를 검사 조건으로 추가하지 않는다.

계기 변경은 음수·0·양수와 범위 끝에서 방향·단위가 정확한지 확인한다. 가속도 `g` 표시 변경이 저장값에 영향을 주지 않아야 한다. 키보드·확대·좁은 화면은 대표 사례에 모으고, 실제 모바일 입력기와 실물 센서 검증은 모의 브라우저 검사와 구분한다.

## 6. 이번 검토의 확인 범위

- 시안 6장의 원본 일치, SHA-256, PNG 크기를 확인하고 첨부 순서를 기록했다.
- 코드와 실제 Controller·RunStore·View를 사용하는 브라우저 검증 화면을 확인했다. 모의 자기장 수신값, 기록 6개, 조건 미입력 1개, 펼친 X/Y/Z, 명시한 주 계기 범위로 넓은 화면과 390px 화면을 비교했다. 검증 페이지 자체의 상단 제목은 제품 UI 평가에서 제외했다.
- 모의 연결 해제 후 현재값이 `—`로 바뀌고 캡처가 비활성화되며 기존 6개 행이 남는 것을 확인했다. 실제 센서·모바일 운영체제 키보드는 이번에 검증하지 않았다.
- 이번 변경은 참고 이미지·검토 문서·문서 연결뿐이다. 실행 코드 변경이나 전체 테스트, 커밋·배포는 수행하지 않았다.
