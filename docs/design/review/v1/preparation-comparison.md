# 준비 화면 A/B 비교

2026-10-25 · V1 사용자 검토 · **B안 채택, A안 보관** · 현재 작업 트리, 미커밋.

로컬 서버의 `/dev/design/preparation-comparison.html`에서 같은 단계의 캡처를 나란히 비교한다. 각 안의 직접 조작 링크는 실제 앱의 준비 화면을 연다. 코드·실행 방법은 [개발 검토 안내](../../../../dev/design/README.md)에 있다.

| | A · 밝은 공통형 | B · 몰입형 통일 |
|---|---|---|
| 구성 | 기존 밝은 준비 화면에 프로그램을 맞춤 | 프로그램의 남색 무대를 전체 준비 단계로 확장 |
| 배치 | 그림 왼쪽, 설명 오른쪽 | 설명 왼쪽, 그림 오른쪽 |
| 장치 표현 | 옅은 청회색 바탕, 빛과 그림자 유지 | 남색·청색 표면과 은은한 빛, 주황 행동 버튼 |
| 공통 | 직선 단계 탭, 준비 확인과 상태 소유권, 그림 크기 조절 | 동일 |

B의 3D 배선 작업면은 검은 접지선과 단자 글자를 읽기 쉽도록 밝게 유지했다. 모형·배선색·물리적 연결은 바꾸지 않았다.

## 확인

- BMP280의 준비물·배선·프로그램·연결/수신 화면을 두 안에서 확인하고 `preparation-{light|dark}-{equipment|wiring|program|connection}.png`로 보관했다. 캡처는 같은 넓은 Chrome 창, 연결 전 모의 장치 상태다.
- A/B를 바꿀 때 현재 단계, 준비 확인, 모의 수신과 기존 3D 뷰가 유지되는 것을 확인했다.
- 1366·1024·390px 너비의 배선 화면에서 두 안 모두 페이지 가로 넘침이 없고 직선 탭을 유지했다. 작은 화면은 세로로 이어진다.
- 개발용 JavaScript 구문 검사와 변경 공백 검사를 통과했다.
- 실물 USB/BLE, 모든 센서·활동·브라우저의 전체 조합은 미확인이다. 전체 검사나 배포는 수행하지 않았다.

## 채택 후 다듬기

사용자는 B안을 선택하고 A안 보관을 요청했다. 새 디자인의 준비 화면은 B안을 기본으로 사용한다. 작은 안내 글의 대비·크기, 도움말 표시, 비활성 버튼 구분을 다듬었고 장치 카드 바탕을 밝게 조정했다. 장치 그림·배선색과 3D 작업면은 유지한다. 측정·분석은 밝은 화면을 유지한다.

최초 A/B 비교 캡처는 덮어쓰지 않는다. A는 `/dev/design/preparation.html?variant=light`에서 계속 조작할 수 있다. 보관 비교 페이지의 B 직접 조작 링크는 현재 다듬은 B안으로 연결된다. 새 B안 캡처는 `preparation-b-refined-*.png`로 구분한다. V2 공통화·배포는 별도 단계다.

채택 후 타입 검사와 기존 준비 브라우저 검사 5개를 통과했다. 새 B안의 네 준비 단계에서 1366px·390px 너비의 가로 넘침이 없음을 확인했고, 1366×768의 준비물·USB 안내는 세로 넘침 없이 들어간다. A 직접 조작 경로의 밝은 스타일과 프로그램 진입도 확인했다. 새 실물 장치 검증은 수행하지 않았다.

## 중간 커밋 검사 (2026-10-25)

타입 검사·단위 테스트 165개·빌드·vendor 해시 확인은 통과했다. Chrome 브라우저의 문구·저장·파일·분석 UI·측정·앱 통합·화면 이동·장치 검사는 통과했다. 전체 실행에서는 준비 안내의 3D 문서 로딩 검사가 실패했고, 레이아웃 검사는 프레임 로딩 대기에서 완료되지 않았다. 새 디자인 단독 검사에서는 일시정지 후 재개 버튼으로 키보드 초점을 옮기는 검사가 실패했다. 앞선 개별 확인 결과와 구분하며, 이번 중간 커밋을 전체 브라우저 검사 통과나 배포 승인으로 해석하지 않는다. 실패 원인과 실물 USB/BLE는 후속 확인이 필요하다.
