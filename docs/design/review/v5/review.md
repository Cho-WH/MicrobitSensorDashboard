# V5 기본 적용 검토

2026-10-25 · Windows / Codex 앱 내 Chromium · 로컬 서버. 운영 배포·커밋은 이번 작업에 포함하지 않는다.

## 채택 결과

Luminous를 홈과 센서·활동 직접 주소의 기본 화면으로 적용했다. 준비 B, 직선 탭·메모 강조, 밝은 측정·분석 표면을 유지한다. A는 개발 archive에 보관한다. 글자용 채널색과 자료선 색을 나누고 입력 경계를 강화했다. 기본 크기에서 숫자 자릿수가 바뀌어도 주변 위치가 유지되며, 200% 글자에서는 계기가 재배치되고 가상 표의 행 높이가 함께 늘어난다.

- [기본 측정 화면](measurement.png): 1280×720 CSS 창, BMP280 모의 원자료 600개, 일시정지·메모 1건.
- [기본 준비 B](preparation-default.png): 테마 매개변수 없는 `/sensors/bmp280/`, 연결 전 준비물.
- [200% 글자·대체 환경](text-200-fallback.png): 같은 측정 자료, 시스템 서체 대체·필터 없음·모션 감소 분기. 화면 전체 확대와 구별되는 글자 확대다.

## 성능 관찰

같은 1366×768 iframe, 가속도 4채널, 600→700개 모의 자료를 사용했다. 검토 페이지의 고정 시계와 별도로 부모 페이지의 실제 시계로 Chart.update를 측정했다. UI 전환·표 이동 수치는 검사 대기 280ms를 포함하므로 순수 렌더링 시간이나 입력 지연으로 해석하지 않는다. 아래는 한 번의 비교 관찰이며 성능 보증이나 통계적 우열이 아니다.

| 최종 비교 | Chart.update 중앙값 / p95 | 분석 전환 관찰 | 표 끝 이동 관찰 | 정지 1.2초 갱신 |
|---|---:|---:|---:|---:|
| 기존 표현 | 3.5 / 7.0ms | 314ms | 283ms | 0회 |
| 기본 Luminous | 3.7 / 6.8ms | 327ms | 285ms | 0회 |

수정 전에는 두 표현 모두 일시정지한 동일 자료를 1.2초 동안 6회 다시 그렸다. 수정 후 0회이며, 기록을 재개하면 700개가 관계 그래프와 가상 표 끝 행까지 전달된다. 표/그래프/분할 전환에서 차트 인스턴스가 누적되지 않는 것도 확인했다. 일정한 자료를 그리는 비용만 줄였으며 원자료 수집 주기·정밀도·저장 형식은 바꾸지 않았다.

## 확인 범위

- 타입 검사, 경로 단위 검사 2개, 정적 빌드 통과.
- 관련 브라우저 검사 43개: 배치 8, 접근성 3, 측정 8, 준비 6, 화면 전환·저장 재열기 2, 새/기존 분석 각 7, 성능 비교 2.
- 1920/1366/1024/390/320px 및 683×384 CSS 영역(1366 화면의 200% 확대에 대응), 다섯 센서·게이뤼삭의 관련 배치·조작 확인. 모든 크기와 모든 상태의 전체 조합을 검사한 것은 아니다.
- 200% 글자는 1366px BMP280 측정·분석과 390px 4채널 측정·분석/준비 B에서 확인했다. 입력 경계·채널 글자 대비, 페이지 가로 넘침, 설정 진입/닫기 초점, 확대 표의 600번째 행 접근을 검사했다.
- 실제 키보드로 본문 바로가기 → main 초점, Enter로 설정 열기, Escape로 닫기와 호출 버튼 초점선 복귀를 확인했다. 기존 회귀 검사는 저장 메뉴·기록 버튼 교체·표 선택·계산 오류·해석 보존·PNG/인쇄 자료와 색을 포함한다.
- 글꼴 실패는 개발 페이지의 실패 FontFace와 시스템 서체로, 모션 감소는 CSS/JS 분기 강제로 확인했다. 운영체제 설정은 바꾸지 않았다. CSS 글자 확대와 Canvas의 고정 축 글자 크기는 서로 다르며 Canvas 판독은 화면 확대·자료 표와 함께 확인한다.

전체 suite는 실행하지 않았다. 실물 USB/BLE·장시간 측정·저사양 장치·다른 브라우저 엔진·스크린리더·운영체제 고대비/모션 설정·프로젝터·실제 인쇄는 미확인이다. 기존 장치 검증 기록을 이번 디자인 검증으로 대체하지 않는다. 전면적인 WCAG 적합성 인증 결과가 아니다.

## 후속 커밋·배포 전 검증 (2026-10-25)

V5 기본 적용 이후 같은 물리량의 공통 축·스케일, 선택적인 오른쪽 세로축, 분석 화면 높이 조절, 원자료 그래프 높이와 결과 해석의 저장·인쇄 배치까지 함께 확인했다.

- 타입 검사·전체 단위 검사 169개·정적 빌드 통과.
- 전체 브라우저 suite에서 64개 통과 후, 파일 호환성 suite를 수정·재실행하여 4개 추가 통과(총 68개). 구형 수치 모델 비교에서 새 카탈로그의 물리량 메타데이터만 분리했으며 원자료·회귀·근거 수치의 동일성 검사는 유지했다.
- 단위 검사의 구형 그래프 오류 문구 기대값도 현재 ‘수신 시각’ 안내에 맞췄다. 잘못된 축 거부·상태와 이력 보존 검증은 유지했다.
- 실물 USB/BLE 및 실제 인쇄 등 위의 미확인 범위는 그대로다. 배포는 기존 GitHub Pages workflow의 검사·빌드를 다시 거친다.
