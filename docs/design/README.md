# Luminous Lab · 센서 실험실 시각 디자인 v2

**상태:** V5에서 대비·확대·초점·성능을 점검하고 Luminous를 기본 앱에 적용했다. 홈과 센서·활동 직접 주소에 별도 테마 매개변수가 필요하지 않다. 역할별 토큰·공통 조작 상태·화면 배치는 분리해서 유지한다. A안의 캡처와 구현은 별도 보관 경로에 두고 현재 준비 화면에는 B안만 표시한다. 운영 배포는 기존 `main` → GitHub Pages 검사·빌드 절차를 따른다.

**진행 상태 — 1–3차 구조 전환 적용:** 최종 화면 틀과 CSS 선언을 HTML로 옮기고 조작 연결·초기 표시의 책임을 나눴다. 기존 Chrome 제어 세션에서 멈췄던 iframe 검사 5개 묶음은 독립 Chromium에서 조건 변경 없이 통과했다. 결과 해석의 높이 분배도 수정했다. [원인 추적·수정 기록](visual-rollout-plan.md#148-탐색-실패-분리와-결과-해석-수정)에 확인 범위와 제한을 구분했다. [기본 UI 구조 전환 계획](visual-rollout-plan.md#14-기본-ui-구조-전환-계획)에 초기 로딩, CSS 소유권, A안 보관, 단계별 완료 기준을 정리했다. [목표 구조](visual-language.md#8-기본-ui의-목표-구조)를 따르며 2차에서 공통 조작과 화면별 CSS를 통합하고 A안 스타일을 개발 보관 경로로 분리했다. [2차 적용 기록](visual-rollout-plan.md#149-2차-css-소유권-통합-적용)을 따르며, 3차의 공통 조작·측정/분석 공간 배분·CSS 전달도 적용했다. [3차 적용 기록](visual-rollout-plan.md#1410-3차-재사용공간-배분스타일-전달-적용)에 성능 관찰 조건과 검증 범위를 구분했다. 아래 V2–V5 검사 결과는 각 단계 당시 기록이며 이번 구조 전환의 검증 결과가 아니다.

- [준비 화면 A/B 검토](review/v1/preparation-comparison.md): 두 방향의 차이와 검토 조건
- [로컬 검토 실행 방법](../../dev/design/README.md): 현재 B안과 별도 보관된 A안

새 디자인의 측정 화면은 값과 단위를 한 줄로 묶고, 기록 조작에 아이콘과 글자를 함께 사용한다. 그래프의 조작·메모 표찰은 가까우면 묶고 선택 시 개별 시각과 전체 내용을 보여 준다. 하단은 최근 조작·메모와 펼쳐 보는 기록·수신 상태로 나누며 원자료와 사건 보관은 유지한다. 상단의 JSON·CSV는 `파일 저장` 메뉴에서 선택하고 저장 실패 재시도는 바로 표시한다. 경과 시간·미니 그래프·배경 장식 확장은 이번 수정에 포함하지 않는다.

[측정 화면 검토 캡처](review/v1/measurement-refined.png)는 1366×768, BMP280 모의 기록 600개·메모 1건 상태다. 메모 표찰과 목록은 직선 강조선·배경 오버레이를 사용한다. 실제 저장 메뉴로 내려받은 JSON·CSV의 600개 측정값이 같음을 확인했다.

2026-10-25 커밋 전 타입 검사·전체 단위 테스트 165개·빌드·전체 브라우저 검사 54개가 통과했다. 브라우저 전체 실행은 Codex 앱 내 Chromium에서 수행했으며, 3D WebGL·연속 화면 크기 검사·새 측정 화면의 다섯 조합을 모두 포함한다. 비동기 저장 중 기록 버튼이 비활성화되어 초점을 잃던 오류를 수정했고, 레이아웃 검사의 프레임 로딩에는 제한 시간과 실패 주소를 추가했다. Chrome 자동화 환경에서는 다음 iframe이 요청 없이 `about:blank`에 남는 현상이 재현되었으며, 그 환경의 원인까지 수정한 것으로 보지 않는다. 이번 실물 USB/BLE 재검증은 수행하지 않았다.

## V2 확인

타입 검사·빌드와 관련 브라우저 검사 14개(새 측정 8, 기존 준비 5, 기존 측정 1)를 통과했다. 같은 855×1039 검토 창에서 측정 화면의 주요 8개 영역의 위치·크기·색·모서리를 전후 비교해 유지됨을 확인했다. 준비 B의 장면·주황 행동·직선 탭, A의 밝은 화면, 배선 3D 적용도 확인했다. 어두운 준비의 초점선과 비활성 버튼 표현은 공통 상태 규칙으로 정리했다. 기존 대비 한계는 [대비 기록](contrast-check.md)에 남겼다. 전체 검사·실물 USB/BLE 재검증·기본 배포 전환은 이번 단계에서 수행하지 않았다.

## 시안 이미지

사용자가 제공한 기준 시안을 [approved-moodboard.png](reference/approved-moodboard.png)에 원본 그대로 보관한다. 디자인 작업을 시작할 때 이 이미지를 함께 참조한다.

참고 이미지에 등장하는 장치 연결 상태, 수치, 단위는 제품 기능 명세가 아니다. 실제 기능과 측정 정보는 저장소의 센서 정의를 따른다.

## V3 준비 화면

- 장치 그림과 실험 도구를 설명 양쪽에 배치하고 넓은 화면의 준비물 그림 밀도를 조정했다. 내장 센서의 공통 본체·USB와 BMP280의 센서·확장 보드·연결선은 기존 자산을 사용한다. 배선 3D는 필요한 단계에서만 열고 밝은 작업면을 유지한다.
- 수신 대기·연결 해제·연속 수신과 마지막 값을 구분한다. 센서별 수신 해석은 각 모듈의 `uiCopy`에서 제공하며, 상대 밝기·내장 온도·중력 포함 가속도·자기장·온도/기압의 의미를 유지한다. 설치 대상·진행·실패·완료를 수신 상태와 분리한다.
- 자기장 보정 생략은 수신 확인과 준비 결과에도 생략으로 표시한다. 보정 완료 체크나 근거로 바꾸지 않는다. 게이뤼삭은 배터리 확인과 용기 배치를 순서 있는 안내로 나누고, 배치도와 보정 그림은 밝은 면에 둔다.
- 보조 조작의 호버·선택·초점을 공통 규칙에 연결했다. 준비 탭은 직선 강조선과 오버레이를 유지한다. 준비 체크·측정 허용·원자료·저장 계약은 바꾸지 않았다.

검토용 경로는 [실행 안내](../../dev/design/README.md)를 따른다. 실물 USB/BLE, 프로젝터, 전체 접근성·성능 검증은 별도이며 V3 외형·모의 검사로 대체하지 않는다.

타입 검사·빌드, 관련 단위 검사 17개(준비·모듈 등록), 관련 브라우저 검사 19개(새 준비 6·기존 준비 5·배치 8)를 통과했다. 당시 새 준비 검사는 같은 문서에서 1366/390px 크기 변경과 A/B 전환을 확인했다. 이후 비교 선택 UI를 제거하고 A안을 별도 보관 경로로 옮겼으며 현재 검사는 단계 이동·크기 변경의 상태 보존을 확인한다. 기존 배치 검사는 1920px와 683×384 CSS 영역도 포함한다. [용기 배치 캡처](review/v3/placement.png)는 1280×720 검토 창의 B안이다. 키보드 End 이동과 초점, 프로그램 패널·보정 선택·수신 장면도 수동 확인했다. 전체 검사와 실물 장치 검증은 실행하지 않았다.

## V4 분석·해석·홈·저장·출력

- 분석 작업과 표/그래프 보기 탭은 직선 밑줄·오버레이로 통일했다. 구간 도구, 가상 표의 체크/살펴보기/제외, 계산 열 메뉴·오류·대화상자는 공통 색과 조작 규칙을 사용한다.
- 해석은 보관 근거와 글쓰기 표면을 나란히 두고 질문·입력·저장 상태의 읽기 크기를 정리했다. 질문 내용과 근거 갱신 조건은 유지한다. 홈의 센서/활동 탐색, 소개, 저장 목록과 빈 상태도 같은 밝은 표면을 사용한다.
- 원자료 차트·관계 그래프·보관 근거·PNG·인쇄에 같은 표시값을 전달한다. 세로축 채널색, 포함/제외 점, 추세선/연장선과 글꼴을 공유하고 출력은 흰 바탕을 유지한다. 저장 모델·원자료·단위·JSON/CSV 형식은 변경하지 않았다.

[분석 캡처](review/v4/analysis.png) · [해석 캡처](review/v4/interpretation.png) · [홈 캡처](review/v4/home.png). 1280×720 검토 창에서 실제 앱을 사용했으며 분석·해석은 BMP280 모의 자료 600개, 온도/기압 축, 추세선 상태다. 계산 열 입력 오류·비활성·초점과 빈 저장 목록도 수동 확인했다.

타입 검사·빌드와 관련 브라우저 검사 24개(새 분석 7, 기존 분석 7, 새 화면 전환 2, 측정 8)를 통과했다. 구간 초안/적용, 제외 복원·되돌리기, 표/그래프 전환, 1,500행 가상 표, 시각 없는 자료, 해석의 근거/글 보존, 화면/PNG/인쇄의 Canvas 자료·표현 일치와 흰 바탕을 확인했다. 실제 앱 하나를 1366→1024→390→320px로 바꾸고 저장 목록에서 근거와 글을 다시 열었다. 전체 검사·실물 USB/BLE·실제 프린터/PDF 출력·프로젝터 검증은 수행하지 않았다. 검사 산출물과 임시 DB는 정리하며 재사용하는 검사만 기존 브라우저 검사에 포함했다.

## V5 대비·접근성·성능·기본 적용

- 작은 채널 글자·계기 숫자의 색을 자료선 색과 분리하고 입력 식별 경계를 보강했다. 밝은 표면에서 글자 4.5:1, 입력 경계 3:1 이상을 기준으로 계산했다. 실제 값은 [대비 기록](contrast-check.md)을 따른다.
- 글자 크기를 rem 기반으로 바꾸고, 200% 글자에서 계기 재배치·숫자 높이·사이드바 스크롤·가상 표 행 높이를 조정했다. 긴 숫자는 원래 값을 보존하며 내부 스크롤로 읽는다. 본문 바로가기의 초점과 대화상자 이름 연결도 보강했다.
- 일시정지·마친 기록의 동일한 그래프는 반복해서 다시 그리지 않는다. 새 수신값의 계기 표시, 기록 재개, 채널·범위·사건 변경, 크기 변경은 계속 반영한다. 원자료나 저장 계약은 변경하지 않았다.
- V5 당시 기본 bootstrap이 DOM 구성 모듈과 `luminous.css`를 사용했다. 후속 1차 전환에서는 고정 구조·스타일을 HTML에서 직접 선언한다. 사용자 경로의 테마 분기와 링크 매개변수 전파를 제거했다. A안과 기존 표현 비교는 개발 경로에만 남는다. 외부 자산 추가는 없으며 기존 Pretendard/Lucide 출처·라이선스를 유지한다.

실측과 남은 확인은 [V5 검토 기록](review/v5/review.md)에 정리한다. 전체 접근성 인증이나 실물 장치 성능 검증을 뜻하지 않는다.
