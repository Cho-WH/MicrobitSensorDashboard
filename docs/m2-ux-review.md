# M2 마무리 전 UX·재사용 재점검

2026-10-19. 참조 앱의 소스와 실제 브라우저 화면을 직접 대조했다. **§1–6은 구현 전 도입 결정과 인수 기준이며, 반영 결과는 §7에 기록한다.** 검토·설계·구현·검증을 서브에이전트 없이 수행했다.

결정: **게이뤼삭의 단계별 준비·탐구 안내를 공통 UX의 기준으로 삼고, 대시보드의 간결한 측정 표시를 결합한다.** 이미 이식한 저장·분석·장치 기반은 유지한다. 기능 통합과 UX 보완의 소프트웨어 검증을 마쳤지만, 실물 인수 전에는 M2 전체 완료로 판정하지 않는다.

## 3. 우리 앱에 적용할 흐름

### 3.1. 큰 단계와 세부 단계

| 경로 | 표시할 큰 단계 | 단계 안에서 확인할 내용 |
|---|---|---|
| BMP280 자유 측정 | 준비물 → 배선 → 프로그램 → 연결·수신 | 배선은 전원·접지·클록·데이터의 네 세부 단계. 프로그램 안에 USB 연결과 설치. 마지막에 온도·기압의 새 값 확인 |
| 게이뤼삭 | 준비물 → 배선 → 프로그램 → 연결·수신 → 배터리 → 용기 배치 | 공통 BMP 준비를 재사용하고 활동 도구·USB 분리 뒤 수신·용기 그림과 배치 확인을 추가 |
| 내장 자기장 | 준비물 → 프로그램 → 무선 연결 → 보정·수신 | 외장 배선·BMP 3D·용기를 표시하지 않음. 연결 뒤 보드의 보정 안내와 네 채널 수신을 구분하여 확인 |

원본의 독립 USB 단계를 프로그램 그룹 안에 넣는다. USB 연결은 설치를 위한 하위 행동이고, 이미 프로그램이 있는 경로에서는 생략할 수 있기 때문이다. 화면 그룹을 줄여도 기존 세부 단계 ID·완료 근거·무효화 조건은 보존한다. 그룹 목록을 보았거나 다른 단계로 이동했다는 이유로 완료 처리하지 않는다.

완료한 단계와 다음 단계를 자유롭게 살펴볼 수 있다. 수동 확인 버튼은 해당 확인과 이동을 함께 처리하고, 이전/그룹 이동은 확인을 만들지 않는다. 설치 중에는 설치 대상·구성을 바꾸는 행동을 막고 이유를 가까이 표시한다. 마지막에는 준비 결과와 남은 항목을 보여 주며, 실제 기록은 측정 화면의 `기록 시작`에서만 시작한다.

`준비된 장치 확인`은 배선 재조립을 강제하지 않는 빠른 경로다. 필요한 준비물·배선·설치 여부를 요약에서 직접 확인하고 연결로 이동한다. 기존 이력만으로 현재 장치를 준비 완료로 표시하지 않는다. 새 수신, 자기장 보정, 배터리 단독 검사와 활동 배치는 필요한 경우 그대로 확인한다.

### 3.2. 화면 구성과 상태 표현

- **상단:** 현재 센서·활동, 큰 단계·진행 상태. 파일 도구는 주 안내를 밀어내지 않도록 묶고 준비 화면에서 비활성 내보내기 버튼을 나열하지 않는다.
- **데스크탑 본문:** 시각 자료 약 60%, 설명·주 행동 약 40%를 출발점으로 한다. BMP 배선은 3D/표를 탭으로 전환하며 둘을 세로로 중복 배치하지 않는다. 원본의 안정적인 버튼 위치를 계승하되 고정 높이로 글을 잘라내지 않는다.
- **3D 표시 안정성:** 로딩 안내는 그림을 밀지 않게 겹쳐 표시한다. 최초 로드·재시도는 화면 공간을 유지한 채 첫 장면 적용 완료를 기다리고, 이후 배선 단계 전환 중에는 그림을 계속 표시한다. 전환 완료 후뿐 아니라 응답을 기다리는 동안의 위치·크기도 검사한다.
- **문맥에 맞는 시각 자료:** 준비물 목록과 장치 개요, 배선 단자 강조, USB 연결 그림, 수신값 카드, 배터리 점검, 용기 배치 그림. 자기장은 보정 안내를 사용하고 빈 3D 칸을 남기지 않는다.
- **장치 상태:** `프로그램 설치 완료`, `무선 연결됨`, `새 값 수신 중`, `보정 확인 필요`를 구별한다. 설치 진행률은 실제 전송 상태와 함께 표시하고 100%를 성공으로 간주하지 않는다. 직접 확인한 설치를 앱이 검증한 설치 버전처럼 표시하지 않는다.
- **수신 점검:** 값·단위·마지막 수신과 점검 결과를 같은 영역에서 보여 준다. 숫자가 일정해도 새 값이 오면 정상이며, 중단되면 마지막 값을 현재 정상값처럼 보여 주지 않는다. 보정 중 대기는 통신 실패와 다른 안내를 쓴다.
- **문제 해결:** 취소는 취소로, 미지원은 지원 기능 안내로, 단절은 재연결로 이어진다. `이전 장치에 다시 연결`과 `다른 장치 선택`을 구분한다. 기록 중 재연결이 필요하면 기존 정책에 따라 먼저 일시정지하고, 재확인 후 명시적으로 재개한다. 자동 재연결·자동 기록 재개는 도입하지 않는다.
- **활동 안내:** 게이뤼삭의 `setup.svg`와 네 페이지 안내를 복원한다. 기록 전에는 `기록 시작 → 처음 값 관찰 → 가열 시작`을 명확히 한다. 안내를 여는 행위가 기록을 시작하거나 멈추지 않으며, 기록 중에만 계속 기록된다는 문구를 표시한다. 다시 열기와 닫은 뒤 초점 복귀를 보존한다.
- **측정 표시:** D의 채널 선택을 공통 UI에 적용한다. BMP 기본 표시는 온도·기압, 자기장 기본 그래프는 크기로 하고 X/Y/Z를 추가할 수 있게 한다. 채널 숨김은 원자료 저장·준비 판정·분석 대상에 영향을 주지 않는다. G의 최근/전체 표시 선택도 복원하되 `전체`는 기록된 전체 자료를 의미하며 미리보기 버퍼를 전체 기록으로 부르지 않는다.

## 5. 프런트엔드와 내부 연결의 작업 경계

전체 재작성은 필요하지 않다. 아래 세 가지를 화면 개편과 함께 처리한다.

1. **같은 상태를 같은 근거로 표시:** 현재 controller와 transport가 각각 수신 monitor를 갖는다. 실제 장치와 모의 장치 모두 준비용 `연결·새 수신·최근 시각·보정` 사실을 같은 인터페이스로 공급하도록 정리한다. 가이드의 사용자 확인, 장치 관측, Session의 기록 연속성을 하나의 모호한 `ready`로 합치지 않는다.
2. **이미 있는 복구 기능 연결:** transport의 `reuseDevice`는 존재하지만 controller의 연결 호출에서 사용하지 않는다. 이전 장치 재연결을 명시적 UI 명령으로 연결하고, 실패하면 다른 장치 선택으로 이어지게 한다. 기록·저장 가드를 우회하지 않는다.
3. **UI 경계도 검사 대상에 포함:** 현재 `jsconfig.json`의 검사 범위는 controller와 `src/ui/`를 포함하지 않는다. 이번에 바꾸는 준비 UI·장치 표시 모델·controller 호출 계약부터 JSDoc 검사에 포함하고 관련 오류를 해결한다. 검사 제외나 `any` 확대로 통과시키지 않으며, 무관한 코드 전체 타입 전환은 하지 않는다.

유지할 통합 앱의 개선점은 명시적 기록 시작, 현재 실험을 보존하는 탐색, 센서·활동 정의, 검증된 펌웨어 선택, 새 수신으로 준비 판정, 파일 복원과 장치 준비의 분리다. 원본의 준비 시 Run 생성·연결 후 준비 자료 기록, 대시보드의 별도 원자료 상태·기록 초기화, 임의 명령 설정을 그대로 복사하지 않는다.

## 6. 실행 순서와 M2 완료 기준

### 실행 순서

1. **준비 UI 복원:** 그룹 탐색·이전/주 행동·문맥별 시각 영역·준비물 도움말을 먼저 구현. 세 센서/활동 경로의 구성을 함께 확인한다.
2. **장치 상태와 복구 연결:** 수신 사실 소유권, 설치 진행, 실제 값 표시, 보정 대기, 배터리 재검사, 명시적 재연결을 통합한다.
3. **활동과 측정 보완:** 배치 그림·실험 방법, 채널 표시 선택·최근/전체 범위, 준비 결과에서 측정으로 이어지는 흐름을 구현한다.
4. **원본 대비 인수:** 아래 항목별 결과와 남은 문제를 기록한다. 통과한 기존 검사를 이유 없이 반복하지 않고, 바뀐 동작과 그 영향 경로를 확인한다.

200%는 1366×768의 절반인 **683×384 CSS viewport로 배치 동등성**을 검사했다. 실제 브라우저 확대 설정·OS 동작 줄이기 설정을 바꾼 수동 검사는 수행하지 않았다. 원본의 `prefers-reduced-motion` 대응은 유지했다.

**남은 인수:** 실제 micro:bit V2에서 두 프로그램의 설치, BLE 선택·취소·단절·재연결, 자기장 보정, USB 분리 뒤 배터리 단독 수신과 센서 정확도. 모의 통신·USB 상태 주입은 이 항목을 대신하지 않는다. 장시간 기록 성능과 M3 공유도 별도 범위로 남는다. 따라서 현 상태를 M2 전체 완료로 표시하지 않는다.


## 준비 체크와 측정 허용 분리 (2026-10-20)

사용자 결정에 따라 이전의 모든 필수 체크 완료 조건을 측정 이동·기록 시작·재개에서 제거했다. 현재 장치의 정상 연속 수신이 확인되면 연결·수신 단계에서 바로 측정으로 이동할 수 있다. 준비 결과에서도 같은 조건을 사용한다. 준비 체크와 보정·배터리 근거는 안내·이력으로 유지하며 수신 성공을 근거로 체크를 채우지 않는다. 수신 중단·단절·새 연결에서는 새 수신 확인이 필요하다. 실제 기록은 여전히 사용자가 기록 시작을 누를 때 시작한다.
