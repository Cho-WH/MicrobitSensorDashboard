# M1 이식·호환성 검증 기록

2026-10-19 공통 측정·저장·분석 기반을 구현했다. 현재 사용법은 [README](../../README.md), 저장·파일 계약은 [기술 설계 §8](../unified-sensor-lab-architecture.md#8-저장복원파일)을 따른다.

## 이식 결정과 출처

- 게이뤼삭 고정 원본 `bme280@59c5c149450f970bace2deaa183857c275595853`의 Workspace·RunStore·Repository를 재사용했다. 센서 채널은 일반화하고 가열·물 추가·탐구 질문은 활동으로 분리했다.
- 원본 Workspace와 파일 출력 코드를 실행해 [호환성 픽스처](../../tests/fixtures/README.md)를 만들었다. 새 분석의 수치·후보·제외·고정 근거를 원본 결과와 비교할 수 있게 했다.
- 게이뤼삭 JSON v1/v2·기존 CSV·대시보드 기본 CSV를 가져오되 원본 파일을 수정하지 않고 독립 Run으로 보관하도록 했다. 시각 없는 자료는 시각을 만들어 넣지 않았다.
- BMP280의 미지원 습도 자리는 측정값으로 표시하지 않고 원문 보조 정보로 보존했다. 그래프 표시 제한은 원자료 삭제와 분리했다.
- 라이선스와 원본 경로는 [외부 자원 고지](../../THIRD_PARTY_NOTICES.md), 고정 외부 파일의 해시는 [자산 목록](../../vendor/manifest.json)에 있다.

## 당시 검증 결과

Node 검사 90개, Chromium 브라우저 검사 16개, 타입 검사·빌드·변경 공백 검사를 통과했다.

- 저장 실패·재시도·쓰기 중 변경·잠금·기록 시작 조건, 계산·회귀·제외·되돌리기·근거 불변성, JSON/CSV 호환과 입력 제한을 검사했다.
- 브라우저에서 실제 IndexedDB·Web Locks·분석 DOM·가상 표·Chart.js를 사용했다. UI 전용 메모리 픽스처 검사는 DB 검증과 구분했다.
- 모의 기록 중 분석 이동, 회귀·근거·해석 작성, 일시정지·종료, 새로고침 후 복원, 구형 v2 파일 가져오기를 직접 확인했다.

M1 당시에는 실물 BLE·USB, 장시간 수신, 준비·공유 기능을 검증하지 않았다. 후속 결과는 [M2 기록](m2-implementation.md)과 [M4 인수 기록](m4-verification.md)에 있다.
