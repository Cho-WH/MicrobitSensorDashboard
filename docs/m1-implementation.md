# M1 구현과 검증

2026-10-19. 기획·기술 설계의 M1 범위를 구현했다. 기존 `index.html` 대시보드는
배포 호환성을 위해 유지하고, 측정 기록·분석 진입점은 `lab.html`에 연결했다.
이 문서는 M1 당시의 기록이다. 홈·직접 진입·USB/BLE·자기장 확장은 [M2 구현 현황](m2-implementation.md), 새 공유 링크는 M3 범위를 참고한다.

## 실행

Node 24.18.0을 사용한다. 브라우저 코드는 빌드 없이 native ES Modules로 실행된다.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
npm run test:browser
```

개발 서버가 출력한 주소의 `lab.html`을 연다. `?mock=1`은 실제 센서가 아닌
모의 BMP280 수신이며, 기록 시작 전에는 DB에 Run이나 원자료를 만들지 않는다.
기본 포트는 8080이다. 사용 중이거나 Windows가 예약한 포트라면 PowerShell에서
`$env:PORT='8766'` 설정 후 실행한다. 브라우저 검사는 출력된 `/tests/browser/`에서
**검사 실행**을 누르는 유지보수용 러너다. `npm run test:browser` 자체의 서버 시작은
검사 통과를 의미하지 않는다.

실제 측정은 BMP280 프로그램이 이미 설치된 micro:bit를 연결한다. M1은 기존
BLE 모듈을 재사용하며, 검증된 HEX·WebUSB 설치·센서별 단계별 준비 및 새 BLE
어댑터는 M2 범위다. 실제 장치 검증 없이 설치·측정 정확성을 보증하지 않는다.

## 사용할 수 있는 흐름

- BMP280 자유 측정과 게이뤼삭 활동이 같은 채널·펌웨어·저장·분석 기반을 사용한다.
  활동만 장치 배치·가열·물 추가 기록과 Kelvin 계산 예시·탐구 질문을 제공한다.
- 기록 시작·일시정지·재개·종료·추가 측정, 사용자 메모, 원자료 자동 저장을 제공한다.
  연결 해제와 화면 전환은 원자료를 지우지 않는다. 분석 화면으로 이동해도 기록은 계속된다.
- 분석에서는 표 필터·정렬과 실제 분석 대상을 구분한다. 구간 또는 체크한 자료로
  분석 대상을 지정하고, 제외 사유·계산 열·회귀·근거와 해석을 저장한다.
  새 자료는 버튼을 눌러 반영하며 기존 지정 범위와 근거 사본을 유지한다.
- 저장된 실험은 명시적으로 열어 이어서 분석한다. 새로고침이나 파일 가져오기는
  장치 자동 연결·기록 재시작을 하지 않는다.
- 전체 실험 JSON은 원자료·사건·작업 정의를 보관한다. CSV는 표 자료용이며
  전체 분석 작업 복원의 대체 파일이 아니다.
- Web Locks/IndexedDB를 쓸 수 없는 파일 분석은 임시 메모리에서 처리하며
  영구 저장으로 표시하지 않는다. 전체 실험 JSON으로 보관할 수 있다.

## 모듈과 저장 형식

`src/catalog/`는 센서·활동 정의, `src/domain/`은 채널·검증 계약,
`src/measurement/`는 기록 수명, `src/data/run-store.js`는 원자료와 미저장 변경,
`src/data/repository.js`는 `microbit.sensor-lab` IndexedDB v1의 원자적 쓰기,
`src/analysis/`는 분석 정의와 계산, `src/ui/`는 재사용한 분석 화면을 담당한다.
`src/app/controller.js`는 모듈 연결과 화면 전환을 맡는다.

Sample은 `values`와 채널별 `validity`를 갖고 0·결측·미지원·범위 밖·오류를 구분한다.
BMP280 CSV의 습도 자리는 측정값으로 표시하지 않고 원문 보조 정보로 보관한다.
원자료는 그래프의 표시 제한으로 삭제하지 않는다.

전체 실험 파일은 `{format:'microbit-sensor-lab',fileVersion:1,run,samples,events,workspace}`다.
게이뤼삭 JSON v1/v2와 기존 CSV, 대시보드 기본 CSV를 지원한다. 가져온 파일은
수정하지 않으며 새 Run ID와 재연결한 참조로 보관한다. 알 수 없는 CSV는 열의 뜻과
단위를 확인한다. 시각이 없으면 `null`을 유지하고 자료 번호로 표시한다.

파일 32 MiB·원자료 100,000개·원자료와 가져온 숫자 열 16개·계산 열 32개 제한을
입력과 저장에 함께 적용한다. 계산 열을 숫자로 내보낸 CSV가 원자료 16열을 넘으면
내보내기를 거부하고 전체 JSON 사용을 안내한다.

## 검증의 근거와 경계

최종 확인: Node 테스트 90개, 실제 Chromium 브라우저 검사 16개,
`npm run typecheck`, `npm run build`, `git diff --check`를 통과했다.

고정 원본 `bme280@59c5c149450f970bace2deaa183857c275595853`을 직접 확인했다.
원본 Workspace와 파일 출력 코드를 실행하여 만든 픽스처는 `tests/fixtures/`에 있다.
이를 통해 새 분석의 수치·후보·제외·고정 근거가 원본과 일치하는지 확인한다.

Node 검사는 저장 실패·동일 묶음 재시도·지연 중 새 revision·잠금·기록 게이트,
범용 채널·계산 오류·회귀 경계·범위·제외·되돌리기·근거 불변성,
JSON/CSV 호환과 입력 제한을 검사한다. `typecheck`는 도메인·카탈로그·저장·분석·
세션 모듈과 그 공개 호출 관계를 검사한다. DOM 화면 코드는 실제 브라우저로 확인한다.

브라우저 러너는 실제 IndexedDB 트랜잭션·Web Locks·Papa Parse와 실제 분석 DOM·
가상 표·Chart.js를 검사한다. 저장 검사는 고유 이름의 테스트 DB만 사용하고 정리한다.
UI 검사는 별도 메모리 픽스처를 쓰며 DB 검증과 혼동하지 않는다.

수동 브라우저 확인에는 모의 기록 중 분석 이동, 회귀·근거·해석 작성,
일시정지·종료, 새로고침 후 실험 복원, 구형 v2 파일 가져오기를 포함한다.
실물 BLE·USB 전송, 장시간 10Hz 성능, M2 준비 흐름, M3 공유는 검증하지 않았다.

이식 출처·라이선스 상태는 `THIRD_PARTY_NOTICES.md`, 외부 자산 해시는
`vendor/manifest.json`에서 확인한다.
