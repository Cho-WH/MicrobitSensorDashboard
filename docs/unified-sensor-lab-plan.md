## 1. 목표

센서를 선택하면 맞춤 펌웨어·배선·측정 항목·그래프가 준비되고, 실험 활동을 선택하면 탐구 절차·기록 버튼·분석 제안이 추가되는 하나의 앱을 만든다. **공통 구조는 게이뤼삭 앱의 준비→USB 프로그램 전송→BLE 수신 확인→측정·자동 저장→학생 주도 분석→근거·해석 기록을 기준으로 한다.** 기본 공유는 도구를 바로 여는 링크 복사와 QR 생성으로 한정한다. 교사의 실험 JSON을 바탕으로 수업 자료를 배포하는 기능은 후순위로 분리한다.

기본 원칙은 센서가 측정 가능 범위를 결정하고, 활동이 탐구 맥락을 결정하며, 도구 링크가 그 도구의 진입점을 전달하는 것이다. 공유를 위해 별도의 수업 설정을 작성하게 하지 않는다. 분석 구간·축·계산·자료 제외·해석의 판단은 학생에게 남긴다.

**범위:** 이 저장소에 센서 측정·특화 실험 활동을 모두 담는 **단일 센서 실험 앱**을 구축한다. 센서마다 또는 게이뤼삭 같은 활동마다 별도 앱·저장소를 만들지 않는다. 이 문서는 앱 내부의 탐색, 준비·측정·분석, 데이터·상태, 도구 공유와 후속 자료 공유의 경계를 정의한다. 앱의 공식 도메인 연결·기존 주소 전환과 Cloudflare 공유 저장소 연계를 포함한다. 상위 포털은 앱 소개·실행 링크의 연결 경계만 다루며, 포털 자체 기능과 다른 교육 도구의 이전은 범위 밖이다.

## 3. 시작 화면과 진입 경로

### 3.1. 앱 홈

이 앱의 첫 화면은 **센서로 측정하기**와 **실험 활동 시작하기**를 동등한 선택지로 제공한다. 센서를 먼저 고르지 않아도 활동을 바로 선택할 수 있고, 센서를 선택한 뒤에는 그 센서를 사용하는 추천 활동으로 이어질 수 있다. 처음 사용자에게는 센서 카드와 활동 카드의 목적을 간결하게 안내한다.

이 앱에 저장된 실험 이어하기와 실험 파일 열기도 같은 첫 화면에서 제공한다. 앱의 홈은 센서·활동 탐색만 담당하며, 준비·측정·분석 기능을 별도 앱으로 분산시키지 않는다.

실시간 Bluetooth 측정이 지원되지 않는 환경에서는 권한 요청이나 팝업 없이 홈·실험 소개·준비·측정 화면에 공통 안내를 표시한다. HTTPS 접속 문제와 페이지 접근 제한은 브라우저 미지원과 구분한다. 준비 안내 열람과 파일 분석은 유지하고, 분석·저장 목록에서는 연결 안내를 반복하지 않는다. iPhone·iPad의 미지원 브라우저에는 Bluefy App Store 링크와 현재 주소 복사를 제공하고, 앱 설치 후 복사한 주소로 다시 접속하도록 안내한다. 복사가 거부되면 직접 선택할 수 있는 주소를 보여 준다. 카드 안에는 파일 열기 버튼을 중복 배치하지 않으며, 이 실험실과의 실물 연결 미검증 및 센서 프로그램의 별도 설치 필요성을 도움말에 명시한다.

### 3.2. 선택 이후의 경험

**센서로 측정하기:** 센서 카드에서 BMP280 또는 내장 자기장 등을 선택한다. 펌웨어·배선·측정값·단위·기본 그래프를 자동 준비하고 자유 측정으로 이어진다. 활동 선택은 필수가 아니다.

**실험 활동 시작하기:** 게이뤼삭 실험 등을 선택하면 호환 센서와 준비물, 용기·수조 안내, 활동 전용 조작 기록과 분석 제안을 함께 연다. BMP280 자유 측정과 게이뤼삭 활동은 동일한 펌웨어와 분석 엔진을 사용할 수 있다.

**도구 링크로 시작하기(M3):** 도구 미리보기에서 제공하는 링크와 QR은 보고 있는 센서·활동의 실험 소개 화면을 연다. 학생이 **처음부터 준비하기 / 준비된 장치 확인**을 선택한 뒤 자신의 장치를 연결하고 기록한다. 링크를 열거나 다시 방문하는 것만으로 기록을 만들거나 기존 기록을 초기화하지 않는다. 이전 기록은 저장된 실험에서 명시적으로 이어간다.

선택 후에는 상단에 **BMP280 · 온도와 기압 측정** 또는 **기체의 온도와 압력**처럼 현재 센서·활동 이름과 준비·측정·분석 흐름을 표시한다. 모든 경로는 같은 UI와 엔진을 사용하되, 해당 탐구에 필요한 항목만 보여 준다. 전체 센서·활동 목록은 홈으로 돌아갈 때 열고, 센서 준비 화면에는 그 센서로 할 수 있는 활동을 선택적으로 안내한다.

### 3.3. 탐색·전환과 실험 보존

- 카드·도구 주소·실험 소개를 여는 것만으로 측정 Run을 만들지 않는다. 준비 설정은 시작 구성으로 유지하고, 새 측정 Run은 최초 **기록 시작** 때 생성한다. 이어하기는 기존 Run을 열고, 파일 가져오기는 파일의 실험을 복원한다. 후속 공유 자료의 학생 사본은 별도의 **내 분석 시작** 동작으로 만든다.
- 같은 실험실의 준비·측정·분석 화면을 오갈 때는 구성·기록을 유지한다. **실험 선택** 또는 **새 실험 준비**로 나가는 동작은 현재 실험실 종료다. 분석 초안과 기록을 마감·저장한 다음 장치 연결을 종료하고 현재 실험을 닫는다. 저장 실패 시 현재 화면·실험·연결을 유지하며 재시도할 수 있다. 임시 분석처럼 브라우저에 저장할 수 없는 자료는 파일 보관 또는 현재 화면에 머무르기를 선택한다.
- 선택 화면에는 활성 실험이 없다. 카드를 열면 미리보기부터 선택한 실험의 이름을 상단에 표시한다. 미리보기는 안내만 제공하며 장치 연결·기록 권한은 **처음부터 준비하기** 또는 **준비된 장치 확인**을 누른 뒤 열린다. 같은 센서의 다른 활동도 종료한 실험의 연결·준비 확인을 자동 상속하지 않는다. 이전 기록은 저장된 실험에서 명시적으로 열어 이어간다.
- 미리보기 주소는 센서·활동 경로에 `?view=preview`를 붙여 구분한다. 새로고침·뒤로 가기·앞으로 가기에서도 미리보기 소속을 유지한다. 이력 이동으로 현재 실험실을 벗어날 때도 동일한 저장·연결 종료 규칙을 적용하며 실패하면 현재 실험의 주소로 복구한다. 기존 센서·활동 직접 준비 주소는 유지한다.
- 브라우저의 다른 사이트로 이동하거나 현재 앱을 닫는 것은 센서 앱을 떠나는 동작이다. 기록 중이거나 분석 글 등 미저장 변경이 있으면 기록을 마치고 저장한 뒤 이동하거나 현재 실험에 머물 수 있게 한다. 주 버튼은 상태에 맞게 **기록을 마치고 이동** 또는 **저장하고 이동**으로 표시한다. 저장 실패는 재시도·파일 보관으로 해결하고, 앱을 떠나도 기록이 계속된다고 안내하지 않는다.

## 4. 센서·활동 설정과 공유의 경계

| 구분 | 포함 정보 |
|---|---|
| 센서 정의 | ID·버전, 지원 micro:bit와 모듈, 배선, 펌웨어 파일·해시, 통신 프로토콜, 측정 채널·단위·유효성, 보정, 기본 표시 |
| 활동 정의 | ID·버전, 호환 센서, 준비물, 진행 단계, 전용 사건·버튼, 기본 분석 제안, 탐구 질문 |
| 도구 공유(M3) | 현재 미리보기 중인 센서·활동의 실험 소개 주소. 별도 수업 구성 없음 |
| 교사 자료 공유(후순위) | 검증된 실험 JSON에서 만든 자료 사본, 수업 제목·질문·안내, 공유 식별자와 만료일 |

도구 진입의 적용 순서는 **센서의 지원 범위 → 활동의 필수 조건과 기본값 → 학생의 분석 선택**이다. 링크는 교사의 표시 채널·축·회귀·계산식이나 장치 설정을 전달하지 않는다. 후속 자료 공유도 파일에 없는 채널·측정 명령을 만들거나 학생에게 장치 권한을 넘기지 않는다.

실험에는 적용된 센서·프로그램·활동의 버전과 사본을 보관한다. 기록이 있는 실험의 센서·활동은 유지하며, 다른 구성으로 시작하는 동작은 §3.3을 따른다. 기존 실험 이어하기는 당시 보관한 구성을 사용한다. 도구 링크는 현재 제공 중인 도구를 여는 주소이며 과거 화면·정의 버전을 고정하는 자료 보관 링크가 아니다. 후속 교사 자료 공유의 사본·출처 보존은 §8에서 별도로 정한다.

## 5. 장치 준비 UX

내장 센서의 준비물은 micro:bit V2 앞·뒷면, USB 연결, AAA 전지 2개 케이스를 정지 그림으로 보여 준다.
USB 설치 안내와 펼쳐 보는 배터리 전원 안내도 같은 그림을 사용한다. 준비 화면에서 3D 조작은 요구하지 않는다.
BMP280도 준비물·프로그램 단계에서 같은 카드와 본체·USB 그림을 쓰며, 센서·확장 보드·연결선은 기존 모델의 정지 그림으로 보완한다. 배선 단계의 3D 조작은 유지한다.

게이뤼삭의 단계별 안내를 재사용하되 센서·활동에 필요하지 않은 단계는 생략한다. 내장 자기장은 외장 배선 단계 없이 펌웨어·보정·수신 확인으로 진행한다. 연결 후 앱에서 보정 시작 또는 이번 보정 생략을 선택한다. 보정 중에는 숫자 대신 보드 움직임 안내를 보여 주고, 장치의 완료·생략 응답 뒤 수신 확인으로 자동 전환한다. 생략은 보정 완료로 표시하지 않고 기록 시작의 준비 이력에 남긴다. BMP280는 배선 안내를 추가한다. 게이뤼삭은 용기·수조 준비, 무선 수신과 배터리 확인을 더한다.

**M2 재점검 결정:** 원본의 큰 단계/세부 단계 탐색, 시각 자료와 설명의 병렬 배치, 이전/행동 버튼, 준비물 도움말을 보존한다. 배선·USB·수신·용기에 맞는 자료를 보여 주며, 준비 항목의 체크는 측정 진입을 막지 않는다. 현재 장치의 정상 연속 수신이 확인되면 측정 화면으로 이동하고 기록을 시작할 수 있다. 보정·배터리·활동 안내와 확인 이력은 유지하며 수신 성공만으로 완료 처리하지 않는다. 게이뤼삭의 배치 그림과 실험 방법 안내를 복원하고 대시보드의 표시 채널 선택을 측정 화면에 적용한다. 표시 선택은 원자료 수집을 바꾸지 않는다. 당시 채택·제외 이유와 검증 근거는 [M2 인수 기록](history/m2-implementation.md)에 보존한다.

센서별로 사전에 검증한 HEX 파일을 제공하고, 게이뤼삭의 공식 USB 전송 어댑터를 재사용한다. 최초 브라우저 장치 선택·권한 부여는 유지한다. 설치 성공, BLE 연결 성공, 실제 측정값 확인을 구분한다. 프로그램 식별 정보를 확인할 수 없으면 이전 설치 이력이나 숫자 CSV만으로 설치 버전을 확정하지 않는다.

**M6 설치 UX 결정·제품 통합 미구현(2026-10-27):** USB 설치를 기본으로 두고 **Bluetooth로 설치**를 제공한다. 재부팅 뒤에는 “보드가 다시 연결되는 중입니다.”를 표시하며 연결·조회에 즉시 시도 + 2초·4초·8초 재시도를 적용한다. 모두 실패하면 **“micro:bit 뒤쪽의 리셋 버튼을 한 번 누른 뒤 다시 시도해 주세요.”**와 **[다시 시도] / [USB로 설치하기]**를 제공한다. 다시 시도는 보드 상태 확인부터 진행하고 성공한 전송을 반복하지 않는다. 권한 거부·취소·비호환·전송 손상은 별도로 처리한다. 브라우저 미지원은 보드 조작 전에 안내하고 USB도 미지원이면 고정 파일 받기를 제공한다. 상세 상태·문구·재진입은 [설치·연결 설계 §3](sensor-program-installation-roadmap.md#3-설치-화면과-사용자-흐름)을 따른다.

일반 사용자에게 MakeCode 코드나 CSV 열 순서를 맞추게 하지 않는다. 사용자 정의 펌웨어와 임의 센서 조합은 고급·후속 경로로 둔다.

## 6. 측정·저장 계약

장치 연결 후 수신값은 **준비용 미리보기**로 사용한다. 사용자가 **기록 시작**을 누른 뒤부터 측정값을 원자료로 보관한다. 게이뤼삭에서는 기록 시작 후 가열 전 기준 자료를 관찰하고, 별도의 **가열 시작** 사건을 남긴다.

모바일 측정 화면은 연결·기록 상태를 왼쪽, 기록 조작을 오른쪽에 모으고 그 아래에 실시간 숫자와 그래프를 배치한다. 시작 전에는 중복되는 준비 표시와 기록 개수를 생략한다. 그래프 제목 옆의 공통 드롭다운에서 최근 60초·전체 범위를 선택하며, 채널 범례와 표시 단위는 다음 줄에 둔다. 표시 범위·단위 변경은 원자료 수집·보관에 영향을 주지 않는다.

측정 화면은 현재 값·단위, 수신/기록/저장 상태, 시간 그래프, 일시정지·재개·기록 마치기, 조작 메모를 제공한다. 활동은 물 추가·장치 변경 같은 전용 버튼을 추가한다. 수신이 끊겨도 기존 자료를 보존하고 시간 공백을 기록한다. 값이 일정하다는 이유만으로 단절을 판단하지 않는다.

가속도는 앱에서 m/s²로 환산해 기록한다. 측정·기록 화면의 **g로 보기** 토글은 실시간 숫자와 그래프 축의 표시만 바꾸며, 저장·분석·내보내기 단위는 m/s²를 유지한다. 중력을 포함하므로 정지 상태의 크기는 약 9.8m/s²(약 1g)다. 기존 mg 기록은 원래 단위로 열어 분석하고, 새 측정은 새 실험으로 시작해 서로 다른 단위가 섞이지 않게 한다.

**화면 전환과 측정 세션 수명을 분리한다.** 분석으로 이동해도 측정·저장이 계속되고, 새 자료는 명시적인 '새 자료 반영'으로 가져온다. 기록 일시정지는 새 측정값을 저장하지 않으며, 기록 마치기는 기존 자료와 분석을 보존한다. 새로고침 복원은 자동 장치 재연결이나 기록 재시작을 의미하지 않는다.

RunStore를 원자료·사건·분석 작업·미저장 변경의 단일 소유자로 사용한다. 표시용 그래프 버퍼의 상한과 원자료 보존량을 분리하고, 저장 실패·재시도·한 탭 작성 권한·읽기 전용 복원을 계승한다.

저장된 실험 목록에서 이름 변경과 삭제를 제공한다. 삭제는 대상 이름과 삭제 범위를 확인한 뒤 수행하며,
다른 탭의 작성 잠금이나 저장 실패를 우회하지 않는다. 사용자 조작의 메모는 측정 종료 후에도 추가·수정·비울 수 있고,
사건 시각·종류·조건과 원자료는 유지한다. 게이뤼삭의 물 추가·장치 변화는 일시정지 중에도 기록할 수 있다.
측정 그래프의 사건·메모 표찰은 시간축 아래에 표시하고 해당 시점의 세로 점선을 유지한다. 가까운 표찰은 묶어 상세 내용을 열며, 현재 표시 범위에 사건이 없으면 표찰 공간을 두지 않는다.
추가 측정에서는 같은 센서·프로그램·활동 사용을 확인하고 용기·부피, 밀폐, 센서·배선·설정의 변경 없음/변경됨/불확실을
각각 남긴다. 변경 또는 불확실한 조건이 있으면 메모를 필수로 받는다.

원본 앱에서 저장한 전체 실험 JSON도 현재 앱에서 분석하고 이어 측정한다. 실제 장치 출처와 등록된 센서·활동·펌웨어·채널 규약이
맞는 파일만 장치 연결을 허용하며, 열기만으로 연결하거나 기록하지 않는다. 사용자가 연결과 수신 확인을 마친 뒤 기록 재개 또는
추가 측정을 선택한다. CSV·출처 불명 파일·호환되지 않는 구성·임시 분석은 분석용으로 유지한다.

## 7. 공통 분석과 활동별 지원

게이뤼삭의 **원 자료 보기 → 관계 그래프 → 결과 해석**을 모든 센서에 적용한다. 표·필터·구간 선택·제외와 사유·계산 열·축 선택·산점도·시간 그래프·회귀·추세선 연장·근거 보관·해석 글을 재사용한다. 활동은 권장 축·계산 예시·질문을 제공하지만 학생의 결론을 자동 입력하지 않는다.

관계 그래프는 가로축 하나를 유지하고 기본 세로축에 `[+]`로 오른쪽 비교 항목 하나만 추가하며 다시 제거할 수 있다. 같은 물리량·단위의 방향 성분과 크기는 하나의 스케일을 공유하고, 다른 물리량은 좌우 축을 쓴다. 추세선·연장은 각 세로축 아래에서 따로 조작하며 공간이 충분하면 나란히, 좁으면 줄을 바꿔 표시한다. 그래프 모양은 제목 오른쪽 메뉴에, 계산 열 추가는 표에 둔다. 분석 화면과 그래프의 최대 폭을 제한하며 작은 화면에서는 축 조작을 아래로 재배치한다. 넓은 화면은 상하단 조작·통계의 실제 높이를 제외한 공간을 그래프와 표에 배분한다. 상세 설명·선택한 자료 정보·글자 확대에 필요한 공간은 최소 그래프 높이와 함께 보장하고, 부족하면 페이지 스크롤을 허용한다.

분석 중 새 자료가 도착해도 확정 구간, 제외 사유, 계산 열, 보관한 근거와 글을 유지한다. 보관한 근거는 당시 분석 조건의 사본이며 사용자가 명시적으로 교체할 때만 변경한다.

시간 그래프는 첫 수신을 0으로 하는 **경과 시간**으로 표시하며 구간 선택·자료 제외로 기준점을 옮기지 않는다. 축 제목에 실제 시각을 덧붙이지 않고, 눈금 간격에 맞춰 초·분·시간 및 필요한 소수 자릿수를 표시한다. 측정·원자료·관계 그래프·결과 해석·PNG·인쇄는 같은 눈금 규칙을 사용한다. 측정의 최근 범위는 기존의 ‘지금으로부터’ 기준을 유지한다. 상세 수신 시각과 원자료는 정밀도를 유지한다.

축 설정은 처음에 펼쳐 보여 주고 사용자가 접으면 가로축 요약과 채널 색상의 세로축 범례를 남긴다. 펼친 상태에서는 축 이름·선택창·추가/제거 버튼을 같은 줄에 배치하고 관련 옵션을 아래에 둔다. 추세선 연장은 추세선을 켰을 때만 표시한다. 접힘 상태는 같은 분석의 탭 이동 동안 유지하는 화면 상태이며 축·추세선·원자료·저장된 분석 정의를 변경하지 않는다. 접힌 조작은 키보드 탐색에서 제외하고, 전환 효과는 동작 줄이기 설정을 따른다.

분석 개수·전체/지정 구간·제외 개수는 공통 범위 요약에서 안내하며 제외 0개와 제목 옆의 중복 개수는 생략한다. 모바일에서는 요약을 왼쪽 좁은 칸에 세로로 배치하고 구간 수정·실행 취소/다시 실행을 오른쪽 같은 줄에 둔다. 그래프의 유효 자료 수가 범위 요약과 다를 때만 축별 표시 개수와 결측 안내를 표시한다. 새 자료 반영과 표의 필터 결과·행 위치 안내는 유지한다.

분석 CSV는 현재 분석 범위와 제외 결과를 기준으로 출력 행 수를 안내하고 내보낼 계산 열을 선택하게 한다.
원자료·분석 CSV에는 수신 시각과 경과 초를 함께 저장한다. 일부 구간을 다시 열어도 원래 경과 시간을 유지한다. 두 시간 열의 기준이 행마다 다르면 ‘원본 시각 기준으로 복원’과 ‘취소’만 제공한다. 복원하면 수신 시각을 유지하고 파일의 첫 유효 수신을 0초로 경과 시간을 다시 계산한다. 취소하면 현재 실험을 유지하며, 잘못된 수신 시각이나 측정값은 복원으로 우회하지 않는다.
원자료 열은 항상 포함하며 다시 가져올 수 있는 숫자 열 한도 안에서 선택한다. 계산식 전체와 근거·해석은 전체 실험 JSON에 보관한다.

채널별로 **0 / 결측 / 미지원 / 범위 밖 / 측정 오류**를 구분한다. BMP280의 미지원 습도를 0%로 대체하지 않는다. 내장 온도는 보드 온도 기반 근사이며, 밝기·소리 크기의 0–255는 상대값임을 안내한다. 고속 진동 등은 장치 측정 시각·간격의 정확성을 검토한 뒤 지원한다.

## 8. 도구 공유와 후속 교사 자료 공유

### 8.1. 기본 도구 공유 — M3

**2026-10-26 최종 결정:** 기본 공유는 **도구 미리보기에서 보고 있는 실험 소개 페이지의 링크·QR을 제공하는 기능**으로 한정한다. 공유 대상을 따로 선택하지 않으며 홈·준비·측정·분석·저장 목록에는 공유 UI를 추가하지 않는다. 장치 연결·로그인·저장 서버는 필요하지 않다.

| 화면 | 표시와 조작 |
|---|---|
| 데스크톱 미리보기 | 넓은 화면은 소개 오른쪽, 좁은 데스크톱은 소개·시작 버튼 아래에 공유 영역을 왼쪽 정렬. 하단 공유 영역은 왼쪽에 제목·안내와 두 줄 버튼(첫 줄 **링크 복사**, 둘째 줄 **크게 보기 · QR 저장**)을 쌓고, 오른쪽 QR은 왼쪽 내용 전체 높이에 맞춰 배치. QR의 흰 여백은 유지한다. 데스크톱 공유 제목은 본문보다 뚜렷한 크기로 표시. 크게 보기는 확대 QR을 여는 대화상자 |
| 모바일 미리보기 | 실험 제목 옆 **도구 공유** 버튼을 누르면 큰 QR과 **링크 복사 · QR 저장**을 보여 주는 대화상자 |

공유 안내는 **‘실험 소개 화면으로 연결됩니다.’** 한 문장만 사용한다. QR은 표시 시 자동 생성하며 별도의 생성 버튼·설정 단계는 두지 않는다. QR 저장은 PNG 파일로 제공한다. 확대·모바일 대화상자를 닫으면 기존 미리보기와 버튼으로 돌아온다. 링크 복사 성공을 짧게 알리고, 복사가 차단되면 직접 선택할 수 있는 주소를 제공한다. QR 생성·저장 실패 시에도 링크 복사는 유지한다.

센서·활동의 공유 주소는 `sensors/bmp280/?view=preview`, `activities/gay-lussac/?view=preview`처럼 **현재 미리보기의 공식 주소**를 사용한다. 복사·화면 QR·저장 QR은 모두 같은 주소다. 수신자는 같은 소개 화면에서 **처음부터 준비하기 / 준비된 장치 확인**을 선택한다. 기존의 직접 준비 주소는 그대로 지원한다.

공유 조작은 기록·연결·분석을 변경하지 않는다. 주소에 `mock`, 임의 검색 매개변수, 로컬 실험 ID와 파일 내용을 포함하지 않는다. 공유 링크를 연 학생에게 자동 연결·기록 시작·기존 실험 덮어쓰기를 수행하지 않는다. 앱 안에서 다른 실험으로 이동할 때는 §3.3의 저장·종료 규칙을 따른다.

공개 기준 주소는 배포 설정으로 제공한다. 앱을 다른 도메인이나 하위 경로로 옮겨도 이 설정과 등록된 내부 경로로 링크를 생성한다. 개발 서버 주소를 공식 공유 주소로 자동 선택하지 않으며 공개 주소가 설정되지 않으면 공식 링크 생성이 불가능함을 알린다. 같은 설정을 링크 미리보기의 OG URL·이미지 주소에도 사용한다. 공식 주소는 **`https://lab.sco.pe.kr/`**로 확정하며, 연결 완료 전에는 현재 GitHub Pages 주소를 사용한다. 전환 순서는 §8.3을 따른다.

기존 계획의 수업 제목·안내 편집, 표시 설정 전달, 압축 `cfg` 코덱, 교사용 학생 화면 미리보기, 구형 v1 설정 링크 복원은 M3에서 제외한다. 현재 앱의 미지원 `cfg` 오류 안내를 유지하며 잘못된 링크를 임의 기본 실험으로 바꾸지 않는다. 기존 JSON·CSV 파일 호환은 유지한다. 페이지의 OG 이미지·문구는 링크 미리보기이며 수업 자료 공유 기능과 구분한다.

### 8.2. 교사 자료 공유 — Cloudflare 연계 후의 별도 단계

교사가 실험 JSON을 바탕으로 수업 제목·질문·짧은 안내와 분석할 자료를 공유한다. **원측정값·조작 기록·교사 안내를 전달하고 학생은 새로 분석한다.** 센서·활동 참조, 채널·단위·시각·유효성 등 자료 해석에 필요한 정보는 보존한다. 교사의 제외 구간·계산 열·회귀·보관 근거·해석 답안은 전달하지 않는다. 업로드 전 공유 내용과 조작 메모를 확인할 수 있으며 교사 원본은 수정하지 않는다.

흐름은 **JSON 검증 → 공유 자료 확인·안내 작성 → 업로드 → 학생용 링크·QR과 비밀 관리 링크 발급**이다. JSON 본문을 주소에 넣지 않고 서버에 저장된 자료의 식별자만 학생용 링크에 넣는다. 로그인은 요구하지 않는다. 비밀 관리 링크를 가진 사람이 자료를 삭제할 수 있으므로 학생용 링크·QR과 분리해 안내하고 보관하게 한다.

학생은 링크에서 수업 안내와 자료 개요를 확인하고 **내 분석 시작**으로 브라우저에 독립 사본을 만든다. 장치 없이 분석할 수 있고, 교사 원본과 다른 학생의 분석에 영향을 주지 않는다. 같은 링크 재방문 시 기존 사본 이어하기와 새 사본 만들기를 구분하며 진행 중인 분석을 초기화하지 않는다. 로컬 저장이 불가능할 때는 기존 파일 열기의 임시 분석·파일 보관 규칙을 따른다. 링크 열람만으로 사본을 계속 생성하지 않는다.

**보관은 서버의 생성 시점부터 30일이며 이후 자동 삭제한다. 연장 기능은 초기 범위에 넣지 않는다.** 교사는 그 전에 비밀 관리 링크로 즉시 공유를 종료·삭제할 수 있다. 관리 링크를 잃으면 복구·계정 확인을 제공하지 않고 자동 삭제를 기다린다. 학생용 링크만으로 삭제할 수 없다. 만료·삭제 시 새로운 다운로드를 막지만 이미 학생 브라우저에 저장된 사본은 지우지 않는다.

이 단계의 범위는 생성·링크 전달·조회·삭제·자동 만료다. 교사 계정, 수업 목록 서비스, 학생 답안 수집·제출·채점·동기화는 포함하지 않는다. Cloudflare 저장소·API는 공유 기능만 담당하고 기존 로컬 측정·저장·파일 열기는 독립적으로 유지한다. 무료 제공량을 무제한 사용 보장으로 취급하지 않으며, 실제 파일 크기를 바탕으로 업로드·총저장량 제한을 후속 구현 전에 확정한다.

### 8.3. 공식 도메인과 포털 연결

**2026-10-26 사용자 결정:** 포털은 `https://sco.pe.kr/`, 센서 실험실은 **`https://lab.sco.pe.kr/`**로 구분한다. 포털의 기존 소개 주소 `https://sco.pe.kr/tools/sensor/`는 유지하고 실행 버튼을 새 앱 주소에 연결한다. 센서·활동은 앱 아래의 기존 `sensors/<id>/`, `activities/<id>/` 경로를 사용한다. `sco.pe.kr/apps/sensor-lab/`에 앱을 중복 제공하지 않는다.

앱은 포털과 별도의 Cloudflare Workers Static Assets 배포로 운영한다. 먼저 기존 측정·분석 앱과 도구 링크·QR을 새 도메인에서 제공하고, 후속 단계에서 같은 주소의 `/api/shares`에 교사 자료 공유 API를 추가한다. 학생용 자료 링크는 `/share/?id=…`, 교사용 비밀 관리 링크는 `/share/manage/?id=…#token=…`으로 분리한다. 도메인 연결이 곧 서버 자료 공유의 구현 완료를 뜻하지 않는다.

주소가 바뀌면 브라우저에 저장된 실험과 USB/Bluetooth 권한은 자동 이전되지 않는다. 기존 GitHub Pages 앱에서 **전체 실험 JSON 내보내기 → 새 주소에서 파일 열기**로 옮기도록 안내하고, 이전 주소를 즉시 강제 이동시키거나 저장소를 지우지 않는다. 기존 저장 자료의 열기·내보내기 경로를 유지하고 새 주소에서 필요한 장치 권한을 다시 받는다. 새 주소 사용 후의 기록은 그 주소에서 보관·내보낸다.

공식 전환은 새 주소의 HTTPS·직접 진입·자원·파일 복원 확인 후에 수행한다. 그때 공개 링크·QR·OG·홈 화면 바로가기와 포털의 앱 이름·설명·실행 주소를 맞춘다. 포털에 남은 ‘센서 데이터 대시보드’와 ‘설정 링크·QR 공유’ 설명은 실제 센서 실험실 기능에 맞게 수정하되, 미구현 교사 자료 공유를 사용 가능한 기능으로 소개하지 않는다. 구현·배포 책임과 전환 검사는 [기술 설계 §12.4](unified-sensor-lab-architecture.md#124-도메인-연결과-배포-전환)를 따른다.

## 9. 구현 경계

- **App/Navigation:** 앱 홈과 센서·활동 직접 진입, 구성 검증, 화면 전환, 현재 실험 복귀와 앱 이탈 처리. 배포 위치는 외부 설정으로 수신.
- **Sensor Registry:** 채널·단위·유효성, 펌웨어·배선·보정, 수신 해석.
- **Activity Registry:** 준비 단계, 활동 사건, 탐구 질문과 기본 분석.
- **Device Adapters:** USB 전송, BLE 수신, 상태와 오류.
- **RunStore/Repository:** 실험·원자료·사건·분석·복원.
- **Analysis Engine:** 표 투영, 계산, 구간, 회귀, 근거 보관.
- **Tool Share(M3):** 미리보기 중인 도구의 공식 소개 주소를 링크 복사·QR 표시·확대·PNG 저장으로 제공. 측정·분석 상태를 변경하지 않음.
- **Teacher Material Share(후순위):** 실험 JSON 기반 공유 자료 업로드·조회·만료·삭제, 학생의 독립 분석 사본 생성. 기본 도구 공유·로컬 측정은 이 서버에 의존하지 않음.
- **UI:** 공통 준비·측정·분석 화면과 도움말.

센서·활동 정의는 작은 모듈로 시작한다. 데이터로 표현하기 어려운 활동별 동작만 함수로 분리한다. 임의 플러그인 시스템, 코드 생성 서버, 여러 장치 동시 수집, 실시간 학급 관리와 활동 제작 편집기는 첫 버전 범위에서 제외한다.

**진행 순서:** M5를 우선 진행한다. M6은 M5와 독립적이다. M6-1의 파일·환경 안내 기반을 재사용하되 M6-2의 기술 검증은 먼저 진행할 수 있다. 2026-10-27에는 전체 교체 비교와 BMP280 부분 전송 실측을 거쳐 부분 교체를 무선 설치 1안으로 확정했다. 이를 기준으로 센서별 반복·정확도와 중단/USB 복구 → 설치 UI 통합과 기기 교체·브라우저별 검증으로 진행한다. 본딩 후보 성공은 요구하지 않으며, 기존 배포 펌웨어는 검증 전에 교체하지 않는다. M7은 M5의 공식 주소·정적 배포를 바탕으로 구현하되 M6 완료를 필수로 요구하지 않는다. M8은 대상·사용 흐름 확정 후 진행하며 공유 서버에 의존하지 않는다. 교사 자료 공유는 기존 결정대로 후순위다.

**별도 검토 목록:** 본딩을 요구하는 전체 DFU는 M6 제품 범위에서 제외하고 기존 개발 시험·실패 기록만 보존한다. 네이티브 앱 제작은 확정하지 않는다. 공통 런타임 안의 부분 전송은 M6-2에 포함하며 지원 환경은 실물 검증으로 확정한다. 고속 측정을 위한 장치 timestamp·sequence, 사용자 정의 프로그램·임의 센서 조합도 구체 수업 요구와 호환 계약을 정한 뒤 판단한다. 오프라인/PWA·백그라운드 기록, 여러 장치 동시 수집, 실시간 학급 관리·활동 제작 편집기 등 기존 범위 밖 항목을 M5–M8의 필수 구현으로 자동 편입하지 않는다.

**상태 관리:** 각 단계는 자신의 산출물과 관련 검증·운영 반영으로 독립적으로 완료 판정한다. 제안·대상 미정 항목은 먼저 채택·보류·제외 결정을 기록하고, 채택 시 범위와 완료 기준을 확정한다. 단계 안의 미구현 항목을 남긴 채 완료로 표시하지 않으며, 보류 항목은 별도 목록으로 이관 근거를 남긴다. 이미 구현한 도구 링크·QR·아이콘과 M2·M4 인수는 후속 단계에 다시 넣지 않는다. 기존 실기기·브라우저별 미확인 범위는 검증 기록으로 보존하고 새 기능으로 세지 않는다.

## 11. 검증과 전환

검증할 핵심 상황은 첫 센서 선택과 실제 수신, 준비 단계의 차등 표시, 미리보기와 기록의 분리, 측정 중 분석 이동, 원자료 보존, 분석 상태 유지, 저장 실패·복원, 도구 링크 재진입, QR·링크 동등성, 게이뤼삭 CSV·JSON의 안전한 가져오기다. 구형 cfg는 지원되지 않는 링크임을 명시하고 임의 기본 실험으로 바꾸지 않는다. 후속 교사 자료 공유의 만료·삭제·학생별 사본 검사는 그 기능을 구현할 때 추가한다.

탐색과 관련해서는 앱 홈과 센서·활동 직접 경로의 새 탭 접속·새로고침·뒤로 가기, 내부 경로에서 필요한 스크립트·그림·HEX 로딩, 잘못된 경로·cfg의 복구, 기록 중 홈 이동의 저장·연결 종료, 미리보기의 장치 권한 차단, 다른 구성의 독립 준비, 미저장 분석이 있는 상태의 앱 이탈을 확인한다. 앱의 공개 기준 주소가 달라져도 내부 경로와 공유 링크 생성이 정상 동작하는지 시험한다. 검증은 변경된 범위에 집중한다.

현재 기본 배포는 GitHub Pages의 새 센서 실험실이며 이전 대시보드는 운영을 종료했다. `lab.sco.pe.kr`은 연결할 공식 주소로 확정했으며 DNS·호스팅은 아직 변경하지 않았다. 센서·활동 직접 주소와 M3의 미리보기 링크 복사·QR 표시·확대·PNG 저장을 구현했다. M3는 §8.1의 반응형 배치를 확정했다. 기능 구현 시 관련 자동 검사와 데스크톱·모바일 화면을 확인했고, 최종 배치 수정 후에는 좁은 데스크톱 네 가지 너비에서 정렬과 가로 넘침을 확인했다. 소스 검토에서 중복·폐기 배치 규칙이 남지 않음을 확인했다. 도구 공유와 아이콘 보정은 이번 릴리스에 포함하며 실제 휴대폰 카메라 판독은 미확인이다. 검사 범위와 남은 작업은 [진행 현황](UNIFIED-PLAN-INDEX.md)에 정리한다. 교사 자료 공유는 후순위 미구현 상태다. 관련 사용 문서에 현재 소스와 배포 상태를 구분하고 실물 검증과 모의 검사 결과를 구분한다.
