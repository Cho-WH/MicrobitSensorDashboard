# 통합 센서 실험 앱 기획

> 상태: 통합 목표 기획 · 2026-10-19 · [M2 구현·검증 현황](m2-implementation.md)
> 대상: Cho-WH/MicrobitSensorDashboard
> 확정 방향: 이 저장소의 단일 앱 안에서 센서·활동 선택 · 수업 직접 진입 · 공통 측정·분석

## 1. 목표

센서를 선택하면 맞춤 펌웨어·배선·측정 항목·그래프가 준비되고, 실험 활동을 선택하면 탐구 절차·기록 버튼·분석 제안이 추가되는 하나의 앱을 만든다. **공통 구조는 게이뤼삭 앱의 준비→USB 프로그램 전송→BLE 수신 확인→측정·자동 저장→학생 주도 분석→근거·해석 기록을 기준으로 한다.** 기존 대시보드의 설정 링크와 QR 수업 공유를 통합한다.

기본 원칙은 센서가 측정 가능 범위를 결정하고, 활동이 탐구 맥락을 결정하며, 수업 공유가 시작 환경을 전달하는 것이다. 분석 구간·축·계산·자료 제외·해석의 판단은 학생에게 남긴다.

**범위:** 이 저장소에 센서 측정·특화 실험 활동을 모두 담는 **단일 센서 실험 앱**을 구축한다. 센서마다 또는 게이뤼삭 같은 활동마다 별도 앱·저장소를 만들지 않는다. 이 문서는 앱 내부의 탐색, 준비·측정·분석, 데이터·상태, 수업 공유, 모듈 경계와 구현 단계를 정의한다. 상위 사이트·다른 종류의 교육 도구·배포 도메인·도구 간 경로 구성은 여기서 설계하지 않는다.

## 3. 시작 화면과 진입 경로

### 3.1. 앱 홈

이 앱의 첫 화면은 **센서로 측정하기**와 **실험 활동 시작하기**를 동등한 선택지로 제공한다. 센서를 먼저 고르지 않아도 활동을 바로 선택할 수 있고, 센서를 선택한 뒤에는 그 센서를 사용하는 추천 활동으로 이어질 수 있다. 처음 사용자에게는 센서 카드와 활동 카드의 목적을 간결하게 안내한다.

이 앱에 저장된 실험 이어하기와 실험 파일 열기도 같은 첫 화면에서 제공한다. 앱의 홈은 센서·활동 탐색만 담당하며, 준비·측정·분석 기능을 별도 앱으로 분산시키지 않는다.

### 3.2. 선택 이후의 경험

**센서로 측정하기:** 센서 카드에서 BMP280 또는 내장 자기장 등을 선택한다. 펌웨어·배선·측정값·단위·기본 그래프를 자동 준비하고 자유 측정으로 이어진다. 활동 선택은 필수가 아니다.

**실험 활동 시작하기:** 게이뤼삭 실험 등을 선택하면 호환 센서와 준비물, 용기·수조 안내, 활동 전용 조작 기록과 분석 제안을 함께 연다. BMP280 자유 측정과 게이뤼삭 활동은 동일한 펌웨어와 분석 엔진을 사용할 수 있다.

**수업 링크로 시작하기:** 교사가 공유한 링크·QR은 센서/활동 목록을 건너뛰고 해당 수업의 준비 화면을 연다. 학생은 자신의 장치로 별도 실험을 만든다. 같은 링크 재방문 시 이어하기와 새 실험 시작을 구분하고 기존 기록을 자동 초기화하지 않는다.

선택 후에는 상단에 **BMP280 · 온도와 기압 측정** 또는 **기체의 온도와 압력**처럼 현재 센서·활동 이름과 준비·측정·분석 흐름을 표시한다. 모든 경로는 같은 UI와 엔진을 사용하되, 해당 탐구에 필요한 항목만 보여 준다. 전체 센서·활동 목록은 홈으로 돌아갈 때 열고, 센서 준비 화면에는 그 센서로 할 수 있는 활동을 선택적으로 안내한다.

### 3.3. 탐색·전환과 실험 보존

- 카드·주소·학생 미리보기를 여는 것만으로 측정 Run을 만들지 않는다. 준비 설정은 시작 구성으로 유지하고, 새 측정 Run은 최초 **기록 시작** 때 생성한다. 이어하기는 기존 Run을 열고, 파일 가져오기는 파일의 실험을 복원한다.
- 같은 실험실의 준비·측정·분석 화면을 오갈 때는 구성·기록을 유지한다. **실험 선택** 또는 **새 실험 준비**로 나가는 동작은 현재 실험실 종료다. 분석 초안과 기록을 마감·저장한 다음 장치 연결을 종료하고 현재 실험을 닫는다. 저장 실패 시 현재 화면·실험·연결을 유지하며 재시도할 수 있다. 임시 분석처럼 브라우저에 저장할 수 없는 자료는 파일 보관 또는 현재 화면에 머무르기를 선택한다.
- 선택 화면에는 활성 실험이 없다. 카드를 열면 미리보기부터 선택한 실험의 이름을 상단에 표시한다. 미리보기는 안내만 제공하며 장치 연결·기록 권한은 **처음부터 준비하기** 또는 **준비된 장치 확인**을 누른 뒤 열린다. 같은 센서의 다른 활동도 종료한 실험의 연결·준비 확인을 자동 상속하지 않는다. 이전 기록은 저장된 실험에서 명시적으로 열어 이어간다.
- 미리보기 주소는 센서·활동 경로에 `?view=preview`를 붙여 구분한다. 새로고침·뒤로 가기·앞으로 가기에서도 미리보기 소속을 유지한다. 이력 이동으로 현재 실험실을 벗어날 때도 동일한 저장·연결 종료 규칙을 적용하며 실패하면 현재 실험의 주소로 복구한다. 기존 센서·활동 직접 준비 주소는 유지한다.
- 브라우저의 다른 사이트로 이동하거나 현재 앱을 닫는 것은 센서 앱을 떠나는 동작이다. 기록 중이거나 분석 글 등 미저장 변경이 있으면 기록을 마치고 저장한 뒤 이동하거나 현재 실험에 머물 수 있게 한다. 주 버튼은 상태에 맞게 **기록을 마치고 이동** 또는 **저장하고 이동**으로 표시한다. 저장 실패는 재시도·파일 보관으로 해결하고, 앱을 떠나도 기록이 계속된다고 안내하지 않는다.

## 4. 설정의 세 층

| 구분 | 포함 정보 |
|---|---|
| 센서 정의 | ID·버전, 지원 micro:bit와 모듈, 배선, 펌웨어 파일·해시, 통신 프로토콜, 측정 채널·단위·유효성, 보정, 기본 표시 |
| 활동 정의 | ID·버전, 호환 센서, 준비물, 진행 단계, 전용 사건·버튼, 기본 분석 제안, 탐구 질문 |
| 수업 구성 | 수업 제목·안내, 센서·활동 참조, 허용된 초기 표시·분석 설정, 시작 화면 |

적용 순서는 **센서의 지원 범위 → 활동의 필수 조건과 기본값 → 수업 초기 설정 → 학생의 분석 선택**이다. 수업 설정은 실제 펌웨어가 지원하지 않는 채널이나 측정 명령을 만들 수 없다.

실험에는 적용된 센서·프로그램·활동·수업 구성의 버전과 사본을 보관한다. 기록이 있는 실험의 센서·활동은 유지하며, 다른 구성으로 시작하는 동작은 §3.3을 따른다. 기존 실험 이어하기는 당시 보관한 구성을 사용한다.

## 5. 장치 준비 UX

내장 센서의 준비물은 micro:bit V2 앞·뒷면, USB 연결, AAA 전지 2개 케이스를 정지 그림으로 보여 준다.
USB 설치 안내와 펼쳐 보는 배터리 전원 안내도 같은 그림을 사용한다. 준비 화면에서 3D 조작은 요구하지 않는다.
BMP280도 준비물·프로그램 단계에서 같은 카드와 본체·USB 그림을 쓰며, 센서·확장 보드·연결선은 기존 모델의 정지 그림으로 보완한다. 배선 단계의 3D 조작은 유지한다.

게이뤼삭의 단계별 안내를 재사용하되 센서·활동에 필요하지 않은 단계는 생략한다. 내장 자기장은 외장 배선 단계 없이 펌웨어·보정·수신 확인으로 진행한다. 연결 후 앱에서 보정 시작 또는 이번 보정 생략을 선택한다. 보정 중에는 숫자 대신 보드 움직임 안내를 보여 주고, 장치의 완료·생략 응답 뒤 수신 확인으로 자동 전환한다. 생략은 보정 완료로 표시하지 않고 기록 시작의 준비 이력에 남긴다. BMP280는 배선 안내를 추가한다. 게이뤼삭은 용기·수조 준비, 무선 수신과 배터리 확인을 더한다.

**M2 재점검 결정:** 원본의 큰 단계/세부 단계 탐색, 시각 자료와 설명의 병렬 배치, 이전/행동 버튼, 준비물 도움말을 보존한다. 배선·USB·수신·용기에 맞는 자료를 보여 주며, 준비 항목의 체크는 측정 진입을 막지 않는다. 현재 장치의 정상 연속 수신이 확인되면 측정 화면으로 이동하고 기록을 시작할 수 있다. 보정·배터리·활동 안내와 확인 이력은 유지하며 수신 성공만으로 완료 처리하지 않는다. 게이뤼삭의 배치 그림과 실험 방법 안내를 복원하고 대시보드의 표시 채널 선택을 측정 화면에 적용한다. 표시 선택은 원자료 수집을 바꾸지 않는다. 경로별 구성, 재사용 범위와 인수 기준은 [M2 UX·재사용 재점검](m2-ux-review.md)에 따른다.

센서별로 사전에 검증한 HEX 파일을 제공하고, 게이뤼삭의 공식 USB 전송 어댑터를 재사용한다. 최초 브라우저 장치 선택·권한 부여는 유지한다. 설치 성공, BLE 연결 성공, 실제 측정값 확인을 구분한다. 프로그램 식별 정보를 확인할 수 없으면 이전 설치 이력이나 숫자 CSV만으로 설치 버전을 확정하지 않는다.

일반 사용자에게 MakeCode 코드나 CSV 열 순서를 맞추게 하지 않는다. 사용자 정의 펌웨어와 임의 센서 조합은 고급·후속 경로로 둔다.

## 6. 측정·저장 계약

장치 연결 후 수신값은 **준비용 미리보기**로 사용한다. 사용자가 **기록 시작**을 누른 뒤부터 측정값을 원자료로 보관한다. 게이뤼삭에서는 기록 시작 후 가열 전 기준 자료를 관찰하고, 별도의 **가열 시작** 사건을 남긴다.

측정 화면은 현재 값·단위, 수신/기록/저장 상태, 시간 그래프, 일시정지·재개·기록 마치기, 조작 메모를 제공한다. 활동은 물 추가·장치 변경 같은 전용 버튼을 추가한다. 수신이 끊겨도 기존 자료를 보존하고 시간 공백을 기록한다. 값이 일정하다는 이유만으로 단절을 판단하지 않는다.

**화면 전환과 측정 세션 수명을 분리한다.** 분석으로 이동해도 측정·저장이 계속되고, 새 자료는 명시적인 '새 자료 반영'으로 가져온다. 기록 일시정지는 새 측정값을 저장하지 않으며, 기록 마치기는 기존 자료와 분석을 보존한다. 새로고침 복원은 자동 장치 재연결이나 기록 재시작을 의미하지 않는다.

RunStore를 원자료·사건·분석 작업·미저장 변경의 단일 소유자로 사용한다. 표시용 그래프 버퍼의 상한과 원자료 보존량을 분리하고, 저장 실패·재시도·한 탭 작성 권한·읽기 전용 복원을 계승한다.

저장된 실험 목록에서 이름 변경과 삭제를 제공한다. 삭제는 대상 이름과 삭제 범위를 확인한 뒤 수행하며,
다른 탭의 작성 잠금이나 저장 실패를 우회하지 않는다. 사용자 조작의 메모는 측정 종료 후에도 추가·수정·비울 수 있고,
사건 시각·종류·조건과 원자료는 유지한다. 게이뤼삭의 물 추가·장치 변화는 일시정지 중에도 기록할 수 있다.
추가 측정에서는 같은 센서·프로그램·활동 사용을 확인하고 용기·부피, 밀폐, 센서·배선·설정의 변경 없음/변경됨/불확실을
각각 남긴다. 변경 또는 불확실한 조건이 있으면 메모를 필수로 받는다.

원본 앱에서 저장한 전체 실험 JSON도 현재 앱에서 분석하고 이어 측정한다. 실제 장치 출처와 등록된 센서·활동·펌웨어·채널 규약이
맞는 파일만 장치 연결을 허용하며, 열기만으로 연결하거나 기록하지 않는다. 사용자가 연결과 수신 확인을 마친 뒤 기록 재개 또는
추가 측정을 선택한다. CSV·출처 불명 파일·호환되지 않는 구성·임시 분석은 분석용으로 유지한다.

## 7. 공통 분석과 활동별 지원

게이뤼삭의 **원 자료 보기 → 관계 그래프 → 결과 해석**을 모든 센서에 적용한다. 표·필터·구간 선택·제외와 사유·계산 열·축 선택·산점도·시간 그래프·회귀·추세선 연장·근거 보관·해석 글을 재사용한다. 활동은 권장 축·계산 예시·질문을 제공하지만 학생의 결론을 자동 입력하지 않는다.

관계 그래프는 가로축 하나를 유지하고 기본 세로축에 `[+]`로 오른쪽 비교 항목 하나만 추가하며 다시 제거할 수 있다. 같은 물리량·단위의 방향 성분과 크기는 하나의 스케일을 공유하고, 다른 물리량은 좌우 축을 쓴다. 추세선·연장은 각 세로축 아래에서 따로 조작하며 공간이 충분하면 나란히, 좁으면 줄을 바꿔 표시한다. 그래프 모양은 제목 오른쪽 메뉴에, 계산 열 추가는 표에 둔다. 분석 화면과 그래프의 최대 폭을 제한하며 작은 화면에서는 축 조작을 아래로 재배치한다. 넓은 화면은 상하단 조작·통계의 실제 높이를 제외한 공간을 그래프와 표에 배분한다. 상세 설명·선택한 자료 정보·글자 확대에 필요한 공간은 최소 그래프 높이와 함께 보장하고, 부족하면 페이지 스크롤을 허용한다.

분석 중 새 자료가 도착해도 확정 구간, 제외 사유, 계산 열, 보관한 근거와 글을 유지한다. 보관한 근거는 당시 분석 조건의 사본이며 사용자가 명시적으로 교체할 때만 변경한다.

분석 CSV는 현재 분석 범위와 제외 결과를 기준으로 출력 행 수를 안내하고 내보낼 계산 열을 선택하게 한다.
원자료 열은 항상 포함하며 다시 가져올 수 있는 숫자 열 한도 안에서 선택한다. 계산식 전체와 근거·해석은 전체 실험 JSON에 보관한다.

채널별로 **0 / 결측 / 미지원 / 범위 밖 / 측정 오류**를 구분한다. BMP280의 미지원 습도를 0%로 대체하지 않는다. 내장 온도는 보드 온도 기반 근사이며, 밝기·소리 크기의 0–255는 상대값임을 안내한다. 고속 진동 등은 장치 측정 시각·간격의 정확성을 검토한 뒤 지원한다.

## 8. 수업 공유 UX

교사는 센서 자유 측정 또는 활동을 선택한 뒤 **수업 공유**에서 제목·짧은 안내·허용된 초기 표시·기본 그래프를 정하고 학생 화면을 미리 본다. 실제 장치 연결 없이 링크 복사·QR 표시가 가능하다. 공유 편집은 교사의 열린 측정 세션이나 분석을 초기화하지 않는다.

새 공유 링크는 **앱 내부의 센서·활동 직접 진입 경로 + `?cfg=...`**로 만든다. 앱을 배포한 기준 위치를 시작점으로 `sensors/bmp280/`, `activities/gay-lussac/`처럼 탐구 대상을 표시한다. 경로는 탐구 대상을 정하고, cfg에는 공유 형식 버전, 센서 ID·정의 버전, 활동 ID·버전 또는 자유 측정, 수업 안내와 초기 설정을 담는다. **학생의 측정값·분석·메모·연결 권한은 담지 않는다.** 학생은 해당 준비 화면에서 자기 장치의 실제 수신을 확인하고 기록 시작으로 자기 실험을 만든다.

경로에 명시된 대상과 cfg의 ID·자유 측정/활동 구분이 일치하는지 먼저 검사하고, 활동과 센서의 호환성을 검증한 뒤 §4의 설정 순서를 적용한다. 서로 다른 대상을 덮어쓰거나 잘못된 cfg를 기본 설정으로 조용히 대체하지 않는다. 예를 들어 BMP280 자유 측정 경로에 자기장 또는 게이뤼삭 활동 cfg가 붙으면 링크 오류와 다시 열기 안내를 제공한다. 대상 경로가 없는 기존 cfg 링크는 별도 호환 경로에서 해석한다.

**호스팅 위치는 앱 외부에서 제공받는 설정이다.** 링크 생성 기능은 설정된 앱의 공개 기준 주소와 내부 경로를 결합하며, 특정 도메인이나 상위 경로를 코드에 고정하지 않는다. 교사의 현재 분석 화면 주소·로컬 실험 ID·개발 서버 주소를 그대로 복사하지 않는다. 미리보기와 개발 중 생성한 링크는 공식 수업 링크와 구분하고, 정의 버전이 지정된 공유 링크는 해당 버전을 유지한다.

기존 압축 cfg와 QR 생성 코드를 재사용하되 새 공유 형식은 버전으로 구분한다. 과거 v1 링크는 기존 임의 필드·시작 명령을 해석하는 호환 경로로 열며, 검증된 센서나 펌웨어로 자동 둔갑시키지 않는다. 알 수 없는 센서·활동·버전은 명확한 오류와 복구 안내를 제공한다. 이미 배포한 링크의 시작 조건이 앱 업데이트로 조용히 바뀌지 않도록 정의 버전을 관리한다.

## 9. 구현 경계

- **App/Navigation:** 앱 홈과 센서·활동 직접 진입, 구성 검증, 화면 전환, 현재 실험 복귀와 앱 이탈 처리. 배포 위치는 외부 설정으로 수신.
- **Sensor Registry:** 채널·단위·유효성, 펌웨어·배선·보정, 수신 해석.
- **Activity Registry:** 준비 단계, 활동 사건, 탐구 질문과 기본 분석.
- **Device Adapters:** USB 전송, BLE 수신, 상태와 오류.
- **RunStore/Repository:** 실험·원자료·사건·분석·복원.
- **Analysis Engine:** 표 투영, 계산, 구간, 회귀, 근거 보관.
- **Class Share:** 앱 내부 경로와 cfg의 일치 검증, 기준 주소 설정을 이용한 링크 인코딩/디코딩, QR.
- **UI:** 공통 준비·측정·분석 화면과 도움말.

센서·활동 정의는 작은 모듈로 시작한다. 데이터로 표현하기 어려운 활동별 동작만 함수로 분리한다. 임의 플러그인 시스템, 코드 생성 서버, 여러 장치 동시 수집, 실시간 학급 관리와 활동 제작 편집기는 첫 버전 범위에서 제외한다.

## 10. 구현 단계

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| M1 | 게이뤼삭 공통 기능 이식, 가변 센서 채널, 센서·활동 정의, 저장·분석 연결 | BMP280 자유 측정과 게이뤼삭 활동이 같은 공통 엔진 사용 |
| M2 | 센서·활동 선택 홈, 앱 내부 직접 진입, 준비 단계 조립, 내장 자기장, 펌웨어 선택 | BMP280와 자기장 모두 코드·열 설정 없이 측정·분석, 직접 진입과 새로고침 가능. [재점검의 UX·실물 인수 기준](m2-ux-review.md) 충족 |
| M3 | 교사 수업 구성·학생 미리보기·공유 링크/QR·재진입·v1 호환 | 장치 없이 공유 가능, 경로·cfg 일치, 학생별 독립 실험 |
| M4 | 실물 장치, 복원, 기존 실험 파일·공유 링크 호환, 앱 이탈, 학생·교사 사용성 검증 | 세 대표 경로가 앱 안에서 완결되고 기존 기록·공유 설정을 안전하게 가져올 수 있음 |

첫 통합판의 대표 경로는 **BMP280 자유 측정 / 게이뤼삭 활동 / 내장 자기장 자유 측정**이다. 세 경로 모두 앱 주소로 바로 진입할 수 있어야 한다. M2 확장으로 **내장 온도·밝기(조도)·가속도 자유 측정**도 같은 준비·기록·저장·분석 흐름에 추가했다. 밝기는 0–255 상대값이며 가속도는 중력을 포함한 X·Y·Z·크기를 기록한다. 실물 설치·수신 인수는 남아 있다. 이후 주요 외장 센서, 조건별 값 기록과 새로운 특화 활동을 추가한다.

## 11. 검증과 전환

검증할 핵심 상황은 첫 센서 선택과 실제 수신, 준비 단계의 차등 표시, 미리보기와 기록의 분리, 측정 중 분석 이동, 원자료 보존, 분석 상태 유지, 저장 실패·복원, 수업 링크 재진입, QR·링크 동등성, 기존 v1 공유 링크 및 게이뤼삭 CSV·JSON의 안전한 가져오기다.

탐색과 관련해서는 앱 홈과 센서·활동 직접 경로의 새 탭 접속·새로고침·뒤로 가기, 내부 경로에서 필요한 스크립트·그림·HEX 로딩, 잘못된 경로·cfg의 복구, 기록 중 홈 이동의 저장·연결 종료, 미리보기의 장치 권한 차단, 다른 구성의 독립 준비, 미저장 분석이 있는 상태의 앱 이탈을 확인한다. 앱의 공개 기준 주소가 달라져도 내부 경로와 공유 링크 생성이 정상 동작하는지 시험한다. 검증은 변경된 범위에 집중한다.

기존 게이뤼삭 앱과 대시보드의 현재 배포 동작을 유지하면서 작업 브랜치에서 통합한다. 이 문서는 구현 전 기획이며 현재 README의 사용 안내는 기존 앱을 설명한다. 단계별 구현이 끝날 때 해당 프로토콜·구조·사용 문서를 갱신하고 실물 검증 결과와 모의 검사를 구분한다.
