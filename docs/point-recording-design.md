## 1. 목적과 문서의 역할

센서를 원하는 조건에 놓고 사용자가 고른 순간의 값에 거리 같은 조건을 대응시켜 기록한다. 연속 측정에서도 같은 기능을 사용하여 전체 과정과 조건별 비교 자료를 함께 남긴다. 한 점의 결과에서 당시 연속 기록으로 돌아가 선택 근거를 살펴볼 수 있어야 한다.

대표 시나리오는 거리별 자기장 탐구다. 센서를 이동하며 연속 기록을 유지하고, 각 거리에서 **한 점 기록**을 누른다. 거리–자기장 관계를 분석하다 이상한 점을 발견하면 해당 시점 앞뒤의 시간 흐름을 확인한다. 과정 기록이 필요 없는 실험은 **한 점씩 측정** 화면만 사용한다.

[통합 기획](unified-sensor-lab-plan.md)은 전체 범위와 단계, [기술 설계](unified-sensor-lab-architecture.md)는 공통 상태 소유권과 저장 경계, [시각 디자인 문법](design/visual-language.md)은 화면·조작의 공통 기준을 소유한다. 이 문서는 M8-2의 상세 UX와 그에 필요한 계약 확장을 소유한다. 공통 문서의 현재 동작을 이미 변경한 것으로 해석하지 않는다.

### 1.1. 핵심 결정

| 구분 | 결정 |
|---|---|
| 측정 화면 | **연속 측정 / 한 점씩 측정**은 그래프 중심 / 한 점 기록 중심 배치. 기록 중에도 이동 가능 |
| 저장 정책 | 탭 옆 **연속 기록** 토글. ON은 연속 원자료와 점 기록, OFF는 캡처한 점의 원자료만 저장. Run 생성부터 추가 측정까지 고정 |
| 한 점 기록 | 두 측정 화면이 같은 캡처·조건 입력·표 편집 기능을 사용 |
| 실시간 표시 | 두 화면이 같은 현재값·최근 60초 메모리 자료를 사용. 일시정지 중 숫자·계기·그래프 시간축도 정지 |
| 연속 화면 | 기존 시간 그래프와 기록 수명을 유지하고 한 점 기록을 보조 기능으로 제공 |
| 분석 자료 | 분석 화면 안에서 **연속 기록 / 한 점 기록**을 선택. 같은 분석 도구 사용 |
| 자료의 관계 | 한 실험 안에 불변 센서 원자료와 이를 참조하는 점 기록을 함께 보관 |
| 분석 상태 | 축·범위·제외·계산·근거·해석을 자료별로 유지 |
| 조건 편집 | 사용자가 입력한 숫자·메모만 수정. 센서값·수신 시각은 읽기 전용 |
| 첫 범위 | 숫자 조건 열 최대 1개, 순간값 1점 캡처, 원자료 시점 추적, JSON/CSV 연동 |
| 후속 범위 | 구간 평균·표준편차, 조건 자동 증가, 복수 조건 열, 보드 버튼·자동 트리거 |

### 1.2. 교육적 의미와 적용 경계

조건별 비교와 선택 시점의 맥락을 함께 확인하는 실험에 적합하다. 시간 변화만 필요하면 연속 기록, 몇 점의 대응값만 필요하면 수동 전용이 간단하다. 사건의 시각만 남기려면 기존 사건·메모를 사용한다.

한 번 누른 값은 평균값이나 안정값이 아니다. UI에 자동 안정 판정·정확도 점수를 만들지 않는다. 같은 조건에서 새 수신값을 반복 기록할 수 있고, 제외한 기록과 이유를 확인할 수 있어야 한다. 짧은 충돌·고속 진동의 순간을 사람이 정확히 누를 수 있다고 안내하지 않는다.

## 3. 정보 구조와 화면 이동

| 위치 | 표시·조작 | 변경하는 것 |
|---|---|---|
| 공통 상단 | 실험 이름, 현재 기록 방식·자료 개수 요약 | 맥락 표시 |
| 기존 주요 탐색 | 측정·기록 / 자료 분석 | 작업 화면 |
| 측정 화면 최상단 | 연속 측정 / 한 점씩 측정 | 화면 배치. 시작 전 탭 이동은 연속 기록의 기본값도 선택 |
| 측정 탭 옆 | 연속 기록 ON/OFF + 물음표 도움말 | 연속 원자료를 저장할지 결정. 첫 기록 후에는 변경 불가 |
| 분석 제목·맥락 영역 | 분석할 자료: 연속 기록 / 한 점 기록 | 분석 입력과 해당 작업 상태 |
| 기존 분석 작업 탭 | 원 자료 보기 / 관계 그래프 / 결과 해석 | 선택 자료로 할 작업 |
| 기존 관계 그래프 보기 | 표 / 표 & 그래프 / 그래프 | 배치 |

현재 측정 제목은 CSS에서 시각적으로 숨겨져 있으므로, 측정 방식 행은 **측정 section의 최상단, 기존 장치·기록·현재값 overview 앞**에 독립 배치한다. 제목의 가시성을 전제로 삽입하지 않는다.

분석 자료 선택은 두 자료가 존재할 때만 소형 밑줄 선택기로 표시한다. 좁은 화면에서는 이름이 보이는 공통 선택 메뉴로 바꿀 수 있다. 한 종류만 있으면 정적 자료 이름을 보여 준다. 모든 점을 취소하거나 분석에서 제외해 유효 점이 0개가 되어도 이미 존재하는 자료 선택지는 사라지지 않는다.

공통 상단은 현재 보고 있는 실험·자료의 정보를 표시한다. 다른 저장 자료를 분석할 때 활성 장치의 측정 방식을 그 자료의 방식처럼 표시하지 않는다.

### 3.1. 화면 선택·저장 정책·실험 수명

화면 배치와 저장 정책을 분리한다. UI의 탭 이름은 **연속 측정 / 한 점씩 측정**을 유지하지만 기록 중 탭 이동은 표시만 바꾼다. **연속 기록** ON은 연속 원자료 저장, OFF는 **연속 기록 하지 않기**를 뜻하며 장치 수신 자체를 끄는 기능이 아니다.

| 시점·조작 | 연속 기록 | 결과 |
|---|---|---|
| 새 실험에서 연속 측정 탭 선택 | 자동 ON | 그래프 중심 화면, 연속 저장을 기본으로 준비 |
| 새 실험에서 한 점씩 측정 탭 선택 | 자동 OFF | 한 점 중심 화면, 점만 저장하도록 준비 |
| 시작 전 토글 수동 변경 | 선택한 값 | 현재 화면 유지. 탭과 반대 설정도 허용 |
| 시작 전 다른 탭으로 이동 | 이동한 탭의 기본값 | 이전 수동 선택보다 탭 기본값 우선. 선택된 탭을 다시 누르는 것만으로 초기화하지 않음 |
| Run 생성·첫 캡처 처리 중 | 요청 시점 값 임시 고정 | 탭·설정 변경으로 비동기 시작 요청의 의미를 바꾸지 않음 |
| Run 생성 성공 이후 | 저장된 값으로 비활성화 | 탭은 자유롭게 이동. 기록·일시정지·종료·추가 측정에도 정책 유지 |
| Run 생성 실패, 생성된 자료 없음 | 설정 다시 변경 가능 | 실패한 요청 때문에 영구 고정하지 않음 |

**시작 규칙은 2026-10-29 사용자 확인 완료:** ON은 **기록 시작**을 누른 뒤 한 점을 기록한다. OFF는 첫 유효 **한 점 기록**이 Run과 첫 Sample·PointRecord를 함께 만든다. 이 규칙은 어느 탭에서든 동일하다. ON인 한 점 화면에도 시작 버튼을, OFF인 연속 화면에도 즉시 캡처 가능한 한 점 버튼을 제공한다. 탭 선택·토글·수신만으로 Run을 만들지 않는다.

- 기록 중 두 화면의 한 점 버튼은 같은 명령·후보·조건 초안·중복 방지 상태를 사용한다. 화면 이동으로 후보나 점 번호를 초기화하지 않는다.
- 탭 이동으로 Session을 종료하거나 Run을 새로 만들지 않는다. 변인·메모 초안·표 선택·그래프 채널·표시 범위를 보존하고 기존 입력 확정 규칙을 적용한다.
- 조작부의 **새 실험**은 기존 기록을 안전하게 마감·저장한 뒤 같은 구성의 별도 실험을 준비한다. 현재 측정 탭·연속 기록 ON/OFF·유효한 연결·준비 상태를 유지하며 설정을 자동 반전하지 않는다. 새 실험에서는 연속 기록 설정을 다시 선택할 수 있다. 새 Run의 후보·이번 조건 초안·미리보기는 초기화하고, 명시적 기록 조작 때 Run을 만든다. 저장 실패 시 기존 Run·연결을 유지한다.
- 측정·분석 이동과 무관하게 활성 기록은 계속된다. 추가 측정은 같은 Run의 ON/OFF를 그대로 사용하며 화면 기본값을 다시 적용하지 않는다.
- 새로고침·파일 열기에서는 저장 정책을 복원한다. 같은 탭 복원은 선택했던 측정 화면도 UI 참조로 복원하며, 선택 정보가 없는 자료를 처음 열 때만 정책에 맞는 기본 화면을 사용한다. 자동 연결·자동 기록·이전 수신값 캡처는 하지 않는다.

### 3.2. 토글·도움말과 공통 조작부

- **2026-10-29 UX 검토 반영:** 토글 이름은 **연속 기록**으로 확정한다. 시작 전 다른 탭으로 이동할 때마다 수동 설정보다 탭 기본값을 우선하는 §3.1 규칙은 사용자 요청대로 유지한다. 설정 자동 전환은 토글 상태에 즉시 반영하되 별도 알림·확인 팝업을 만들지 않는다.
- 측정 탭 옆에 레이블 **연속 기록**, ON/OFF 토글, 물음표 버튼을 한 그룹으로 배치한다. 넓은 화면은 같은 줄, 좁은 화면·글자 확대 시 그룹 전체를 다음 줄로 이동할 수 있다. 안내 문장으로 상단을 채우지 않는다.
- 내장 센서의 **센서 위치** 버튼은 측정 탭 줄 오른쪽에 둔다. 안내 정의가 위치를 지정하며 활동의 실험 방법 버튼은 기존 자리를 유지한다. 연속 기록 설정·물음표는 탭보다 작은 글자·스위치와 좁은 간격의 보조 그룹으로 표현하고, 모바일에서도 공간이 허용하면 탭·설정·센서 위치를 같은 줄에 두며, 실제 공간이 부족할 때만 줄바꿈한다. 도움말의 터치 영역은 유지한다.
- 도움말 초안: **켜면 시간에 따른 값을 계속 저장합니다. 꺼도 현재값과 최근 60초 그래프를 볼 수 있으며, 한 점 기록을 누른 값만 저장합니다. 기록을 시작한 뒤에는 추가 측정에서도 이 설정이 유지됩니다.**
- 기존 토글·도움말 부품을 우선 재사용한다. 토글은 접근 가능한 이름·ON/OFF 상태·실제 비활성 상태를 제공한다. 물음표는 마우스·키보드 초점·터치로 열 수 있고 Escape·바깥 클릭으로 닫으며, 토글이 고정되어도 사용할 수 있다. title 속성만으로 모바일 도움말을 대신하지 않는다.
- 기록 중 탭에는 자물쇠를 붙이지 않는다. 기존 ‘첫 기록 후에는 이 실험…’ 상시 문구는 제거하고 비활성 토글과 도움말로 설명한다.
- 두 화면 모두 기록 상태에 따라 **일시정지 / 기록 재개 / 기록 마치기 / 추가 측정**을 같은 규칙으로 제공한다. 연결·저장 오류 복구 조작은 기존 위치·경로를 유지한다.

설정 토글과 진행 상태는 역할을 나눈다. 토글은 이 실험이 무엇을 저장하는지, 기록 상태는 지금 기록하고 있는지 보여 준다. ON으로 고정된 토글을 현재 기록 중이라는 표시로 대신하지 않는다.

| 수명·설정 | 두 화면의 상태 표시 | 우선 제공하는 조작 |
|---|---|---|
| 시작 전 ON | 토글 ON. 기록 중 표시는 없음 | **기록 시작**을 주 행동으로 표시. 미시작 한 점 버튼은 숨겨 비활성 버튼을 나열하지 않음 |
| 시작 전 OFF | 토글 OFF. 기록 중 표시는 없음 | **한 점 기록**을 주 행동으로 표시. 별도 기록 시작 버튼 없음 |
| 기록 중 ON | 어느 탭에서도 **연속 기록 중** | 한 점 기록과 일시정지. 기록 마치기는 보조 행동 |
| 기록 중 OFF | **한 점 기록 중** | 한 점 기록과 일시정지. 기록 마치기는 보조 행동 |
| 일시정지 | 현재값 가까이에 **일시정지** | **기록 재개**를 주 행동으로 표시. 한 점 캡처는 비활성 |
| 마침 | 기존 기록 마침 상태 | 데스크톱은 첫째 줄 **추가 측정**, 둘째 줄 **새 실험**. 모바일은 같은 줄에 제공. 한 점 기록은 숨김 |

- 두 탭 모두 데스크톱은 최대 두 줄을 사용한다. 첫째 줄은 한 점 기록 / 일시정지(또는 재개), 둘째 줄은 기록 마치기 / 새 실험이다. 시작 전에는 설정에 맞는 시작 행동만 전체 너비로 표시한다. 종료 후에도 새 실험은 둘째 줄에 유지하며, 추가 측정과 새 실험을 각각 전체 너비로 표시한다. 새 실험은 다른 버튼과 같은 높이·글자 크기의 공통 보조 버튼이다. 일시정지 중 한 점 기록은 같은 자리에 비활성으로 유지하며, 마감 처리 중에도 직전의 일시정지 또는 재개 버튼을 비활성으로 남겨 배치를 유지하고 조작을 막는다. 모바일(760px 이하)은 표시되는 모든 버튼을 같은 너비의 한 줄에 배치한다. 장식 아이콘을 생략하고 필요하면 버튼 안의 문구를 줄바꿈하되 공통 터치 높이는 유지한다.
- 연결이 필요하면 기존 주 행동 자리를 재연결 버튼으로 대체하고 한 점 기록·일시정지·재개를 숨긴다. 기존 실험이 있으면 마치기·새 실험을 유지한다. 기록 중 재연결을 누르면 먼저 일시정지하며, 연결 성공만으로 기록을 재개하지 않는다. 연결·저장 오류로 필요한 조작을 제한할 때는 기존 오류 안내를 사용하며 단순 미시작 상태의 안내를 중복 추가하지 않는다.
- 한 점 화면에서도 연속 저장이 진행 중임을 즉시 알 수 있도록 기록 상태와 일시정지를 같은 공통 조작 영역에 유지한다. 그래프나 접힌 표 안에 넣지 않는다. 탭 전환 후에도 같은 화면 위치·순서를 우선한다.
- 한 점 중심 화면의 기록 중 주 행동은 한 점 기록, 그래프 중심 화면에서는 기존 기록 제어 위계를 따른다. 상태 표시·일시정지의 접근성은 동일하게 유지하고 강한 강조색의 주 버튼을 한 영역에 여러 개 경쟁시키지 않는다.
- 작은 화면은 측정 탭을 먼저, 연속 기록 토글·물음표를 다음 그룹으로 읽히게 배치한다. 긴 상태 문구·200% 확대에서는 줄바꿈을 허용하고 터치 영역·입력칸을 좁혀 맞추지 않는다. 기존 버튼·간격·타이포그래피 토큰을 재사용한다.
- 고정된 토글은 조작부만 비활성 외형으로 표시하며 레이블·설정값은 읽을 수 있게 유지한다. 상태를 색이나 점멸만으로 표현하지 않고, 시작·정지·재개 때만 필요한 상태 알림을 제공한다.

## 4. 수동 전용 화면 UX

2026-10-29 변경 설계에서 이 절의 ‘수동 전용’은 **한 점씩 측정 탭의 배치**를 뜻한다. 연속 기록 ON도 허용하며, 시작·일시정지·재개는 §3.1의 공통 규칙을 따른다.

### 4.1. 데스크톱 구성

넓은 화면은 실시간 값·기록 조작과 편집 표를 동시에 보여 준다. 표 머리글에는 변인 이름·단위 설정만 두고 별도의 조건 카드를 만들지 않는다. 초기 배치는 왼쪽 약 40%, 오른쪽 약 60%를 검토 기준으로 삼되 최소 가독성과 실제 화면 폭에 따라 조정한다. 고정 비율로 내용을 자르지 않는다.

| 영역 | 내용 | 조작 결과 |
|---|---|---|
| 위쪽 맥락 | 한 점씩 측정, 수신 상태, 점 개수, 저장 상태 | 연결·기록·저장을 서로 구분 |
| 왼쪽 계기 | 큰 현재값·단위, 읽기 전용 눈금, 선택적 성분값 | 값은 수신에 따라 계속 갱신 |
| 표 머리글 | **+ 변인 추가**, 이름·단위 버블, 설정 후 연필 아이콘 | 기록할 변인의 정의 설정 |
| 상단 공통 조작부 | **한 점 기록**, 기록 시작·일시정지·재개·마치기 | 센서값·수신 시각·이번 조건을 한 행으로 확정하며 두 화면에서 같은 위치로 조작 |
| 오른쪽 표 | 번호·변인값·주 채널·메모 아이콘·옵션 | 과거 값 편집, 메모 버블 입력, 옵션에서 시각·나머지 채널·기록 취소와 복원 |
| 표 아래 보조 | 최근 기록 취소·복원, 접힌 관계 미리보기, 자료 분석으로 | 기록 정정과 상세 분석 진입 |

측정 방식 탭 아래 공통 안내줄에는 저장 관련 안내와 모의 장치 안내만 남기고, 기록 개수도 여기에서 확인한다. 한 점 기록 완료는 표가 접혀 있을 때 펼치기 버튼의 개수 자리에 잠깐 표시하고, 표를 펼치거나 표시 시간이 지나면 개수로 돌아간다. 시작·재개·마침·처리 중·수신 대기·편집 완료 등의 반복 안내는 생략한다. 실제 오류와 셀 입력 검증은 기존 오류 표시를 사용한다. 연결·기록 상태는 장치 카드에서 같은 크기의 점과 글자로 나란히 표시한다.

변인은 선택적으로 설정한다. 기록표 머리글의 **+ 변인 추가**를 눌러 버블에 이름·단위를 입력한다. 버블을 떠나면 유효한 설정이 적용되어 기록 행에 입력칸이 나타난다. 이후 머리글의 연필 아이콘으로 이름·단위를 수정한다. 센서 공통 화면에 거리/cm를 고정하지 않으며, 변인을 설정하지 않아도 시각과 센서값을 기록할 수 있다.

기록표 제목·개수·펼치기는 같은 카드의 머리글로 통합한다. 접어도 현재값·기록 조작은 계속 사용할 수 있다. 표의 행·셀·머리글·입력 조작은 분석 표와 공통 [표 스타일](../src/ui/data-table.css)을 사용한다. 입력 가능한 셀은 항상 경계선을 표시한다. 페이지 버튼 없이 표 안에서 스크롤하며, 분석 표와 [행 높이·가상 표시·키보드 스크롤](../src/ui/table-viewport.js)을 공유한다. 각 View는 행 내용·열 폭·편집 초안을 맡는다.

번호·메모·옵션 열은 짧은 번호와 아이콘만 표시한다. 메모는 아이콘 옆 버블에서 입력하고, 내용이 있으면 채워진 색 아이콘과 접근 가능한 이름으로 구별한다. 행을 펼치는 방식은 사용하지 않는다.

이번 조건값의 보관·숫자 검증·캡처 전달·기록 후 유지 계약은 보존한다. **현재 입력 UI는 숨겼으며, 후속 작업에서 한 점 기록 버튼 옆으로 옮긴다.** 현재 화면에서는 기록된 행에 변인값을 입력할 수 있다. 자동 증가는 첫 범위에서 제외한다. 증감 버튼을 제공할 경우 사용자가 정한 간격을 사용하고, 과거 표의 값을 자동 변경하지 않는다.

### 4.2. 기록 피드백

성공하면 새 행에 짧은 강조와 **6번 기록 완료** 같은 알림을 제공한다. 현재값 계기는 멈추지 않는다. 사용자는 계속 변하는 현재값과 고정된 기록 행을 구별할 수 있어야 한다.

기록 완료는 RunStore가 값을 수락했다는 뜻이다. 브라우저 저장까지 끝났다는 뜻으로 바꾸지 않는다. 자동 저장 중·실패 상태는 기존 공통 저장 표시가 계속 담당한다.

빈 상태는 **원하는 위치에 센서를 놓고 한 점 기록을 눌러 보세요**처럼 다음 행동을 안내한다. 저장이 불가능하거나 수신이 오래된 상태에서는 원인과 가능한 다음 행동을 함께 보여 준다.

### 4.3. 관계 미리보기

표 아래의 **기록한 값의 관계**는 기본 접힘 상태로 제공할 수 있다. 펼치면 확정된 조건값과 선택 채널의 간단한 산점도를 보여 준다. 표의 행과 점을 연결하고, 조건 편집 확정 후 위치를 갱신한다.

계산·필터·회귀·범위 도구는 기존 자료 분석에서 사용한다. 간단한 미리보기에 분석 작업공간을 하나 더 만들지 않는다. 아직 기록하지 않은 현재값을 실제 자료점이나 제외점과 같은 기호로 혼합하지 않는다.

## 5. 연속 화면의 한 점 기록 UX

기존 실시간 시간 그래프, 시작·일시정지·재개·마치기, 사건·메모 흐름을 유지한다. 기록 조작 근처에 보조 **한 점 기록** 버튼과 점 개수를 둔다.

- 변인 입력과 점 표는 같은 접이식 보조 영역으로 펼친다. 수동 화면과 같은 표 머리글·메모 버블을 사용한다. 충분한 콘텐츠 너비가 있으면 펼친 기록표를 그래프 오른쪽에 두고, 그래프에 더 넓은 공간을 배분한다. 표는 그래프 카드 높이 안에서 내부 스크롤한다. 좁은 화면과 글자 확대 시에는 그래프 아래에 기록표를 둔다.
- 넓은 화면에서 기록표를 접으면 오른쪽 위에 짧은 보조 버튼만 남기고, 그래프가 그 외의 너비를 모두 사용한다. 표 아이콘·`한 점 / 기록표` 두 줄 제목·펼치기 화살표·기록 개수를 묶고, 기존 보조 버튼의 테두리·모서리·상태 색상을 사용한다. 펼치기 조작을 그래프 아래로 옮기지 않으며, 버튼 아래에 이전 높이의 빈 카드가 남지 않도록 전환한다. 펼침 여부로 그래프의 세로 공간을 줄이지 않으며, 배치 변경과 접기·펼치기는 기존 표·입력 초안을 유지한다.
- 좌우 배치의 펼침·접힘은 그래프와 기록표의 너비를 함께 보간한다. 상하 배치와 다른 접이식 박스는 높이를 보간하며, 두 방향 모두 [공통 패널 전환](design/visual-language.md#공통-패널-전환)의 시간·곡선·움직임 줄이기 규칙을 따른다.
- 펼침·접힘 표시는 공통 선형 꺾쇠를 사용한다. 오른쪽 기록표를 접으면 아이콘 → 제목 → 개수·새 기록 안내 → 왼쪽 꺾쇠 순서로 중앙 정렬한다. 새 기록 직후 개수 자리에 `{number}번 기록`을 잠깐 강조하고 개수로 복귀하며, 두 줄 안내와 기존 개수 문구의 공간을 확보해 버튼 높이·화살표 위치가 흔들리지 않게 한다. 펼친 상태에서는 오른쪽 꺾쇠를 헤더 왼쪽에 둔다. 상하 배치에서는 접혔을 때 아래, 펼쳤을 때 위를 가리킨다. 헤더 전체 클릭과 기본 키보드 조작을 유지한다.
- 상하 배치에서 기록표를 접으면 공통 터치 높이를 유지한 간결한 한 줄 버튼으로 표시한다. 기록표·실험 메모의 펼침 여부에 관계없이 그래프는 상단 조작부와 하단 기록표·메모 영역을 제외한 화면 높이에 맞춘다. 어느 영역을 펼치든 그래프가 읽을 수 있는 최소 높이까지 줄어들며, 그 이상 공간이 필요하면 페이지 스크롤을 허용한다.
- 보조 영역을 열기 전에도 한 점 기록을 누를 수 있다. 조건이 없으면 빈 값으로 기록하고 나중에 입력할 수 있음을 알린다.
- 이번 조건 입력을 기록 버튼 옆으로 옮길 때 패널을 접어도 적용할 값을 확인할 수 있게 한다. 현재는 이번 조건의 입력·요약 UI를 숨기며, 접기는 조건값 초기화가 아니다.
- 한 점 기록은 수동 화면과 같은 명령이다. 연속 기록 ON에서는 기존 Sample을 참조하고 OFF에서는 캡처한 Sample과 점을 함께 저장한다. 탭 배치 때문에 저장 정책이 바뀌지 않는다.
- 조건 입력·과거 행 편집·패널 열기·닫기가 수신과 연속 저장을 막지 않는다.
- 시간 그래프에는 점 기록 번호와 시점 표시를 제공한다. 가까운 표시는 묶고 기존 사건·메모와 구별되는 이름을 사용한다.
- 사건과 점 기록이 같은 시점에 있어도 하나를 다른 것으로 대체하지 않는다. 표시·위치 계산은 기존 사건 표시 도구를 가능한 범위에서 재사용한다.
- 점 표는 표 내부의 연속 스크롤로 모든 기록에 접근한다. 화면 근처의 행만 표시하되, 초점·메모 버블이 있는 행은 유지한다. 새 기록은 맨 아래를 보고 있고 편집 중이 아닐 때만 따라가며, 그 외에는 **새 기록 n개**로 이동 기회를 제공한다.
- 한 점 버튼의 허용 여부는 탭이 아니라 §9의 공통 수명·저장 정책으로 결정한다. OFF의 시작 전 첫 캡처도 이 화면에서 허용한다.

## 6. 실시간 계기의 표시 계약

[visual-language.md](design/visual-language.md)와 [tokens.css](../src/ui/tokens.css)를 단일 시각 기준으로 사용한다. 이 문서의 배치 설명은 CSS 값의 새 사본을 만들라는 뜻이 아니다.

| 항목 | 적용 규칙 |
|---|---|
| 기본 표시 | 센서 정의가 정한 주 채널의 숫자·단위를 가장 크게 표시 |
| 눈금 | 읽기 전용 막대·눈금·가는 표식. 드래그 손잡이·슬라이더 모양을 사용하지 않음 |
| 성분 | 자기장·가속도 X/Y/Z는 0 중심, 같은 물리량·단위의 성분은 같은 표시 범위 |
| 크기·일반 스칼라 | 물리량에 맞는 범위. 온도를 무조건 0부터 표시하지 않음 |
| 범위 | 정의의 표시 제안 또는 사용자가 명시한 범위 사용. 매 수신마다 자동 재조정하지 않음 |
| 범위 미정 | 숫자를 우선하고 명시적 범위 설정 제공. 임의 범위를 검증된 센서 한계로 안내하지 않음 |
| 범위 밖 | 숫자는 보존하고 눈금 밖임을 표시. 실제 값을 범위 끝 값으로 바꾸지 않음 |
| 무효·끊김 | 결측·오류·마지막 수신값임을 글자로 구별. 마지막 정상값을 현재 정상값처럼 대체하지 않음 |
| 채널색 | readVisualTheme의 선·읽기용 색 사용. 숨긴 채널 때문에 색을 다시 배정하지 않음 |
| 수신과 움직임 | 실제값을 보간하지 않음. 매 수신마다 패널 전환 효과·스크린리더 알림을 실행하지 않음 |
| 표시 단위 | 기존 단위 표시 규칙 유지. 가속도의 g 표시는 저장 m/s²를 변경하지 않음 |
| 저장 채널 | 화면에 표시하는 항목과 관계없이 등록된 모든 채널값·유효성을 보관 |

현재 장치의 주 표시와 이번 캡처에 사용된 값의 시각이 다를 수 있음을 상세 보기에서 확인할 수 있게 한다. 계기를 매번 잠그거나 센서 좌표·자기장 방향을 추정하는 장식을 추가하지 않는다.

### 6.1. 연속 기록 OFF의 그래프와 메모리

- OFF에서도 센서 수신·현재값 표시·시간 그래프 미리보기는 계속한다. 시간 그래프는 연속 측정 탭에서 볼 수 있으며 한 점 탭에 차트를 중복 생성하지 않는다.
- 그래프 입력은 메모리의 수신 미리보기다. 저장한 점이 생겨도 드문 캡처 Sample들을 시간 그래프의 연속 자료로 대신 사용하지 않는다. 한 점 캡처 후보는 표시용 자료의 축약·버퍼 축출과 독립적으로 원래 수신값을 사용한다.
- 표시 범위는 **최근 60초**만 허용한다. 기존 전체 범위 항목은 숨기지 않고 비활성화하며, 이전 전체 선택은 최근 60초로 되돌린다. 단축키·복원 경로에서도 전체 선택이 적용되지 않는다. 그래프 머리글에는 **최근 60초 · 저장 안 함**을 간결하게 표시한다. 범위 선택기와 상태 표시에 ‘최근 60초’를 중복 나열하지 않으며, 이 안내는 그래프에만 속한다. 옆의 한 점 기록표에는 기존 기록 개수·저장 상태를 유지해 저장된 점까지 사라진다고 오해하지 않게 한다.
- 메모리는 개수가 아니라 **실제 수신의 단조 시각 기준 최근 60초**로 축출한다. 고정 개수의 사전 할당 대신 실제 수신 빈도·묶음 도착에 따라 배열을 늘리고 시간 경계로 축출한다. 고정 600개 한도 때문에 표시 기간이 줄어들지 않게 한다. 1 Hz는 약 60개, 10 Hz는 약 600개, 50 Hz는 약 3,000개가 필요하며 경계·묶음 수신 여유를 둔다. 50 Hz는 검증용 합성 입력이며 현재 펌웨어 지원 주장을 뜻하지 않는다.
- 왼쪽 경계의 선을 그릴 때 필요한 직전 관측 하나는 추가 보관할 수 있으나 60초 밖을 표시 범위로 늘리지 않는다. 수신이 늦거나 아직 60초가 지나지 않았으면 실제로 받은 구간만 보여 준다. 빈 구간을 보간하거나 데이터를 만들어 채우지 않는다.
- 덱·링 버퍼 등으로 앞부분 삭제 비용을 줄이고, 수신 처리와 화면 갱신 주기를 분리한다. 그래프 성능용 축약은 표시 단계에서만 수행하며 극값·공백을 보존한다. 장시간 실행에서도 보관 기간이 누적되지 않도록 한다.
- 탭 이동은 버퍼를 유지한다. 새 실험·새로고침·장치 재연결은 버퍼와 시간 구간을 새로 시작한다. UTC 역행·수신 공백은 기존 불연속 규칙으로 구분하며 서로 다른 연결의 선을 잇지 않는다. UTC 수신 시각과 단조 보관 시각을 혼동하지 않는다.
- 미리보기의 경과 시간 원점은 해당 수신 구간 시작 시 고정한다. 오래된 행을 축출할 때마다 시간을 0초로 다시 매기지 않는다. 미리보기 관측의 식별자는 영속 sampleId와 구별하며, 점 표식은 저장된 수신 시각으로 대응시킨다.
- 버퍼는 DB·JSON·CSV·Workspace·과거 근거에 포함하지 않는다. OFF도 캡처한 Sample·PointRecord와 필요한 사건·설정·분석은 정상 저장한다. ‘연속 저장 안 함’을 ‘아무것도 저장 안 함’으로 구현하지 않는다.
- ON의 그래프는 기존 저장 원자료의 최근/전체 보기를 유지한다. ON의 기록 시작 전 미리보기도 같은 60초 버퍼를 사용하며, 시작할 때 과거 미리보기를 소급 저장하지 않는다.

### 6.2. 일시정지·재개와 표시

| 상태 | 센서값 저장·한 점 기록 | 현재값·계기·그래프 | 연결·저장 상태 |
|---|---|---|---|
| 시작 전 | 자동 저장 없음. OFF의 첫 캡처만 허용 | 수신 미리보기 갱신 | 계속 갱신 |
| 기록 중 | ON은 연속 저장+캡처, OFF는 캡처만 저장 | 계속 갱신 | 계속 갱신 |
| 일시정지 | 두 설정 모두 차단 | 정지 시 값·눈금·최근 구간의 오른쪽 끝 시각 고정 | 계속 갱신 |
| 재개 | 기존 정책으로 게이트 열기. OFF는 자동 점 생성 안 함 | 재개 뒤 새 수신부터 갱신 | 새 연결·신선도 검증 유지 |

일시정지는 BLE 연결을 끊거나 보드를 멈추는 명령이 아니다. Transport의 수신 확인은 계속하지만 표시 버퍼에 새 값을 넣지 않고 캡처 후보로도 받아들이지 않는다. 정지 중 화면을 바꿔도 같은 고정값을 표시한다. 채널·표·기존 자료 보기 조작은 가능하지만 시간축이 자동으로 움직이거나 기록 수가 늘어나지 않는다. 연결 끊김·저장 실패를 숨기지 않으며, 고정된 숫자 가까이에 **일시정지** 상태를 표시해 현재 센서값으로 오해하지 않게 한다. 표시값의 시각도 함께 고정하고, 별도 연결 진단의 최근 수신 시각으로 덮어쓰지 않는다.

재개 버튼은 현재 연결의 정상 수신 사실로 판단한다. 표시 고정 때문에 준비 완료를 영원히 기다리는 순환 조건을 만들지 않는다. 재개 시 이전 후보를 무효화하고, 재개 명령 이후 도착한 유효 관측을 기다린다. 정지 중 수신값을 한꺼번에 저장하거나 캡처하지 않는다. 그래프는 실제 시간으로 돌아오며 정지 구간을 선으로 잇지 않는다. 60초 넘게 정지했다면 이전 그래프 점은 재개 후 범위 밖으로 사라질 수 있다.

저장 오류·한도 도달로 자동 일시정지되어도 같은 표시 정지 규칙을 적용한다. 이미 수락한 자료·저장 대기열·편집 초안은 보존한다. 기록 마치기는 기존 입력 마감·저장 경계를 유지하며 자동 재개하지 않는다. 새로고침으로 복원한 정지 상태에는 메모리 그래프를 복구한 것처럼 표시하지 않고 저장값만 마지막 기록으로 구분한다.

## 7. 조건 입력과 표 편집

### 7.1. 수동 열

첫 범위는 숫자 조건 열 최대 1개다. 공통 열 계약으로 이름·단위·안정적인 ID를 관리한다. 이름은 1–60자, 단위는 기존 열 계약의 30자 한도를 사용하고, 채널·계산·가져온 열의 ID와 충돌하지 않게 한다. 내부 ID는 화면 이름을 바꾸어도 유지한다.

| 입력 | 처리 |
|---|---|
| 빈칸 | null로 기록. 표에는 입력하기 표시 |
| 0 | 유효한 숫자 0으로 보존 |
| 유한한 음수·소수 | 허용. 거리 등 이름만 보고 물리적 제약을 추정하지 않음 |
| 비어 있지 않은 잘못된 숫자·비유한 값 | 해당 입력 옆에 수정 안내. 그 입력을 사용하는 캡처·편집 확정 차단 |
| 조건을 나중에 추가 | 기존 점은 null로 시작. 센서값·시각 유지 |
| 조건 이름·단위 변경 | 같은 열의 메타데이터 정정. 숫자를 자동 환산하지 않으며 기존 점에 적용됨을 안내 |
| 조건 열 삭제 | 값이 있는 열의 삭제는 첫 범위에서 제공하지 않음. 숨김은 자료 삭제와 구분 |

이번 조건 초안과 과거 셀의 편집 초안은 독립이다. 잘못된 과거 셀 초안이 있어도 유효한 이번 조건으로 별도 캡처할 수 있으며, 두 값이 서로 덮어쓰이지 않는다.

### 7.2. 편집과 기록의 동시성

- 센서값·원래 수신 시각·캡처 시각은 읽기 전용이다. 수동 조건값·메모만 수정한다.
- 표 초안은 행 DOM과 분리해 UI가 소유하고, 확정값은 RunStore 명령으로 전달한다.
- 변인 이름·단위·값과 메모에는 확인·취소 버튼을 두지 않는다. 셀 또는 버블 바깥으로 초점이 이동하거나 바깥을 클릭하면 유효한 입력을 자동 확정한다. 같은 버블의 필드·휴지통 사이 이동은 편집을 유지하며, 잘못된 입력은 오류와 초안을 남긴다.
- 입력칸 오른쪽의 휴지통은 해당 입력 내용만 비우고 입력칸에 초점을 유지한다. 숫자 빈칸은 null, 메모 빈칸은 빈 문자열로 확정한다. 변인 열·행·센서 원자료를 삭제하지 않으며 필수 이름을 비우면 수정 안내를 표시한다.
- 새 수신·새 행·가상 스크롤 때문에 입력값·포커스·커서 선택 범위·IME 조합이 사라지지 않는다.
- 편집 중인 행을 DOM에서 제거해야 한다면 먼저 유효 초안을 확정하거나 초안을 보관한다. 재그리기로 조용히 취소하지 않는다.
- 표 셀의 Enter는 해당 편집 확정, Escape는 해당 초안 취소다. 버블의 Escape는 유효한 초안을 확정하고 닫으며, 메모의 Enter는 줄바꿈한다. IME 조합 중 Enter를 확정·캡처로 처리하지 않는다.
- 전역 Enter를 한 점 기록 단축키로 사용하지 않는다. 캡처 버튼에 초점이 있을 때는 표준 버튼 키보드 조작을 지원한다.
- 표 맨 아래를 보고 있고 편집 중이 아니면 새 행을 따라간다. 과거 행을 읽거나 편집 중이면 위치를 유지하고 **새 기록 n개**로 이동 기회를 제공한다.
- 화면·자료 전환 전에 유효한 편집 초안은 확정한다. 잘못된 초안은 위치를 유지한 채 수정·취소를 선택할 수 있게 한다.
- 수동 필드 변경은 센서 원자료·다른 점의 입력값을 변경하지 않는다. 같은 조건으로 반복한 점은 독립된 행이다.

### 7.3. 실수 기록과 분석 제외

실수로 추가한 점은 **기록 취소 / 복원**으로 점 목록의 포함 상태를 변경한다. 원래 점 번호·센서 원자료·시각은 남기고 번호를 다시 매기지 않는다. 취소한 행도 상태를 확인하고 복원할 수 있어야 한다.

주 개수는 취소하지 않은 기록 수를 사용하고, 취소 기록이 있으면 **한 점 기록 4개 · 취소 2개**처럼 구별한다. 점 번호는 개수와 별개이며 재사용하지 않는다.

기존 상세 분석의 **분석에서 제외 / 복원**은 해당 분석 자료의 제외 상태만 변경한다. 기록 취소와 분석 제외는 다른 범위의 동작이므로 같은 이름·아이콘만으로 혼용하지 않는다. 연속 기록의 분석 제외는 한 점 분석에 자동 전파하지 않으며, 반대 방향도 같다.

조건이 없는 점은 시간–센서값 분석에서 사용할 수 있다. 조건을 축으로 선택했을 때는 해당 값이 없음을 알리고 그래프·회귀에서 결측으로 처리한다. 0으로 채우거나 행 자체를 삭제하지 않는다.

## 8. 분석 UX와 원자료 추적

### 8.1. 자료별 작업 상태

두 자료에 [기존 분석 도구](../src/analysis/workspace.js)를 사용한다. 표·필터·구간·선택·제외·계산·양쪽 세로축·회귀·추세선·근거·해석을 별도로 복제하지 않는다.

각 자료는 축, 적용 범위, 제외 사유, 계산 열, 표 정렬·필터, 회귀, 보관 근거, 해석 글을 각각 유지한다. 실행 취소·다시 실행 이력은 자료별 런타임 이력으로 구분하고 기존처럼 파일 저장 대상으로 약속하지 않는다.

처음 연 한 점 자료는 조건 열이 있으면 조건–주 채널 산점도를 제안한다. 조건 열이 없으면 시각–주 채널 또는 시각 없는 가져오기 자료의 순번 보기를 사용한다. 관계 그래프 진입은 명시적인 **자료 분석으로** 동작에서 제안할 수 있다. 이미 사용자가 설정한 축과 작업 탭은 다음 방문에 보존한다.

한 점 자료의 표·그래프 병렬 보기에서는 점 번호와 선택한 축을 우선 표시한다. 제외·범위 밖·취소 상태는 번호 옆과 접근 가능한 행 이름에 표시하고, 전체 열은 표 보기에서 제공한다. 선택한 점 정보는 조건과 주 측정값·선택한 축을 먼저 보여 주고 나머지 성분과 연결된 원자료 번호는 펼쳐 볼 수 있다. 상세 정보는 페이지 흐름에서 확장하며 별도 내부 스크롤로 자르지 않는다.

수동 전용의 원 자료 보기에서는 점들의 수신 시각과 값을 볼 수 있으나, 측정하지 않은 점 사이를 실제 연속 측정처럼 연결하지 않는다. 연속 자료의 기존 시간선·불연속 표시 계약은 유지한다.

한 점 자료의 범위 선택은 **기록 선택 → 표에서 행 체크 → 선택 자료 분석**으로 진행한다. 비연속 번호도 선택할 수 있고 원자료 시각은 선택 기준으로 강제하지 않는다. 적용 후 관계 그래프를 보여 주며 **전체 기록 분석**으로 전체 후보로 돌아갈 수 있다. 두 방식 모두 기존 제외 사유·계산·보관 근거를 유지한다. 초 단위 구간 선택은 연속 자료에만 제공한다.

### 8.2. 새 기록과 수정된 조건 반영

측정 표·관계 미리보기·상세 분석은 사용자가 확정한 변경을 자동 반영한다. 계속 수신되는 연속 자료만 **새 자료 반영**으로 가져온다.

- 최초 진입·재진입과 자료 전환: 저장된 분석 설정을 유지하며 최신 확정 점 자료를 읽는다.
- 새 점 추가, 조건값·열 정의 편집 확정, 기록 취소·복원은 점 분석 입력 사본을 자동 갱신한다. 입력 중인 초안은 반영하지 않는다.
- 표·정렬·필터·그래프·계산·분석 CSV는 같은 적용 입력을 사용한다. 별도의 입력 반영 대기 안내는 두지 않으며, 브라우저 저장 성공 여부는 공통 저장 표시로 구분한다.
- 연속 수신과 일시정지만으로는 연속 분석 입력을 바꾸지 않는다. 기록 마치기를 확정하면 대기 중인 연속 자료도 자동 반영한다. 추가 측정에서도 같은 규칙을 적용한다.
- 자동·수동 반영 모두 전체 범위는 적용 입력 스냅샷의 유효 자료 집합으로 확장한다. 지정 범위는 취소한 점의 후보 ID도 보존하고, 적용 스냅샷의 취소 상태로 실제 사용 대상만 거른다. 복원 시 원래 후보였던 점은 다시 사용할 수 있지만 명시적인 분석 제외는 유지한다. 계산·회귀 캐시도 함께 갱신한다.
- 범위·제외 사유·계산식·해석 글은 유지한다. 보관 근거는 자동 교체하지 않는다.
- 한 점 자료가 처음부터 없었던 연속 실험에 점을 추가하면 분석 자료 선택지를 제공하되, 현재 분석 자료를 자동 전환하지 않는다.

### 8.3. 연속 기록에서 보기

연속 기록 중 만든 점의 상세 보기에 **연속 기록에서 보기**를 제공한다.

1. 편집 초안을 처리하고 현재 한 점 분석 위치를 기억한다.
2. 분석 자료를 연속 기록으로 바꾸고 **원 자료 보기**에서 해당 수신 시점 주변을 임시 강조한다.
3. 기존 연속 분석의 축·후보 범위·제외·회귀·근거를 덮어쓰지 않는다. 시간 뷰포트와 살펴보는 점만 일시 변경한다.
4. **한 점 기록으로 돌아가기**로 직전 점·작업 탭·스크롤 맥락에 돌아온다.

참조 샘플이 연속 분석의 읽기 경계보다 새로우면 해당 원자료를 포함하는 읽기 스냅샷만 확장한다. 기존 분석 후보와 적용 입력 revision을 변경하지 않고 **새 자료 반영** 안내를 유지한다. 읽은 원자료 경계와 분석에 적용한 자료 경계를 구분하며, 변경 안내는 단순히 읽은 행 수가 아니라 마지막 적용 입력 경계를 기준으로 계산한다.

수동 전용·점 CSV만 가져온 자료에는 연속 기록 링크를 표시하지 않는다. 존재하지 않는 출처를 찾는 링크를 만들지 않는다. JSON의 실제 내부 참조가 손상된 경우에는 가져오기 검증에서 거부한다.

### 8.4. 보관 근거

현재 근거는 불변 센서 원자료를 다시 읽을 수 있다는 전제로 구성되어 있다. 편집 가능한 조건값을 추가한 뒤에는 근거에 다음을 함께 고정한다.

- 분석 자료 ID와 사용한 원자료·점 참조.
- 당시 수동 열의 정의·단위와 사용한 조건값 사본.
- 당시 포함·제외·계산식·축·입력 경계.
- 근거 생성에 사용한 입력 revision.

revision 번호만 저장하고 예전 조건값을 남기지 않는 방식은 허용하지 않는다. 이후 거리 수정·열 이름 정정·기록 취소가 과거 근거·PNG·인쇄를 바꾸지 않아야 한다. 근거 교체는 기존 명시적 조작으로 수행한다.

## 9. 캡처와 오류 상태 계약

### 9.1. 캡처 대상과 시각

한 점 기록은 버튼 명령 시점에 앱이 받은 **가장 최근의 캡처 가능한 수신값**을 고정한다. 보드에 새 측정을 요청하거나 정확히 클릭 시각에 센서가 측정했다고 보장하지 않는다.

원자료 receivedAt은 앱의 UTC 수신 시각으로 보존하고, 사용자 명령 시각 capturedAt을 별도로 저장한다. UI의 기록 시각은 수신 시각을 기준으로 하며 상세 보기에서 두 시각의 의미를 확인할 수 있다. 런타임의 단조 시각은 신선도 판단용이며 장치 측정 시각으로 내보내지 않는다.

연속 기록에서는 선택한 수신값에 대응하는 **이미 수락된 Sample**을 참조한다. 최신 미리보기만 있고 원자료가 없으면 임의의 이전 정상 샘플로 대체하지 않는다. 첫 수동 점의 Run 생성·잠금 획득이 비동기여도 클릭 당시 값과 이번 조건을 먼저 고정한다. 준비 완료 후 새로운 최신값으로 몰래 바꾸지 않는다.

### 9.2. 허용 조건

Controller·Transport는 현재 연결과 시도 ID를, Session은 기록 수명과 캡처 가능 여부를, RunStore는 쓰기·저장 상태를 판단한다. UI가 별도 타이머나 기록 플래그로 상태를 재구성하지 않는다.

- 현재 연결이 확인되었고 후보가 같은 연결 시도의 수신값이다.
- 센서 connectionPolicy의 신선도·필수 채널·수신 확인 조건을 충족한다.
- 필수 채널 정책이 없으면 적어도 한 채널이 valid다. 나머지 채널의 결측·오류는 원래 유효성대로 함께 보관한다.
- RunStore 생성 또는 쓰기가 가능하고 저장 오류·종료·한도 초과로 입력이 막히지 않았다.
- 이번 조건값이 비어 있거나 유한한 숫자다.
- 같은 수신 관측을 이미 한 점으로 수락하지 않았다.

수신 모니터의 disconnected는 최신값 자체를 지우지 않으므로 latest의 존재만으로 허용하지 않는다. 중복 방지는 연결 시도와 수신 관측의 식별로 판단한다. 같은 숫자값이 다시 도착한 것을 중복으로 취급하지 않는다.

| 상태 | 한 점 기록 | 안내·후속 동작 |
|---|---|---|
| 연속 기록 OFF, 첫 기록 전, 수신·저장 가능 | 두 탭에서 허용 | 첫 점과 Run 생성 |
| 연속 기록 OFF, 기록 중 | 두 탭에서 허용 | Sample과 점 추가, 미리보기 계속 |
| 연속 기록 ON, 기록 중, 후보 Sample 존재 | 두 탭에서 허용 | 기존 Sample에 점 참조 추가 |
| 연속 기록 ON, 미시작 | 비활성 | 기록 시작 후 새 수신 대기 |
| 일시정지, ON/OFF 공통 | 비활성 | 표시도 정지. 명시적 재개 뒤 새 수신 대기 |
| 기록 마침 | 비활성 | 기존 추가 측정 확인 후 재개 |
| 연결 중·미수신·끊김·오래된 값 | 비활성 | 연결·수신 확인, 마지막 값 표시 구분 |
| 같은 관측을 연속 클릭 | 새 점 생성 안 함 | 새 수신값을 기다리도록 짧게 안내 |
| 이번 조건이 잘못된 숫자 | 확정 차단 | 해당 입력에 수정 안내, 연속 저장은 유지 |
| 읽기 전용·임시 분석·저장 오류 | 비활성 | 기존 쓰기 권한·재시도·파일 보관 경로 |
| 요청 처리 중 | 중복 요청 차단 | 결과 후 복귀. 기록 성공을 미리 알리지 않음 |

저장 재시도는 같은 기록 ID와 내용을 사용한다. DB 응답 유실이나 첫 클릭의 중복 실행으로 새 점·새 Run이 생기지 않아야 한다. 두 화면·두 저장 정책 모두 사용자 일시정지와 **기록 재개**를 제공한다. 원인 해결 후에도 자동 재개하지 않으며, OFF의 재개는 캡처 가능한 상태만 복구하고 점은 자동 생성하지 않는다.

## 10. 모바일과 접근성

수동 전용은 **공통 안내줄 → 연결·기록 상태와 기록 조작 → 현재값 요약 → 기록 표**가 읽히도록 한 열로 배치한다. X/Y/Z 등 부가 계기는 기본 접힘으로 시작할 수 있다.

| 상황 | 동작 계약 |
|---|---|
| 좁은 표 | 번호·조건·주 채널 우선. 시각·다른 채널·메모는 행 상세에서 접근 |
| 하단 기록 영역 고정 | 실제 높이·safe area만큼 공간 확보. 마지막 행·확정 버튼을 가리지 않음 |
| 소프트 키보드 표시 | 편집 셀과 해당 확정 조작을 볼 수 있게 재배치. 필요하면 기록 영역을 일반 흐름으로 전환 |
| 과거 행 편집 중 새 기록 | 편집·스크롤 유지. 새 기록 안내만 추가 |
| 현재값을 지나 스크롤 | 작은 현재값 요약으로 줄일 수 있으나 두 개의 독립 수신 표시 상태를 만들지 않음 |
| 연속 화면 보조 표 | 시간 그래프 최소 가독성 유지, 필요한 페이지 스크롤 허용 |
| 200% 글자 확대 | 글자·단위·조작을 자르지 않고 줄바꿈·재배치 |
| 키보드 | 방식·자료 선택, 기록, 셀 편집, 취소·복원, 원자료 추적 가능 |

수신 상태·결측·취소·분석 제외를 색만으로 구별하지 않는다. 비활성 버튼은 실제 disabled와 근거 안내를 함께 제공한다. 기록 완료·실패·자료 전환은 상태 알림으로 전달하고, 매 수신값을 aria-live로 읽지 않는다. 대화상자·메뉴를 닫으면 기존 공통 초점 복귀 규칙을 따른다.

## 12. 모듈 경계와 의존 방향

### 12.1. 상태 소유권

| 소유자 | 확장 책임 |
|---|---|
| Transport | 현재 연결 시도·수신 사실·시각 제공. 캡처 때문에 새 센서 스트림을 만들지 않음 |
| Controller | 측정 탭·시작 전 설정 초안, 사용자 명령, 첫 Run 생성, 연결·전환 가드, Session·View 연결 |
| Session | Run의 고정 저장 정책 적용, 공통 기록·표시 게이트, 후보 고정·중복 방지·캡처 순서 |
| 측정 미리보기 런타임 | 시작 전부터 사용하는 현재값·최근 60초 버퍼·정지 표시 시각. 두 View가 같은 읽기 모델 사용 |
| RunStore | Run의 확정 저장 정책, 불변 Sample, 점 기록·조건 확정값, 변경 revision·저장 대기열 |
| Repository | DB 버전 변환, 원자적 저장·읽기·삭제 |
| Workspace | 선택 자료의 입력 스냅샷·분석 상태·이력·근거 |
| UI | 표시 모델, 이번 조건·셀 편집 초안, 초점·스크롤·접힘 |

공통화에서 아래 작성 경계를 지킨다.

- **Controller:** 시작 전 탭 이동 시 ON/OFF 기본값 적용과 수동 초안을 담당한다. 시작 요청의 설정을 고정해 RunStore에 넘기고, 이후에는 저장된 정책을 읽는다. 탭 이동을 Session 정책 변경·새 Run 생성 명령으로 바꾸지 않는다.
- **Session·point-capture:** 기록 수명·신선도·캡처 허용 여부를 검증한다. 두 버튼은 같은 명령에 연결하며 화면 이름·DOM 상태로 저장 여부를 판단하지 않는다. 정지·재개는 한 번의 상태 전이로 저장·캡처·표시 게이트에 적용한다.
- **미리보기 런타임:** 승인된 수신값·고정 시각·최근 60초 버퍼의 단일 작성자다. 장치가 살아 있는지 판단하거나 DB에 저장하지 않는다. 두 View는 동일한 스냅샷을 읽고 렌더링만 한다.
- **기록 조작 표시 모델:** 기존 `recording-actions.js`에서 수명·확정 정책·연결 사실로 버튼 노출·활성화·주 행동·상태 표현을 일관되게 계산한다. 자체 기록 상태나 타이머를 저장하지 않는다. View가 따로 버튼을 숨기거나 CSS가 기록 가능 여부를 결정하지 않는다.
- **UI:** 공통 조작부의 DOM 작성 경로는 하나로 유지한다. 개별 View는 그래프/표 배치와 입력 초안만 담당한다. 공통 문구 적용이 동적 기록 상태를 덮어쓰지 않도록 해당 요소의 작성자를 분리한다. 센서·활동의 표현 차이는 기존 정의와 문구 해석 경로를 사용한다.
- **RunStore·Repository·Workspace:** 원자료 작성·영속 저장·분석의 기존 경계를 유지한다. UI나 미리보기에서 저장용 Sample을 직접 생성하거나 분석용 버퍼를 별도로 영속화하지 않는다.

JS ES Modules·JSDoc·기존 DOM/CSS 구조를 유지한다. 수신·저장·분석 상태를 새 전역 이벤트 버스나 UI 저장소에 중복 보관하지 않는다.

### 12.3. 캡처 처리 흐름

~~~mermaid
flowchart TD
  A["한 점 기록 명령"] --> B{"현재 연결·수신·쓰기·입력 유효"}
  B -->|아니오| C["원인 안내 · 기존 자료 유지"]
  B -->|예| D["후보 값·시각·이번 조건 고정"]
  D --> E{"고정 저장 정책 · 화면 탭과 독립"}
  E -->|연속 기록 ON| F["수락된 Sample 참조"]
  E -->|연속 기록 OFF| G["필요한 Run 생성 · Sample 추가 준비"]
  F --> H["RunStore가 PointRecord 수락"]
  G --> H
  H --> I["동일 저장 묶음으로 보관 · UI 피드백"]
~~~

공개 API 이름은 구현 시 기존 호출 스타일에 맞출 수 있다. 의미상 capturePoint, appendPointRecord, updatePointRecord, setPointWithdrawn, getAnalysisSourceSnapshot, saveWorkspace(sourceId, state)가 필요한 경계다. UI가 원자료 배열이나 저장 snapshot을 직접 변경하는 API는 제공하지 않는다.

로직 통일은 두 버튼이 같은 `capturePoint` 진입점·신선도·입력 검증·중복 방지·성공/실패 처리를 사용하는 것이다. ON에서 Sample을 다시 복사하거나 OFF에서 아직 없는 Sample ID를 참조하도록 저장 처리를 억지로 같게 만들지 않는다. ON의 후보에 연결된 Sample이 없으면 새 관측을 기다리고, OFF는 Sample+PointRecord를 원자적으로 추가한다. 저장 정책 분기는 이 자료 작성 경계에 한정하고 탭 이름으로 판단하지 않는다.

## 13. 자료 모델과 불변식

### 13.1. 단일 원자료와 점 참조

기존 samples를 센서값의 단일 원본으로 유지한다.

- 연속 기록 ON: 수신값을 기존처럼 samples에 추가. 한 점 기록은 이미 존재하는 Sample을 참조.
- 연속 기록 OFF: 캡처한 수신값만 samples에 추가하고 해당 PointRecord를 함께 수락·저장.
- 이번 조건 초안은 UI에 있고, 캡처·편집 확정 후의 값은 PointRecord에 있음.
- 거리값은 sample.values/validity의 센서 채널에 끼워 넣지 않음.
- importedColumns/importedValues를 편집 가능한 실시간 수동 열의 저장소로 우회 사용하지 않음.
- 기존 sourceSampleId는 가져오기 출처 번호이므로 새 참조 의미로 재사용하지 않음.

목표 레코드의 핵심 형태를 계약 설명용 의사 형식으로 나타낸다. 실행 코드는 아니며 생략된 기존 필드·잠금·출처·한도 계약은 유지한다.

~~~text
Run {
  recordingMode: 'continuous' | 'point' | null, // 저장 정책: ON / OFF / 출처 불명
  manualColumns: [{ id: 'manual-condition', name, unit, type: 'number' }],
  pointDataRevision
}

PointRecord {
  runId, pointRecordId, capturedSampleId,
  capturedAt,
  manualValues: { 'manual-condition': number | null },
  note, withdrawn, revision
}

WorkspaceEnvelope {
  runId, envelopeRevision,
  activeSourceId: 'recorded' | 'points',
  bySource: { recorded?: WorkspaceState, points?: WorkspaceState }
}
~~~

recorded는 연속 자료나 일반 가져오기 자료의 기존 원자료 보기다. 실제 출처에 따라 **연속 기록 / 불러온 자료**로 표시한다. point 방식에서는 중복된 recorded 보기를 노출하지 않고 points만 분석 대상으로 제공한다. 출처가 불명확한 가져오기 자료의 recordingMode는 null이며 연속 측정했다고 추정하지 않는다.

**2026-10-29 호환 결정:** 저장 형식의 `recordingMode`를 그대로 사용한다. `continuous`는 연속 기록 ON, `point`는 OFF이며 이제 선택된 탭을 의미하지 않는다. `skipContinuousRecording` 같은 역방향 플래그와 같은 의미의 boolean을 Run에 중복 저장하지 않는다. UI의 ON/OFF는 이 정책에서 파생하고 시작 전 초안만 Controller에 둔다. 탭 선택은 UI 상태로 분리하며 동일 탭 복원 참조에만 보관한다. 이 변경만으로 DB·JSON 버전을 올릴 필요는 없다. 기존 JSON·Run의 정책, 점 참조, sampleId, provenance, 분석 envelope는 바꾸지 않는다.

OFF의 미리보기에는 분석 가능한 연속 원자료가 없다. 전체 분석·연속 CSV·‘연속 기록에서 보기’ 기능은 노출하지 않으며 점 분석·점 CSV·JSON은 유지한다. 그래프의 점 표식은 캡처한 **수신 시각**에 놓되 해당 시각이 실제 미리보기 구간에 있을 때만 보여 준다. 표식은 기존 점 표로 이동할 수 있지만 사라진 메모리 곡선을 영속 원자료처럼 복원하지 않는다. `recordingMode:null`인 일반 가져오기 자료에는 편집 가능한 연속 기록 설정을 부여하거나 출처를 추정하지 않는다.

### 13.2. 식별자·참조

- Sample의 sampleId는 기존 Run 내부 증가 정수이며 불변이다. 점 분석에 맞추어 다시 번호를 매기지 않는다.
- pointRecordId는 점 목록의 안정적인 증가 번호이고, capturedSampleId는 같은 Run의 실제 Sample을 가리킨다.
- 한 Sample에는 점 기록 하나만 연결한다. 취소한 동일 점을 다시 캡처하려면 새 수신값을 기다리거나 기존 점을 복원한다.
- 동일한 센서 숫자가 새로 수신된 것은 새 관측이므로 반복 기록할 수 있다.
- 캡처 시각·원자료 참조는 생성 후 수정하지 않는다. 조건·메모·취소 상태만 검증된 명령으로 수정한다.
- 원자료와 점을 함께 추가하는 수동 캡처는 둘 다 수락되거나 둘 다 실패한다.
- 캡처 수락 이전에 저장 예산·채널·참조를 검증한다. 실패한 점의 고아 Sample을 남기지 않는다.

### 13.3. 공통 분석 입력

자료 소스 투영은 sourceId, availableIds, rows, sourceColumns, sourceRevision, timeOrigin을 제공한다. points의 분석 행은 원래 sampleId를 identity로 유지하고 PointRecord의 조건값을 읽기용으로 결합한다. pointRecordId는 점 번호·편집 대상으로 별도 전달한다.

모든 사용 경로에서 동일한 열 카탈로그와 readCell 경계를 확장한다. 그래프·계산·표·CSV가 각자 거리값을 읽는 분기를 만들지 않는다. 수동 열은 points에만 존재하고, 연속 원자료 전체에 조건값을 임의로 복사하거나 구간별로 채워 넣지 않는다.

P4에서 Workspace의 연속 ID 가정을 아래 자료 소스 기준으로 변경했다.

| 현재 가정 | 목표 계약 |
|---|---|
| 전체 자료 수와 마지막 sampleId를 같은 의미로 사용 | 원자료 읽기 경계·가용 ID 집합·자료 개수를 구별 |
| 전체 분석의 ID 수가 마지막 번호와 같음 | 전체 분석은 해당 소스의 마지막 적용 입력 스냅샷에 속한 유효 ID 집합과 같음 |
| 같은 Store면 같은 Workspace | Run ID와 sourceId로 작업 상태 식별 |
| 새 자료 = 원자료 개수 증가 | 소스별 추가·조건 수정·정의 변경·취소 revision 비교 |
| 시간 원점 = 현재 표시한 부분집합의 첫 점 | Run의 기존 timeOrigin 또는 전체 원자료의 첫 유효 수신을 유지 |

원자료 samples 배열 자체의 증가 ID·참조 무결성 검증은 유지한다. 희소한 점 자료를 지원한다는 이유로 원자료 검증을 약화하지 않는다. 적용 대상·표에 불러온 자료·임시 살펴보기의 경계를 구분한다.

점 자료의 sourceRevision과 저장 봉투의 envelopeRevision, 자료별 workspaceRevision/analysisInputRevision은 역할이 다르다. 조건 편집 확정은 RunStore의 pointDataRevision과 측정 화면의 미리보기를 갱신한다. 상세 Workspace는 확정된 점 revision을 자동 반영하여 analysisInputRevision과 계산·그래프 캐시를 갱신하며, 연속 자료의 분석 입력에는 영향을 주지 않는다. 연속 자료는 수동 반영 또는 기록 마치기에서 적용 경계를 갱신한다.

RunStore의 saveWorkspace(sourceId, state)는 봉투에서 지정한 자료의 상태만 병합하고 envelopeRevision을 증가시킨다. 다른 자료의 상태를 낡은 봉투 사본으로 덮어쓰지 않는다. 활성 자료 선택만 바뀌면 봉투 revision만 갱신하고 각 자료의 분석 입력 revision은 유지한다. Repository는 봉투 revision으로 충돌·재시도를 검증한다. 적용 입력 경계와 단순 원자료 살펴보기 경계는 봉투 저장·복원에서도 구분한다.

### 13.4. 입력 스냅샷과 근거 사본

점 분석에는 마지막으로 적용한 수동 열·값·포함 상태 사본을 보관한다. 확정 변경은 자동 반영하지만, 읽기 전용이나 저장 실패로 갱신하지 못한 분석도 복원 가능해야 하므로 입력을 revision 번호만으로 표현하지 않는다. 보관 근거의 사본은 자동 반영과 독립적으로 유지한다.

P1의 저장 계약에서 점 분석과 보관 근거는 각각 `inputSnapshot`에 `sourceRevision`, 원자료 읽기 경계 `throughSampleId`, `manualColumns`, 점별 ID·원자료 참조·조건값·취소 상태·revision을 보관한다. 센서값은 이 사본에 복제하지 않는다. 분석 적용 경계를 읽기 경계와 분리할 때는 `appliedThroughSampleId`를 사용하며, 없는 기존 상태는 `tableLastSampleId`를 적용 경계로 해석한다. P4에서 화면의 변경 반영과 시점 탐색을 연결했다.

보관 근거는 사용한 조건값·열 정의를 별도로 고정한다. 측정 표의 최신 값, 상세 분석의 적용 입력 사본, 보관 근거의 사본을 각각 명시적인 갱신 경계로 연결한다. 센서값은 불변 Sample 참조를 재사용하고 불필요하게 반복 복제하지 않는다.

## 14. 저장·파일·호환

### 14.1. 버전과 DB

P1에서 DATABASE.version, run.schemaVersion, JSON fileVersion을 각각 2로 확장했다. 세 버전은 별도 상수로 관리한다. v1 DB는 원자료를 다시 쓰지 않고 구조·실험 메타데이터·분석 봉투만 변환하며, v1 JSON과 기존 지원 파일도 v2 내부 형식으로 변환한다.

- 기존 runs/samples/events/workspaces store와 자료를 삭제·재생성하지 않는다.
- pointRecords store를 [runId, pointRecordId] 키와 Run 조회 인덱스로 추가한다.
- workspaces는 기존 runId 키를 유지하고 자료별 상태를 담는 봉투로 확장한다.
- 구형 workspace는 recorded 상태로 보존한다. 구형 장치 연속 기록은 continuous, 일반 CSV·출처 불명 자료는 기록 방식 미상으로 정규화한다.
- 과거 자료에 점을 임의 생성하거나 기존 범위·근거·해석을 초기화하지 않는다.
- 구조 업그레이드와 레코드 변환은 기존 자료를 유지하는 트랜잭션 경계에서 수행한다. 대용량 변환 전략은 관련 저장 검사를 통과해야 한다.
- 실패 묶음 재시도, 저장 중 추가 revision, 작성 잠금, 읽기 전용·임시 분석, 삭제 원자성을 새 레코드까지 확장한다.
- 저장 완료는 sample·점·작업 봉투를 포함한 트랜잭션 완료 이후에만 응답한다.
- 삭제·가져오기·복제에서 점 레코드와 모든 Run 참조를 함께 처리한다.

### 14.2. 전체 JSON

새 전체 실험 JSON은 기존 run/samples/events와 pointRecords, 수동 열, 자료별 workspace 봉투, 적용 입력 사본·근거를 함께 보관한다. 기존 단수 workspace 위치는 버전 2에서 봉투를 담는 것으로 명시하고 변환을 한 경계에서 처리한다.

v1 및 기존 지원 파일은 기존 변환 경로를 거쳐 손실 없이 읽는다. v2는 누락·잘못된 점 참조, 다른 Run 참조, 중복 ID, 잘못된 수동 값, 불가능한 자료별 범위를 저장 전에 검사한다. 알 수 없는 상위 버전을 일부 필드만 읽어 정상 파일로 받아들이지 않는다. 구형 앱에서 새 형식을 지원한다고 약속하지 않는다.

가져오기 시 새 Run ID를 부여하고 내부 참조를 일관되게 다시 연결한다. 기존 장치 출처·펌웨어 호환 검사를 통과한 파일만 재개할 수 있으며, recordingMode가 있다는 이유로 CSV·출처 불명·임시 분석의 쓰기 권한을 승격하지 않는다.

### 14.3. 내보내기 범위

한 점 CSV는 `point_record_id`, `timestamp`, `elapsed_seconds`, 센서·조건 숫자 열과 메타데이터, `source_sample_id`, `captured_at`, `withdrawn`을 사용한다. 시각은 UTC ISO 형식이며 경과 초는 전체 Run의 원점을 유지한다. 가져온 조건 열은 고정 숫자 열로 변환하고 캡처 출처는 원자료 메타데이터로 보존한다.

| 출력 | 포함 내용 |
|---|---|
| 전체 실험 JSON | 두 자료·원자료 연결·수동 값·자료별 분석·보관 근거 |
| 연속 기록 CSV | 기존 연속 센서 자료와 원래 시간 기준 |
| 한 점 기록 CSV | 점 번호·조건값·센서값·수신 시각·경과 초·캡처 시각·출처 번호·기록 취소 상태 |
| 분석 CSV | 현재 자료의 적용 범위·제외 결과·선택 계산 열 |
| PNG·인쇄 | 현재 자료 또는 보관 근거가 사용하는 정의·값·단위 |

CSV 저장은 자료가 둘일 때 대상 이름과 행 수를 명확히 선택하게 한다. 연속 행과 점 행을 한 표에 섞어 중복 측정처럼 내보내지 않는다. 분석 CSV는 기존 범위·제외 규칙을 유지하고, 원자료용 점 CSV에는 취소 상태를 포함해 원래 점을 확인할 수 있게 한다.

점 CSV만 다시 열면 그 파일의 행을 독립 분석 자료로 취급한다. 조건값은 숫자 열로 사용할 수 있고 원자료 출처 번호는 출처 정보로만 보존한다. 앱의 점 CSV 취소 상태를 인식하여 취소 행은 기본 분석에서 제외하고 가져오기 제외 사유를 남긴다. 제외 복원은 기존 분석 조작으로 제공한다. 다른 실험의 동일 번호와 연결하거나 존재하지 않는 연속 기록 보기를 만들지 않는다. 전체 관계·편집 역할·분석 상태의 정식 왕복 형식은 JSON이다.

현재 파일 크기·행·채널·계산 열 한도를 유지한다. 점 레코드 수는 참조 Sample 수를 넘지 않으며 조건값·메모·입력 사본·근거·workspace 봉투도 직렬화 예산에 포함한다. 내보낸 JSON을 자체 한도 때문에 다시 읽지 못하는 상태를 만들지 않는다.

기존 session·point-capture·RunStore 단위 검사, measurement·point-recording·recovery·copy 브라우저 검사를 보완한다. 탭·문구 문자열이나 버퍼 내부 개수를 고정하는 대신 다음 회귀를 막는다.

- ON의 어느 화면에서도 기록 시작 전 캡처가 Run을 만들지 않는다. 시작 후에는 같은 수신 관측의 중복 점을 막고 같은 숫자의 새 관측은 허용한다.
- OFF의 첫 점 생성 중 탭/토글 변경·연결 전환·저장 실패에도 후보와 정책이 뒤섞이지 않으며 고아 Sample·빈 Run을 남기지 않는다.
- 탭 왕복 중 활성 Run ID·저장 정책·기록 순번·초안이 유지되고, 숨겨진 화면 때문에 수신·저장이 중단되지 않는다.
- 시작 전에는 수동 토글 선택 뒤 다른 탭으로 이동해도 그 탭의 기본값이 다시 적용된다. 시작 후에는 같은 탭 왕복으로 정책이 바뀌지 않는다. ON인 한 점 화면에서도 실제 기록 상태와 일시정지에 접근할 수 있다.
- 정지 시 표시 모델과 실제 차트의 시간축이 함께 고정된다. 정지 중에도 연결 상태·오류·표 편집은 동작하고 재연결만으로 표시/기록이 재개되지 않는다.
- 재개·추가 측정 뒤 새 수신만 받아들이며, OFF에서는 버튼을 누르기 전 점 수가 늘지 않는다. 저장 오류의 재시도도 자동 캡처·자동 재개를 만들지 않는다.
- 정상 지원 빈도와 합성 고빈도에서 실제 최근 60초가 잘리지 않고 실행 시간에 비례해 메모리가 누적되지 않는다. 표시 축약이 저장값·캡처값을 변경하지 않는다.
- OFF의 첫 점 이후에도 시간 그래프는 계속 미리보기를 사용한다. 강제로 전체 범위를 선택하거나 복원해도 최근 범위로 제한된다. 새로고침 후 사라진 버퍼는 복구했다고 표시하지 않는다.
- 기존 JSON의 ON/OFF 정책·원자료·점 참조·분석 근거가 왕복 보존되며, OFF의 미리보기는 내보낸 자료에 포함되지 않는다.

대표 데스크톱·작은 화면·글자 확대에서 탭과 토글의 줄바꿈, 도움말의 터치/키보드 접근, ON인 한 점 화면의 시작 조작, OFF인 그래프 화면의 첫 캡처를 시각 검토한다. 저장 경로가 실제 변경되면 관련 대용량 검사도 포함한다. 커밋 요청 전에는 관련 검사만 실행하며 문서 수정 자체에는 코드 검사를 실행하지 않는다.

## 16. 후속 범위

구간 평균은 순간값과 다른 기록 방식이므로, 추가할 때 구간·샘플 수·집계 방법·원자료 연결과 근거 재현을 함께 설계한다. 자동 증가·조건 순서표·복수 조건 열·반복 측정 통계도 실제 수업 요구를 확인해 확장한다.

micro:bit A/B 버튼 캡처·자동 트리거는 센서 프로그램과 통신 계약의 별도 확장이다. 첫 범위의 앱 버튼 캡처에는 펌웨어 변경이 필요하지 않다. 사후 그래프 선택으로 점을 추가하는 기능과 여러 실험 사이의 비교도 이번 필수 범위에 포함하지 않는다.

완료의 핵심은 **원하는 순간과 조건을 기록하고, 기록 중 편집하며, 기존 분석 도구로 두 자료를 오가고, 선택한 점의 원래 맥락을 확인하는 흐름**이다.
