# M2 구현과 검증

2026-10-19. 앱 홈·센서/활동 직접 진입·맞춤 장비 준비·USB/BLE 어댑터·자기장 측정을 구현했다.
**기능 통합과 UX 보완의 소프트웨어 검증을 마쳤으며, 실물 인수 전이므로 M2 전체 완료는 아니다.**
[M2 UX·재사용 재점검](m2-ux-review.md)의 결정에 따라 준비 UI·활동 안내·측정 표시를 보완했다.
해당 문서의 §7에 원본 대비 반영 결과와 검증 범위를 기록했다. 검토·설계·구현·검증은
서브에이전트 없이 직접 수행했다.

소프트웨어 검사와 실물 검증을 구분한다. **실제 micro:bit V2 설치, 배터리 BLE 수신,
센서 정확도와 자기장 보정 대기 시간은 아직 실물 검증하지 않았다.**

## 사용 흐름

- `lab.html`에서 BMP280·내장 자기장 센서 또는 게이뤼삭 활동을 선택한다.
- `/sensors/bmp280/`, `/sensors/magnetometer/`, `/activities/gay-lussac/`로 직접 들어갈 수 있다.
  개발 서버와 `dist/` 정적 배포 모두 지원하며 프로젝트 하위 경로에서도 자원을 찾는다.
- 준비 화면은 센서별 배선·프로그램·연결·수신, 자기장 보정, 활동별 배터리·배치를 조합한다.
  큰 단계와 세부 단계를 구분하고, 현재 그림과 설명·행동을 나란히 배치한다. 수동 확인은
  다음 단계로 이어지고 이전·단계 탐색은 확인을 만들지 않는다. 준비된 장치 경로도 제공한다.
  USB 설치 완료와 사용자의 확인은 다른 근거다.
- 연결만으로 준비 완료가 되지 않는다. 새 유효값 여러 개가 일정 시간 들어와야 수신이 확인된다.
  자기장은 숫자 수신만으로 보정 완료를 추정하지 않는다. 재연결 뒤에는 보정을 다시 확인한다.
- 기록 시작 버튼을 누르기 전에는 Run과 원자료를 만들지 않는다. 2026-10-24 변경으로
  실험 선택·새 실험 준비로 나가면 분석 초안·기록을 저장한 뒤 연결과 현재 실험을 닫는다.
  저장 실패 시 이동하지 않는다. 미리보기는 선택한 실험 이름을 표시하며 준비 진입 전에는
  장치·기록 권한이 없다. 같은 센서의 새 활동도 이전 연결·준비 확인을 자동 상속하지 않는다.
- 기록 중 다시 연결하려면 먼저 일시정지한다. USB 재설치는 기록 종료·저장 완료·무선 해제 뒤에만
  허용한다. 파일에서 가져온 자료는 장치 연결과 새로운 수신 기록 없이 분석한다.
- 게이뤼삭은 원본 용기 배치 그림과 네 페이지 실험 방법을 제공한다. 안내를 열어도 기록은
  유지되고, 닫으면 호출 버튼으로 초점을 돌려준다. 자동 안내 선호는 활동·안내 버전별로 저장한다.
- 측정 그래프에서 표시 채널과 최근 60초/전체 기록을 고를 수 있다. 자기장 기본 표시는 크기다.
  숨긴 채널도 계속 저장하고, 전체 기록은 미리보기 600개가 아닌 RunStore의 기록 전체다.
  기록의 UTC 시각과 일시정지·재연결 사건을 사용해 그래프의 공백을 표시한다.

기존 저장·분석·JSON/CSV 계약은 [M1 구현 문서](m1-implementation.md)를 따른다.
`?mock=1`은 선택한 센서의 모의 수신이다. 모의 연결도 명시적으로 실행하며 `setup.simulated`
표시를 남긴다. 실제 설치·보정·물리적 배선의 증거가 아니다.

## 재사용과 장치 경계

게이뤼삭 고정 원본 `bme280@59c5c149450f970bace2deaa183857c275595853`의 준비 단계 내용,
진행 확인 로직, USB 전송 흐름, UART 연결·정리와 BMP280 3D 자료를 재사용했다.
원본의 그룹 탐색·설명 높이 고정·이전/행동 버튼·맥락 도움말·실험 방법 탐색을 이식했다.
3D는 배선 안내를 처음 열 때 불러오며, 실패하면 배선표로 전환하고 다시 열 수 있다.
용기 배치에는 `setup.svg`를 사용한다. 활동 그림 네 개는 원본과 바이트 해시가 일치하며
[자원 기록](../public/activities/gay-lussac/README.md)에 선별·변경 이유를 남겼다.

Transport가 실제·모의 장치 모두의 준비 수신 사실을 공급한다. controller의 중복 monitor와
별도 모의 수신 경로를 제거했으며, 늦어진 타이머와 무관하게 호출 시점의 수신 유효성을 판정한다.
GuideProgress는 사용자 확인과 현재 시도의 보정·배터리 근거, Session은 기록·활동 진행을 맡는다.
이전 장치 재연결을 UI에 연결했고 준비·측정 UI와 controller를 JSDoc 타입 검사에 포함했다.

`src/device/firmware.js`의 등록된 HEX만 설치할 수 있다. 파일 메타데이터의 주소·명령으로
설치 대상을 바꾸지 않는다. CRLF를 LF로 정규화한 SHA-256 확인 및 공식 V2 HEX 해석을
장치 접근 전에 완료한다. 사용자 클릭 안에서 USB 선택을 시작하고 V2 확인 후 전체 전송한다.
진행률 100%와 전송 성공은 구분하며 전송 뒤 USB를 정리한다.

BMP280 HEX는 원본을 그대로 보존했다. 자기장 HEX는 이 저장소의
`firmware/examples/magnetometer.js`를 고정된 PXT 환경에서 실제 빌드했다.
기존 `firmware/legacy/magnetometer.hex`는 시작 명령이 달라 새 설치용으로 사용하지 않는다.
빌드 환경과 재현 절차는 [펌웨어 빌드](../dev/firmware/README.md),
[USB 라이브러리 빌드](../dev/usb-library/README.md)를 참고한다.
출처와 라이선스는 [외부 자원 고지](../THIRD_PARTY_NOTICES.md)에 있다.

UART는 분할 UTF-8·여러 행·CRLF를 처리하며 1 KiB 초과 프레임은 다음 개행까지 버린다.
연결 시도마다 수신 상태를 초기화하고 오래된 콜백은 무시한다. BMP280은 `bme` 명령,
첫 유효값 3초·300ms 간격 최대 5회다. 자기장 v2는 `prepare` 뒤 선택 대기 상태를 받고,
앱에서 보정 시작/생략을 선택한다. 보정 시작·완료·생략 응답을 확인하며 보정 대기는 최대 120초다.
두 센서 모두 유효값 3개 이상·1초 이상으로 수신을 확인하고 5초 중단이면 무효화한다.
자기장은 X/Y/Z 성분과 크기 네 채널을 µT로 저장·표시·분석한다.

## 검사 실행과 남은 확인

UX 보완과 준비 안내·등록 정리 후 `npm run typecheck`, Node 검사 **141개**,
브라우저 검사 **32개**, `npm run build`, `git diff --check`가 통과했다.
브라우저 검사 결과와 인수 항목별 근거는 [재점검 §7](m2-ux-review.md#7-구현-반영과-인수-결과)에 있다.
실제 IndexedDB·Web Locks·Chart.js·원본 WebGL을 실행했으며, 통신 입력과 USB 상태는 모의다.

[M1 실행 명령](m1-implementation.md#실행)은 그대로 사용한다. Node 검사는 HEX 해시·공식
V2 해석·빌드 입력, 모의 USB의 취소/실패/잘못된 보드/전송 가드, UART 분할·초과 복구,
연결 시도 경합·센서별 시간 정책, 준비 근거와 뷰어 메시지 경계를 포함한다.

브라우저 러너 `/tests/browser/`는 실제 IndexedDB·Web Locks·Chart.js·원본 3D iframe과
통합 앱 DOM을 사용한다. `?suite=app`은 실험 선택·준비·기록·전환만 다시 검사한다.
`?suite=guide`, `?suite=measurement`, `?suite=layout`은 각각 준비 UI, 표시와 원자료 보존,
실제 iframe 크기별 배치를 검사한다. 1366×768·1920×1080에서는 배선 그림·설명·행동이
한 화면에 들어오고 네 배선 단계의 버튼 높이가 유지됨을 확인한다. 390×844 및 683×384
CSS 영역(1366×768의 200% 확대와 같은 영역)에서 가로 넘침과 팝업 경계를 확인한다.
실제 브라우저 배율 설정과 OS 동작 줄이기 설정을 바꾼 수동 인수는 별도 확인 대상이다.
검사 전용 DB는 고유 이름으로 만들고 종료 시 정리한다. 통합 수신과 USB는 모의이며
실제 장치 검사로 보고하지 않는다.

실물 인수에서는 두 센서의 V2 설치, 케이블 분리·취소·재연결, 배터리 단독 연속 수신,
자기장 보정 완료 및 실제 대기 시간을 확인해야 한다. 장시간 10Hz 기록 성능도 남아 있다.
M3 수업 설정 링크·QR은 구현하지 않았으며 `cfg`가 있는 통합 앱 주소는 지원하지 않는다고
안내한다. 기존 `index.html` 대시보드와 기존 공유 링크는 유지한다.

### 기본 앱·배포 전환 (2026-10-20)

사용자가 기존 앱의 운영 종료를 결정했다. 위의 기존 대시보드 유지 결정은 이 시점부터
적용하지 않는다. 기본 주소와 `lab.html`은 새 센서 실험실을 열며 기존 대시보드 이동 링크는
제거했다. 소스의 `index.html`은 로컬 진입용 연결 페이지이고, 빌드에서는 같은 실험실 HTML을
루트와 센서·활동별 진입 페이지로 생성한다. 이전 대시보드의 `js/`·`styles.css`는 배포하지 않는다.

GitHub Pages는 브랜치 루트 배포에서 GitHub Actions의 `dist/` 배포로 전환한다.
`main` 푸시 때 타입 검사·Node 검사·정적 빌드를 거쳐 배포하며, 이전 빌드의 파일이
남지 않도록 고정된 생성 폴더를 비우고 다시 만든다. 사용자의 브라우저 저장 자료는 건드리지 않는다.

## 2026-10-20 자기장 준비 흐름

연결 → 장치 응답 → 보정 시작/이번 보정 생략 → 보정 중 안내 → 수신 확인으로 이어진다.
수치 카드는 완료 또는 생략 응답 후에 나타난다. 자기장 전용 상태·그림·조작·시간 정책은
센서 모듈에 두고 공통 가이드·Transport는 선택적 준비 확장만 호출한다.
장치 응답으로 자동 진행되는 연결·보정 단계에는 수동 다음 버튼을 두지 않는다.

보정 완료를 사용자가 대신 체크하는 버튼은 제거했다. 생략은 `setup.calibration: skipped`로
DB와 전체 JSON에 남으며 보정 완료 체크를 만들지 않는다. 선택 중에는 기록을 만들지 않고,
완료 신호만으로 기록을 허용하지도 않는다. 새 연결·시간 초과·단절은 근거와 대기 작업을 지운다.

미배포 v1 호환은 요구하지 않는다는 사용자 결정에 따라 설치 허용 목록을 v2로 교체했다.
실제 사용 전 자기장 프로그램을 다시 설치해야 한다. 다른 네 센서의 HEX는 변경하지 않았다.
검증: Node 160개(전체 158개 및 추가한 준비 수명·생략 2개), 타입 검사, 펌웨어 재빌드 일치,
준비 UI 4개·통합 앱 9개·배치 8개 브라우저 검사. DB/JSON의 생략 이력과 CSV 네 채널 보존,
다른 네 센서의 준비·저장·분석을 확인했다. 실제 v2 보드 설치·보정·BLE 응답은 별도 인수가 남아 있다.

후속 사용자 보고(2026-10-20): 자기장 v2 실기기 확인을 완료했다고 알렸다. 이는 사용자의
확인 결과로 기록하며, 개별 오류·시간 초과·배터리·장시간 인수까지 완료했다고 확대하지 않는다.
응답 없음 처리는 모의 입력으로 별도 재검사한다. 연결·알림 준비 후 `prepare` 1회 전송,
10초 내 선택 대기 응답이 없으면 연결·보정 근거·타이머를 정리하고 오류 안내와 재연결을
제공한다. 현재 최초 명령의 전송 실패도 같은 10초 오류 경로로 처리하며 원인을 단정하지 못한다.

## 준비 안내·등록 정리 (2026-10-19)

센서별 준비 단계·그림·도움말을 각 센서의 `guide.js`로, 배터리·용기 배치와 실험 안내를
활동 모듈로 옮겼다. 공통 조립기는 준비물·설치·연결·수신과 세 개의 고정 슬롯만 다룬다.
`src/catalog/modules.js`에 센서·활동 모듈을 등록하면 홈 목록, 진입 주소, codec·모의 입력,
준비 안내, 활동 policy가 함께 연결된다. 기존 데이터 정의와 저장 형식은 유지했다.

검사용 세 번째 내장 센서와 활동으로 공통 코드 수정 없는 등록·경로·준비·실행 연결,
최신/과거 버전 선택, 미등록 버전 거부, 준비 단계 충돌과 확인 생략 방지를 검사했다.
브라우저에서는 기존 두 센서와 게이뤼삭의 준비·3D·기록·분석·저장 및 기존 JSON/CSV
복원을 다시 확인했다. 이 검사는 실물 센서가 아닌 모의 통신을 사용했다.

이 정리에서는 새 센서 기능을 추가하지 않았고 펌웨어 허용 목록을 유지했다.
다음 센서 구현 시 필요한 변경 지점과 검증 순서는 [등록 안내](../src/catalog/README.md)에 있다.

## 펌웨어 빌드 공통화 (2026-10-19)

자기장에 고정된 빌드를 공통 UART 프로필과 대상별 설정으로 분리했다. 기존 온도·온도+밝기
소스를 빌드 전용 대상으로 추가해 실제 컴파일과 공식 V2 해석, HEX 내장 소스·설정 검사를
통과했다. 앱의 센서 카드나 설치 허용 목록은 추가하지 않았다.

자기장 재빌드는 기존 배포 HEX와 동일한 SHA-256을 확인했으며 BMP280 고정 HEX도 유지했다.
결과는 Git에서 제외하는 개발용 후보 폴더에 생성하고, 기존 배포본은 `--check`로 비교한다.
상세 입력·명령·출력 위치와 네이티브 캐시 한계는 [펌웨어 빌드 안내](../dev/firmware/README.md)에 있다.
검증은 세 대상 실제 빌드, 자기장 `--check`, Node 전체 **147개**, 타입 검사, 앱 정적 빌드,
변경 파일 공백 검사를 통과했다. 이번 변경은 개발 빌드 도구에 한정되어 브라우저 검사는
다시 실행하지 않았다. 실제 장치 설치·수신 인수는 수행하지 않았다.

## 내장 온도·밝기·가속도 추가 (2026-10-19)

세 센서를 등록 절차에 따라 독립 모듈로 추가했다. 기존 공통 홈·직접 진입·준비 안내·설치기·
Transport·저장·분석을 사용하며 controller나 분석기에 센서별 분기를 넣지 않았다.
서브에이전트 세 개는 펌웨어, 센서 정의·codec, 준비 안내를 각각 맡았고 개별 검사 없이
구현만 전달했다. 통합 담당자가 단위·채널·간격·준비 근거를 검토하고 검사를 실행했다.

| 센서·직접 진입 | 기록과 표시 | 준비 및 측정 조건 |
|---|---|---|
| `/sensors/temperature/` | `temperatureC`, ℃ (기존 BMP280와 동일 표기), 명목 1초 간격 | 보드 온도 기반 근사. 손·전원·열원 영향을 안내하며 정밀 공기 온도계로 표시하지 않음 |
| `/sensors/light-level/` | `lightLevel`, 0–255 상대값, 명목 100ms 간격 | 앞면 LED의 방향·가림에 주의. lux가 아니며 초기 준비용 값 이후 실제 0은 보존 |
| `/sensors/accelerometer/` | X·Y·Z·크기 네 채널, mg, 명목 100ms 간격 | 중력 포함, ±8g 설정. 기본 그래프는 크기만 표시하고 원자료 네 채널은 모두 저장 |

세 경로는 준비물 → USB·프로그램 → 연결·새 수신 확인으로 이어진다. 불필요한 외장 배선,
자기장 보정, 가열 안내를 붙이지 않는다. 다른 센서로 바꿀 때 이전 설치 확인을 재사용하지
않으며, 각 펌웨어는 단절 후 새 `start`를 기다린다. 밝기의 준비 대기 중 중단·재연결이
생겨도 이전 시작 요청이 송신을 다시 켜지 못하게 했다.

공통 빌드에 밝기·가속도 대상을 등록하고 온도 소스의 연결 상태 처리를 보완했다.
다섯 소스 빌드를 모두 실행해 공식 V2 해석·HEX 내장 소스·프로젝트 설정을 확인했다.
새 센서의 HEX·TS·빌드 기록을 배포 폴더에 넣고 별도 허용 목록에 해시를 고정했다.
기존 자기장 재빌드는 기존 배포 해시와 같으며 BMP280 HEX도 변경하지 않았다.
온도+밝기 결합 예제는 빌드 전용으로 유지한다. 모의 송신도 허용 목록의 센서별 간격을
사용하며, 모의 준비·기록은 실제 장치 근거로 저장하지 않는다.

API 의미는 공식 MakeCode [온도](https://makecode.microbit.org/reference/input/temperature),
[밝기](https://makecode.microbit.org/reference/input/light-level),
[가속도](https://makecode.microbit.org/reference/input/acceleration),
[가속도 범위](https://makecode.microbit.org/reference/input/set-accelerometer-range)를 기준으로 했다.
수신 시각으로 기록하므로 이 간격을 정밀 장치 시각으로 취급하거나 고속 진동 측정을
지원한다고 표시하지 않는다. 구현 완료 시점에는 실제 보드 설치·측정·정확도·무선 성능을 검증하지 않았고
다섯 배포 펌웨어 모두 `hardwareVerified: false`를 유지한다.

통합 검증은 Node **153개**, 브라우저 **35개**, JSDoc 타입 검사와 정적 빌드를 통과했다.
새 센서 각각의 실제 IndexedDB 저장, JSON/CSV 값·단위 보존, 가속도의 숨긴 채널 저장,
분석 화면 진입 및 기존 BMP280·자기장·게이뤼삭 파일 호환을 확인했다. 모의 송신 간격에
따라 샘플 수만 기다리던 가열 검사는 실제 수신 안정 상태를 기다리도록 보완했다.
분석 뒤 다음 실험으로 이동할 때의 저장 확인도 통합 검사에 포함했다.
센서 카드가 늘어난 홈은 폭에 따라 열 수를 조절해 데스크톱에서 두 줄 이내로 보여 준다.
홈 배치 변경 뒤 화면 검사 5개를 다시 실행했다. 1366×768·1920×1080에서 다섯 센서 카드가
첫 화면 안에 있고, 390×844·683×384에서 가로 넘침이 없다. 새 세 센서의 직접 진입과
모든 준비 단계도 확인했다. BLE 입력은 모의이며 이 결과를 실물 검증으로 간주하지 않는다.

## 내장 센서 실기기 기본 확인 (2026-10-19~20)

사용자가 준비한 micro:bit V2 한 대로 새 세 센서의 실제 USB 설치·BLE 수신·기록·저장·
분석 재열기를 확인했다. 온도 33개, 조도 341개, 가속도 364개의 실측 기록을 보존했다.
조도의 명시적 연결 해제·재연결·기록 재개도 통과했다. 수신 간격은 온도 약 1.05초,
조도·가속도 약 0.15초로 관측됐다. 정확도·장시간·배터리 단독 동작·설치 오류 복구 등
전체 인수는 남아 있어 `hardwareVerified`는 변경하지 않았다.
[실측 근거·남은 확인·숫자 변화 시 레이아웃 수정 결과](hardware-acceptance-2026-10-19.md)에
범위를 구분해 기록했다.

2026-10-20 UI 후속 수정에서는 다섯 센서의 측정·준비 값, 상태 표시, 분석 값 읽기·통계·
선택 자료 영역의 크기를 안정화하고 불필요한 내부 설명과 중복 안내를 정리했다.
1366·1920·390·683px 숫자 변화 회귀 검사를 포함해 브라우저 **38개**, 타입 검사,
정적 빌드가 통과했다. 기록·저장·파일 형식과 펌웨어는 변경하지 않았다.

## 준비 체크와 측정 허용 분리 (2026-10-20)

현재 장치의 정상 연속 수신을 확인하면 준비 체크가 비어 있어도 측정 이동·기록 시작·
재개를 허용한다. 설치·보정·배터리·배치 확인 이력은 실제 확인한 것만 보존한다.
수신 중단·새 연결 시에는 새 수신 확인을 요구하고, 기록 생성 중 단절에 대한 취소도
유지한다. 준비 단위 검사 10개, 준비 UI 4개와 앱 통합 9개, 타입 검사·빌드를 통과했다.
자기장과 내장 온도·밝기·가속도에서 체크를 생략한 모의 기록·저장·분석을 검사했으며
실기기 검사를 새로 수행한 것은 아니다.
