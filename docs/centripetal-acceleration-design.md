# 구심가속도 탐구 활동 설계
2026-10-30 · MicrobitSensorDashboard · 설계안(실기기 미검증)

## 목표
수평 회전판에 고정한 micro:bit V2의 가속도 3축과 자기장 3축을 함께 기록한다. 고정 자석의 통과 시각으로 회전 주기를 측정하고, 가속도 센서값으로 별도로 구한 구심가속도와 비교한다. 앱은 계산을 돕지만 학생이 안정 구간·통과점·측정 조건을 선택하고 근거를 설명한다.

## 장치·물리 조건
보드와 배터리를 원판에 단단히 고정하고 자석과 회전부의 충돌·케이블 이탈을 방지한다. 회전축에서 **가속도 센서 칩**까지의 반지름 r을 측정한다. 센서 칩 위치는 보드 버전별 공식 도면과 실물로 검증한 안내 그림을 제공한다. 정지 상태에서 축 방향과 중력 크기 기준을 확인한다. 자석이 한 회전에 정확히 하나의 분명한 신호를 만드는지 느린 회전으로 먼저 검증한다. 자석·배터리·주변 금속의 자기장 간섭을 점검한다.

이상적인 수평 등속 회전에서는 a_period=4π²r/T², a_sensor≈sqrt(mean(|A|)²-g_ref²)이다. |A|는 중력을 포함하는 가속도계의 specific force 크기다. g_ref는 9.80665 m/s² 또는 별도로 선택한 정지 기준 구간의 평균 크기다. 정지 기준은 센서 편향을 완전히 제거하지 않는다. mean(|A|)≤g_ref이면 계산 불가로 표시하며 0으로 대체하지 않는다. 저속에서는 두 크기의 차이가 작아 오차가 증폭된다. 기울기·진동·접선 가속도·센서 축 정렬도 한계로 설명한다. 선택적인 수평 성분 분석은 보조 도구이며 정지 기준 성분과 반지름 방향의 확인이 선행되어야 한다.

## 사용자 흐름과 화면
| 단계 | 학생 활동 | 도구 |
|---|---|---|
| 준비 | 반지름 측정, 배치·고정·안전 확인 | 센서 위치 확대 그림, 반지름·불확도 입력 |
| 신호 확인 | 천천히 2~3회전해 신호 특징 확인 | 자기장 크기/X/Y/Z 전환, 확대, 임시 통과점 |
| 측정 | 안정 회전 구간 기록, 메모 | 가속도 주 그래프·자기장 보조 그래프, 공유 시간 커서 |
| 분석 | 구간 선택, 통과점 수정, 회전별 주기 검토 | 피크 제안 편집기, 주기표, 주기 분포, 가속도 통계 |
| 비교 | 계산과 차이 해석, 근거 보관 | 수식 전개, 비교표, 원자료 링크, 탐구 질문 |

가속도·자기장 그래프는 서로 다른 단위를 분리하고 시간축·선택 구간·커서를 공유한다. 그래프 축과 채널은 독립적으로 전환할 수 있다. 실시간 그래프는 표시용 축약을 허용하되 극값·결측을 보존하고 계산에는 원자료만 쓴다. 단계 이동은 자유롭고 결과를 정답처럼 채점하지 않는다.

## 특화 분석 도구
### 통과점 편집기
학생이 먼저 안정 구간을 드래그한다. 앱은 선택한 자기장 채널의 피크/골을 후보로 제안한다. 검출 방향, 최소 간격, 돌출 정도(prominence), 평활화 폭은 조절 가능하며 초기값은 실측 후 정한다. 후보와 승인점을 구별하고 클릭·키보드로 승인/삭제/추가/위치 이동할 수 있다. 각 표식에는 원본 sample ID·보드 시각이 연결된다. 원파형은 수정하지 않는다. 비정상적으로 짧거나 긴 간격과 결측은 '중복·누락 가능'으로 표시한다. 누락된 회전을 추정해 자동 연결하지 않는다. 신호가 불명확하면 수동 통과점 또는 별도 측정한 회전수·시간을 출처와 함께 입력할 수 있다.

### 회전별 주기 분석
승인된 인접 통과점 ti,ti+1의 차이를 Ti로 표·그래프에 보여 주고 클릭하면 원파형의 해당 회전을 강조한다. 연속 유효 구간에서는 평균 T=(t_last-t_first)/(n-1). 일부 회전을 제외하면 **포함한 회전의 시간 합 / 포함 회전수**로 계산하며 서로 떨어진 구간을 한 긴 회전으로 잇지 않는다. 회전별 주기 범위·표준편차·변동계수를 보여 주지만 등속 여부는 학생이 판단한다. 후보 구간과 실제 계산에 사용한 완전 회전 구간을 시각적으로 구별한다.

### 가속도 분석
주기에 사용한 것과 **동일한 유효 회전 구간들의 합집합**에서 |A| 평균·표준편차·표본수·최솟값·최댓값·결측률을 구한다. 불규칙 샘플링에서는 큰 공백을 제외한 시간 가중 평균을 기본으로 하며 구간 경계 처리·보간 정책을 명시한다. 정지 기준 구간은 회전 구간과 독립된 선택 객체로 보관한다. 수식에 넣은 평균, 기준 중력, 계산 가능 여부와 오차 민감도를 보여 준다. 보조 수평 성분 방식은 장착 방향·정지 기준 검증 후 선택적으로 연다.

### 비교·해석
a_period와 a_sensor, 절대 차이, |a_sensor-a_period|/a_period×100%를 보여 준다. 주기 기반 값 역시 r과 T의 측정 오차를 포함하므로 참값으로 단정하지 않는다. 유효 숫자와 반지름 불확도를 반영하고 의미 없는 자릿수는 숨긴다. 질문: '어떤 신호를 한 바퀴의 기준으로 정했나요?', '주기는 얼마나 일정했나요?', '차이의 원인을 어떤 자료로 설명할 수 있나요?' 계산 근거는 학생이 확정한 뒤 보관한다.

## 펌웨어·전송 계약
기존 가속도·자기장 단독 프로그램과 별도로 복합 센서 펌웨어를 등록한다. 같은 루프에서 A_x/y/z, B_x/y/z를 순차 읽으며 측정 묶음마다 boot/session ID, 증가하는 seq, 보드 경과 ms, 유효성·상태를 남긴다. 완전 동시 측정이라고 표시하지 않는다. 벡터 크기는 앱에서 원 성분으로 계산한다. 보드 타이머 래핑·재시작은 세션 경계로 다룬다.

측정 간격과 BLE 전송 간격을 분리한다. 링 버퍼는 유한하므로 초과 시 버린 개수와 seq 공백을 보고한다. BLE UART의 작은 알림 조각을 고려해 프레임 분할·재조립·길이·버전·순번·중복 검증을 설계한다. 묶음 크기와 20/50/100ms 같은 후보 수집 간격은 실제 센서 갱신률·피크 폭·전송량을 실측해 결정한다. 수집·전송 지연은 주기 계산에 반영하지 않는다. 기록 시작·정지·재개는 보드 seq 경계와 ACK를 확인하고 이전 버퍼의 지연 도착을 소급 기록하지 않는다. 재연결·누락 구간을 주기로 잇지 않는다.

현재 앱의 Sample.receivedAt은 브라우저 UTC 수신 시각이다. 이를 보드 시각으로 바꾸지 말고 boardElapsedMs·seq·sessionId를 별도 보관하고 **활동 전용 분석 시간 투영**을 사용한다. 수신 시각은 진단용으로 유지한다. 과거 단독 센서 자료와 기존 분석 시간축을 훼손하지 않는다.

## 저장·재현
기존 불변 Samples, Events, RunStore, Workspace, JSON/CSV와 원자료 근거 저장을 재사용한다. 활동 분석 상태에는 선택 채널, 후보 구간, 승인/거부 통과점의 원자료 참조, 제외 회전과 사유, 실제 계산 구간, 반지름·불확도, 정지 기준 구간·값, 평균 방법, 계산 버전, 학생 메모와 고정 근거를 저장한다. 값 수정 시 최신 결과는 재계산하되 과거 근거는 명시적 교체 전까지 유지한다. JSON 왕복·CSV/PNG/인쇄에서 출처와 계산 조건을 보존한다. 기존 JSON v2에 무검증 필드를 추가하지 않고 schema/validation·버전 호환을 먼저 설계한다. '한 점 기록'과 여러 회전의 구간 집계를 서로 다른 자료로 취급한다.

## 기존 모듈과 결합
- src/catalog/sensors 및 activities: 복합 센서 definition/codec/guide, 구심가속도 activity/policy/questions. registry와 기존 준비 화면 재사용.
- firmware/examples, dev/firmware/targets.json: 별도 펌웨어 ID·버전. 정식 기존 HEX/BIN 덮어쓰기 금지. 공통 런타임 호환 검증.
- src/device/ble-client.js, transport.js: UART 연결·재연결 재사용, 배치 프레이밍과 seq/ACK는 별도 모듈.
- src/measurement/session.js, reception-monitor.js: 기존 수명·저장 게이트 유지, 선택적 보드 수집 경계와 결측 이벤트 확장.
- src/analysis/workspace.js, scope.js: 범위·계산·근거 재사용. src/analysis/activities/centripetal/에 피크 제안·주기·구간 집계 순수 함수 분리.
- src/ui: 기존 그래프·공유 커서·시각 디자인 문법(docs/design/visual-language.md, tokens.css) 재사용. 활동별 통과점 오버레이와 주기표·비교 패널만 추가.
- src/data/files: 새 메타데이터 검증·왕복·구형 파일 호환 테스트. 일반 센서의 시각·저장 의미 유지.

## 구현 단계와 수용 기준
| 단계 | 작업 | 통과 기준 |
|---|---|---|
| C0 | 실제 원판·자석에서 임시 펌웨어로 신호 수집 | 갱신률·피크 수/폭·자기장 간섭·BLE 누락·센서 포화·버퍼 용량 측정 |
| C1 | 복합 펌웨어·배치 전송·보드 시각·저장 | 분할/지연/중복/누락/재부팅/일시정지 경계가 정확히 보존 |
| C2 | 공유 그래프·통과점 편집·회전별 주기표 | 피크 추가/삭제/이동과 회전 제외가 원자료를 바꾸지 않고 재계산 |
| C3 | 동일 구간 가속도 집계·기준 중력·비교·근거 | 계산 조건 불충족 시 명시적 실패, JSON 왕복·CSV/PNG 재현 |
| C4 | 여러 속도·반지름 관계 그래프 | 후속 확장; 첫 버전 필수 아님 |

검사는 변경 범위 중심으로 수행한다. 합성 데이터로 일정/가속/감속 회전, 2중 피크, 누락, jitter, BLE 묶음 도착, 시간 래핑, 불규칙 샘플링, 정지 기준보다 작은 평균, 기울어진 보드, 낮은 신호 대 잡음비를 검증한다. 모의 검증과 실기기 검증을 구분한다. 실측 C0를 통과하기 전에는 검출 기본값·수집 주기·측정 정확도를 확정하지 않는다.
